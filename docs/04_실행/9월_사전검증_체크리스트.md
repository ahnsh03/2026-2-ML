## ① 라벨 분산 확인 — 반나절

**무엇을**: v4 val 1,404장에 대해 **프레임별 IoU 히스토그램**을 그린다.

```
대상: data/dataset_versions/twinlite_morai_v4_comp8_train_val_sample_b/val.jsonl
산출: lane IoU / front lane IoU / drivable IoU 각각의 분포
```

**판정 기준**

| 결과 | 조치 |
|---|---|
| lane IoU 또는 front lane IoU에 충분한 분산이 있다 | 통과 → 타깃 확정, τ 결정 |
| 분산이 부족하다 | `data/rejected_runs/` 와 foggy 계열 run 추가 후 재확인 |
| 그래도 부족하다 | → **[B1 휠 슬립·stuck 검출](../02_주제후보/B1_휠슬립_stuck검출.md)** 로 전환 |

> **주의**: drivable IoU는 현재 0.9842로 분산이 거의 없다. 이 값은 타깃으로 쓰지 않는다.
> lane IoU 0.8930, front lane IoU 0.8015가 후보다.

## ② 베이스라인 신호 확인 — 하루

**무엇을**: feature CSV를 만들고 logistic regression을 돌려 본다.

```
산출: frame_features.csv
컬럼: sample_id, run_id, view, weather, sim_time,
      <영상 통계 feature 10~15개>, <확률맵 통계 feature 10~15개>,
      lane_iou, front_lane_iou, drivable_iou
```

**판정 기준**

| 결과 | 조치 |
|---|---|
| **ROC-AUC ≥ 0.7** | 통과 → 주제 확정 |
| 0.6 ~ 0.7 | feature 보강(시계열·멀티뷰) 후 재확인 |
| < 0.6 | → **B1으로 전환** |

이 CSV는 그대로 팀원 배포용이 된다. 만들어 두면 이후 모든 작업의 기반이 된다.

## ③ 센서 정합 가능성 확인 — 3인이 30분 `[A2 전용]`

**무엇을**: 손재호의 LiDAR 출력과 장원태의 MGeo bake를 **카메라 프레임 타임스탬프에 맞출 수 있는지**
세 사람이 같이 확인한다.

**확인 항목**

- [ ] LiDAR 출력에 카메라 프레임과 대응 가능한 타임스탬프가 있는가
- [ ] 좌표계(ego / map)와 변환이 명확한가
- [ ] MGeo bake 산출물의 좌표·버전이 capture run과 일치하는가
- [ ] 세 출처를 같은 run에 대해 동시에 재생할 수 있는가

> "공통 BEV 범위·해상도·ego origin·확률 표현"은 **먼저 정해야 하는 항목**이다.
> 이 프로젝트가 그 사전 실험이 되지만, 10주 안에 합의까지 끌고 갈 수는 없다.
> **정합만 되면 충분하고, 표준화는 목표가 아니다.**

**판정 기준**

| 결과 | 조치 |
|---|---|
| 세 출처를 프레임 단위로 붙일 수 있다 | → **[A2 센서 불일치](../02_주제후보/A2_센서불일치_인지실패예측.md)** 확정 |
| LiDAR만 붙는다 | A2에서 지도 feature를 빼고 진행 (2센서 버전) |
| 어느 쪽도 어렵다 | → **[A1 카메라 단독](../02_주제후보/A1_카메라_인지신뢰도_예측기.md)** 으로 축소. LiDAR·지도는 분석 축으로만 |
