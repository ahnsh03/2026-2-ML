## 세부 설계 취합 시 맞출 규약

- checkpoint SHA·binary class 정책·입력 해상도·primary target. 현재 초안은 M/384×640/`lane_full`.
- 부모 세션·f0 학습 노출과 meta 역할 구분, final_test 접근 담당.
- ROI는 개발 데이터에서만 정하고 test를 보며 수정하지 않기.
- X에는 output-only 열만 사용. GT·환경·장소는 label/분석 metadata로 분리.
- 파일 소유권과 sample_id·버전·해시 규약. 팀원은 작은 feature/label 표로 GPU 없이 모델·평가 작업 가능.

## 진행 판단과 축소 기준

| 시점 | 문제 | 대응 |
|---|---|---|
| W1 | 기존 capture/cache와 M 기하가 맞지 않음 | 새 기능보다 같은 모델·정책의 작은 parity fixture부터 해결 |
| W2 | 새 독립 세션 또는 실제 실패가 부족함 | GT 평가로 수집 조건을 설계하되 final_test는 보지 않음. PCA/시간 특징 추가보다 수집 우선 |
| W3 | ROI가 baseline보다 좋지 않음 | 전체 통계 모델을 유지하고 ROI의 무효/조건 의존성도 결과로 보고 |
| W3 | g가 confidence보다 낫지 않음 | GT/기하 누수·background 집계·표본/과신 사례 점검. 이득을 약속하거나 test로 튜닝하지 않음 |
| W4 | 필수 결과·GPU 시간이 부족함 | 추가학습·temporal·실시간 연결을 제외. 품질/선별/한계 분석은 완료 |
| W5 | 새 아이디어가 생김 | 고정 test와 결과를 유지하고 향후 연구로 기록 |

추가학습 실험을 생략하면 최종 제목·결론도 **품질 추정과 검수 선별**에 맞춘다.
필수 지표를 얻기 전에 모델 전이·conformal 보장·실차 fail-safe를 필수 작업으로 늘리지 않는다.
