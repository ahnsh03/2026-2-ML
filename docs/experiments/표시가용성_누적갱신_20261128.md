# 표시 가용성과 누적 인지 갱신 — 진행 중

11월28일19시까지의 자율 개발·실험 단위다. 사용자는 기존 재학습 모델 중 좋은 인지모델을 개발 기준으로 승격하고, 새 데이터 분류·추가학습·RF/GP·불확실성·군집·BO를 새 독립 확인까지 연결하도록 요청했다. 이 문서는 실행 중이며 미완료 항목을 채택으로 읽지 않는다.

## 개발 인지 기준 승격

`m-v6-r1-20261128`을 인지 개발 기준으로 등록했다. 체크포인트 SHA는 `dddcc0164ea5b6782049605318c235166dbacc94153406c6dbcac8c170504e2a`다. 원래 성능 유지 기준을 통과한 원시 가중치 중 기존 표시 도로3개와 이미 개봉한 유효 표시 도로1개를 동일 가중으로 합친 IoU가0.75565로 가장 높았다. 이미 개봉한 자료는 과거 근거이며 이번의 새 독립 시험이 아니다. 원래v6는 불변 대조로 보존한다.

인지 기준 승격은 [직전 검수 정책의 보류](환경검증_전체원본재생_20261128.md)를 해제하지 않는다. [버전 등록부](../../config/perception_releases.json)와 [현재 버전 로더](../../src/quality_estimation/active_perception.py)가 인지 가중치와 학습 계보를 검증한다. 실제 경로는 로컬 `ML_ACTIVE_PERCEPTION_RUN` 또는 명시 인수로 전달한다.

```bash
PYTHONPATH=src:ros/src/data_collection/src python3 -m quality_estimation.active_perception \
  --adaptation-run "$ML_ACTIVE_PERCEPTION_RUN"
```

## 이번 비교의 순서

1. **자료와 검수 목표:** Q와 표시 가용성·근거리 FN/FP·미지원 사유를 분리한다. 무출력을 일괄 제외하지 않는다. 기존 자료에서 새벽·무표시 지원을 확인하고, 학습에 편입한 과거 진단/확인은 시험 지위를 명시적으로 폐기한다.
2. **누적 학습:** 새 후보2,048장을 먼저 환경별로 선별한다. 원본26,001장과 부모가 이미 학습한3,072장을 모두 replay에 보존한다. 부모에서 출발하고 새 은행에 과거 노출 프레임이 섞이지 않도록 [누적 계보 검사](../../src/quality_estimation/adaptation_lineage.py)를 적용한다.
3. **방법 결정:** 고정9영역에서 RF·GP와 검수 가치 목표를 같은 역할·예산으로 비교한다. GP SD는 실패 자체로 해석하지 않고 잔차 보정·보류/감사 예산에서의 이득을 검증한다. 환경 분류·군집 해석·데이터 선별 이득을 따로 판단한다.
4. **BO·군집:** 공식 구현·논문 기준 BO를 동일 예산 무작위와 비교하고 합집합에서 후보를 고른다. BO와 e-means는 실제 이득이 있을 때만 채택한다. 시뮬 환경 태그는 오프라인 대조/정답이며 RGB 없는 온라인 입력으로 사용하지 않는다.
5. **새 확인과 갱신:** 모델·특징·기준을 먼저 고정하고 새 장면/날씨의 독립 확인을 연다. 인지모델의 채택과 검수 정책 채택을 따로 기록한다. 가중치가 바뀌면 X/y·품질모델·보정·정책도 새 버전으로 만든다.

## 재현과 현재 구현

[누적 학습기](../../src/quality_estimation/retrain_streaming.py)의 `--parent-adaptation-run`은 프로토콜에 고정한 부모 신원과 전체 부모 학습 구성원을 검증한다. 새로운 은행의 기존 ID/픽셀 재사용, 부모 replay 누락/변조, resume 시 부모 변경을 거부한다. 기존의 같은v6 출발 비교 경로는 유지한다. 현재40/50 두 의존성 이미지에서 CPU287검사가 통과했다. 실제 누적 역전파·장시간 학습·새 독립 확인 결과는 실행 뒤 추가한다.
