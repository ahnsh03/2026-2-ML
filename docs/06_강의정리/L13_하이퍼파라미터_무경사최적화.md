# L13. 하이퍼파라미터 튜닝과 무경사(gradient-free) 최적화

> 작년 강의영상: "Lecture 13 - Gradient-free optimization" (`7IeMtSqjoTU`) — 자동 자막 기반 · 기준일 2026-09-25

## 한눈에

- 하이퍼파라미터 튜닝과 모델 선택은 **기울기를 쓸 수 없는 최적화 문제**다. 변수가 이산·혼합형이고, 목적함수(교차검증 점수)가 블랙박스이며 잡음이 섞여 있다.
- 후보는 교차검증으로 평가하고, **test 데이터로는 튜닝하지 않는다**.
- grid search는 조합 수가 지수적으로 늘고, 중요하지 않은 축에 예산을 낭비한다. 그래서 **같은 예산이면 random search가 더 낫다**.
- random search를 개선하는 네 계열을 본다: ① 기울기 모사(FD·ES·SPSA) ② 국소 탐색(hill climbing·pattern search) ③ 개체군(GA·PSO·ACO) ④ 표본 분포 갱신(random shooting·CEM·MPPI·CMA-ES).
- 교수님 결론: 튜닝은 "웬만해서 랜덤 서치면" 되고, 더 해 보고 싶으면 CMA-ES·MPPI·CEM을 쓴다.

## 핵심 내용

### 1. 최적화 문제와 볼록성 (p.2–3)

- 일반형은 `minimize_x J(x)  s.t.  f_i(x) ≤ 0 (i=1..k),  h_j(x) = 0 (j=1..l)`이다. J는 목적함수, f·h는 제약이다.
- 지금까지 배운 것도 전부 최적화다. 선형회귀 `min_w ||Xw − y||^2`, 로지스틱 회귀 `min_w Σ_i log(1 + exp(−y_i x_iᵀ w))`, MLE `max_θ Σ_i log p_θ(x_i)`, K-means `min_μ Σ_j Σ_{x∈C_j} ||x − μ_j||^2`.
- 볼록 문제는 최소점이 하나뿐이고(local = global), 기울기만 따라가면 도달한다. 비볼록 문제는 local minimum이 여러 개이고 초기점에 따라 결과가 달라진다.
- (강의 설명) 교수님은 "대부분의 문제는 넌컨벡스 옵티마이션"이라고 했다.

### 2. 왜 gradient-free인가 (p.4)

| 상황 | 예 |
|---|---|
| 기울기를 **계산할 수 없다** | 불연속·비매끄러운 설계공간(이산·혼합정수 변수), ML 하이퍼파라미터(learning rate, kernel 종류, 정규화 선택), 해석적 미분이 없는 블랙박스 시뮬레이터 |
| 기울기를 따라가는 것이 **비효율·불안정하다** | 기울기 계산·근사 비용이 함수 평가보다 지나치게 큼, 목적·제약에 잡음이나 확률성이 있음, local minimum이 많아 기울기가 탐색을 오도함 |

- 슬라이드는 gradient-free 방법이 전역 최적을 찾을 가능성이 더 높다고 정리한다.
- (강의 설명) K-means의 K는 1, 2, 3…만 가능하고 1.1개 같은 값은 없다. 그래서 K를 미분 기반으로 최적화할 수 없다.

### 3. 튜닝의 범위와 교차검증 (p.5–8)

- **Model selection**: 어떤 입력 feature를 넣을지, 어떤 전처리를 할지, 어떤 ML 방법을 쓸지 고른다.
- **Hyperparameter tuning**: 예를 들어 kNN의 `k`와 거리 metric(Euclidean 등)을 고른다.
- 교차검증 오차가 가장 작은 모델·하이퍼파라미터를 고른다. p.6 그림은 전체 데이터를 training/test로 나누고, training을 5 fold로 나눠 split마다 한 fold를 검증에 쓰는 구조다("Finding parameters"). test는 마지막 "Final evaluation"에만 쓴다.
- 와인 품질 예(p.7–8): feature 후보는 winter rain, summer temp, harvest rain, September temp, age이고 모델은 kNN이다.
- (강의 설명) 단위가 다른 feature(강수량 1~1000 mm, 기온 20~30 °C)로 Euclidean 거리를 재면 스케일이 큰 feature만 쓰이고 나머지는 무시된다. 그래서 scaler 선택도 튜닝 대상이다.

### 4. Grid search와 휴리스틱 (p.9–10)

- 예시: `k ∈ {1..6}` × metric {Manhattan, Euclidean} = 12, scaler 2종(standard, minmax), feature 5개의 포함 여부 `2^5 = 32` → `32 × 12 × 2 = 768`개 모델.
- 큰 데이터에서는 모든 조합을 시도할 수 없다. 그래서 최적은 보장하지 않지만 실전에서 잘 되는 휴리스틱을 쓴다.
  - **Randomized search**: 파라미터 조합을 무작위로 시도한다.
  - **Coordinate optimization**: 모든 파라미터를 초기 추정값으로 둔 뒤, 한 파라미터만 가능한 값을 모두 시도해(나머지 고정) 최적값으로 고정하고, 다음 파라미터로 넘어가며 순환한다.
- (강의 설명) metric을 먼저 비교해 Manhattan으로 고정하고, 그다음 k를 1~6 중에서 고르는 식이다. "축마다 좋으면 합쳐도 좋을 것"이라는 믿음이 깔려 있다. (보충) 파라미터 사이 상호작용이 크면 이 가정이 틀릴 수 있다.

### 5. Random search (p.11–13) ★

- 매 반복마다 탐색공간 전체에서 완전히 무작위로 새 위치를 뽑는다.
- 이론적 성질: 결정적(deterministic) 목적함수에 적합하고, 확률수렴한다. **hitting probability**는 ε-최적 영역에 확률 p 이상으로 착지하는 것을 말한다.
- 장점: 구현이 매우 쉽다. 매끄러움·연속성을 가정하지 않는다. i.i.d. 표본이라 완전 병렬이 가능하고, 모든 점을 미리 생성할 수 있다.
- 단점: 연속성·기울기를 쓰는 방법보다 수렴이 느리다. 좋은 확률 보장을 얻으려면 N이 커야 한다.
- **grid보다 나은 이유** (p.11 그림: 가로 Important parameter, 세로 Unimportant parameter, 각 9점)
  - grid 3×3은 중요한 축에서 **서로 다른 값을 3개만** 본다. 중요하지 않은 축 방향으로 쓴 나머지 6번은 사실상 중복 실험이다.
  - random 9점은 중요한 축에서 서로 다른 값을 9개 본다. 그래서 좁은 최적 구간을 맞힐 확률이 높다.
  - p.13: grid는 미리 정한 방향을 따라 체계적으로 훑기 때문에, 시작점과 방향이 나쁘면 좋은 영역에 도달하기까지 오래 걸린다.
  - (보충) p.11 그림은 Bergstra & Bengio (2012, JMLR) "Random Search for Hyper-Parameter Optimization"의 그림 1이다. 핵심은 성능을 좌우하는 **유효 차원이 낮다**는 관찰이다.
- (보충) hitting probability 계산: 전체 공간에서 부피 비율이 v인 "좋은 영역"에 N개의 i.i.d. 균등표본 중 하나 이상이 떨어질 확률은 `1 − (1 − v)^N`이다. 상위 5% 영역(v = 0.05)을 95% 확률로 맞히려면 `N ≥ ln(0.05)/ln(0.95) ≈ 59`, 즉 약 60회면 된다. 이 값은 **차원 수와 무관하다**. 차원마다 곱으로 늘어나는 grid와 다른 점이다.

### 6. 기울기 모사 방법 (p.14–17)

random search는 눈을 감고 탐색한다(상태공간 구조와 이력을 무시한다). 정보가 모이면 탐색 방향을 유도할 수 있다.
슬라이드는 두 가지를 구분한다. **Gradient-free**는 진짜 기울기가 없거나 잡음일 때 표본 섭동으로 기울기를 근사하는 방법이다. **Derivative-free**는 기울기를 근사하지 않고 함수값만으로 표본 위치를 유도한다(유망한 영역을 더 탐색한다).
교수님은 앞의 것을 "그레디언트 라이크"라고 부르면 덜 헷갈린다고 했다.

| 방법 | 기울기 추정 | 추정 1회 비용 | 특징 |
|---|---|---|---|
| Finite difference (p.15) | 전진 `f'_j = (f(x + h e_j) − f(x)) / h`, 중앙 `f'_j = (f(x + h e_j) − f(x − h e_j)) / (2h)` (후진 차분도 그림에 있음) | 차원 d에 비례 | 단순하고 투명하다. 차원이 커지면 나빠지고, 잡음·미분 불가능한 점에 민감하다 |
| Evolution strategy (p.16) | 현재 평균 주변에 가우시안 잡음으로 표본을 뽑고, 보상 가중 평균으로 기울기를 추정 | 표본 n개 | 고차원에서 FD보다 표본 효율적이다. **Nesterov's random search**는 과거 업데이트의 모멘텀으로 가속한다 |
| SPSA (p.17) | 무작위 `Δ ∈ {±1}^d`, `ĝ_j = (f(x + cΔ) − f(x − cΔ)) / (2c Δ_j)` | **차원과 무관하게 2번** | 기울기 근사의 극단적인 경우다. 초고차원·잡음 문제에 좋지만 ES보다 분산이 크다 |

- ES 업데이트(강의 중 유도, 슬라이드에는 식 없음): `ε_i ~ N(0, I)`, `ω_new = ω + η · (1/(nσ)) · Σ_i F(ω + σ ε_i) ε_i`. 근거는 `∇_μ E[F(μ + σε)] = (1/σ) E[F(μ + σε) ε]`(log-likelihood trick)이다.
- (강의 설명) 딥러닝처럼 파라미터가 10^6~10^9개이면 FD는 그만큼 함수를 평가해야 해서 비효율적이다. SPSA는 "스토캐스틱 그레디언트와 비슷한 느낌"이라고 설명했다.

### 7. 도함수 없는 국소 탐색 (p.18–20)

- **Hill climbing**: ε-근방의 이웃 n개를 평가해 가장 좋은 곳으로 옮긴다(탐욕적 국소 개선). 매끄러운 지형에서는 잘 되지만 local optimum에 갇힌다.
- 변형: **stochastic**은 더 나쁜 위치로도 확률적으로 이동한다. **random restart**는 n회 반복한 뒤 무작위 위치로 옮겨 다시 시작한다.
- **Pattern search**: 주어진 step 크기로 방향 집합(예: 상하좌우)을 탐색한다. 개선이 있으면 이동하고 step을 키울 수 있으며, 없으면 step을 줄여 다시 시도한다. 잡음·비매끄러움에 강건하지만 ill-conditioned 지형에서는 비효율적이다. (강의 설명) 변수 공간이 잘 정의되어 있을 때 쓸 수 있다.

### 8. 개체군 기반 메타휴리스틱 (p.21–33)

- Local search는 현재 해의 근방만 탐색한다. 매끄러운 저차원 문제에서 효율적이지만 local optimum에 쉽게 갇히고, stochastic·random restart도 부분적으로만 전역적이다. Global search는 전체 공간을 체계적으로 탐색하며, 개체군(population) 기반과 분포(distribution) 기반이 있다.
- **Genetic algorithm (GA)**: 자연 진화를 모방한다(mutation, selection, crossover). 핵심은 "select the best, discard the rest"다.
  - 이진 인코딩(p.25–26): 행동 4개를 2비트(00/01/10/11)로 나타내 행동열을 비트열로 만든다. 적합도(fitness)를 평가하고, 적합도 순으로 선택 확률을 준다. 다음 세대는 elitism, replication, crossover, mutation으로 만든다.
  - 실수 인코딩(p.27): θ를 255단계로 binning하면 127/255 `01111111`과 128/255 `10000000`처럼 **값은 인접한데 비트는 전부 다르다**. 그래서 유전자를 실수 `[1.2, 3.5, …]`로 두고, crossover는 `child = α x^(1) + (1 − α) x^(2)`, mutation은 `child = x + N(0, σ^2)`로 한다.
  - 장점: 점 하나가 아니라 개체군을 병렬로 탐색하고 병렬화가 쉽다. 이산·연속 혼합 문제에 잘 맞고, 이해·설정이 쉽다. 단점: 수렴이 튜닝 파라미터(mutation·crossover 비율)에 크게 좌우되고, 제약을 반영하기 번거로우며, 명확한 종료 기준이 없다.
- **Particle Swarm Optimization (PSO)** (p.29–32): 새 떼가 먹이를 찾는 행동을 모방한다. 각 입자는 위치 `x_i`, 속도 `v_i`, 개인 최고 위치 `p_i`를 갖고, 전체가 전역 최고 위치 `g`를 공유한다.
  - `x_i(t+1) = x_i(t) + v_i(t+1)`
  - `v_i(t+1) = w v_i(t) + c1 r1 (p_i − x_i(t)) + c2 r2 (g − x_i(t))`. 세 항은 순서대로 inertia(같은 방향 유지), cognitive(자기 최고 위치로 당김), social(무리 최고 위치로 당김)이고, `r1, r2`는 확률성을 주는 난수다.
  - 장점: 간단하고, 고차원·비선형·잡음 문제에서 잘 된다. 단점: local minimum으로 조기 수렴할 수 있고, 파라미터에 민감하며, 이론적 수렴 보장이 없다. 응용 예로 제어 시스템 파라미터 튜닝을 든다.
- 기타 군집지능(p.33): ACO(이산 영역, 경로 최적화·TSP), BFO, ABC, Firefly 등이 있다.

### 9. 확률적 표본 기반 최적화 (p.34–37)

- 기울기 정보가 필요 없고, 무작위성으로 공간을 탐색한다. 기울기 방법보다 local minimum 탈출에 유리하고 병렬화할 수 있지만, 고차원으로 가면 나빠진다. (강의 설명) 1차·2차 방법과 비교해 "0차" 방법이다.
- 아래에서 `A = {a_t, …, a_{t+H}}`는 행동열이고, 표본 `A_1 … A_n`을 뽑는다.

| 방법 | 절차 | 분포 갱신 방식 |
|---|---|---|
| Random shooting | 어떤 분포(예: 균등)에서 `A_1..A_n`을 뽑고, return이 최대인 `A_i`를 고른다("guess and check") | 없음. 한 번 뿌리고 끝낸다. 사전지식으로 표본 분포를 개선할 수 있는지가 다음 질문이다 |
| CEM | `p(A)`에서 표본 → 평가 → elite `A_{i1}..A_{im}` 선택 → `p(A)`를 elite에 refit → 수렴할 때까지 반복 | elite(예: 상위 10%)만 동일 가중으로 쓴다 |
| MPPI | `p(A) ~ N(μ, Σ)`에서 표본 → 비용 `C_1..C_n` → `w_i = exp(−C_i/λ) / Σ_j exp(−C_j/λ)` → `μ ← Σ_i w_i A_i` | 모든 표본을 비용의 softmax로 가중한다 |
| CMA-ES | `N(μ, Σ)`에서 표본 → 비용 → 가중치 `w_i`(지수, top-K 등) → `μ ← (1 − γ_μ) μ + γ_μ Σ_i w_i A_i`, `Σ ← (1 − γ_Σ) Σ + γ_Σ Σ_i (A_i − μ)(A_i − μ)ᵀ` | 평균과 **공분산을 함께 적응**시킨다. 처음에는 Σ가 커지며 넓게 보고, 수렴하면서 줄어든다(p.37 그림) |

- (강의 설명) random shooting은 자율주행에서 장애물을 피하면서 경로를 따르는 행동 후보를 무작위로 여럿 뽑고, 부딪히지 않으면서 경로 오차가 가장 작은 것을 고르는 예로 설명했다.
- (보충) λ(temperature)가 작을수록 MPPI는 최선 표본에 집중한다. 원래 CMA-ES의 공분산 갱신은 가중치와 evolution path를 포함하며, 슬라이드 식은 이를 단순화한 것이다.

### 10. Bayesian optimization과의 관계 (보충)

- 이 노트에는 BO 본문이 없고, p.38 참고문헌에 BO 강의자료(Deisenroth)만 있다. BO 본문은 불확실성·GP 강의(`Lecture 11 - UQ and GP.pdf` p.32–35, 올해 12주차 → [L11 정리](./L11_불확실성_가우시안프로세스.md))에 있다. 비싼 블랙박스 함수에 GP 대리모형을 세우고, acquisition function(예측 평균(cost) + 불확실성; expected improvement, upper confidence bound, Thompson sampling)으로 다음 평가점을 고르는 방식이다.
- 대비하면 grid·random·CEM은 병렬로 **많이** 평가하고, BO는 순차적으로 **적게** 평가한다. 평가 한 번이 비쌀수록 BO가 유리하다.

### 정리 — 방법 지도 (보충 정리)

| 계열 | 쓰는 정보 | 병렬성 | 차원이 늘 때 | 튜닝에서의 자리 |
|---|---|---|---|---|
| Grid | 없음 | 완전 | 매우 나쁨(지수적) | 축이 1~2개이고 이산일 때 |
| Random | 없음 | 완전 | hitting probability가 차원과 무관 | **기본값**(교수님 권장) |
| FD / ES / SPSA | 기울기 근사 | 표본 단위 | FD는 나쁨, ES·SPSA는 양호 | 연속 파라미터 개선 |
| Hill climbing / Pattern | 국소 비교 | 낮음 | 보통 | 소규모·저차원 |
| GA / PSO | 개체군 | 높음 | 보통~양호 | 혼합 변수, 제어 파라미터 |
| CEM / MPPI / CMA-ES | 표본 분포 갱신 | 높음 | 중간 차원까지 | 연속 공간의 확장 옵션 |

## 슬라이드의 코드·라이브러리

슬라이드에는 코드가 없다. 참고문헌은 Stanford DATASCI 112 lecture 13, `gradient-free-optimizers` 문서(1.5), Deisenroth의 BO 세미나 자료다.
아래는 A1 구현에 쓸 도구다 **(보충)**.

| 도구 | 용도 | 메모 |
|---|---|---|
| `GridSearchCV(est, param_grid, cv=..., scoring=..., n_jobs=-1)` | 격자 전수 탐색 | `param_grid`를 dict의 list로 주면 조건부 파라미터(kernel별 gamma 등)를 표현할 수 있다 |
| `RandomizedSearchCV(est, param_distributions, n_iter=N, random_state=s, ...)` | 무작위 탐색 | **`n_iter`가 예산**이다. list는 균등 이산 표본, scipy 분포는 연속 표본 |
| `GroupKFold(n_splits=5)`, `LeaveOneGroupOut()` + `fit(X, y, groups=run_id)` | run 단위 분할 | 같은 run의 프레임과 3뷰가 한 fold에 들어간다 |
| `scipy.stats.loguniform(a, b)` | C, gamma, learning_rate, l2 정규화 | 로그 스케일 파라미터. 예: `loguniform(1e-2, 1e3)` |
| `scipy.stats.randint(lo, hi)` | 정수(max_leaf_nodes, min_samples_leaf) | `hi`는 포함되지 않는다 |
| `scipy.stats.uniform(loc, scale)` | 선형 범위 | 구간은 `[loc, loc + scale]`이다(`[lo, hi]`가 아니다) |
| `Pipeline([("sc", StandardScaler()), ("svc", SVC())])` | 전처리까지 CV 안에서 | 파라미터 이름은 `svc__C` 식이다. `{"sc": [StandardScaler(), RobustScaler()]}`처럼 scaler 자체를 후보로 둘 수 있다 |
| `search.cv_results_["mean_test_score"]`, `["std_test_score"]` | 예산 곡선 | RandomizedSearchCV는 표본 순서대로 기록되므로 누적 최대가 곧 예산 곡선이다 |
| `HalvingRandomSearchCV` (`from sklearn.experimental import enable_halving_search_cv`) | successive halving | 선택. 적은 자원으로 후보를 먼저 걸러 낸다 |
| Optuna `TPESampler`, `CmaEsSampler`(`cmaes` 패키지 필요) | BO 계열 / CMA-ES | 선택 확장. 외부 라이브러리다 |

```python
# (보충) §7 단계 6 골격 — HGB, 같은 예산 27회
import numpy as np
from scipy.stats import loguniform, randint
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import GridSearchCV, GroupKFold, RandomizedSearchCV

cv = GroupKFold(n_splits=5)
hgb = HistGradientBoostingClassifier(early_stopping=False, max_iter=300, random_state=0)
grid = {"learning_rate": [0.01, 0.05, 0.3], "max_leaf_nodes": [8, 31, 127],
        "l2_regularization": [1e-4, 1e-2, 1.0]}                       # 3^3 = 27
dist = {"learning_rate": loguniform(0.01, 0.3), "max_leaf_nodes": randint(8, 128),
        "l2_regularization": loguniform(1e-4, 1.0)}                   # 같은 범위
gs = GridSearchCV(hgb, grid, cv=cv, scoring="average_precision", n_jobs=-1).fit(X, y, groups=run_id)
curves = []
for seed in range(10):
    rs = RandomizedSearchCV(hgb, dist, n_iter=27, cv=cv, scoring="average_precision",
                            n_jobs=-1, random_state=seed).fit(X, y, groups=run_id)
    curves.append(np.maximum.accumulate(rs.cv_results_["mean_test_score"]))
```

## 교수님이 강조한 것 (작년 영상)

1. **튜닝을 프로젝트에서 생각하라.** "그 대표적인 예시가 머신 러닝 모델에서는 하이퍼파라미터 튜닝인 거 같고 그래서 하이퍼파라미터 튜닝, 여러분들이 프로젝트를 할 때 이런 것들에 대해서 생각을 해 봐야 될 것 같아요." 바로 이어서 feature 선택, 전처리(min-max 정규화 등), SVM·결정트리·랜덤 포레스트 중 모델 선택도 "하나의 초이스"라고 했다.
   → 튜닝 파트는 사실상 기대되는 요소이고, 범위는 모델 선택과 전처리까지 포함한다.
2. **test로 튜닝하지 않는다.** "테스트 데이터에 대해서는 우리가 튜닝을 하면 안 됩니다." / "파라미터 튜닝은 밸리데이션과 트레이닝으로만 해야 된다. 여기서 파라미터 튜닝을 잘 한 다음에 테스트 데이터로 마지막 파이널 성능 체크를 하는 거다."
   → A1의 O·L 묶음을 잠가 두는 설계(§8.1)와 정확히 같은 원칙이다.
3. **조합 폭발.** "KNN에 대해서만 해도 768개의 모델 (…) 이게 익스포넨셜하게 증가합니다."
   → 모든 조합을 돌리는 것은 전략이 아니라는 문제 제기다.
4. **예산을 정해 놓고 찾는다.** "우리가 베스트를 찾지 못하겠지만 700개를 쓰진 않더라도 (…) 30개만 쓰자. 그럼 30개를 잘 써 가지고 그래도 적절하게 잘 되는 값을 찾자. (…) 가장 단순한 방법은 우리가 생각해 볼 수 있는 게 랜덤 서치입니다."
   → "같은 예산에서 누가 더 좋은 값을 찾나"라는 비교(예산 대비 최고 점수 곡선)의 근거다.
5. **random이 grid보다 나은 이유.** "어떤 파라미터는 안 중요할 수도 있잖아요. 얘가 안 중요하다고 하면 이렇게 3 * 3을 했는데 (…) 의미가 없었던 실험인 거고 얘 세 개만 진행이 돼서 우리가 찾은 실제 코스트에서 찾은 것은 세 개 값밖에 안 되는 거예요." / "랜덤 서치는 각 상황에서 다 랜덤하게 뿌리는 거기 때문에 (…) 안 중요한 거가 있다고 하더라도 (…) 솔루션을 잘 찾을 수 있는 확률이 증가" / "사람은 보통 그리드 서치를 할 거예요 (…) 그것보다 랜덤 서치를 해 가지고 찾는 게 더 효과적일 수가 있다"
   → 이 강의의 핵심 논지다. A1에서는 파라미터별 marginal 그림으로 "어느 축이 중요하지 않았나"를 보여 주면 된다.
6. **grid는 방향이 나쁘면 오래 걸린다.** "시작점과 방향을 잘못 선택했다 (…) 잘못된 방향으로 찾았을 때 찾는 게 오래 걸릴 수 있다. 그래서 사람은 그리드 서치를 좋아하고 뭔가 체계적으로 보는 걸 좋아하지만 생각보다 랜덤 서치가 작동할 수 있다"
   → 체계적인 것이 효율적인 것은 아니라는 경고다.
7. **병렬성.** "요즘 같은 GPU를 사용하는 시간에 패러렐 계산이 많이 이용되는 상황에서 컴퓨팅 파워만 있으면 옵티마이션이 잘될 수가 있고요. (…) 파라미터 세트를 미리 설정해 놓을 수 있는 장점도 있습니다."
   → random search는 `n_jobs=-1`로 그대로 병렬화된다.
8. **GA·PSO에 대한 평.** "지금은 제네틱 알고리즘 아무도 로봇에 사용하려는 사람이 없습니다. 이미 RL이 다 대체를 해 버렸지만" / PSO는 "이번에 준비하면서 PSO가 뭐지 하고 공부를 했더니 아 생각보다 간단한 거였네" / "파라미터 튜닝을 하기 위해서 이런 (…) 옵티마이션들을 배우고 있는데 (…) 옵티마이션 자체에서도 파라미터 튜닝을 해야 된다"
   → 메타휴리스틱은 그 자체로 튜닝할 값이 많다. 파라미터 3~4개짜리 튜닝에 들일 이유가 없다.
9. **MPPI는 자율주행 알고리즘.** "MPPI라고 얘도 자율주행에서 많이 사용되는 알고리즘이긴 한데" / "처음에 나온 게 2015년 조지아텍(자막 '도지아 타입')에서 나왔는데 (…) 지금도 계속 이용되고 있는 알고리즘"
   → 교수님이 자율주행 맥락을 직접 쓴다. 다만 A1에서 MPPI를 쓸 일은 없다.
10. **결론.** "하이퍼파라미터 튜닝을 했을 때 그냥 단순하게는 랜덤 서치를 이용하면 될 거 같고요 (…) 근데 웬만해서 랜덤 서치면 될 거 같은데 (…) 그 이상으로 최적화를 다른 방식으로 해 보고 싶다라고 하면은 이런 CMA-ES, MPPI, CEM 이 정도는 지금 시대에서도 많이 이용되는 알고리즘이니까"
    → 기본은 random search이고, 확장이 필요하면 CMA-ES(또는 BO)를 선택지로 둔다.

## 우리 프로젝트(A1)에서 쓰는 곳

| 강의 내용 | A1에서 쓰는 곳(계획 §) | 구현 메모(scikit-learn 클래스·하이퍼파라미터·주의점) |
|---|---|---|
| random vs grid, 같은 예산 (p.9–13) | §7 단계 6, §10 14주차 | GBM: `HistGradientBoostingClassifier` 격자 3×3×3 = 27 vs `RandomizedSearchCV(n_iter=27)`. SVM: `Pipeline(StandardScaler, SVC)`의 C×gamma 격자 4×4 = 16 vs `n_iter=16`. `scoring="average_precision"`(PR-AUC, §8.2). **격자 값의 범위와 분포의 범위를 같게 둔다** |
| 예산 대비 최고 점수 곡선 (p.12 hitting probability) | §7 단계 6 "확인할 것" | x축 = 평가한 설정 수(= CV 실행 수). random은 `np.maximum.accumulate(cv_results_["mean_test_score"])`를 seed 10~20개로 반복해 중앙값과 사분위 띠로 그린다. grid는 2^3 = 8, 3^3 = 27, 4^3 = 64 격자 각각의 최고점을 점으로 찍는다 |
| 중요/비중요 파라미터 (p.11 그림) | §7 단계 6 결과 해석 | random 결과로 "점수 vs 각 파라미터" 산점도를 그린다. 영향이 없는 축이 드러나면 슬라이드 그림을 우리 데이터로 재현한 것이 된다. HGB의 `l2_regularization`은 비중요 축 후보다 |
| CV로 선택, test는 튜닝 금지 (p.6) | §8.1 P1 GroupKFold(run), 최종 L 묶음 | `cv=GroupKFold(5)`, `fit(..., groups=run_id)`. `best_score_`는 낙관적으로 편향되므로 보고 수치는 바깥 fold 또는 L 묶음 1회로 낸다. O(cloudy)·L 묶음은 탐색에 넣지 않는다. 중첩 CV는 바깥 루프를 for문으로 직접 짜서 안쪽 `search.fit(X_tr, y_tr, groups=g_tr)`에 groups를 넘기는 것이 안전하다 |
| 전처리·모델 선택도 튜닝 대상 (p.5, 9) | §7 단계 1–2 (표준화 LR, SVM) | scaler는 반드시 `Pipeline` 안에 넣는다(fold 밖 통계가 새지 않게). 모델 간 비교는 계단 표(§7) 자체가 model selection이다 |
| feature 부분집합 `2^5` (p.9) | §5 feature 그룹, §7 단계 3 H3 ablation | 그룹 A·B·C·D 4개의 부분집합은 15개라 전수로 돌릴 수 있다. 이건 최고를 고르는 튜닝이 아니라 **가설 검증이므로 전부 보고**한다(A+B+D vs +C 비교 포함) |
| 이산 파라미터는 기울기 불가 (p.4, 강의의 K 예) | §6 단계 4 GMM 군집 수(BIC, 2~12) × full/diag | 11 × 2 = 22 조합이므로 전수(grid)가 맞다. random이 이기는 상황은 축이 많고 일부가 무의미할 때다 |
| 비볼록·초기점 민감 → random restart (p.3, 19) | §6 GMM/K-means, §7 단계 5 GP | `GaussianMixture(n_init=5~10)`, `KMeans(n_init=10)`, `GaussianProcessRegressor(n_restarts_optimizer=5~10)`. GP 커널 하이퍼파라미터는 log marginal likelihood를 L-BFGS-B로 최대화하는데, 재시작 초기값을 허용 범위에서 log-uniform으로 무작위 추출한다(= random restart) |
| 혼합 변수 공간 (p.4) | §7 단계 2 SVM linear vs RBF | `param_distributions=[{"svc__kernel": ["linear"], "svc__C": loguniform(1e-2, 1e2)}, {"svc__kernel": ["rbf"], "svc__C": loguniform(1e-2, 1e2), "svc__gamma": loguniform(1e-4, 1)}]`. SVC는 `probability=False`로 튜닝하고(`average_precision`이 decision_function을 쓴다), 확률 보정은 튜닝이 끝난 뒤 따로 한다 |
| BO·CMA-ES (p.37–38, [L11](./L11_불확실성_가우시안프로세스.md)) | §7 단계 6 확장 (선택) | 교수님 기준으로는 random search면 충분하다. 시간이 남을 때만 Optuna TPE/CMA-ES를 같은 예산 곡선에 한 줄 추가한다 |

> 쓰지 않는 것: FD·ES·SPSA·hill climbing·GA·PSO·CEM·MPPI. 튜닝할 파라미터가 3~4개이고 CV 한 번이 수 초~수 분이라 random search로 충분하다.
> MPPI는 교수님이 자율주행 알고리즘으로 소개한 것일 뿐이며, 데이터 수집에 쓰는 자동주행 controller(§3.3 `morai_auto`/MPC)와도 별개다.
> 주의: HGB는 표본이 10,000개를 넘으면 `early_stopping="auto"`가 켜진다. 이때 내부 검증 분할은 group을 모르는 무작위 분할이므로 `early_stopping=False`로 두고 `max_iter`를 고정하거나 탐색한다.
> SVM(RBF)은 표본 수에 대해 비용이 빠르게 늘어나므로, run 층화 서브샘플에서 탐색하고 HGB는 전체에서 탐색한다.

## 구현 체크리스트

- [ ] 탐색 공간(범위·분포)을 코드 한 곳에 dict로 정의했고, 격자 값과 random 분포의 범위가 같다.
- [ ] 모든 탐색이 `GroupKFold`(run 단위) + `groups=run_id`로 돌고, 전처리는 `Pipeline` 안에 있다.
- [ ] O(cloudy)·L 묶음은 탐색·조기종료·임계값 선택 어디에도 쓰지 않았다. `best_score_`를 최종 수치로 보고하지 않는다.
- [ ] random search를 seed 10회 이상으로 반복해 예산 곡선을 중앙값+띠로 그렸고, grid는 여러 격자 크기의 점으로 그렸다. fold 간 표준편차도 함께 적었다(CV 점수 자체가 잡음이 있는 목적함수다).
- [ ] HGB는 `early_stopping=False`로 두었고, SVC는 `probability=False`로 튜닝한 뒤 보정(§7 공통)을 따로 했다.
- [ ] GMM·K-means의 `n_init`, GP의 `n_restarts_optimizer`를 1보다 크게 두었다.
- [ ] τ·N_min 같은 **라벨 정의 값은 튜닝 대상에서 뺐다**(점수로 고르면 문제가 바뀐다. §4 민감도 분석으로만 보고한다).
