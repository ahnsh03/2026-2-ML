> 확정 주제 구현 계획: [A1 구현 계획](../05_구현계획/A1_구현계획.md)

강의마다 한 문서로 정리했다. 모든 문서는 같은 순서다:
**한눈에 → 핵심 내용(개념·수식) → 슬라이드의 코드 → 교수님이 강조한 것(작년 영상) → 우리 프로젝트(A1)에서 쓰는 곳 → 구현 체크리스트 → 올해와 다를 수 있는 점.**
슬라이드에 없는 내용을 보탠 곳은 `(보충)`으로 표시했다. 수식은 텍스트 추출이 깨져서 슬라이드 이미지를 직접 보고 확인했다.

## 정리하면서 확인한 구현 주의점

강의 내용을 구현 계획에 대 보면서 나온 것이다. 해당 문서의 체크리스트에 자세히 있다.

| # | 주의점 | 출처 |
|---|---|---|
| 1 | 실패율이 10.4%라 **모두 "성공"으로 찍어도 accuracy 89.6%**다. 주 지표는 PR-AUC로 둔다 | L02 |
| 2 | 슬라이드 분류로는 cloudy 조건이 새 의미 범주(semantic OOD)가 아니라 **covariate shift**에 가깝다. 발표 용어를 맞춘다 | L02 |
| 3 | 고유 오류맵은 모든 셀이 같은 단위(오류 비율)라 **`StandardScaler`를 쓰지 않는다.** 대신 첫 주성분은 실패 "크기"(≈ 1 − IoU)가 될 가능성이 커서, 모양만 보려면 실패 sample만 쓰거나 합으로 정규화한 PCA를 함께 본다 | L05 |
| 4 | v0 데이터는 **sample 수 < 차원**(front 468 < 1,920)이다. 새 held-out 수집 전까지 PCA 결과는 예비로만 쓴다 | L05 |
| 5 | **오류맵에서 나온 값은 예측기 입력으로 쓰면 안 된다**(GT를 쓰므로 누수). 분석·군집에만 쓴다 | L05 |
| 6 | 슬라이드의 SVM `C`(허용 위반량, 클수록 bias↑)는 **scikit-learn의 `C`(클수록 규제↓)와 방향이 반대**다 | L06 |
| 7 | 군집 번호는 임의라 사람 분류와 비교할 때는 **라벨 순서와 무관한 ARI·NMI**를 쓰고, 사람끼리의 κ를 먼저 구한다 | L07 |
| 8 | impurity 기반 feature importance는 치우칠 수 있어 **permutation importance**를 함께 본다. "앙상블은 항상 좋아진다"는 발언은 슬라이드의 한계 설명과 함께 조심해서 인용한다 | L09 |
| 9 | scikit-learn GP에 `WhiteKernel`을 넣으면 `return_std`에 **잡음이 포함**된다. epistemic 분산은 `std² − noise_level·ystd²`(normalize_y 사용 시)로 따로 계산한다 | L11 |
| 10 | GP에서 feature별 length scale(ARD)을 쓰면 n = 3,000·d = 40일 때 gradient 메모리가 수 GB다. 커널 탐색은 1k로 하고 최종 적합만 3k로 한다. v2는 1차원 GP라 해당이 적다 | L11 |
| 11 | IoU는 [0, 1] 범위라 가우시안 예측 구간이 벗어날 수 있다. logit(IoU) 적합과 비교한다 | L11 |
| 12 | `HistGradientBoosting`은 sample이 1만 개를 넘으면 **early stopping이 자동으로 켜지고, 검증 분할이 run을 무시**한다. `early_stopping=False`로 두거나 run 단위로 직접 나눈다 | L13 |
| 13 | **τ와 하이퍼파라미터를 test(O·L 묶음)로 고르지 않는다.** 교수님: "테스트 데이터에 대해서는 우리가 튜닝을 하면 안 됩니다" | L13 |

## 교수님 발언 — 프로젝트·평가 관련 (작년 영상, 자동 자막)

| 발언 | 강의 | 프로젝트에 주는 의미 |
|---|---|---|
| "알고리즘의 구현이 별로 중요한 거 같진 않고 … 데이터를 찾고, 알고리즘을 찾고, 구현을 했고, 거기에 성능을 높였다 … 완성을 했다" | L01 | 발표 구성 = 문제 → 데이터 → 알고리즘 → 성능 향상 → 완성 |
| 데이터셋을 직접 가지고 와서, 그 안의 재밌는 데이터 분포에 맞는 모델을 고른다 | L03 | 직접 수집한 MORAI 데이터와 실패 분포가 출발점 |
| "절대로 트레이닝 셋에서 학습이 잘된 것만으로 … 잘될 거야라고 하면 안 돼요" | L02 | held-out·잠금 테스트 설계의 근거 |
| 자율주행 예: 사고 확률이 "10%라도 있다고 하면 안 가야" / "최선이야, 근데 사고 확률이 80%야" | L02, L11 | 실패 예측과 불확실성이 왜 필요한지에 대한 교수님 자신의 동기 |
| GP·BO는 연구 주제이고 "잘하면 페이퍼도 쓸 수 있다" | L11 | GP 파트를 성의 있게 하면 차별점 |
| "여러분들의 프로젝트에 대해서도 베이스라인이랑 비교를 하라고 했잖아요 … 앙상블을 쓰는 것도 한 가지 방법" | L09 | 베이스라인 비교는 필수, 앙상블은 권장 카드 |
| "하이퍼파라미터 튜닝, 여러분들이 프로젝트를 할 때 이런 것들에 대해서 생각을 해 봐야" / "웬만해서 랜덤 서치면 될 거 같은데" | L13 | random vs grid 비교를 넣는다 |
| 과제 코드는 GPT를 써도 되지만 틀린 것을 알아내고 이해하는 능력이 핵심이다 | L02, L03 | 코드 설명 가능성 확보 |

**시험·과제 (작년 기준)**: 중간고사는 계산 위주가 아니며 두 시간 분량을 세 시간 동안 본다(L01). 작년 과제 예시는 "왜 시그모이드인가"(L03), "정의로 QP의 볼록성 보이기"(L04), BLR·GP로 불확실성 예측(L11)이었다. 올해도 같다는 보장은 없다.

## 슬라이드 오탈자로 보이는 곳

각 문서 본문에 표시했다. 시험 공부 때 헷갈리지 않도록 모아 둔다.

| 강의 | 위치 | 내용 |
|---|---|---|
| L03 | p.19, p.24, p.38 | Bayes 식 라벨, `g'(z)`, loss 괄호 |
| L04 | Adam | γ₁·γ₂ 이름이 원 논문과 반대 (값은 같음) |
| L07 | 거리 정의 | Mahalanobis는 공분산의 **역행렬**을 써야 한다(교수님이 강의에서 직접 정정). Manhattan 식도 오기 |
| L11 | p.15, p.29 | 경사하강 갱신 부호, marginal likelihood 식의 잡음 항 누락 |
| L12 | p.29 | `log p(z|X,θ*)` → `log p(X|θ*)` |
