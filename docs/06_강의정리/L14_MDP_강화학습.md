## 한눈에

- RL은 환경과 상호작용하며 **누적 보상을 최대화하는 정책**을 시행착오로 배우는 방법이다. 지도(정답 있음)·비지도(정답 없음)와 달리 데이터를 스스로 만들어 가며 배운다.
- multi-armed bandit으로 **exploration–exploitation 딜레마**와 ε-greedy를 본다.

## 핵심 내용

### 1. RL과 multi-armed bandit (p.2–12)

- RL = trial-and-error learning. 환경과 상호작용하며 보상을 최대화하는 정책을 학습한다. 행동마다 즉시 보상을 받고, 기대 보상이 최대인 행동을 고르고 싶다.
- **Multi-armed bandit**: 슬롯머신 N대 중 하나를 당긴다. 상태는 변하지 않고, 행동은 N개다. 각 기계의 보상 확률은 고정되어 있지만 모르며, 목표는 누적 보상의 최대화다.
- 예(p.8–9): 한 번씩 당기면 3번 기계(200₩)가 좋아 보인다. 네 번씩 당기면 합계가 400/700/200/590₩이 되어 2번 기계가 가장 좋다. 표본이 적으면 판단이 틀린다.
- 행동가치 `Q*_t(a) = E[R_{t+1} | A_t = a]`, 추정값 `Q_t(a) ≈ Q*_t(a)`, 탐욕 행동 `A*_t = argmax_a Q_t(a)`.
  `A_t = A*_t`이면 exploitation(보상 수집), `A_t ≠ A*_t`이면 exploration(정보 수집)이다. 둘 다 필요하다.
- 딜레마는 RL만의 문제가 아니라 모든 지능형 에이전트의 의사결정 문제다(단골 식당 vs 새 식당, 예제 풀이 vs 추가 자료 읽기).
- **ε-greedy** (p.12): 확률 ε로 탐색하고 1−ε로 탐욕 행동을 한다. 정보가 쌓일수록 탐색 비중을 줄인다(강의 설명: ε을 시간에 따라 지수적으로 감소).

### 2. MDP와 POMDP (p.13–17)

- 궤적: bandit은 `τ = (A_t, R_{t+1}, A_{t+1}, R_{t+2}, …)`, MDP는 `τ = (S_t, A_t, R_{t+1}, S_{t+1}, A_{t+1}, …)`.
- **Markov property**: `p[R_{t+1} = r, S_{t+1} = s' | S_0, A_0, R_0, …, S_t, A_t] = p[R_{t+1} = r, S_{t+1} = s' | S_t, A_t]`. 현재만 미래를 결정하므로 이력을 무시해도 된다.
- **Finite MDP** `(S, A, T, r, γ)`: 상태 집합 S, 행동 집합 A, 1-step 전이 `T = p(s' | s, a)`, 보상 `r(s, a, s')`, 할인율 `0 ≤ γ ≤ 1`. 정책 `π(a|s)`는 상태가 주어졌을 때 행동의 분포다.
- 누적 보상(return): `G = R_1 + γR_2 + γ^2 R_3 + …`. 미래 보상은 덜 중요하게 둔다. p.15의 "다리마다 통행료" 예는 뒤 노드의 최소 비용을 재사용하면 모든 경로를 열거하지 않아도 된다는 DP의 직관이다.
- **POMDP** `(S, A, O, T, h, r, γ)`: `h = p(o|s)`는 관측 모델이고, 정책은 `π(a|o)`다. Atari DQN(p.17)은 화면 한 장으로는 공의 속도를 알 수 없어서 연속 프레임을 쌓아 상태를 추정한다(강의 설명).

### 3. 에이전트의 구성요소 (p.18–22)

- **Policy**: 결정적 `A_t = π(s)`, 확률적 `π(a|s) = p[A_t = a | S_t = s]`.
- **Value function**: 각 상태(또는 상태-행동)가 얼마나 좋은지를 나타낸다.
- **Model**: 환경이 다음에 어떻게 될지 예측한다. 다음 상태 `p[S_{t+1} = s' | S_t = s, A_t = a]`, 다음 보상 `p[R_{t+1} | S_t = s, A_t = a]`.
- 미로 예: 보상이 한 step마다 −1이면 최대한 빨리 목표에 가는 정책이 최적이다. 가치는 "목표까지 남은 칸 수 × (−1)"이 된다(γ = 1).

### 4. 가치함수와 Bellman 방정식 (p.23–32)

- 목표는 누적 보상 `G_t = Σ_t γ^t r(s_t, a_t)`를 최대화하는 정책을 찾는 것이다(유한/무한 horizon).
- `V_π(s) = E_π[G_t | S_t = s]`, `Q_π(s, a) = E_π[G_t | S_t = s, A_t = a]`. 최적값은 `V*(s) = max_π V_π(s)`, `Q*(s, a) = max_π Q_π(s, a)`.
- 최적 정책 구하기 (p.25):
  - `Q*`가 있으면 `π*(a|s) = 1  if a = argmax_a Q*(s, a)`(아니면 0)로 바로 구한다.
  - `V*`만 있으면 `argmax_a Σ p(s', r | s, a)(r + γV*(s'))`처럼 **dynamics로 한 step 앞을 봐야** 한다.
- 재귀: `G_t = R_{t+1} + γG_{t+1}`. 여기서 **Bellman 기대 방정식** `V_π(s) = Σ p(s', r | s)[r + γV_π(s')]`이 나오고, 행렬로 쓰면 `V_π = R_π + γP_π V_π`다.
- 선형이므로 직접 풀 수 있다: `V_π = (I − γP_π)^{-1} R_π`. 다만 비용이 상태 n개에 대해 `O(n^3)`이라 큰 문제에는 반복법(DP, Monte-Carlo, TD)을 쓴다.
- V–Q 관계: `V_π(s) = Σ_a π(a|s) Q_π(s, a)`, `Q_π(s, a) = Σ_{s'} p(s', r | s, a)[r + γV_π(s')]`.
- **Bellman 최적 방정식**(합 대신 최선 행동): `V*(s) = max_a Σ_{s'} p(s', r | s, a)[r + γV*(s')]`, `Q*(s, a) = Σ_{s'} p(s', r | s, a)[r + γ max_{a'} Q*(s', a')]`. 비선형이라 일반적으로 닫힌 해가 없다. 풀이법은 모델을 쓰는 value/policy iteration, 표본을 쓰는 Monte Carlo·Q-learning·SARSA다.
- 확장(p.32): 연속 상태·행동은 선형-이차 모델에서 LQR로 닫힌 해가 있고, 연속 시간은 HJB 편미분방정식이 필요하다.

### 5. 동적 계획법 (p.33–48)

- DP는 MDP를 완전히 안다고 가정한 planning이다. prediction(입력 MDP+π → `V_π`)과 control(입력 MDP → `V*`, `π*`)로 나눈다.
- **Iterative policy evaluation**: `V_{k+1}(s) = Σ_a π(a|s) Σ_{s'} p(s', r | s, a)[r + γV_k(s')]`를 모든 상태에 동기식으로 반복한다. 예는 4×4 GridWorld(γ = 1, 보상 −1, 균등 무작위 정책)다.
- 수렴 근거: `T_π V = R_π + γP_π V`는 γ-수축(contraction) 연산자다. `||T_π U − T_π V||_∞ ≤ γ||U − V||_∞`이므로 유일한 고정점으로 선형 속도 γ로 수렴한다.
- **Policy iteration**: 평가 → `π' = greedy(V_π)`로 개선을 반복하면 항상 `π*`로 수렴한다. 개선 단계는 `V_π(s) ≤ Q_π(s, π'(s)) ≤ … ≤ V_π'(s)`로 단조 개선이 보장되고, 개선이 멈추면 Bellman 최적 방정식이 성립한다.
- **GPI**: 평가와 개선을 어떤 식으로든 번갈아 하면 된다(부분·근사·비동기 허용). 모든 RL 방법은 GPI의 한 형태다.
- **Value iteration**: `V_{k+1}(s) = max_a [R(s, a) + γ Σ_{s'} p(s', r | s, a) V_k(s')]`. 한 step만 평가하며, 명시적 정책 없이 Bellman 최적 방정식으로 갱신한다.

| 문제 | Bellman 방정식 | 알고리즘 |
|---|---|---|
| Prediction | 기대 방정식 | Iterative policy evaluation |
| Control | 기대 방정식 + greedy 개선 | Policy iteration |
| Control | 최적 방정식 | Value iteration |

- 복잡도는 반복당 V 기반 `O(mn^2)`, Q 기반 `O(m^2 n^2)`이다(행동 m, 상태 n).

### 6. 시뮬레이터와 로봇 학습 (p.49–59)

- Gymnasium(p.49): 단일 에이전트 RL 환경의 공통 API다. (보충) 슬라이드는 "Maintained by OpenAI"라고 적었지만, 원래 OpenAI Gym이었고 현재 Gymnasium은 Farama Foundation이 관리한다.
- Isaac Sim(NVIDIA, p.50): GPU 가속으로 수천 개 환경을 병렬로 돌리며, PhysX 5 물리엔진을 쓴다.
- RL은 표본 효율이 매우 낮다. Google QT-Opt는 4개월, 로봇 7대, 800 로봇시간, 580,000회 시도가 걸렸다(p.52).
- **시뮬레이션 데이터의 장점**(p.53): 싸고 빠르고 확장 가능, 안전, **라벨이 있다(ground truth 접근)**, 기계 마모가 없다. **단점**: 실제 환경과 같지 않다(sim2real).
- 현재 지형(p.55–59): 비학습(최적·강건 제어, trajectory optimization + MPC)과 학습(NVIDIA Sim2Real, Mobile ALOHA 실데이터 수집, 제어 foundation model GNM).

   → 개괄 강의다. 수식 유도보다 개념 이름과 관계를 잡는 것이 목표였다.
2. "RL은 주어진 상황에서 (…) 리워드를 맥시마이즈 하도록 스스로 학습하는 방법이에요. 이게 제일 중요합니다." / "RL은 데이터 자체를 스스로 계속해서 만들어 내면서 스스로 학습을"
   → 지도·비지도와 RL을 가르는 기준은 "데이터가 주어지는가, 스스로 만드는가"다.
3. "이 익스플로레이션과 익스플로이테이션의 밸런스를 맞추는 게 가장 중요한 키포인트" / "RL에 대해서 유니크한 문제는 아니고요"
   → 식당 고르기와 공부에 이어, 20대는 탐색이고 30대는 활용이라는 인생 비유까지 들었다.
4. "같은 주제에 대해서도 이 스테이트 베리어블을 어떻게 만드냐에 따라서 (…) 과거에 영향이 있냐 없냐를 설정할 수가 있는 거고 (…) 마르코프 프로퍼티를 맞춰서 (…) MDP를 구성을 해야"
   → "공부한 양의 이력"은 Markov가 아니고, "지금 머릿속 지식"을 상태로 두면 Markov가 된다. MDP는 상태를 어떻게 설계하느냐의 문제다.
5. "RL에서 가장 중요한 컨셉들이 이런 애들이에요. 밸류 펑션, 스테이트 액션, 리워드, MDP, POMDP, 리턴, 감마도 있는 거고"
   → 교수님이 직접 꼽은 핵심 용어 목록이다.
6. Bellman 이후의 식에 대해서는 "대충 넘어갈게요" / "모든 식을 그냥 빠르게 넘겼습니다"라고 했다. 더 공부하려면 David Silver 강의, 인공지능공학과 강화학습 수업, 교수님의 대학원 수업을 권했다.
   → DP 수식은 참고 수준이다.
7. 시뮬레이터의 장점으로 "추가적으로 그라운드 트루스 정보를 알 수 있다"를 들었고, 단점으로 "결국 실제와 시뮬레이터는 다를 수밖에 없고 그 다른 것을 어떻게 잘 반영을 할까에 대한 이슈"를 들었다.
   → 시뮬레이터의 GT와 sim2real이라는 두 개념만은 우리 프로젝트의 데이터 논리와 직접 겹친다(아래).
8. 보스턴 다이내믹스 로봇은 MPC 기반 고전 제어로 알려져 있고, 로켓 제어에는 아마 아무도 러닝을 쓰지 않을 것이라고 했다.
   → 교수님은 모든 제어 문제를 학습으로 푸는 쪽이 아니다. 문제에 맞는 도구를 고른다는 관점이다.

## 우리 프로젝트(A1)에서 쓰는 곳

**RL·MDP·DP 알고리즘은 A1에서 쓰지 않는다.** A1은 고정된 대상 모델(TwinLiteNet+)의 실패를 지도학습·군집·불확실성으로 예측하는 문제다. 순차적 의사결정이나 정책 학습이 없다.
실제로 겹치는 것은 시뮬레이션 관련 두 개념뿐이다.

| 강의 내용 | A1에서 쓰는 곳(계획 §) | 구현 메모 |
|---|---|---|
| 시뮬레이터는 **GT 라벨**을 준다 (p.53) | §3.3 GT 센서셋, §4 라벨 | MORAI 시뮬레이터 데이터의 Semantic 카메라가 차선 GT를 주기 때문에 프레임별 lane IoU와 실패 라벨을 만들 수 있다. 발표의 "왜 시뮬레이터 데이터인가"에 이 논리를 쓴다 |
| **sim2real** 한계 (p.53) | §8.2 주석(실주행 로그), 한계 절 | 실주행 rosbag에는 Semantic GT가 없어 정량 테스트셋이 될 수 없고 정성 데모에만 쓴다. "시뮬레이터에서 찾은 실패 유형이 실차에서도 같은가"는 검증하지 않은 한계로 명시한다 |

> 억지로 연결하지 않는 것: planner와의 연결(§14)은 "실시간 신뢰도 신호를 넘겨줄 수 있다"까지만 말하고 RL 정책이나 보상 설계로 확장하지 않는다.
> random search·CMA-ES의 탐색 폭 조절을 exploration–exploitation 비유로 설명할 수는 있지만([L13](./L13_하이퍼파라미터_무경사최적화.md)), 방법론으로 주장하지 않는다.

- 올해 lec1 주차표에는 RL 주가 없다. 다만 강의계획서 PDF는 14주차를 "MDP and RL"로 적고 있고, 이 노트의 파일 이름도 "MDP and simulation"이다. 교수님이 14주차나 16주차(보강)에 일부를 다룰 가능성은 남아 있다. 올해 노트가 올라오거나 공지가 있으면 갱신한다.
- 기말고사가 프로젝트로 대체되었으므로 이 내용이 시험에 나올 가능성은 낮다. 과제로 나오는지만 확인한다.
