## 핵심 내용

### 1. 머신러닝 유형과 시스템 로드맵 (p.2–3)

- 지도학습: 분류(이미지 분류, 신원 사기 탐지, 고객 이탈, 진단), 회귀(광고 인기·날씨·시장·기대수명·인구 증가 예측).
- 비지도학습: 차원 축소(압축, 구조 발견, 빅데이터 시각화, feature 도출), 군집(추천, 타깃 마케팅, 고객 세분화). 강화학습: 실시간 결정, 게임 AI, 로봇 내비게이션.

```text
Data collection ──(결측치 처리, 초기 feature 추출)──> Dataset ──> Training set / Test set
Training set ──(정규화, 차원 축소, feature 추출)──> Processed training set
  ──(하이퍼파라미터 튜닝)──> ML algorithm ──> Prediction model ──(Test set으로)──> Evaluation
```

### 2. 기본 용어 (p.4–10)

| 용어 | 뜻 |
|---|---|
| instance, observation, (data) sample | 데이터 한 건, 즉 i번째 `(x_i, y_i)` 쌍. 영상: 영어의 "example"과 같은 말 |
| sample space | 데이터가 가질 수 있는 공간. 동전 {0, 1}, MNIST `256^(28×28)`(gray), CIFAR-10 `256^(32×32×3)`(RGB). 픽셀값은 0~255 이산값이지만 작은 이미지라도 공간이 엄청나게 크다 |
| feature, feature vector / input | 입력 `x` |
| label, label space / output, target | 출력 `y`. MNIST {0, …, 9}, CIFAR-10 {airplane, automobile, bird, cat, deer, dog, frog, horse, ship, truck} |
| ground truth | 실제 `y` 값. (영상) 항공 측량 지도가 맞는지 땅(ground)에 가서 확인한 데서 나온 말 |
| training / validation / test set | 학습용 / 학습 중 모델 선택용 / 최종 평가용 |

- **Feature의 예 (p.9)**: 이름·나이·소득 → 결혼 여부, 날짜·위도·경도·기온·습도·구름양·풍향·기압 → 강수량(label).
- **머신러닝 vs 딥러닝의 feature (p.10)**: 머신러닝은 사람이 feature를 뽑고(개·고양이라면 코 모양, 수염, 동공, 귀 모양, 주둥이 길이) 분류기가 분류한다. 딥러닝은 feature 추출과 분류를 네트워크가 함께 하며 층마다 low → mid → high-level feature가 생긴다.
- (영상) 그래서 딥러닝 문맥의 "feature"는 입력 자체가 아니라 중간 표현(latent)을 가리키기도 한다.

### 3. 데이터셋 분할 (p.8, 40–41)

- Original set을 training + testing, 또는 training + validation + testing으로 나눈다.
- 검증 셋 절차: training set으로 학습 → validation set으로 평가 → 결과에 맞춰 조정(반복) → validation 최고 모델 선택 → **test set으로 결과 확인**.
- 그림 예: Model 1/2/3의 validation 정확도 85% / **92%** / 87% → Model 2 선택 → test 정확도 90%. 선택에 쓴 validation 점수는 test보다 약간 높게 나온다.
- (영상) 비율은 80/20, 70/15/15, 60/20/20 정도이고, 데이터가 아주 많으면 test는 1%나 0.1%로도 충분하다.
- (영상) `stratify=y`는 label 비율(예: cat 70%, dog 30%)을 train/test에서 똑같이 유지한다. **연속값 y에는 쓸 수 없다.**

### 4. 일반화 (p.11–14, 34)

- **일반화(generalization)**: 학습에 쓰지 않은 데이터에서의 성능.
- 과소적합(underfitting)은 모델이 너무 단순해 학습 데이터조차 설명하지 못하는 것이고, 과적합(overfitting, over-training)은 학습 데이터에 지나치게 맞춰 새 데이터에서 오차가 커지는 것이다.
- 용량(capacity)이 커질수록 bias는 줄고 variance는 늘어, 일반화 오차는 **U자**가 된다. 바닥이 optimal capacity다.
- (영상) 과소적합 모델은 새 점이 들어와 다시 맞춰도 선이 거의 변하지 않는다(**variance 작음, bias 큼**). 과적합 모델은 점 하나에 선 전체가 틀어진다(**variance 큼, bias 작음**).
- **내삽(interpolation) vs 외삽(extrapolation)**: 데이터 사이를 채우는 것과 데이터 바깥을 추정하는 것이다. p.34 그림처럼 회귀선은 데이터 범위 밖의 새 입력 `X*`에서 실제 함수와 크게 어긋날 수 있다.
  (영상) "머신 러닝은 인터폴레이션을 잘하자"가 목표이고 외삽은 불확실성이 큰 위험한 작업이다.

**불확실성 (p.13)**

| | Aleatoric (데이터 불확실성) | Epistemic (모델 불확실성) |
|---|---|---|
| 원인 | 데이터 자체의 잡음 | 데이터를 얻지 못한 영역 |
| 그림에서 | 점들이 넓게 퍼진 구간 | 데이터가 없는 구간 (sin 곡선 바깥, 점 사이 빈 곳) |
| 데이터를 더 모으면 | **줄지 않는다** | **줄어든다** |
| 대응 | 줄일 수 없으니 범위(경계)를 측정해 안전하게 쓴다 | 불확실성이 큰 곳의 데이터를 더 모은다 |

**Inductive bias (p.14)**: 학습 알고리즘이 제한된 데이터에서 본 적 없는 경우로 일반화하려고 두는 가정의 집합이다.

- Restriction bias: 학습을 특정 함수 부류로 **제한**한다(선형·다항·사인 중 무엇으로 맞출지).
- Preference bias: 특정 함수를 **선호**하지만 제한하지는 않는다. 예: 침팬지 얼굴에 레몬 질감을 입힌 이미지를 shape-biased 모델은 침팬지로, texture-biased 모델은 레몬으로 본다.
- (영상) `F = ma`를 이미 안다면 딥러닝 대신 선형회귀로 충분하고, 데이터가 없는 구간에서도 잘 맞는다. 도메인 지식을 inductive bias로 넣는 하이브리드 접근은 교수님의 연구 관심사다.

### 5. 분포 (p.15–17)

- **i.i.d.**: 학습과 테스트 데이터가 독립이고 같은 분포에서 나왔다고 가정한다. 그림: 기기마다 0~9가 고루 있으면 IID, 한 기기는 0·4만 있고 다른 기기는 5·7만 있으면 Non-IID.
- **Distribution shift** (p.17 그림, 세로축 covariate shift · 가로축 semantic shift):

| 구분 | 예 | 의미 |
|---|---|---|
| (i) Training ID | CIFAR-10 | 학습 분포 |
| (ii) Covariate-shifted ID | CIFAR-10-C(손상 이미지), ImageNet-10 | 입력 `x` 분포만 바뀜, label은 같음 |
| (iii) Near-OOD | CIFAR-100, Tiny-ImageNet | 비슷하지만 다른 클래스 |
| (iv) Far-OOD | MNIST, FashionMNIST, Texture, CIFAR-100-C | 전혀 다른 데이터 |

- (영상) covariate는 `x`를 뜻한다. 비행기 사진에 잡음이 더해져도 여전히 비행기라면 covariate shift, 사과나 금붕어 사진이 들어오면 label 자체가 바뀐 OOD다. RL 예: 네모 블록만 학습했는데 테스트에서 둥근 블록이 나오는 경우.

### 6. 평가 지표 (p.15, 18–19)

| 지표 | 식 | 의미 |
|---|---|---|
| Accuracy | `(TP + TN) / (TP + TN + FP + FN)` | 전체 중 맞힌 비율 |
| Specificity | `TN / (TN + FP)` | 실제 음성 중 음성으로 맞힌 비율 |
| Precision | `TP / (TP + FP)` | 양성이라 한 것 중 진짜 양성 |
| Recall (sensitivity) | `TP / (TP + FN)` | 진짜 양성 중 찾아낸 비율 |
| F1 | `2 × Precision × Recall / (Precision + Recall)` | 둘의 조화평균 |
| MSE | `1/N Σ_i (pred_i − target_i)^2` | 큰 오차에 큰 벌점 |
| RMSE | `sqrt( 1/N Σ_i (pred_i − target_i)^2 )` | MSE를 원래 단위로 되돌림 |
| MAE | `1/N Σ_i abs(pred_i − target_i)` | 절댓값 오차 (슬라이드의 "mean average error"는 mean absolute error의 오기) |

- (영상) 임계값을 올리면 precision이 올라가고(1까지) recall이 떨어지며, 내리면 그 반대다. 둘은 서로 맞바꾸는 값이라 **F1(조화평균)** 으로 묶는다. 조화평균은 한쪽이 낮으면 급격히 떨어져 둘 다 높아야 점수가 높다.
- (영상) 제곱 오차는 크게 틀린 값을 강하게 막지만 이상치 하나에 크게 흔들린다. MAE 손실은 V자라 기울기가 일정하고 0에서 미분되지 않으며, MSE 손실은 볼록한 포물선이라 초반 수렴이 빨라 비용함수로 많이 쓴다(p.19 그림).

### 7. Bias–variance와 과제 유형 (p.20–22)

- 과녁 그림: low bias·low variance가 이상적이고, bias는 정답에서 떨어진 정도, variance는 예측이 퍼진 정도다.
- 모델 복잡도가 커지면 Bias²는 줄고 Variance는 늘어 Total Error가 U자가 된다. (보충) 통상 `기대 오차 = Bias² + Variance + 잡음`으로 쓴다.
- 과제: 분류, 회귀, 군집, 차원 축소, 생성. 지도학습(분류·회귀), 비지도학습(군집·연관 규칙), 강화학습.

### 8. 일반 원칙 (p.23)

| 원칙 | 내용 | 영상의 보충 |
|---|---|---|
| No Free Lunch | 모든 문제에 최고인 알고리즘은 없다 | 모델마다 inductive bias가 달라 데이터·도메인에 따라 성패가 갈린다 |
| 차원의 저주 | 차원이 늘면 공간 부피가 지수적으로 커져 데이터가 희소해진다 | 1,000명을 feature 1개 축에 두면 충분하지만, 2개면 축당 약 33칸, 3개면 칸당 약 10명 → **좋은 feature만 적게 고른다** |

| Bias–variance | 단순함과 유연함의 균형이 일반화의 핵심 | — |

### 9. 파이썬 패키지와 numpy·pandas 기초 (p.24–32)

- numpy(배열·선형대수·난수), pandas(정형 데이터, CSV 읽기·정리·필터링), matplotlib(기본 그래프), scikit-learn(분류·회귀·군집·전처리·평가). 그 밖에 Seaborn, SciPy, TensorFlow, PyTorch, MLflow, Optuna.

- pandas: Series는 1차원, DataFrame은 2차원 표. `loc`은 이름(라벨) 기준, `iloc`은 정수 위치 기준으로 가져온다.

### 10. 결측치 처리 (p.32–35)

| 방법 | API | 비고 |
|---|---|---|
| 확인 | `pd.isna(df)`, `df.isnull().sum()` | NaN = Not a Number, NA = not available |
| 삭제 | `dropna(how="any")`, `dropna(thresh=4)`, `dropna(subset=["C"])` | 행 기준이 기본, `axis=1`이면 열을 지운다. `thresh`는 값이 그 개수 이상 있어야 남긴다 |
| 상수·인접값 | `fillna(5)`, `ffill()`, `bfill()` | 앞 값/뒤 값으로 채운다. 순서가 의미 있을 때 쓴다 |
| 통계값 | `fillna(df.mean())`, `SimpleImputer(strategy="mean"/"median"/"most_frequent")` | 열 평균·중앙값·최빈값 |
| 이웃 | `KNNImputer()` (기본 `n_neighbors=5`) | 가까운 이웃의 평균(가중평균 옵션)으로 채운다 |
| 보간 | `interpolate("linear"/"quadratic"/"cubic")`, `method="spline", order=2`, `method="polynomial", order=3` | 곡선 차수에 필요한 점이 모자라면 오류가 난다(영상 시연) |

- 보간 그림: nearest·previous·next는 계단 모양, linear는 직선 연결, cubic은 매끄러운 곡선이다.

### 11. 범주형 데이터 (p.36–39)

- 순서가 있는 범주는 사전으로 직접 매핑한다: `{'M': 1, 'L': 2, 'XL': 3}` → `df['size'].map(...)`, 역매핑 `{v: k for k, v in mapping.items()}`.

| | Label (integer) encoding | One-hot encoding |
|---|---|---|
| 예 | cat, dog, bird → 0, 1, 2 | cat [1,0,0], dog [0,1,0], bird [0,0,1] |
| 장점 | 단순하고 메모리 효율적 | 순서 가정이 없다 |
| 단점 | 없는 순서 관계를 암시해 모델을 헷갈리게 한다 | 차원이 커진다(메모리·계산 비용) |

- (영상) label encoding이면 "dog + dog = bird" 같은 엉뚱한 관계가 숫자에 생긴다. 반대로 단어 수십만 개를 one-hot으로 만들면 너무 희소해서 Word2Vec처럼 작은 연속 공간에 embedding한다(한국어 Word2Vec 시연: "한국 − 서울 + 파리 = 프랑스").

### 12. 스케일링 (p.42–43)

| 방법 | 식 | 언제 |
|---|---|---|
| Linear (min-max) | `x' = (x − x_min) / (x_max − x_min)` | 분포가 대체로 균등할 때 |
| Z-score | `x' = (x − μ) / σ` | 정규분포에 가까울 때 |
| Log | `x' = log(x)` | 한쪽으로 심하게 치우친(heavy skewed) 분포 |
| Clipping | `x' = clip(x, min, max)` | 극단적 이상치가 있을 때 |

- scikit-learn: `StandardScaler`, `MinMaxScaler`, `RobustScaler`, `MaxAbsScaler`를 `fit` 후 `transform`한다.
- (영상) 스케일링하는 이유는 두 가지다. 경사하강법의 학습률 같은 하이퍼파라미터가 스케일에 맞아야 하고, 범위가 0~1인 feature와 0~10^50인 feature가 섞이면 한쪽 영향력이 사라진다. `RobustScaler`는 이상치에 강하다.

## 교수님이 강조한 것 (작년 영상)

1. **반드시 안 본 데이터로 평가** — "절대로 트레이닝 셋에서 학습이 잘된 것만으로 아 이건 잘될 거야라고 하면 안 돼요. 머신 러닝 모델은 항상 안 본 데이터셋 … 트레이닝에 사용되지 않은 데이터셋을 통해서 결과가 평가되어야 합니다."
   → 하이퍼파라미터는 validation으로 고르고 test는 마지막 확인에만 쓴다. 로드맵을 설명할 때는 test를 보며 튜닝을 오간다고 말했다가 분할 설명에서 이렇게 바로잡았으니, 정리된 쪽을 따른다.
2. **불확실성은 아직 열린 문제** — "아직은 딥러닝에서 굉장히 활발하게 연구되고 있는 주제예요." 테슬라 자율주행 사고를 예로 들며 "10%라도 있다고 하면 안 가야 되잖아요"라고 했다.
   → 12주차 UQ·GP로 이어지는 복선이다. 불확실성의 범위를 알면 안전한(robust) 결정을 설계할 수 있다는 논지가 우리 프로젝트의 동기와 같다.
3. **Epistemic은 데이터로 줄인다** — epistemic 불확실성을 보고 "이쪽에 데이터를 더 얻어야 돼"라고 판단할 수 있지만, aleatoric은 "아무리 데이터를 얻어도 줄일 수가 없는" 것이다.
   → 불확실성이 큰 조건을 다음 수집 우선순위로 삼는 근거가 된다.
4. **도메인 지식 = inductive bias** — `F = ma` 예시로 데이터에 인간의 지식을 더하는 하이브리드를 설명하며 "저도 여기에 관심이 있는 부분이고 물론 아직까지는 성능은 안 좋아요. 아직까지는 일단 데이터 다 때려박는 게 성능은 좋아요"라고 했다.
   → 사람이 설계한 feature(도메인 지식)로 푸는 우리 방식이 교수님 관심사와 맞닿는다.
5. **i.i.d. 가정과 그 붕괴** — 보통 i.i.d.를 가정하지만 "실제로는 데이터 디스트리뷰션이 달라요." covariate shift(x만 바뀜)와 OOD를 구분했고, 외삽은 "너무 리스키"하다고 했다.
   → 조건별 분할(날씨·시각·장소)과 OOD 테스트를 설계할 때 쓰는 개념이다.
6. **Precision과 recall이 제일 중요** — "스페시피시티는 사실 잘 안 쓰는 거 같긴 하고 프리시전과 리콜이 제일 중요한데…" F1은 조화평균이라 한쪽이 떨어지면 급격히 떨어진다고 설명했다.
   → 소수 클래스(실패) 탐지에서는 accuracy보다 precision/recall 계열 지표가 맞다.
7. **NFL과 오컴** — "만능적인 알고리즘이 생기면 우리는 다 굶어 죽고…" 비슷한 성능이면 "그나마 가장 심플한 것을 선택을 합니다."
   → 모델 계단에서 성능이 비슷하면 단순한 모델을 채택하고 그 근거를 적는다.
8. **차원의 저주** — feature가 늘면 공간이 지수적으로 커져 데이터가 희소해지므로 "피처를 적절히 적게 좋은 피처들만 선택을 해서 데이터를 만들어야 학습이 잘 될 수가 있어요."
   → feature 수와 표본 수를 함께 보고, 고차원 입력은 차원을 줄인 뒤 모델에 넣는다.
9. **코딩은 스스로, 이해가 핵심** — "오늘과 다음 주까지만 코딩을 조금 아주 조금 알려 드리고 그다음부터 다 알아서" 하라고 했다. "모르는 게 있으면 그냥 GPT한테 물어보세요"라면서도 "틀린 걸 알아내고 내가 그것을 이해하면서 바꿔야 되는데 그 이해하는 능력은 GPT가 여러분들한테 주지 못하기 때문에" 개념 공부를 한다고 했다. 숙제는 다음 주(3주차)부터 나간다.
   → 과제·프로젝트 모두 생성된 코드를 검증하는 능력이 중요하다.
10. **scikit-learn은 한 줄, 중요한 건 하이퍼파라미터** — SVM도 "한 줄 치면은 구현이 되어 있거든요 … 그 한 줄의 코드에서 여러 가지 옵션들이 있을 거예요. 하이퍼파라미터 튜닝을 어떻게 해야 될지 … 살펴보는 일들이 중요하겠죠."
    → 프로젝트는 구현보다 설정·튜닝·평가 설계에 시간을 써야 한다는 1주차 발언과 같은 방향이다.

## 구현 체크리스트

- [ ] 모든 분할이 run 단위(GroupKFold 계열)인가. 같은 frame의 3뷰가 한 fold에 모이는지 assert로 확인했는가
- [ ] Imputer·Scaler·OneHotEncoder를 `Pipeline`/`ColumnTransformer` 안에 넣어 **train fold에서만 fit**했는가 (test 통계 누수 방지)
- [ ] 라벨 결측(`union = 0`, GT 픽셀 < N_min)은 대체하지 않고 제외했으며, 제외 개수를 뷰·run별로 보고했는가
- [ ] feature마다 히스토그램을 보고 log1p·clip을 적용한 목록을 남겼는가
- [ ] 뷰는 one-hot으로 넣고, 날씨·시각·run은 입력에서 뺐는가 (분석 축 전용)
- [ ] 주 지표 PR-AUC와 선택 임계값의 precision·recall·F1을 보고하고, 분할별 양성 비율을 같이 적었는가
- [ ] L 묶음(잠금 테스트)을 튜닝·feature 선택에 한 번도 쓰지 않았는가
- [ ] P2–P5 분할마다 shift 종류(covariate / OOD, 내삽 / 외삽)를 표에 명시했는가
