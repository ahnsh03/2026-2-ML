# L09. 결정트리와 앙상블 방법

> 강의노트: `Lecture Note/Lecture 9 - decision trees and ensemble methods.pdf` (2025 작년 노트, 35쪽) · 올해 11주차
> 작년 강의영상: "Lecture 9 - Decision Tree and Ensemble Method" (`d1bbZlxtzsk`) — 자동 자막 기반 · 기준일 2026-09-25

## 한눈에

- 결정트리는 내부 노드의 규칙으로 데이터를 재귀적으로 나누고 잎에서 클래스를 낸다. 경계는 축에 평행한 직사각형이다. 가장 작은 트리를 찾는 문제는 NP-complete라서 **탐욕적 분할**을 쓴다.
- 분할 기준: 분류 오류는 순수 노드가 생기는 분할을 구분하지 못한다 → **엔트로피·정보 이득**, **지니 불순도**를 쓴다.
- ID3·C4.5·CART의 차이와 가지치기·결측 처리 같은 실무 이슈를 정리한다.
- 단일 트리는 과적합하기 쉽다 → 앙상블. **배깅**(병렬, 분산 감소)과 **랜덤 포레스트**(노드마다 feature를 무작위로 골라 트리 간 상관을 낮춤).
- **부스팅**(순차, 편향 감소): AdaBoost → Gradient boosting → XGBoost·LightGBM(히스토그램 분할).
- 교수님은 이 강의 끝에서 **프로젝트는 베이스라인과 비교하고, 성능 향상 수단으로 앙상블을 쓰라**고 했다.

## 핵심 내용

### 1. 결정트리 (p.3–5)

- 정의: 내부 노드마다 샘플을 자식 노드 하나로 보내는 결정 규칙이 있고, 잎 노드마다 클래스 레이블이 있는 트리다(루트 → 내부 노드 → 잎).
- 예: "Do I say hi?" 순서도, 레몬/오렌지(`width > 6.5cm?` → `height > 9.5cm?` / `height > 6.0cm?`).
- 속성마다 재귀적으로 나누므로 **결정 경계는 직사각형**이다.

### 2. 트리 만들기 — 탐욕적 분할 (p.6–10)

- 가장 단순한(작은) 트리를 학습하는 문제는 NP-complete이고 가능한 트리 수는 지수적으로 늘어난다. 그래서 빈 트리에서 시작해 **그 순간 최선의 속성으로 나누고 재귀하는** 탐욕적 휴리스틱을 쓴다.
- 품질 지표(처음 안): 분류 오류 `Err = (#틀린 예측) / (#예제) ∈ [0, 1]`
- 대출 예제(40건, safe 22 / risky 18)

| 분할 | 자식 (safe/risky) | 다수결 오류 |
|---|---|---|
| Credit | excellent 9/0, fair 9/4, poor 4/14 | 0 + 4 + 4 = **8** |
| Term | 3 years 16/4, 5 years 6/14 | 4 + 6 = 10 |

→ Credit으로 먼저 나눈다. 나머지 노드(fair, poor)에서 Term·Income으로 같은 절차를 반복한다.

- 분할 선택 알고리즘: 데이터 부분집합 `M`에 대해 각 feature `h_i(x)`로 나눠 분류 오류를 계산하고, 오류가 가장 작은 `h*(x)`를 고른 뒤 재귀한다.
- 정지 조건: ① 모든 데이터의 출력이 같다 ② 모든 feature를 이미 썼다 ③ 어떤 분할도 오류를 줄이지 못한다.

### 3. 연속값 — 임계값 분할 (p.11–13)

- `Income >= $60K`처럼 임계값 `t*`로 나눈다. 후보 `t`는 정렬한 값들 사이의 중간점이다.
- 임계값 분할에서는 **같은 feature를 여러 번 쓸 수 있다.** 깊이 1 → 3 → 10으로 갈수록 경계가 복잡해지고 깊이 10은 학습 데이터에 과적합한다.

### 4. 분류 오류가 나쁜 기준인 이유 (p.14)

- 400/400인 데이터를 (300/100, 100/300)으로 나누든 (200/400, 200/0)으로 나누든 오류는 둘 다 200이다.
- 하지만 오른쪽 분할은 **순수 노드(200/0)**를 만들어 더 나눌 필요가 없으므로 더 낫다. 분류 오류는 이 차이를 구분하지 못한다.

### 5. 엔트로피와 정보 이득 (p.15–20)

- 결정적 분포(전부 참 또는 거짓)는 좋고, 균등 분포(모든 클래스가 같은 확률)는 나쁘다. 날씨 예보 "맑음 99%"는 정보가 많고 "50/50"은 정보가 없다.
- **엔트로피**: `H(X) = −Σ_x p(x) log2 p(x)`. 정보의 부족(불확실성)을 잰다. 균등 분포에서 최대, 결정적 분포에서 0이다.
  - 왜 로그인가(Shannon 유일성 정리): 연속성, 균등 분포에서 최대, **독립 사건의 가법성** `H(X,Y) = H(X) + H(Y)`.
  - 엔트로피가 높으면 결과를 예측하기 어렵고(정보가 필요하다), 0이면 완전히 예측된다.
- 결합 엔트로피: `H(X,Y) = −Σ_{x,y} p(x,y) log2 p(x,y)`. 서울–뉴욕 날씨(독립)는 `H(x) + H(y)`, 서울–인천 날씨(종속)는 `H(x) + H(y|x)`.
- 성질: `H ≥ 0`, 연쇄 법칙 `H(X,Y) = H(X|Y) + H(Y) = H(Y|X) + H(X)`, 독립이면 `H(Y|X) = H(Y)`, `H(Y|Y) = 0`, `H(Y|X) ≤ H(Y)`(x를 알면 y의 불확실성은 줄기만 한다).
- **정보 이득(= 상호정보량)**: `IG(Y|X) = H(Y) − H(Y|X)`. x가 y에 대해 아무 정보도 없으면 0, 완전히 알려 주면 `H(Y)`다.
- 계산 예(p.20)
  - 루트: `H(Y) = −(400/800) log2(400/800) × 2 = 1`
  - 분할 (1): 두 잎 모두 300:100 → `H(Y|X1) = 1/2 × H(3/4, 1/4) × 2 ≈ 0.811` → `IG(1) = 0.1887`
  - 분할 (2): `H(Y|X2) = 3/4 × H(2/3, 1/3) + 1/4 × 0 ≈ 0.689` → `IG(2) = 0.3113`
  - → 순수 노드를 만든 (2)를 고른다.

### 6. 지니 불순도 (p.21)

- `Gini = Σ_x p(x)(1 − p(x)) = 1 − Σ_x p(x)^2`. 오분류 확률을 뜻하며 로그 없이 곱셈·덧셈만 쓴다.
- 슬라이드의 예제 값 0.625(분할 1)와 0.667(분할 2)은 잎의 **가중 `Σ p^2`**, 즉 `1 − Gini`다(교수님도 영상에서 "p제곱만 계산"했다고 말함). 불순도로 계산하면 (1) 0.375, (2) 0.333이고 **낮을수록 좋다.** 결론((2) 선택)은 같다(보충).

### 7. 트리 알고리즘과 실무 이슈 (p.22)

- 개념: 타깃에 대한 불확실성을 줄이도록 데이터를 나눈다. 따져야 할 것은 좋은 분할 기준, 다중 vs 이진 분할, **언제 멈출지(과적합을 막는 가지치기)**, 불완전·결측 데이터 처리다.

| 알고리즘 | 분할 | 기준 | 그 밖 |
|---|---|---|---|
| ID3 | 다중 분할 | 정보 이득 | |
| C4.5 | 다중 분할 | gain ratio(IG의 편향 보정) | 연속 feature, 가지치기, 결측값 처리 |
| CART | **이진 분할만** | 분류는 지니, 회귀는 분산 감소 | 비용-복잡도 가지치기, 대리 분할(surrogate) |

### 8. 앙상블 개요 (p.23–25)

- 트리 기반 모델은 해석하기 쉽고, 비선형 관계를 잡고, **데이터 스케일링이 필요 없다.** 하지만 단일 트리는 과적합하기 쉽다.
- 앙상블: 여러 모델을 결합해 더 강한 방법을 만든다. 거의 모든 학습 알고리즘에 쓸 수 있고 특히 결정트리와 잘 맞는다. 결합 예: (가중) 다수결.
- 의미가 있으려면 **모델들이 서로 달라야 한다**: 다른 알고리즘, 다른 하이퍼파라미터, 다른 데이터, 다른 샘플 가중치.
- 배깅: 무작위 부분집합으로 분류기를 **독립적으로** 학습한다. 부스팅: 앞 모델이 틀린 예제에 집중하며 **순차적으로** 학습한다.
- 편향–분산: 모델 복잡도가 오르면 학습 오류는 계속 내려가지만 검증 오류는 U자를 그린다. **평균은 분산을 줄이는 한 가지 방법이다.**

### 9. 배깅과 랜덤 포레스트 (p.26–29)

- 독립 학습셋 m개가 있다면
  - 편향 불변: `E[y] = E[(1/m) Σ_i y_i] = E[y_i]`
  - 분산 감소: `Var[y] = Var[(1/m) Σ_i y_i] = (1/m^2) Σ_i Var[y_i] = (1/m) Var[y_i]`
- 실제로는 데이터 생성 분포에 접근할 수 없으므로 **bootstrap aggregation(배깅)**을 쓴다. 데이터셋 `D` 하나에서 n개씩 (복원) 추출해 새 데이터셋 m개를 만들고, 각각에서 학습한 모델의 예측을 평균한다.
- **랜덤 포레스트** = 배깅한 결정트리 + 트릭 하나: 노드마다 입력 feature 중 **d개만 무작위로 골라** 그 안에서만 분할을 찾는다 → 예측 간 상관을 낮춘다. 최종 예측은 회귀는 평균, 분류는 다수결이다. 가장 널리 쓰이는 알고리즘 중 하나다.
- 원 안/밖 분류 예(p.28): CART 하나는 계단 모양 경계, 배깅한 트리 100개는 원에 가까운 부드러운 경계를 만든다.
- 장점: 평균으로 과적합을 줄인다(수학적으로 보일 수 있다). 하이퍼파라미터를 크게 튜닝하지 않아도 잘 된다. 단일 모델이 훌륭해도 작은 앙상블이 보통 도움이 된다.
- 한계: 메모리가 더 든다, 해석이 어렵다, **편향은 줄이지 못한다**, **분류기 사이에 상관이 여전히 남는다.**
- (보충) 모델 간 상관계수가 ρ이면 평균의 분산은 `ρσ^2 + (1 − ρ)σ^2/m`이라 m을 늘려도 `ρσ^2` 아래로 내려가지 않는다. 슬라이드의 `1/m`은 독립일 때의 값이고, 랜덤 포레스트가 feature를 무작위로 고르는 이유가 여기에 있다.

### 10. 부스팅 (p.30–33)

- 약한 학습기를 순차적으로 학습하고, 각 학습기는 이전 학습기의 실수에 더 집중한다. **편향을 줄이는 데 강하다**(단순한 약한 학습기를 쓴다).
- 오분류 오류 `Σ_i 1[h(x^i) ≠ t^i]` 대신 가중 오류 `Σ_i w^i 1[h(x^i) ≠ t^i]`를 쓴다. 매 반복마다 틀린 샘플의 가중치를 키우고 새 약한 분류기를 앙상블에 더한다.
- 최종 분류기는 약한 학습기의 가중합이다. 예(p.32): `H_final = sign(0.42 h1 + 0.65 h2 + 0.92 h3)` — 깊이 1짜리 트리(선 하나) 세 개.
- 각 약한 학습기가 가중 데이터에서 **오류율 0.5 미만**이면 학습 오류는 0으로 수렴한다.
- 과적합에 꽤 강하지만 과적합할 수는 있다.

| 종류 | 연도 | 핵심 |
|---|---|---|
| AdaBoost | 1996 | 데이터 점에 가중치를 주고 갱신된 가중치로 새 모델 학습 |
| Gradient boosting | 1999 | 이전 모델들의 **잔차**에 새 모델을 적합 |
| Stochastic gradient boosting | 2002 | 새 모델마다 학습 데이터·feature의 무작위 부분집합 사용 |
| XGBoost | 2016 | 정규화·병렬화를 넣은 최적화된 gradient boosting |
| LightGBM | 2017 | leaf-wise 성장과 **히스토그램 기반 분할** (슬라이드 표기 "LightBGM"은 오기) |

### 11. 배깅 vs 부스팅 (p.34)

| | 배깅 | 부스팅 |
|---|---|---|
| 줄이는 것 | 분산 (**앙상블이 커져도 과적합하지 않음**) | 편향 |
| 부작용 | 편향은 (거의) 그대로 | 분산 증가 (**앙상블이 커지면 과적합할 수 있음**) |
| 학습 | 병렬 | 순차 |
| 구성원 관계 | 상관을 최소화해야 함 | 구성원끼리 의존성이 큼 |

## 슬라이드의 코드·라이브러리

슬라이드에 코드는 없다. p.33에 XGBoost·LightGBM 이름만 나온다. 아래는 대응하는 API다(보충).

| 개념 | API | 메모 |
|---|---|---|
| 결정트리(CART) | `sklearn.tree.DecisionTreeClassifier(criterion='gini'|'entropy'|'log_loss', max_depth, min_samples_leaf, ccp_alpha)` | 이진 분할만. `ccp_alpha` = 비용-복잡도 가지치기. 대리 분할은 구현돼 있지 않다 |
| 배깅 | `sklearn.ensemble.BaggingClassifier(estimator, n_estimators, max_samples, bootstrap=True)` | |
| 랜덤 포레스트 | `sklearn.ensemble.RandomForestClassifier(n_estimators, max_features='sqrt', min_samples_leaf, class_weight, oob_score, n_jobs)` | `max_features`가 슬라이드의 d |
| AdaBoost | `sklearn.ensemble.AdaBoostClassifier(estimator=DecisionTreeClassifier(max_depth=1), n_estimators, learning_rate)` | |
| Gradient boosting | `sklearn.ensemble.GradientBoostingClassifier(n_estimators, learning_rate, max_depth, subsample)` | `subsample < 1`이면 stochastic gradient boosting |
| 히스토그램 GB | `sklearn.ensemble.HistGradientBoostingClassifier(max_iter, learning_rate, max_leaf_nodes, min_samples_leaf, l2_regularization, early_stopping, class_weight)` | LightGBM 방식의 히스토그램 분할. 결측값(NaN)을 그대로 받는다 |
| 외부 라이브러리 | `xgboost.XGBClassifier`, `lightgbm.LGBMClassifier` | 없어도 위 클래스로 충분하다 |
| 보팅·스태킹 | `sklearn.ensemble.VotingClassifier(voting='soft')`, `StackingClassifier(final_estimator, cv, stack_method)` | 스태킹은 슬라이드에 없다 |
| 중요도 | `.feature_importances_`(불순도 기반), `sklearn.inspection.permutation_importance` | 슬라이드에 없다. 아래 주의 참고 |

## 교수님이 강조한 것 (작년 영상)

1. **베이스라인 비교는 필수이고, 앙상블은 권장하는 성능 향상 카드다.** 강의 마지막: "여러분들의 프로젝트에 대해서도 어 베이스라인이랑 비교를 하라고 했잖아요. 베이스라인이랑 비교를 하지 않고도 그냥 앙상블 하면 무조건 좋아질 테니까 앙상블을 쓰는 것도 한 가지 방법이라고 볼 수가 있겠습니다."
   → [교수님 프로젝트 요구사항](../01_강의정보/교수님_프로젝트_요구사항.md) 2항을 자막 원문으로 다시 확인했다. "비교를 하지 않고도"는 자막만으로는 뜻이 모호하지만, 요지는 ① 베이스라인 비교는 이미 공지된 요구사항이고 ② 앙상블은 손쉬운 개선 수단이라는 것이다. 다만 "무조건 좋아진다"는 슬라이드가 밝힌 한계(편향 불변, 남는 상관, 부스팅 과적합)와 맞지 않으므로, 우리는 GroupKFold에서 확인된 개선만 주장한다.
2. **앙상블은 분산을 줄여서 항상 도움이 된다.** "아무리 좋은 싱글 모델이 있다고 하더라도 걔를 결국 앙상블로 이용한다 하면 항상 좋아질 수밖에 없어요. 베리언스는 항상 줄어들기 때문에."
   → 근거는 분산 감소다. 우리 데이터는 같은 run의 프레임끼리 상관이 커서 이득이 작을 수 있으니 수치로 확인한다.
3. **랜덤 포레스트는 가볍고 튜닝 부담이 적다.** "딥러닝 시대에 거의 유일하게 살아남은 알고리즘이라고 볼 수가 있어요. 꽤나 가벼우면서 잘 작동이 된다", "하이퍼 파라미터 없이도 그냥 여러 개의 모델이 평균이기 때문에 굉장히 잘 작동".
   → RF를 튜닝이 적게 드는 주력 기준 모델로 둘 근거다.
4. **단일 트리는 학습 오류를 0까지 만든다.** "디시전트리는 결국 에러를 항상 0으로 만들어 낼 수가 있어요 … 실제로 추가적인 테스트셋이 왔을 때 걔네들의 에러가 더 증가할 수가 있어요."
   → 과적합(고분산)을 줄이는 방법으로 앙상블을 소개하는 흐름이다.
5. **Gradient boosting은 지금도 쓰이는 강한 알고리즘이다.** "2016년 2017년 다시 한번 그레디언트 부스팅 … 잘되는 알고리즘이 생겼고 얘네들은 꽤나 성능이 좋아서 지금까지도 쓰이는".
   → HistGradientBoosting(LightGBM 계열)을 주력으로 쓰는 근거로 인용할 수 있다.
6. **공부 범위는 원리까지.** 트리 알고리즘은 "그냥 쓰면 될 텐데 걔네들의 기본적인 원리들이 이렇게 가지치기를 하면서 만드는 것이었다까지만 이해를 하면 될 거 같아". 부스팅 가중치 계산은 "꼭 공부할 필요까진 없을 것 같고".
   → 유도보다 원리와 비교(배깅 vs 부스팅 표)에 집중한다.
7. **로그의 밑은 상관없다.** "로그 2를 쓸 수도 있고 로그 10을 쓸 수도 있고 … 어떤 로그를 써도 상관은 없습니다."
   → 엔트로피 feature를 계산할 때 밑만 일관되게 고정하면 된다.
8. **시험·일정 관련.** 시작할 때 "시험을 안 볼 거지만 어쨌든 … 공부한다는 측면에서 그냥 가볍게"(자막상 이 내용은 시험 범위가 아니라는 뜻으로 보인다). 끝에서 "벌써 팀 하나가 나왔네요. 이거 팀 이렇게 기록 빨리 해 주시고 … 다음 프로포잘 프레젠테이션을 잘 준비해 주시길".
   → 작년에는 이 강의 직후가 proposal이었다. 올해는 milestone 다음에 이 강의가 온다.

### feature 중요도 주의 (보충 — 슬라이드에 없음)

- **불순도 기반(MDI, `feature_importances_`)**: 학습 데이터에서 분할 이득을 합산한 값이다. 일반화 성능과 무관하고, 값의 종류가 많은 연속 feature를 과대평가하며, 서로 상관된 feature끼리 중요도를 나눠 가진다. 보고용 근거로 쓰지 않는다.
- **permutation importance**: held-out fold에서 열 하나를 섞었을 때 점수가 얼마나 떨어지는지 잰다. `permutation_importance(model, X_te, y_te, scoring='average_precision', n_repeats=10, random_state=0)`처럼 주 지표(PR-AUC)로 계산하고, fold마다 구해 평균 ± 표준편차로 보고한다.
- **상관된 feature 문제**: 밝기·대비·엔트로피, 차선 max-prob·엔트로피·불확실 픽셀 비율처럼 서로 상관된 feature가 많다. 한 열을 섞어도 다른 열이 대신하므로 중요도가 과소평가된다 → 상관이 큰 feature끼리 묶어 **함께 섞거나**, H3처럼 **그룹을 빼고 다시 학습하는 ablation**을 주 근거로 쓴다.
- 중요도는 "예측에 쓰인 정도"이지 원인이 아니다. H1(조건 효과)은 중요도가 아니라 §3.3의 같은 경로 반복 수집으로 검증한다.

## 구현 체크리스트

- [ ] 0a 임계값 기준선을 깊이 1 트리로 train fold 안에서 골랐다
- [ ] RF·HGB에는 스케일러가 없고, LR·SVM은 `Pipeline` 안에서 스케일링한다
- [ ] 불균형(실패 10~19%)에 맞춰 `class_weight`를 설정했고, 주 지표는 `average_precision`(PR-AUC)이다
- [ ] OOB 점수나 HGB 내부 early stopping 점수를 보고 수치로 쓰지 않고, GroupKFold(run) 결과만 쓴다
- [ ] `StackingClassifier`의 `cv`에 run 단위 분할 목록을 넘겼다
- [ ] 계단 표의 앙상블 행에 "최고 단일 모델 대비 차이 ± fold 표준편차"가 있다
- [ ] 중요도는 held-out permutation(상관 그룹 단위)과 그룹 ablation으로 보고하고, MDI는 참고로만 본다
- [ ] 트리 계열의 예측 확률은 12주차 calibration 전후 값을 모두 기록한다

## 올해 강의와 다를 수 있는 점

- 2025 작년 노트 기준이다. 올해는 11주차(milestone 다음 주)이며, 올해 노트가 올라오면 이 문서를 갱신한다.
- 작년에는 중간고사 무렵·proposal 직전에 했고 시험 범위가 아니라는 취지로 말했다. 올해는 기말고사 대신 프로젝트라서 이 강의는 프로젝트 적용이 중심이 될 것으로 본다.
- 작년에는 이 강의에서 "베이스라인 비교·앙상블"을 말했지만 올해는 milestone(10주차) 뒤에 온다. 따라서 앙상블 계획은 milestone 슬라이드에 미리 넣어 둔다(계획 §10의 11주차 작업과 같다).
- 스태킹·soft voting·feature 중요도는 작년 슬라이드에 없다. 올해 추가되면 해당 절을 갱신한다.
- 슬라이드 오기("LightBGM", 지니 예제가 `Σ p^2`를 계산한 점)가 고쳐졌는지 확인한다.
