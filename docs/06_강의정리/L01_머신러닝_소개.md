## 한눈에

- AI를 "인지(perception)·추리(reasoning)·추론(inference)을 거쳐 학습하고 결정하는 에이전트"로 정의하고, 튜링 테스트로 AI의 조건을 짚는다.
- 머신러닝은 **데이터에서 지식을 뽑아내는 것**이다. if-else 규칙을 사람이 짜는 방식과 대비해 설명한다.
- AI ⊃ 머신러닝 ⊃ 신경망 ⊃ 딥러닝의 포함 관계, 그리고 기호주의 AI와 머신러닝의 구분을 본다.

## 핵심 내용

### 1. AI란 무엇인가 (p.2–4)

- 정의: *An agent that can learn and make decisions through perception, reasoning and inference.*
- 교과서 그림의 네 가지 정의 (슬라이드 표기 그대로):

| | 인간의 능력 기준 | 합리성 기준 |
|---|---|---|
| 사고 | 인간적인 사고: "기계가 인간처럼 생각과 마음을 가지게 하는 것" (하우겔란드, 1985) | 합리적인 사고: "인지와 추론, 행동을 가능하게 하는 계산의 연구" (윈스턴, 1992) |
| 행동 | 인간적인 행동: "인간이 지능적으로 행동해야 하는 것을 수행할 수 있는 기계를 만드는 기술" (벨만, 1978) | 합리적인 행동: "인공적으로 만들어진 것의 지능적인 행동에 관련된 것" (닐슨, 1998) |

- **일반 에어컨과 AI 에어컨의 차이**: 일반 에어컨도 온도를 센싱하고 제어하지만 정해진 임계값(threshold)을 넘으면 반응하는 순간 판단일 뿐이다.
  AI 에어컨은 카메라로 가족이 머무는 공간을 확인해 냉방 경로를 고르고, 음성·얼굴 인식을 하고, 생활 습관 데이터를 학습해 온도를 스스로 조절한다.
  즉 **스스로 판단하고 결정하는 추론 과정**이 붙어야 AI라고 부른다. 교수님도 "얼마나 똑똑해야 똑똑한 것인지"는 애매하다고 인정했다.
- **튜링 테스트** (1950년 제안): 대화만으로 기계와 사람을 구분할 수 있는가. 통과에 필요한 능력은 자연어 처리, 지식 표현, 자동 추론, 머신러닝이다.
- **토탈 튜링 테스트**: 물리 세계와 상호작용까지 요구한다. 컴퓨터 비전·음성 인식(세상을 인지), 로보틱스(물체 조작·이동)가 더해진다.

### 2. AI의 역사 (p.5)

| 시기 | 주요 기법 | 이 과목과의 관계 |
|---|---|---|
| 1950s | Perceptron | 신경망의 시작 (가중합 → 출력) |
| 1980s | Back-propagation, Bayesian Network, **Decision Tree** | 신경망이 잘 작동하지 않던 시기 |
| 1990s | **SVM, Ensemble, EM, RL** | 이 과목의 주력 |
| 2000s | **Kernel Methods** | 이 과목의 주력 |
| 2010s | AlexNet, RNN, GAN | 딥러닝 부흥 |
| 2020s | Transformer, LLM | 파운데이션 모델 |

- 이 과목은 **1980년대~2000년대 초반에 유행한 알고리즘**(슬라이드의 굵은 글씨)을 다룬다. 원리는 지금의 딥러닝과 이어지므로 딥러닝으로 가기 전 단계로 생각하면 된다.
- 당시 컴퓨터 성능을 전제로 만든 알고리즘이라 **노트북으로 충분히 돌아가고 큰 GPU가 필요 없다**.

### 3. 머신러닝이란 (p.6)

- 정의: *Extracting knowledge from data.*
- **스팸 필터 예시**: 규칙 기반으로 만들면 금지 단어 블랙리스트를 만들고 if-else를 잔뜩 쓴다. 머신러닝은 스팸/정상 라벨이 붙은 데이터를 주면 모델이 구분 기준을 스스로 찾는다.
- 규칙 기반 방식의 단점 (슬라이드):
  - 결정 로직이 **하나의 도메인과 과제에만** 맞춰져 있다.
  - 규칙을 설계하려면 사람 전문가가 결정 과정을 깊이 이해해야 한다.
- 얼굴 검출처럼 규칙으로 쓰기 어려운 과제에서 머신러닝이 큰 성과를 냈다.
- (영상) 교수님은 이 단점을 데이터 기반 모델 전반의 한계로 넓혀 말했다. 특정 과제만 풀도록 학습했으므로 **조건이 조금만 달라져도 데이터를 새로 모으거나 다시 학습해야 하고**, 결정 과정을 설명하기 어렵고, 어떤 모델을 쓸지는 여전히 사람이 정한다.

### 4. 머신러닝으로 할 수 있는 것 (p.7–9)

- Google Quick, Draw!(그림 인식, 수업 중 시연), 첫 블랙홀 이미지(희소한 관측 데이터의 빈 곳을 채움), 췌장암 조기 발견, OpenAI의 Dota 2 세계 챔피언 격파, AlphaFold 단백질 3차원 구조 예측(노벨상).
- 자율주행, 추천 시스템, 헬스케어·의료.

### 5. AI의 층위 (p.10–11)

- **AI ⊃ 머신러닝 ⊃ 신경망 ⊃ 딥러닝**. 층이 깊은 신경망이 딥러닝이다.
- 벤다이어그램 속 머신러닝 알고리즘: 선형/로지스틱 회귀, K-means, SVM, PCA, k-최근접 이웃, 랜덤 포레스트, 결정 트리. 대부분 이번 학기에 배운다.
- AI의 두 갈래:

| 기호주의 AI (Symbolic AI) | 머신러닝 |
|---|---|
| If-then 규칙, PDDL(계획 언어), Prolog(논리 언어), 전문가 시스템 | 지도학습: **라벨이 있다** / 비지도학습: **라벨이 없다** / 강화학습: **경험으로 배운다** |

### 6. 학습 유형 (p.12)

| 유형 | 정의 | 대표 과제 |
|---|---|---|
| 지도학습 | 입력과 정답 데이터로 스스로 학습 | 분류, 회귀 |
| 비지도학습 | 정답 없는 데이터에서 숨은 패턴을 스스로 찾음 | 군집화 |
| 강화학습 | 주어진 상황에서 보상은 최대화, 처벌은 최소화하도록 학습 | 보상과 처벌 |

- (영상) 비지도학습은 이름 없이 "그룹 1, 그룹 2, 그룹 3"으로 나누는 것이다. 지도와 비지도 사이에 준지도학습(semi-supervised)이 있다.
- (영상) 강화학습은 지도·비지도와 결이 다른 알고리즘이라 이 수업에서는 깊게 다루지 않는다.

### 7. 학습 문제의 예와 문제 유형 (p.13–14)

- 예: 숫자 이미지 인식, X선에서 종양 찾기, 스팸 분류, 증상으로 질병 진단, 6개월 뒤 주가 예측, 주택 가격 예측, Netflix 평점 예측, 대출·카드 신용도 판정, 분자식으로 분자에 걸리는 3차원 힘 예측.

| 문제 유형 | 출력 | 영상에서의 보충 |
|---|---|---|
| 분류 (classification) | 유한 집합의 라벨 | loss는 맞았는지 틀렸는지로 계산 |
| 회귀 (regression) | 연속 실수값 | 정답과의 오차로 loss를 만든다. "훨씬 더 어려운 문제" |
| 랭킹 (ranking) | 예제 사이의 상대적 순서만 | 추천처럼 1순위, 2순위를 맞춘다 |
| 비지도 (unsupervised) | 예: ChatGPT, 생성형 AI | 완벽한 정답은 없지만 좋고 나쁨은 대략 알 수 있다 (에세이 채점 비유) |

## 교수님이 강조한 것 (작년 영상)

1. **프로젝트 평가 기준** — "제가 생각하는 프로젝트는 알고리즘의 구현이 별로 중요한 거 같진 않고 … 아이디어를 먼저 잘 생각을 하고 … 이런 일을 위해서 데이터를 찾고 알고리즘을 찾고 구현을 했고 거기에 성능을 높였다. 그래서 이렇게 완성을 했다. 정도로 스토리라인이 되면 저는 만족을 할 것 같습니다."
   → 문제가 먼저이고 알고리즘은 그다음이다. **베이스라인 → 성능 향상** 단계가 스토리에 반드시 있어야 한다.
2. **기말은 시험이 아니라 프로젝트** — "파이널은 시험이 아니라 프로젝트로 가겠습니다. 이 프로젝트에 대한 공지는 미드 끝나고 나서 드릴게요." 작년에는 "두 명에서 세 명", "세 명 이하" 팀이었다.
   → 올해는 4인 팀이 가능하다고 확인되었다. 작년에는 중간고사 뒤에 공지한다고 했지만 올해 주차표에는 5주차에 proposal 발표가 있어 일정이 훨씬 앞당겨졌다.
3. **과제로 직접 구현** — "수업만 쭉 하고 빨리 끝나면 빨리 끝낼게요. 대신 숙제를 많이 내겠습니다. 하나하나 알고리즘을 구현하는데 구현을 직접 해 보면서…"
   → 코딩은 수업 시간에 가르치지 않고 과제로 익히게 한다. 과제에서 알고리즘을 직접 구현해 보는 경험이 쌓인다.
4. **중간고사 형식** — "머신 러닝 시험은 그렇게 막 계산하고 이런 게 아니라서 … 두 시간을 기준으로 제가 시험을 문제를 낼 거고 하지만 시간은 세 시간 드리겠습니다." 작년에는 수요일 오전 9시~12시(10월 22일)였다.
   → 계산보다 개념 이해 위주 시험이다. 올해는 8주차(10/21 수요일 예상)이다.
5. **최적화가 핵심** — "공대생이라면 모든 알고리즘이 다 옵티마이션으로 귀결이 되는 거란 말이에요. 그래서 이 옵티마이션에 대해서 조금 더 딥하게 공부를 해 볼 생각이고…"
   → 4주차 최적화가 이후 모든 모델(LR, SVM, GP 하이퍼파라미터, 튜닝)의 공통 기반이다.
6. **노트북으로 충분** — "이때의 알고리즘들은 여러분 노트북으로 다 돌릴 수 있을 정도일 거예요 … 그렇게 큰 GPU가 필요하지도 않으니까."
   → 고전 ML은 CPU로 충분하다. 우리 팀도 GPU는 대상 모델 추론(export)에만 쓴다.
7. **데이터 기반 모델의 한계** — "하나의 테스크 하나의 임무에 대해서만 목적을 달성하려고 하고 있기 때문에 이게 조금만 달라져도 … 데이터가 새로 필요하거나 아니면 학습을 전체를 새로 해야 된다."
   → 조건이 바뀌면 학습된 모델이 깨질 수 있다는 점이 우리 프로젝트의 동기(도메인 시프트에서의 인지 실패)와 그대로 이어진다.
8. **환경과 언어** — Python을 추천하지만 "처음에 이 두 주 동안만 파이썬을 같이 조금 해 볼 거고 그 이후로는 … 다른 걸로 하셔도" 된다. Colab도 괜찮지만 Anaconda로 자기 컴퓨터에 환경을 만들어 두기를 권했다.
   → 3주차부터는 코딩을 각자 해결해야 한다.
9. **출석** — "저는 출석을 별로 신경 쓰지 않는 사람이라서 … 영상도 다 유튜브에 올라갈 거고." 다만 학칙상 1/4 결석이면 F이고, 실시간으로 듣는 것이 영상을 여러 번 보는 것보다 빠르다고 했다.
10. **추천 부교재** — EBS 고교 AI 입문 교재를 "생각보다 자료가 굉장히 괜찮습니다"라며 수업 시작과 끝에 두 번 권했다. 과제 문의는 교수님, 채점은 조교가 한다.

|---|---|---|
| 프로젝트 스토리라인 (문제 → 데이터 → 알고리즘 → 구현 → 성능 향상 → 완성) | §0 한 줄 정의, §1 가설 H1–H6, §7 계단, §13 proposal | 발표 구성을 이 순서로 잡는다. 제목은 기법명이 아니라 문제 중심("언제, 어떤 식으로 틀리는가")으로 둔다 |

| 비지도학습: 군집 | §6 고유 오류맵 PCA + GMM | 라벨 없이 "그룹 1, 2, 3"을 얻고, 사람 분류와 NMI·ARI로 대조해 이름을 붙인다 |
| 랭킹 문제 | §8.2 ROC-AUC·PR-AUC, risk–coverage | 위험 점수의 **순서**만 맞으면 되는 평가다. 확률값 자체가 맞는지는 calibration(ECE)으로 따로 본다 |
