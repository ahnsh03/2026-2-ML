# C2. 센서 오동작 탐지 — MORAI 결함 주입으로 배우고 ERC 실로그에서 찾기

> 계열 C (MORAI + ERC 결합) · 9/23 신규 · **9/23 순위 3**

## 한 줄 정의

> **"센서가 이상해지는 순간을 알아챌 수 있나"**
> 시뮬에서 GT와 함께 결함을 넣어 탐지기를 배우고, 실차 로그에서 진짜 이상을 찾아 눈으로 확인한다.

## 데이터와 결함 설계

| 출처 | 내용 |
|---|---|
| MORAI 정상 데이터 | rosbag `full_raw`: `/Ego_topic` 50 Hz(GT), `/gps` 5 Hz, `/imu` 약 49 Hz. 기존 raw bag 21개 + 추가 수집 |
| MORAI 내장 노이즈 | 센서셋의 GPS `gnGenerator`, IMU random walk·Gauss–Markov bias·white noise. 현재 전부 꺼짐 → **정상 잡음 수준 설정용** |
| **오프라인 결함 주입** | 기록 후 점프, 고착, 드롭아웃, 바이어스 스텝, 스케일 오차를 주입. 시뮬 재주행 없이 라벨 무제한 |
| 이미 있는 실제 결함 (MORAI) | 원시 파일 GPS의 약 6%가 (0,0), IMU 타임스탬프 역행 — **우리 데이터의 결함부터 찾을 수 있다** |
| 실제 이상 (ERC) | 보정 전 heading 349° 고착, 30° 점프·127~170° 스파이크, GPS course NaN 68~85%, EKF 1,359° 발산. Mini-4K 30개국 로그 |

## 정답이 정해지지 않은 지점

- 시뮬 쪽은 주입한 결함을 찾는 것이라 절반은 정해진 답이다
- 흥미로운 질문은 (1) 어떤 결함이 정상 기동(급회전 등)과 구별되지 않는가, 최소 검출 크기는 얼마인가,
  (2) 시뮬에서 배운 탐지기가 실차 로그에서 무엇을 찾는가

## 방법

| 단계 | 내용 | 주차 |
|---|---|---|
| feature | 윈도우 잔차: GPS 변위 vs IMU·속도 예측 변위, heading 일관성, 고착 지속시간, 분산·최대 점프 | 2 |
| 0 | 고정 임계값 χ² 게이트 (필터의 innovation gate와 같은 원리) | — |
| 1 | Logistic Regression | 3 |
| 2 | GBM — 결함 종류 다중분류 + importance | 11 |
| 3 | GMM likelihood — 비지도 이상 점수 | 13 |
| 시각화 | PCA로 결함 공간 | 6 |

검증: MORAI는 주입 라벨로 정량, ERC는 이상 점수 상위 k개를 플롯·영상으로 확인(precision@k).

## 개발 부담: 중간

- ROS1 bag 읽기(`rosbags` 라이브러리, ROS 설치 불필요), 결함 주입기, 잔차 feature 코드
- ERC CSV는 IMU가 중첩 JSON이라 파싱 필요

## 활용

- MORAI 프로젝트: GPS/IMU 노이즈와 음영 구간 감지
- ERC: heading 신뢰도 게이트
- 캡스톤이 오프라인 노이즈 주입을 계획 중이라 인프라 공유 가능 (질문은 다름)
