# A1. 카메라 인지 신뢰도 예측기 (Perception Failure Prediction & UQ)

> 계열 A (MORAI) · **순위 1** · 상태: **2026-09-23 주제 확정** `[확정]`
> **구현 계획: [A1 구현 계획](../05_구현계획/A1_구현계획.md)** — 아래 9/6 설명보다 계획 문서가 우선한다.

> **9/23 확정 시 바뀐 점**
> - 대상 모델은 v4 e18이 아니라 **기존에 학습해 둔 최신 후보 v5 actor-negative(B) 18 epoch**로 고정한다.
> - 라벨 분산은 확인됐다. v5 B val 기준 lane IoU < 0.7이 전체 10.4%, front 19.0%.
> - **실주행 rosbag 로그는 정량 테스트셋이 될 수 없다.** Semantic GT가 없어 IoU를 계산할 수 없으므로 정성 데모로만 쓴다.
> - 기존 val은 조건마다 다른 구간이라 조건과 장소가 교란된다 → **같은 경로를 조건별로 반복한 held-out 수집**을 새로 한다.
> - 실패 유형 군집(고유 오류맵 PCA + GMM)을 분석 도구가 아니라 **본체의 절반**으로 격상했다.

## 한 줄 정의

> **"우리 차는 자기가 언제 틀릴지 알 수 있었을까"**
> 카메라 인지 모듈이 실패하는 프레임을 GT 없이 미리 예측하고, 그 예측에 신뢰구간을 붙인다.

## 팀 반응 `[확정]`

손재호·장원태에게 이 주제를 설명했고 **두 사람 모두 반응이 긍정적**이었다.
현재 팀 구성의 출발점으로 삼는다. 자세한 내용은 [팀 구성 문서](../03_팀운영/팀구성_분업_진행상황.md).

## 동기 (교수님 스토리라인 ①)

자율주행 인지 모듈은 안개·역광·저조도에서 **조용히** 실패한다.
틀렸다는 사실 자체를 차가 모르는 것이 진짜 위험이다.
실패를 미리 알 수 있으면 감속하거나, 다른 센서로 무게를 옮기거나, 제어를 보수적으로 바꿀 수 있다.

**발표에서 신경망을 설명할 필요가 없다.** 인지 모듈은 "가끔 틀리는 블랙박스"로 두면 되고,
문제는 "고장을 예측한다"는 고전적인 ML 문제로 환원된다.

## 데이터 (②)

| 용도 | 내용 |
|---|---|
| 학습 | `twinlite_morai_v4_comp8_train_val_sample_b` — train 26,001 / val 1,404 샘플 |
| 조건 | front/left/right 3뷰 × sunny·foggy × 11am·1pm·3pm·5pm |
| 라벨 | Semantic GT 마스크 ↔ 모델 확률맵 비교로 **프레임별 IoU 자동 산출 (라벨링 비용 0)** |
| 일반화 테스트 | sunny 학습 → foggy 테스트 / 오전 학습 → 오후 테스트 (run-aware split) |
| 최종 테스트 | 실주행 로그 — 9/23 정정: GT가 없어 정성 데모로만 쓰고, 최종 수치는 잠금 테스트 묶음으로 낸다 |
| 실패 사례 보강 | `data/rejected_runs/`, foggy 계열 run |

### 타깃 선정 주의 `[확정]`

현재 모델 성능이 **drivable IoU 0.9842**로 분산이 거의 없다. 이 값을 타깃으로 삼으면
예측할 것이 남지 않는다.

→ **타깃은 lane IoU (0.8930) 와 front lane IoU (0.8015)** 로 잡는다.
→ 주력 형태는 **이진 분류** `lane IoU < τ` (열화 프레임). τ는 히스토그램을 보고 결정.
→ 회귀(IoU 값 예측)는 GP 파트에서만 사용.

## 입력 feature (프레임당 30~40개, 전부 저비용)

| 그룹 | feature |
|---|---|
| 영상 통계 | 평균 밝기, 명암 대비, 엔트로피, edge density, **dark channel prior(안개 지표)**, 상단 하늘영역 밝기, 채도 분포 |
| 확률맵 통계 | max-prob 평균, 예측 엔트로피 평균, 마스크 면적, 연결요소 개수, 마스크 경계 길이, 좌우 대칭성 |
| 시계열 | 직전 프레임 대비 마스크 일치도(temporal consistency), 면적 변화율 |
| 멀티뷰 | front/left/right drivable 면적 정합도 |
| 자세 | 속도, yaw rate |
| 조건 메타 | 날씨·시간대 — **feature로 넣지 않고 분석 축으로만 사용** (실전에서는 알 수 없는 정보) |

> 확률맵 통계를 쓰려면 학습된 모델로 데이터셋 전체에 한 번 추론을 돌려 feature를 export해야 한다.
> 이건 안승현이 이미 가진 파이프라인으로 처리 가능하며, **한 번 끝내면 팀원은 CSV만 받으면 된다.**

## 알고리즘 (③) 과 성능 향상 계단 (⑤)

교수님이 요구한 **베이스라인 → 개선의 계단**을 그대로 만든다.

| 단계 | 모델 | 강의 주차 | 기대 역할 |
|---|---|---|---|
| 0 | 확률맵 평균 confidence 임계값 (규칙 기반) | — | **베이스라인** |
| 1 | Logistic Regression | 3 | 선형 한계 확인 |
| 2 | SVM (linear vs RBF) | 7 | 비선형 결정경계 |
| 3 | **Random Forest / Gradient Boosting** | 11 | **주력 모델** + feature importance |
| 4 | **Gaussian Process** | 12 | IoU 회귀 + **예측분산 = 신뢰구간** |
| 5 | Random search 튜닝 (vs grid search) | 14 | 교수님이 강조한 비교 |

**분석 섹션** (독립 기여가 아니라 해석 도구로 배치)

| 기법 | 주차 | 용도 |
|---|---|---|
| PCA | 6 | feature 상관 구조 시각화, 조건별 임베딩 분포 |
| GMM / EM | 13 | **실패 모드 자동 군집** — 역광 / 안개 / 원거리 차선 소실 |

## 평가 설계 — 이 주제의 핵심 강점

| 축 | 내용 |
|---|---|
| **도메인 시프트** | 무작위 split이 아니라 sunny→foggy, 오전→오후. "일반화"를 실제로 측정 |
| **run-aware split** | 같은 run의 프레임이 train/test에 섞이지 않게 (누수 방지) |
| 분류 지표 | ROC-AUC, PR-AUC (열화 프레임이 소수 클래스) |
| **calibration** | reliability diagram — 예측 확률이 실제 빈도와 맞는가 |
| **조기 경보 시간(lead time)** | 실패 몇 프레임 전에 경보가 떴는가. 실용적이고 발표에서 잘 보임 |
| 최종 | 잠금 테스트 묶음 (실주행 로그는 정성 데모, 9/23 정정) |

## 차별화 포인트

1. **GP 예측분산 + calibration** — 작년 13개 프로젝트 중 GP 사용 0건. 교수님 전공 정중앙.
2. **Aleatoric vs Epistemic 구분** — 11주차에서 교수님이 *"데이터를 만 개 모아도 데이터 자체가 가진
   불확실성은 줄어들지 않는다"* 고 강조한 개념. 안개 프레임의 불확실성(aleatoric)과
   본 적 없는 조건의 불확실성(epistemic)을 나눠 보이면 강의 이해도의 증명이 된다.
3. **직접 수집한 데이터** — 교수님의 "데이터셋을 직접 가지고 와서" 요구를 최대로 만족.

## 완성 형태 (⑥)

- 프레임 단위로 실패 확률을 출력하는 경량 예측기 (sklearn, GPU 불필요)
- **주행 영상 위에 실패 확률 곡선이 겹쳐 올라가고, 실제 실패 순간 직전에 확률이 치솟는 데모 영상**
- 자율주행 시스템 관점: planner가 안전마진·속도를 조절할 근거 신호

## 확장 모듈 (여유 시)

**GP 기반 Bayesian Optimization으로 후처리 파라미터 자동 튜닝** — 마스크 임계값, morphology 파라미터를
12주차 GP + 14주차 gradient-free 결합으로 최적화. 교수님이 13주차에서 MPPI를 자율주행 알고리즘으로
직접 소개했으므로 언어가 통한다. **단, 시간이 남을 때만.**
