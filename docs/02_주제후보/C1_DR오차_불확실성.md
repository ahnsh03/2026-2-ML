# C1. GPS를 믿을 수 없을 때 — 추측항법(DR) 오차·불확실성 학습

> 계열 C (MORAI + ERC 결합) · 9/23 신규 · 상태: **9/23 1차 추천 → 기준 변경 후 순위 밖** (재검토 가능)
> 기존 B1(휠 슬립), B3(GPS 신뢰도), A5(조건별 센서 신뢰도)를 하나의 문제로 묶은 안

## 한 줄 정의

> **"GPS가 끊기거나 믿을 수 없을 때, 우리 차·로버는 얼마나 오래 자기 위치를 믿을 수 있나"**
> 물리 기반 DR의 오차를 명령·IMU·rpm으로 보정하고, 그 **불확실성**까지 예측한다.

## 동기 — 두 프로젝트가 같은 구멍을 갖고 있다 `[확정]`

| | MORAI 프로젝트 | ERC (Earth Rover Mini+) |
|---|---|---|
| 문제 | 시나리오에 **GPS가 완전히 끊기는 구간**(샘플 씬 기준 약 119 m)이 있고 GPS/IMU 노이즈가 들어갈 수 있다. 음영 구간 측위 보조 방법은 아직 정해지지 않았다 | GPS 1~2 Hz·드리프트. heading 불안정(보정 전 349° 고착, 장시간 EKF 1,359° 발산). 직진이 −15~−24° 휨. 휠 DR이 회전에서 붕괴. stuck 검출 없음 |
| GT | `/Ego_topic` 50 Hz (완벽) | 없음 → 실험으로 만든다 |
| 추가 수집 | rosbag `full_raw` + 센서셋 노이즈 파라미터(`gnGenerator`, IMU random walk·bias·white noise — 현재 전부 꺼짐) | SDK 로거(rpm×4, 명령, gyro/accel/mag, GPS+hdop, 카메라 20 Hz) |

## ERC GT 설계 — 이 주제의 핵심

1. **테이프 실측 폐루프 코스**: `260726_0014`에서 해본 방식(전진 10.3 m, 회전 585°/630°). 출발 = 도착이면 루프 오차가 GT
2. **ChArUco 보드 랜드마크**: 보유한 전방 카메라 캘리브레이션(RMS 0.42 px, 높이 0.146 m)으로 보드 기준 절대 pose
3. **고정 카메라 + 로버 위 ArUco 마커**: 저가형 모캡, 좁은 구역 연속 궤적 GT
4. **노면·조건 통제**: 아스팔트·보도블록·잔디·자갈·경사, 벽 밀기·바퀴 들기로 stuck 유도 → 라벨이 설계로 정해짐
5. **Mini-4K**(14,141 rides, 3,965 h, 30개국): GPS 장구간 변위를 약라벨로, 규모·지역 간 분포 차이 분석

## ML 구성

| 단계 | 내용 | 주차 |
|---|---|---|
| 0 | 물리 기반 DR (IMU 적분 / 휠 오도메트리 / 운동학 모델) | — |
| 1 | 선형·Ridge 잔차 보정 (명령→RPM 지연 0.5~1.5 s를 lag feature로) | 3 |
| 2 | SVR / RF / GBM | 7·11 |
| 3 | **GP**: 보정량 + 예측분산, calibration, aleatoric vs epistemic | 12 |
| 분석 | PCA(IMU 윈도우), GMM(직진·회전·슬립·정지 regime) | 6·13 |
| 튜닝 | random vs grid, CMA-ES로 필터 노이즈 파라미터 | 14 |

평가: MORAI는 GPS를 끊고 119 m 주행 후 종단 오차 + 95% 구간 포함률, ERC는 실측 GT 대비 오차.

## 캡스톤과의 경계 `[확정]`

캡스톤 Phase 3에 GNSS 음영 DR(propagated pose + covariance)이 이미 있다. 이 주제를 택한다면
**ML = 예측 단계(운동 모델과 process noise), 캡스톤 = 갱신 단계(카메라–지도 정합 관측 모델)** 로 나누고,
ML의 본체를 ERC 실차로 옮겨 산출물을 구분한다. 데이터 인프라만 공유하고 결과는 중복 주장하지 않는다.

## 강점

- 두 프로젝트 모두에 인사이트 (MORAI 음영 구간, ERC heading·DR·슬립)
- 실물 수집과 GT 설계 자체가 차별점
- 교수님 연구 영역(로봇 운동 모델링 + 확률론)과 GP가 정중앙

## 약점 — 순위가 내려간 이유

- **개발 부담이 크다.** ERC GT 실험(코스·마커·모캡) 설계와 로봇 세션이 필요
- 시뮬 차량은 슬립이 거의 없어 MORAI 쪽 개선 폭이 작을 수 있다
- 결과를 이미지로 바로 검증하기 어렵다 (궤적 플롯 위주)
- ERC GUI 로그(ERGUIBIN)는 C++ 파서만 있다
