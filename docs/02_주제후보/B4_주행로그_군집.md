# B4. 주행 로그 군집 — 실패 패턴 발견

> 계열 B (ERC) · 순위 9 · **단독 주제로는 비권장**
>
> **9/23 판정: 순위 2로 상향.** 외부 라벨(명령 기반 기동, 태양고도)로 채점하면 성능 축이 생긴다 → 문서 하단 [9/23 재평가](#923-재평가--외부-라벨로-채점하면-단독-주제도-가능-923-순위-2) 참고.

## 한 줄 정의

> **"수백 번의 주행에서 반복되는 실패 패턴을 찾아낸다"**
> FrodoBots-2K 303 rides와 Mini-4K 32시간 로그를 군집화해 주행 패턴·실패 모드를 분류한다.

## 데이터

| 항목 | 규모 |
|---|---|
| FrodoBots-2K | 303 rides (~35 GB) |
| Mini-4K | 마라톤 전 구간 약 32 h |
| 자체 run | ~1.9 GB |

**데이터 규모는 모든 후보 중 가장 크고, 라벨이 전혀 필요 없다.**

## 알고리즘

| 방법 | 주차 |
|---|---|
| PCA로 궤적·IMU feature 축약 | 6 |
| **K-means 군집** | 9 |
| **GMM / EM — soft assignment, 군집 수 선택(BIC)** | 13 |
| 군집별 특성 해석·시각화 | 2 |

작년 예시 `Turbulence Pattern Analysis on the Final Approach Path Using Clustering`과 같은 구조다.

## 강점

- 라벨이 필요 없어 착수가 가장 빠르다.
- 9주차·13주차를 정면으로 쓴다.
- 데이터 규모가 커서 "데이터를 직접 가지고 왔다"는 요구를 강하게 만족한다.

## 결정적 약점

**교수님의 6단계 스토리라인 중 ⑤ "성능을 높였다"를 보이기 어렵다.**

비지도 학습은 베이스라인 대비 성능 향상을 정의하기가 까다롭다.
교수님은 Lecture 9에서 *"여러분들의 프로젝트에 대해서도 베이스라인이랑 비교를 하라고 했잖아요"* 라고
명시했으므로, 이 축이 비면 감점 위험이 크다.

## 권장 처리

**단독 주제로 쓰지 않는다.** 대신 [B1](./B1_휠슬립_stuck검출.md)이나
[A1](./A1_카메라_인지신뢰도_예측기.md)의 **실패 모드 군집 섹션**으로 흡수한다.
(A1의 GMM 실패모드 군집, B1의 주행 regime 군집이 정확히 이 역할이다.)

군집을 살리면서 성능 축을 만들고 싶다면 — **군집 결과를 feature로 넣어 지도학습 성능이
올라가는지**를 보이는 방식이 있다. 이러면 비지도 결과에도 성능 계단이 생긴다.

## 9/23 재평가 — 외부 라벨로 채점하면 단독 주제도 가능 (**9/23 순위 2**)

위의 "성능 축이 없다"는 약점은 **정답이 공짜로 생기는 외부 라벨**로 채점하면 해소된다.

### 정답이 정해지지 않은 지점

- 30개국 3,965시간 크라우드 주행에 어떤 거동·환경이 섞여 있는지 모른다
- stuck·슬립, 좌우 rpm 불균형, 이상 진동이 얼마나 흔하고 어느 나라·하드웨어에 몰리는지 모른다
- 이상 거동이 특정 장면(잔디, 야간)과 겹치는지 모른다

### 두 갈래 군집

| 갈래 | 입력 | 채점용 외부 라벨 | 개발 부담 |
|---|---|---|---|
| **거동 구간** | 2초 윈도우: 명령(linear·angular), rpm×4 좌우 차, 가속도 진동 에너지(49~89 Hz), GPS 속도 | **명령 기반 기동 라벨**(전진·좌회전·우회전·정지) — 정답이 거의 정해져 있어 "군집이 작동하는가"의 채점 기준으로만 쓰고, **벗어나는 군집(명령했는데 안 움직임 등)** 이 발견 대상 | 낮음 (CSV만) |
| **장면** | 프레임 샘플 → 색 히스토그램·HOG(베이스라인) vs 고정 사전학습 임베딩(개선) | **태양고도** — 위도·경도 + `start_utc`로 계산하면 주간·박명·야간이 물리적 정답. 날씨는 공개 과거 기상 아카이브 사용 여부 선택 | 중간 (영상 디코딩) |

성능 축: NMI·ARI 계단(feature 개선), 이상 탐지 precision@k(상위 k개를 영상으로 확인), 군집 id를 넣은 stuck 분류기 성능.

### 데이터 사실 `[확정]`

| 출처 | 내용 |
|---|---|
| Mini-4K | 메타데이터 14,141 rides × 27열(`drive_mode`, `country`, `city`, `hardware_version`, `start_utc` 등). **로컬 shard는 1개(22 rides)** — 추가는 `ERC/scripts/download_frodobots_subset.py`. 성공·실패 라벨 없음 |
| FrodoBots-2K | 303 rides, 약 42 h. **Earth Rover Zero**라 우리 로버(Mini+)와 기종이 다름 |
| 자체 로그 | ERRAWBIN 약 22분(CSV + jpg). GUI 로그(ERGUIBIN) 약 80분, **개입 이벤트** 포함 — C++ 파서만 있음 |
| 센서 주기 | FrodoBots는 gyro·compass 0.5~1 Hz로 희소 → 회전은 rpm 좌우 차와 명령으로 판단 |
| 환경 | 영상 디코딩용 ffmpeg가 PATH에 없음 → 설치 필요 |

### 추가 갈래 — LogoNav 실패 군집

자체 GUI 로그의 LogoNav 추론 trace(6,525건)와 개입 이벤트로 "추론이 깨지는 순간"을 군집한다.
복귀 구간 실패(중앙값 151° 오차), 제어 포화 91~99% 같은 알려진 문제의 원인을 영상으로 확인할 수 있다.
