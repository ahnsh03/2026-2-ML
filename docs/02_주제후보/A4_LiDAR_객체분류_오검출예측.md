# A4. LiDAR 객체 분류·오검출 예측

> 계열 A (MORAI) · 순위 5 · 주 담당 적합: **손재호**
>
> **9/23 판정:** 비추천. GT 객체가 담긴 bag은 34초뿐이고, capture LiDAR GT 박스 파일의 67%가 비어 있으며(중앙값 8점) Obstacle 박스는 신뢰할 수 없다. MORAI 프로젝트에만 도움이 된다.

## 한 줄 정의

> **"이 검출은 진짜 차인가"**
> LiDAR 점군에서 나온 검출 결과에 대해 ① 객체 종류를 분류하고 ② **오검출(FP)/미검출(FN)을 예측**한다.

## 데이터·라벨

| 항목 | 내용 |
|---|---|
| 입력 | 손재호의 LiDAR 파이프라인 출력 — OBB, 점유, 물체 속도, 추적 |
| **라벨** | 기존 인지 코드에 이미 **`/lidar/tracked_objects_map`의 map-frame OBB·절대 속도를 GT와 비교하는 도구**가 있다 → 라벨 산출 가능 `[확정]` |
| 검증 이력 | 고속주로·회전교차로 검증 이력 존재 |

## Feature

OBB 기하(길이·폭·높이·종횡비·부피), 점군 통계(점 개수, 밀도, ego로부터의 거리, 반사강도 분포,
높이 분포), 추적 정보(추적 길이, 속도 크기·일관성, 최근 프레임 수), 조건(날씨·시간대).

## 알고리즘

| 단계 | 모델 | 주차 |
|---|---|---|
| 0 | 크기 규칙 기반 분류 (베이스라인) | — |
| 1 | Logistic Regression / SVM | 3·7 |
| 2 | **Random Forest / Gradient Boosting** | 11 |
| 3 | GP — 검출 신뢰도의 불확실성 | 12 |
| 분석 | PCA(기하 feature 구조), GMM(객체 유형 자동 군집) | 6·13 |

## 강점

- **가장 단순하고 실패 위험이 낮다.** 순수 tabular 데이터, sklearn 궁합 최상.
- 설명이 한 문장에 끝난다. 딥러닝 배경 지식이 전혀 필요 없다.
- 작년 예시 `2LEOD: 2D LiDAR Ensemble Opponent Detector`와 같은 계열 — 통과 전례가 있다.
- GT 비교 도구가 이미 있어 라벨 파이프라인이 사실상 완성 상태.

## 약점

- **안승현의 기여도가 작아진다.** 팀 내 역할이 불균형해지고, 승현님의 자율주행 perception 커리어
  방향(카메라 인지·데이터)과의 연결도 약해진다.
- 오검출 예측은 라벨 불균형이 심할 수 있다(FP가 드묾) → PR-AUC 중심 평가와 클래스 가중치 필요.
