# C3. 센서 간 지연 추정

> 계열 C (MORAI + ERC) · 9/23 신규 · **9/23 순위 5 — 단독 주제로는 비추천**

## 한 줄 정의

> **"센서마다 몇 ms씩 늦게 도착하는가"** — 센서별 지연·시각 오차를 데이터로 추정한다.

## 왜 단독 ML 주제로 약한가

| 이유 | 근거 |
|---|---|
| 본질이 **추정 문제**다 | 상호상관·최소제곱으로 푸는 신호처리·캘리브레이션에 가깝고 ML이 할 일이 적다 |
| MORAI는 배울 게 적다 | 시뮬 지연은 거의 결정적이다. capture gRPC 지연(약 630 ms)도 수집 부산물이다 |
| ERC는 이미 일부 측정됨 | 명령→RPM 지연 1.2~1.5 s를 상호상관으로 측정. RPM은 명령보다 0.5~1 s 늦다 |
| GT 정의가 어렵다 | LTE 왕복은 미측정이고, 타임스탬프가 관측 시각인지 발행 시각인지 불분명하다 (캡스톤 §6.7도 같은 문제를 다룸) |

## ML로 만들 수 있는 각도

ERC GUI 로그의 `network_state`·`signal_level`·프레임 드롭 통계로 **지연·지터를 회귀**하고 GP로 불확실성을 붙인다.
다만 GUI 로그(ERGUIBIN)는 C++ 파서만 있어 Python export부터 필요하다.

## 판정 (9/23)

단독 주제로 쓰지 않는다. [C2 센서 오동작 탐지](./C2_센서오동작_탐지.md)의 **전처리 단계(지연 보정 후 잔차 계산)** 로 넣는다.
