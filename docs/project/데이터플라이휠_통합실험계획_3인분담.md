# 오프라인 데이터 플라이휠 완성과 3인 실험 분담

**11월 23일 결정.** 안승현이 전방 10영역을 기준으로 기존 RGB 재생부터 GT 평가, 선별 데이터 재학습, 모델 채택 판단까지 한 주기를 주도한다. **단위 2의 품질 추정과 단위 3의 검수 정책을 실제 26R1 ROS에 연결하는 시점은 오프라인 주기를 마친 뒤다.** 장원태와 손재호의 실험은 같은 입력을 사용하는 병렬 검증이다. 팀원 결과를 기다리는 동안에도 안승현은 기존 RF와 공통 검수 기준으로 다음 단계를 진행할 수 있다.

## 이번 주기에서 결정할 순서

| 순서 | 작업과 입력 | 완료 근거 |
|---|---|---|
| 1. 기존 수집본 확정 | 원본과 수집 목록 해시를 검증한다. 물리 세션·도로·위치·픽셀 중복과 f0 노출 이력을 대조해 학습, 개발, 보정, 검수 후보, 기존 조건 유지 평가, 미사용 도로 평가를 나눈다. | 제외·미라벨·미복구 장수를 포함한 분할표, 모집단 전체 RGB 목록, 격리한 Semantic 목록, f0·ROI·GT 정책 버전. 이미 평가한 273장은 재현·진단에 사용한다. 독립 야간 정상 위치가 부족하면 그 범위의 결론을 보류하고 부족분만 보강한다. **현재 판정.** 오프라인 첫 주기와 실제 주행 검수 실험은 이미 수행했다. 정차 12위치 576장에서 10영역 품질 추정 MAE가 0.1045에서 0.0669로 줄었으나, 별도 도로에서는 기존·새 모델 모두 회차별 검수 정책으로 25/28장을 찾았다. 야간 정상 16장은 3개 위치에 집중됐다. 선별 재학습 후의 한 새 주행에서 차선 IoU가 개선됐지만, f1에 맞춘 품질 MAE 증가가 +0.01449로 허용치 +0.010을 넘어 f0/g0를 유지했다. 이번 목표는 기존 자료로 **정책 고정 → GT 검증 → 재학습 → 채택·보류**를 재현 가능한 한 주기로 끝내는 것이다. ## 세 사람이 바로 시작할 일

11월 23일 저녁 안승현의 오프라인 통합 실험에서 후보 576행과 과거 주행 273행을 익명화했다. 장원태는 20시 정상 장면 수를 먼저 확인한 뒤 조명별 기준의 이득과 누락을 계산한다. 손재호는 두 모집단을 나눠 같은 예산에서 발견 수와 고유 위치 수를 비교한다. 위치별 할당으로 선별한 자료를 실제 학습에 투입하는 비교도 남아 있다. [검수·갱신 결과 및 팀용 표](오프라인_검수와_동일예산_재학습_20261123.md)

| 담당 | 첫 작업과 대조군 | 독립 산출물과 인계 |
|---|---|---|
| **안승현 · P0 통합 개발과 채택 판정** | 실험 볼륨에서 세션을 등록하고 분할·모델·예산을 동결한다. 기존 RF와 무작위 기준선으로 2~3을 먼저 실행한다. 후보 장수, 학습량, replay 구성의 효과를 나누고 부족한 조건만 보강한다. | 공통 입력의 버전·해시, 팀원이 CPU로 읽을 익명 프레임 표와 열 정의, GT 분리본, 기준선 결과, f0/f1·g0/g1 최종 판정표를 제공한다. 외부 공개 수치와 시연에 사용할 모델 버전을 결정한다. |

[조건 대조 원리](수집데이터_재가공과_논문활용_20261123.md) |

장원태의 첫 질문은 **야간에 정상인 장소에서도 경보가 줄어드는가**, 손재호의 첫 질문은 **같은 검수량으로 더 많은 실패와 서로 다른 위치를 찾는가**다. 두 실험은 저장된 표에서 독립적으로 실행할 수 있다. 팀원용 표에는 익명 프레임/구간 ID, 순서, 동결된 모델별 점수, 예산·검수 창, 개발/보정 역할을 넣는다. 조건 정답과 실제 IoU는 별도 파일로 제공한다. 미사용 평가 GT는 안승현이 설정 동결 후 연결하며 두 팀원이 평가 결과로 다시 보정하지 않도록 노출 시점을 기록한다.

공개 저장소만으로 먼저 볼 자료는 [10영역 집계와 프로토콜 해시](../baselines/roi10_study_20261123.json), [야간 경보 그림](../baselines/figures/roi10_night_decisions.png), [품질 추정 비교 그림](../baselines/figures/roi10_quality_comparison.png)이다. 프레임별 정책 비교에는 실험 볼륨의 동결 점수·지연 GT가 필요하므로 안승현이 같은 버전의 두 목록을 전달한다.

### 논문에서 가져올 실험의 우선순위

- **P1, 장원태**는 TCSR-Monitor의 동일 열화 조건 내 정상·실패 비교와 미관측 조건 전이 검증을 야간·독립 도로에 적용한다. 이후 Roser·Cheng·Lu·Lin에서 차용한 지역 밝기·대비·하늘 단서와 영역 확률 결합이 환경별 경보까지 개선하는지 별도로 측정한다.
- **P1, 손재호**는 Zenk 등의 risk–coverage에서 통과 비율별 평균 실제 손실(1−IoU)을 구한다. 평가 모수가 같은 경우에만 AURC와 동일 예산 발견율을 비교한다.
- **P2, 안승현**은 남은 오검출·누락 유형을 보고 MetaSeg의 연결성분 내부/경계 엔트로피와 확률 마진을 추가한다. Küchler의 특징군 제거·재학습 방식으로 기여를 분리한다. SEE의 평균 logit energy는 같은 RGB·f0에서 재추론해 기존 RF에 추가한 뒤 오차와 비용을 비교한다.
- **모델 갱신 시, 안승현**은 TwinLiteNet+ Medium v6를 출발점으로 같은 장면에서 f0와 f1을 비교한다. GP는 RF와 같은 품질 추정 단계의 비교군, Bayesian optimization은 개발 분할에서 replay·학습 설정을 고르는 오프라인 비교군이다. 각 논문의 원래 과제와 우리 적용 범위는 원문 링크와 함께 정리했다. [초기 6편·후속 날씨 연구 적용표](수집데이터_재가공과_논문활용_20261123.md)

### 결과 올리는 방법과 웹페이지 범위

- 각 담당은 자신의 브랜치에서 팀 레포로 PR을 올린다. 결과 요약은 `docs/project/`에 날짜·주제가 드러나는 이름으로, 공개 가능한 집계·그림은 `docs/baselines/`에 둔다. PR에는 가설, 실행 명령·코드 버전, 부모 세션 목록 해시, 역할·위치·장수, 대조군·예산, 지표와 분모, 실패 사례, 채택/보류와 다음 결정을 적는다. 실패하거나 차이가 없었던 실험도 같은 형식으로 올린다. 원본 영상·프레임별 목록·체크포인트·개인 경로는 실험 볼륨에서 공유한다.
- **손재호가 웹페이지를 맡는 이유**는 검수 순위 그림과 그 분모를 직접 검증할 수 있고, GPU나 시뮬레이터 없이 페이지 준비를 병행할 수 있기 때문이다. 리포지터리의 `site/`에 논문 프로젝트 페이지 형식의 초안을 준비한다. 문제와 기여 → 파이프라인 그림 → 검증된 결과와 한계 → GitHub·재현 명령 → 자막 있는 시연 영상 → 팀·참고문헌 순으로 구성한다. 초기에는 공개된 집계·그림으로 미리 보기를 만들고, 영상이 준비되면 실제 링크와 시연 조건을 연결한다.
- **장원태**는 야간 정상·실패 대조 그림과 캡션, **안승현**은 오프라인 재생 시연 영상과 최종 수치·모델 상태를 제공한다. 페이지에 오프라인 재생과 실제 ROS 시연의 범위를 표시한다. 공개 전 모바일 보기·그림 설명·링크·수치 출처를 확인한다. 기계학습 팀은 세 명, 캡스톤 발표·제출은 안승현·장원태다.

실명은 시나리오·환경 분석, 인지 결과의 GT 비교, 카메라 인지·데이터 통합 경험을 고려한 **팀 검토용 제안**이다. 기계학습 팀은 세 명이며, 캡스톤 발표·제출은 안승현·장원태가 담당한다. 이전 A/B/C는 기술별 인계 기록이며, 위 세 업무는 이번 실험 결과물의 책임 범위다. [팀 운영](팀운영.md)

## 업무 1. 주행 환경 특징과 온라인 수집

기존 단위 1 전체와 단위 3의 입력·수집을 맡는다. **어디서 어떤 영상이 들어왔고, 어떤 환경 표현을 재현할 수 있는지**를 책임진다.

1. **ROI와 특징을 비교한다.** 기존 824장(103개 자세 × 8조건)으로 시작한다. 전체 밝기와 기존 RGB 28열을 기준선으로 두고 보닛만, 하늘·근거리 도로·원거리 도로·좌우 주변, 여기에 보닛을 더한 구성을 같은 군집기로 비교한다. 밝기·대비·경계 밀도부터 시작해 색 분포, 보닛 표면의 미세 밝기 변동, 근·원거리 밝기 차이를 차례로 추가한다. 가림·역광·차량 방향 변화에서 ROI가 실제로 무엇을 담는지 영상으로 점검한다.
2. **특징을 고정하고 군집기를 비교한다.** 밝기 구간, KMeans, MiniBatchKMeans, e-means를 같은 분할에서 비교한다. 첫 군집 수 후보는 2·4·8이다. 같은 조건·다른 위치의 군집 일치율과 같은 위치·다른 조건의 분리율을 함께 본다. 시드별 안정성, 조건별 표본 수, 훈련 시간과 RGB당 배정 지연을 남긴다. 온라인에서는 고정된 변환·중심만 적용한다. 근거가 약한 군집은 밝기 기준선과 함께 인계한다.
3. **파일 재생 후 26R1 ROS에서 시험한다.** 먼저 기존 RGB를 촬영 순서로 재생한다. 이어서 실제 토픽·인코딩·수신률·시각을 확인하고 시간·위치 간격 필터와 픽셀 중복 제거를 적용한다. 짧은 수집 창을 닫을 때 업무 2의 정책으로 검수 목록을 확정한다. 같은 창을 재생했을 때 적격 ID·선택 ID·이유가 일치하는지, 수신→점수 및 수신→저장 지연(p50/p95), 드롭 사유, 피크 저장량, 재시작 후 누락을 확인한다. 전체 후보 GT는 평가용 런에서만 별도로 보존해 선별 후 연결한다.

**인계 기준.** 카메라·ROI 프로필, 세션별 역할표, 행 ID·RGB 해시, 군집 버전·배정 상태를 업무 2에 보낸다. 같은 프레임의 RGB/Semantic 대응과 데이터 출처를 확인한 자료는 업무 3에 제공한다. ROS 수신·저장과 장애 복구는 업무 1, 주어진 후보 중 무엇을 남길지 결정하는 함수는 업무 2가 소유한다. [환경 특징 실험](작업단위1_주행환경_특징과_군집화.md) · [수집 검증 절차](작업단위3_취약장면_선별과_온라인수집.md)

## 업무 2. 인지 품질 추정과 검수 장면 선별

기존 단위 2 전체와 단위 3의 선별 정책을 맡는다. **모델이 틀릴 장면을 알아보는 능력과 실제 검수 목록의 효율**을 각각 측정한다.

1. **RF와 GP를 비교한다.** 동일한 f0 출력, X56, y, 평가 행에서 전역 RF와 가우시안 프로세스 회귀(GP)의 IoU 예측을 비교한다. MAE·야간 편향·추론 지연과 함께 GP 90% 예측구간의 실제 포함률·폭·불확실성별 오차를 낸다. 그다음 업무 1의 ROI 특징을 추가해 효과를 분리한다. 야간 실패는 근·원거리 GT와 FP/FN을 따로 확인한다.
2. **같은 예측에 네 경보 정책을 적용한다.** 고정 0.7, 전역 보정, 밝기 그룹 보정, 환경 군집 보정을 같은 프레임에서 비교한다. 보정용 정상 FPR 예산은 10%로 시작한다. 저표본·미배정 군집은 전역 기준을 쓴다. 주 지표는 야간 정상 장면에서 줄어든 오경보 수와 새로 놓친 실제 저품질 수다. 전체·야간 Recall, 조건별 FPR과 분모도 남긴다.
3. **검수 예산을 고정한다.** 같은 적격 풀에서 무작위·Confidence·Entropy·예상 IoU 순위를 재현한다. 다음으로 30장 중 6장을 잔여 풀 무작위 감사에 공통 배정하고, 나머지 24장을 낮은 예상 IoU 순, 환경 군집별 순번, 또는 낮은 GP 평균 18장+높은 GP 불확실성 6장으로 구성한다. σ 효과는 동일 GP 평균 기준선과 비교한다. 주 검수 비율은 10%, 보조 비율은 5%·20%다. 발견 수, Recall@예산, 실제 저품질을 찾은 고유 구간 수, 정책 간 선택 ID 겹침을 집계한다. 전체 GT가 없는 운영 주행에서는 Recall 분모를 추정하지 않고 검수·발견 수를 보고한다.

**인계 기준.** 업무 1에는 RGB 단독 품질 추론·선별 함수와 버전별 예상 결과를, 업무 3에는 같은 풀에서 만든 정책별 선택 목록과 무작위 대조 목록을 보낸다. 각 행에 점수·선택 이유·순위·시드·모델 버전을 남긴다. GP나 군집 경보가 유리하지 않으면 RF·전역 경보·Confidence 기준선으로도 다음 실험을 진행한다. f1이 준비되면 업무 2가 g1을 재학습하고 전용 cutoff를 고정한다. [품질·경보 실험](작업단위2_인지품질_추정과_경보보정.md) · [선별 정책 비교](작업단위3_취약장면_선별과_온라인수집.md)

## 업무 3. 인지모델 재학습과 갱신 판단

기존 단위 4를 맡는다. **낮은 IoU를 잘 찾은 정책이 실제 재학습에서도 더 유용한지**를 별도 대조군으로 검증한다.

1. **선별의 학습 가치를 비교한다.** 미갱신 f0, 기존 데이터만 추가학습한 ReplayOnly, 무작위 신규 30장, 품질 선별 30장을 비교한다. 초기 f0, replay 풀 256장, 학습 시드, 신규 유효 라벨 수와 업데이트 수를 맞춘다. 기준 설정은 배치 8(신규 4+기존 4), 240회다. 업무 2의 신규 정책도 같은 조건에서 비교한다.
2. **데이터 부족과 학습량 부족을 분리한다.** 첫 계획은 고유 장면 30/60장 × 업데이트 240/1,200회의 2×2 비교다. 추가 장면의 구간·방향·객체 배치와 장당 노출 횟수를 함께 기록한다. 기존 성능 유지용 replay 풀은 장수를 맞춘 뒤 구성 효과를 먼저 보고, 비율 탐색 때는 구성을 고정한다.
3. **제약 있는 베이지안 최적화(BO)를 시험한다.** 고정된 개발용 신규 목록에서 학습률, 배치 내 replay 수, f0 출력 유지 제약 가중치를 탐색한다. 목적은 신규 조건 개발 IoU 이득 최대화, 제약은 기존 조건 개발 IoU 손실 0.005 이내다. 동일 초기 설정·평가 횟수의 무작위 설정 탐색과 비교하고 GPU 시간도 기록한다. 첫 예산안은 공통 시작점 4개 포함 방법당 20회이며 재현 런 비용 확인 후 고정한다. BO는 오프라인 학습 설정을 고른다. 업무 2의 GP는 주행 프레임의 품질을 추정한다.
4. **모델 쌍의 채택 여부를 판정한다.** 업무 3이 f1을 고정하고 업무 1이 해당 버전의 X/y 생성을 지원한다. 업무 2에서 받은 g1·경보와 f1의 버전 일치를 확인한 후, 같은 잠금 RGB/GT에서 f0/g0와 f1/g1을 비교한다. **새 평균 차선 IoU 변화 ≥ 0, 기존 평균 차선 IoU 손실 ≤ 0.005, 짝 품질 MAE 증가 ≤ 0.01**을 모두 만족해야 연구용 채택 적격이다. 각 MAE는 해당 인지모델이 실제 달성한 IoU로 계산한다. 조건별 회복·신규 실패 수도 기록한다. **인계 기준.** 초기·후보 체크포인트, 학습 자료·설정·시드, 짝 품질모델·경보 버전, 신규 및 기존 조건별 변화표와 채택 또는 보류 사유를 남긴다. 제약을 통과한 후보가 없으면 f0/g0가 기준 모델로 남는다. 그때 하락이 컸던 조건과 부족한 세션을 업무 1·2에 돌려주어 다음 수집 계획에 반영한다.
