# 작업 단위 3. 취약 장면 선별과 온라인 수집

2026-11-23 팀 개발·실험 계획. **검수할 수 있는 장수가 같을 때, 실제 차선 IoU가 낮은 장면을 얼마나 많이, 서로 다른 주행 상황에서 확보할 수 있는가?** 먼저 같은 후보 풀에서 선별 규칙을 비교하고, 이어서 26R1 ROS 수신부터 RGB 저장·검수 목록 생성까지 재현한다.

**2026년 11월 23일 실행 결과.** GT 없이 선정한 58장을 실제 재학습 입력까지 연결했다. RF 순위에서는 45장이 같은 교차로에 집중돼, 같은 상위 116장에서 서로 다른 특징의 장면과 균일 무작위 장면을 각각 선별하는 대조를 추가했다. [예산별 발견율과 장소 집중도](환경_ROI와_품질추정_20261123.md)

## 1. 기준 실험과 입력

기존 후보 296장에서 30장을 고르면 예상 IoU 순위와 Confidence 순위가 모두 실제 저품질 30장을 찾았다. 실제 저품질은 144장이므로 두 방법 모두 선택 정밀도 100%, Recall@10%는 30/144 = 20.83%였다. 다른 주행의 10% 예산에서는 흐림 13시에서 RF가 29/38장, Confidence가 26/38장을 찾았고, 눈 13시에서는 각각 32/37장과 37/37장이었다. 같은 수의 장면을 찾았더라도 같은 프레임이나 같은 구간을 골랐는지는 별도 질문이다. [기존 선별 실험](품질추정_실험결과_20261116.md) · [날씨별 주행 결과](품질저하_탐지평가_20261116.md)

- **바로 쓸 수 있는 입력**은 전방 RGB와 고정 f0/g0의 예상 IoU, 전체 화면의 차선 Confidence·마킹 Entropy다. 기존 파일 기반 추론과 후보 선별, 우선순위와 무작위 감사를 섞는 검수 대기열이 있다. 대기열의 30장 기본 예시는 우선 24장과 잔여 후보에서 비복원 무작위 6장이다. 앞 문단의 순위 상위 30장 실험과 별도로 재현한다. [RGB 추론](../../src/quality_estimation/infer_images.py) · [기존 선별](../../src/quality_estimation/select_candidates.py) · [검수 대기열](../../src/quality_estimation/review_queue.py)
- **후속 입력**은 단위 1의 고정 환경 군집 ID·배정 상태와 단위 2의 예상 IoU·경보·적용 기준·선택적 GP 표준편차 σ다. 경보가 없는 후보도 순위와 무작위 감사 대상에 둔다. σ는 실제 오차와의 관계를 검증한 버전만 대상으로 한다. 입력의 행 ID·RGB 해시 및 인지·품질·환경 모델 버전을 맞춘다. [단위 1](작업단위1_주행환경_특징과_군집화.md) · [단위 2](작업단위2_인지품질_추정과_경보보정.md)

## 2. 같은 예산에서 선별 정책 비교

2026-11-23에 저장된 품질 순위 30장과 Confidence 30장의 학습 목록을 행 ID로 대조했다. **20장은 공통이고 각 방법에만 있는 장면은 10장씩**이다. 이 두 목록은 감사 없이 뽑은 순위 상위 30장이다. 이후 비교에서는 차이가 난 20장의 구간·환경을 조사하고, 별도로 감사 6장을 포함한 대기열을 재구성한다.

1. **후보 풀부터 고정한다.** 비교하는 모든 정책에 같은 적격 행 목록을 전달한다. 과거 재현에는 기존 시간·이동·방향 간격 규칙과 동일 픽셀 제거를 그대로 적용한다. 새 주행에서는 RGB 중복 및 사용 가능한 시각·자세만으로 간격을 정한다. 과거 코드의 명시적 날씨 전환 예외는 새 온라인 정책에서 쓰지 않는다. 자세가 없으면 시간 간격을 사용하고 어떤 기준이 적용됐는지 남긴다. 원본 수, 제외 사유별 수, 최종 적격 수 N을 기록한다. [기존 간격·중복 처리](../../src/quality_estimation/splits.py)
2. **예산은 B 비율, 실제 검수 장수는 k = ⌈B × N⌉**으로 정의한다. 주 비교는 10%, 민감도 비교는 5%·20%다. N=296이면 각각 30장, 15장·60장이다. 순위 동점은 행 ID 오름차순으로 푼다. 검수한 뒤 GT가 미정의로 판명된 행도 예산 한 장을 사용한 것으로 센다.
3. **정책만 바꾼다.** 먼저 감사 없이 무작위, 낮은 Confidence, 높은 Entropy, 낮은 예상 IoU 순위를 비교한다. 다음 표에서는 모든 방식에 동일한 감사 장수 ⌈0.2k⌉와 같은 사전 시드 목록을 사용한다. 감사 표본은 각 정책의 우선 선별 후 남은 전체 풀에서 뽑는다. 시드가 같더라도 정책별 잔여 풀이 달라 감사 장면은 다를 수 있다.

| 혼합 정책 | 예산 30장의 첫 실험 배분 | 확인하려는 효과 |
|---|---|---|
| 점수 기준선 | Confidence가 낮은 24장+감사 6장. 별도로 예상 IoU가 낮은 24장+감사 6장 | 센서·후보·감사 비용이 같을 때 품질모델이 주는 이득 |
| 환경 다양성 | 군집별 예상 IoU 오름차순 목록에서 순번제로 24장+감사 6장 | 한 환경의 비슷한 실패가 우선순위를 독점하는지, 서로 다른 구간의 실패를 더 확보하는지 |
| 불확실성 탐색 | 예상 IoU가 낮은 18장, 남은 후보 중 GP σ가 큰 6장, 감사 6장 | 추정기가 자신 있게 점수를 주기 어려웠던 장면에서 추가 오류를 발견하는지 |

군집 순번은 고정 ID 순서로 시작하고 빈 군집은 건너뛴다. 미배정 사례는 한 그룹으로 표시해 선택 수를 따로 보고한다. σ 효과는 **같은 GP 평균**의 24+6 대조군과 비교한다. 다른 예산에서는 우선 슬롯의 1/4(내림)을 σ 탐색에 배정하는 것이 첫 제안이다. σ가 준비되지 않으면 기준선과 환경 다양성 비교부터 끝낸다. 군집·σ의 단독 기여가 확인된 뒤에만 결합 정책을 검토한다.

## 3. 평가 자료와 인계 판단

- 정책·버전·시드와 선택 ID를 GT 열람 전에 고정한다. 전체 후보 GT를 별도로 보유한 평가 세션에서만 실제 저품질(`y < 0.7`) 발견 수, 선택 정밀도(발견 수/k), Recall@B(발견 수/적격 풀의 실제 저품질 수)를 계산한다. 저품질 분모가 0이면 Recall은 NA다. 선택분만 라벨링한 운영 세션에서는 발견 수·검수 수·미정의 수를 보고한다. 감사 적중률은 **우선 선별에서 빠진 잔여 풀**의 관측치다. [기존 선별 지표](../../src/quality_estimation/metrics.py)
- 다양성의 주 지표는 **실제 저품질을 적어도 한 번 찾은 서로 다른 주행 구간 수**다. 평가 전에 경로 구간과 날씨·시간대 묶음을 정하고 조건별 발견 수와 후보 중 저품질 수를 나란히 낸다. 군집 개수 증가만으로 환경 다양성 개선을 판정하지 않는다. 기준선과 선택 ID 교집합, 한쪽만 찾은 저품질 수, 동일 구간 연속 장면 수를 기록한다. 무작위성은 같은 복수 시드로 반복하고 독립 주행 세션별 차이를 제시한다.
- 개발 자료에서 정책을 좁힌 뒤 별도 평가 세션에서 **같은 k로 발견 수를 유지하면서 더 많은 취약 구간을 덮는지**, 또는 **같은 구간 범위에서 발견 수가 늘어나는지** 판단한다. 두 지표가 엇갈리면 교환관계를 장수·구간 수로 보고한다. 기존 296장 결과는 재현 기준으로 쓴다. 추가학습 효용은 단위 4에서 동일 신규 라벨 예산으로 따로 평가한다.

## 4. 26R1 ROS 수집과 재생 검증

센서 수신 단계에서는 전방 RGB를 받아 고정 모델로 품질 점수와 환경을 계산한다. 첫 구현은 **짧은 수집 창을 닫은 뒤 그 창 안에서 순위를 확정**한다. 전체 주행이 끝나야 알 수 있는 상위 10%를 매 프레임 즉시 판정한다고 가정하지 않는다. 창 길이·장수 상한·임시 저장 바이트 상한·검수 장수를 주행 전에 정하고, 로컬 디스크 예산과 사람의 검수 예산을 따로 기록한다. 창별 올림으로 주행 전체 검수 예산을 초과하지 않도록 남은 장수를 관리한다.

| 검증 순서 | 개발·시험 내용 | 확인할 증거 |
|---|---|---|
| ① 파일 재생 | 동일 원본 RGB를 촬영 순서와 창 경계 그대로 입력한다. 같은 간격 필터, 모델, 정책, 시드로 일괄 계산한 결과와 대조한다. | 적격 ID·선택 ID·선택 이유 일치, 점수 오차와 순위 역전 수. 창별 선별과 전체 세션 일괄 선별의 차이도 별도 집계 |
| ② ROS 연결 점검 | 26R1에서 실제 전방 토픽, 메시지 형식·인코딩, 크기, 수신률, 센서 시각·프레임 식별자 유무를 확인한다. 기존 ROS 수집 컨테이너와 ML 추론 환경의 의존성이 다르므로 RGB 인계 경계를 먼저 검증한다. | 수신 RGB와 재생 RGB의 픽셀 해시, 카메라 프로필·모델 버전 일치. 기존 UDP 수집과 26R1 ROS 결과는 런 단위로 구분. [기존 개발·수집 환경](../development/개발환경.md) |
| ③ 짧은 주행 | 수신 콜백과 추론·저장을 분리하고 유한 길이 큐를 사용한다. 미처리·중복·간격 제외·저장 실패를 따로 센다. 점수는 검수 후보 기록에만 사용한다. | 수신·처리·적격·선택·저장 성공 건수, 입력률과 처리율, 큐 최대 깊이, 누락 원인. 발행 측 카운터가 없으면 수신 이전 손실은 미측정으로 표시 |
| ④ 연속 주행·복구 | 주간·야간, 서로 다른 경로에서 반복한다. 별도 시험 디렉터리에서 큐 포화·쓰기 실패·재시작·마지막 미완료 창을 확인한다. | 수신→점수 산출 및 수신→RGB 저장 완료의 p50/p95, 창 종료→목록 확정 시간, 임시 최대 사용량·최종 저장량, 중복·누락·깨진 참조 수 |

이전 로컬 측정의 디코딩된 RGB→f0→특징→RF p95는 **30.60 ms**였다. ROS 수신·저장·창 종료 대기 시간은 새로 측정한다. 같은 프로세스 내 경과 시간은 단조 시계로 기록하고, 센서 시각과 호스트 시각의 기준이 확인된 경우에만 센서→호스트 지연을 계산한다. 목표 수신률과 저장 한도는 실제 인터페이스 점검 뒤 연속 주행 전에 정한다. [기존 지연 측정 범위](품질추정_실험결과_20261116.md)

임시 RGB는 주행별 지정 출력 볼륨에 저장하고 남은 공간과 창 상한을 기록한다. 저장 완료·해시 확인 후 선택 목록을 확정하며, 보관 한도에 이르면 해당 창을 닫거나 수집을 중지하고 사유를 남긴다. 시뮬레이터 평가 런에서는 전체 분모를 계산할 수 있도록 같은 시각의 Semantic을 **별도 평가 기록**에 보존한다. 추론·선별 프로세스에는 RGB만 전달하고, 재촬영 프레임을 원래 RGB의 GT로 간주하지 않는다. 대응 GT가 없으면 미라벨 RGB로 인계한다.

## 5. 완료 기준과 단위 4 인계

창이 닫힌 후 선별된 학습 후보에 같은 시점의 GT를 붙이려면 수집 시점에 대응 자료를 확보해야 한다. 첫 파일 재생은 이미 짝지어진 RGB/Semantic에서 RGB만 선별기에 제공한다. 26R1 학습 후보 런에서는 별도 기록기가 동기화된 Semantic을 창 예산 안에 임시 보관하고 선택 ID 확정 후 대응분을 인계한다. 동기화나 임시 저장이 불가능하면 RGB 검수까지 수행하고 해당 촬영은 미라벨로 남긴다. 평가 런에서 Recall 분모를 계산할 때는 미선택 프레임의 GT도 보존한다.

1. **선별 재현표**에 기존 296장 결과와 새 정책 결과를 구분해 남긴다. 새 평가 세션마다 같은 후보·같은 예산에서 발견 수와 취약 구간 수를 설명할 수 있어야 한다.
2. **수집 검증표**에는 파일 재생과 ROS 수신의 차이, 지연·드롭·저장량, 중단 후 복구를 기록한다. 재시작 시 같은 세션·프레임의 중복 편입과 미완료 산출물의 완료 표시를 검사한다. 파일 기반 검증까지만 수행하면 26R1 실주행 항목은 미검증으로 남긴다.
3. **단위 4용 자료**는 수집 전 학습 후보 용도로 등록한 세션에서 만든다. 후보 목록에 행 ID·RGB 해시·부모 세션·선택 이유·순위·예산·정책 시드·모델 버전을 보존한다. 같은 풀의 무작위 대조 목록도 동결한다. 검수 뒤 대응 Semantic·시각·기하·라벨 정책·중복을 확인한 행만 학습 허용 목록으로 넘긴다. 정책별 라벨 확보율과 제외 사유를 기록해 실제 학습 장수가 같은지 확인한다. 잠금 평가 세션은 비교·시연 전용으로 유지한다. [선별 자료 재학습 규약](../development/선별자료_인지모델_재학습.md)

첫 작업은 **296장 후보에서 순위 상위 30장과 혼합 대기열 24+6장을 각각 재현하고, 저품질 발견 수와 선택 ID 겹침을 표 한 장에 정리하는 것**이다. 단위 1·2의 추가 모델이나 ROS 연결을 기다리지 않고 시작할 수 있다.
