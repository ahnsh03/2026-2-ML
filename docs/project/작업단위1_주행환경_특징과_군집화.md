# 작업 단위 1. 전방 RGB에서 주행 환경 특징 추출과 군집화

2026-11-23 팀 실험 계획 · 적용 대상은 고정 전방 카메라와 TwinLiteNet+ Medium v6 품질 추정 파이프라인이다.

**판단할 문제는 비슷한 조명·가시 조건의 영상을 다른 장소에서도 함께 묶을 수 있는가이다.** 보닛을 매번 관찰할 수 있는 동일 표면으로 쓰고, 하늘의 조명과 전조등이 비추는 노면을 따로 관찰한다. 군집이 유용하면 작업 단위 2에서 환경별 경보 보정에, 단위 3에서 한정된 검수 예산의 환경별 배분에 사용할 수 있다. 날씨 이름을 정확히 맞히는 것과 실제 차선 품질을 판별하는 것은 별도로 평가한다.

## 출발점과 가설

- 현재 품질 입력은 전체 영상과 3행×2열 격자마다 RGB 통계 4개와 인지 출력 통계 4개를 계산한 56차원이다. 단위 1은 기존 행에서 **RGB 28열**을 꺼내 비교를 시작한다. 새 특징은 원본 RGB에서 구한다. 인지 출력은 환경 군집의 입력에서 제외한다. 후속 품질 회귀의 정답은 기존 전방 전체 흰색·노란색 차선 합집합 IoU 한 개다. [현재 특징 명세](../development/X_y_데이터셋.md) · [기존 구현](../../src/quality_estimation/features.py)
- 기존 정지 자료는 8개 조건에서 같은 자세를 반복 촬영했다. 맑음 13시와 18시의 동일 자세 한 쌍에서 보닛 내부 작은 패치의 회색조 중앙값은 **164와 24**였다. 원본 1280×720, 좌상단 원점, 열 520 이상 760 미만, 행 610 이상 635 미만, Pillow `L` 변환, 0~255 척도다. 이 예시는 조명 변화가 보닛에 나타날 수 있다는 관찰이다. 주행 방향·그림자·차량 재질이 바뀌어도 도움이 되는지는 아래 비교로 판단한다. [기존 정지 자료와 위치별 평가](품질추정_실험결과_20261116.md)
- 1차 가설은 **하늘·도로·주변에 보닛을 더하면 같은 조건에서 장소에 따른 군집 변화가 줄어든다**는 것이다. 2차 가설은 **영역 간 밝기 차이가 비슷한 전체 밝기의 장면을 구분한다**는 것이다. 예를 들어 어두운 보닛과 밝은 근거리 노면의 조합은 전체가 어두운 장면과 다르다. 주간·야간만 갈리는 경우에는 환경 표현의 한계를 그대로 기록한다.

## 1. 데이터 역할과 첫 실험 자료

1. 기존 정지 학습 **824행(103개 자세 × 8조건)**으로 시작한다. 먼저 행 ID·원본 RGB 해시·카메라 설정·부모 그룹·자세·날씨·시각의 대응표를 확인한다. 각 조건에 프레임 수와 서로 다른 자세·구간 수를 함께 적는다. 정지 짝자료는 조명 변화 비교에, 주행 자료는 가림·방향 변화와 배정 흔들림 진단에 쓴다. 날씨·시각·위치·실제 IoU는 분할·사후 해석용 메타데이터다.
2. 기존 데이터 역할을 보존한다. 학습 자료 안에서 같은 자세의 모든 조건과 인접 구간을 함께 묶고 부모 그룹 단위로 학습·검증을 교대한다. 다른 부모에 같은 위치가 있으면 같은 쪽으로 묶거나 겹치는 구간을 제외한다. 픽셀 해시·공유 위치·경계 인접 구간을 따로 검사한다. 그룹 수가 적으면 가능한 그룹별 결과를 모두 보인다. 원래 개발 576행은 알려진 조건에서의 진단에 사용하고, 이미 열어 본 후보·최종 자료로 설정을 고르지 않는다. [기존 분할 검사](../../src/quality_estimation/splits.py)
3. 독립 평가 자료는 수집 전에 역할과 조건을 정한다. 같은 조명을 여러 장소·진행 방향에서, 같은 구간을 여러 조명에서 확보한다. 가림이 있는 구간과 맑지만 어두운 장면, 밝지만 흐린 장면을 포함한다. 다른 날짜·세션 또는 지도에서 검증한 범위를 기록한다. 기존 한 지도·물리 세션으로만 끝나면 결과는 내부 비교로 보고한다.

## 2. 카메라 영역과 특징 설계

자료 인수 시 `fresh_completed_train_v2`의 행 수(824), 특징 열 수(56), (부모 그룹, 자세)별 행 수(8)를 먼저 대조한다. 확인된 부모 그룹은 3개다. 한 그룹씩 제외해도 위치가 겹치는 쌍은 따로 표시한다. 독립 위치 수가 부족한 조건에서는 결과표에 그 수를 기재하고 추가 주행 대상으로 둔다.

학습 RGB에 정규화 다각형을 겹쳐 **보닛 내부, 상단, 가까운 도로, 먼 도로, 좌우 주변**을 정한다. 좌우 도로 다각형은 필요하면 합쳐 거리대별로 자른다. 근·원거리는 영상상 구분이며 미터 단위 거리를 주장하려면 투영 보정이 추가로 필요하다. 기존 ROI 양식은 좌표와 보정 해시가 비어 있는 설계 참고다. 검토된 좌표, 원본 크기·화각·카메라 설정 식별자, 영역 정의 버전을 새 프로필에 기록한다. [기존 ROI 양식](../contracts/roi_profile_template.json)

| 관찰 영역 | 첫 비교에 쓸 정보 | 혼동 요인과 추가 특징 후보 |
|---|---|---|
| 보닛 도장면 | 밝기·대비, 좌우 패치의 밝기 차이 | 와이퍼·유리·윤곽선을 피한다. 평탄 패치에서 회색조와 3×3 중앙값 필터 영상 간 절대 잔차의 중앙값을 재면 미세 변동을 비교할 수 있다. 반사·압축·렌더링도 섞이므로 센서 노이즈 측정치로 해석하지 않는다. |
| 하늘이 자주 보이는 상단 | 밝기 분포, 밝은 픽셀 비율, 색 분포 | 건물·수목·터널의 가림, 태양 방향을 기록한다. 고정 상단 마스크가 항상 하늘을 담는다고 가정하지 않는다. |
| 가까운 도로와 먼 도로 | 각 영역의 대비·경계 밀도, 근거리와 원거리의 중앙 밝기 차이 | 전조등, 차선 도색, 선행차 가림을 구분해 사례를 본다. 근거리만 밝은 야간과 원경 윤곽이 약한 조건을 비교한다. |
| 지평선 주변과 좌우 사물 | 원경의 대비·경계 밀도, 좌우 밝기 분포 | 건물·가드레일 모양을 장소 단서로 쓸 수 있다. 같은 조건의 다른 경로에서 흔들리면 해당 영역을 제거해 다시 비교한다. |

먼저 모든 영역에 기존 네 통계(밝기 평균, 어두운 픽셀 비율, 밝기 표준편차, 경계 밀도)를 같은 정의로 적용한다. 다음 비교에서만 밝기 중앙값·P90−P10, 밝은 픽셀 비율(회색조 245 이상), HSV 채도 중앙값, 보닛 잔차와 영역 간 밝기 차이를 추가한다. 수치·필터 크기는 첫 실험 후보값이다. 차이는 동일한 0~1 밝기 척도로 계산한다. 원본 전체에서 경계를 계산한 후 마스크로 집계해 다각형 테두리가 인공 경계가 되는 것을 막는다.

프로필은 직선·곡선·경사·역광·가림 예시에서 오버레이로 검토한다. 사람이 확인한 가림 여부는 진단 표에만 쓴다. 빈 마스크나 다른 카메라 설정은 배정 불가로 남긴다. 같은 카메라에서도 화각·크롭이 바뀌면 프로필을 다시 검토한다. 온라인 입력에는 원본 RGB와 고정 카메라 프로필만 필요하도록 설계한다.

## 3. 실험 순서

| 순서 | 고정할 것 | 바꾸어 볼 것 | 판단할 질문 |
|---|---|---|---|
| ① 밝기와 격자 기준선 | 같은 학습·검증 그룹 | 전체 밝기 분위수 구간, 기존 RGB 28열의 k-means | 평범한 주·야 구분으로 어느 정도까지 설명되는가? |
| ② 영역 제거·추가 비교 | 같은 프레임, 기본 4통계, 같은 k-means·K·시드 | 기존 격자 / 보닛만 / 상단+도로+주변 / 상단+도로+주변+보닛 | 마지막 두 구성 간 차이가 보닛의 추가 기여다. 근·원거리 도로를 합친 대조군으로 거리대 구분 효과도 확인한다. |
| ③ 특징 추가 비교 | ②의 동일한 ROI와 군집기 | 색·밝기 분포, 영역 간 차이, 보닛 미세 변동을 한 묶음씩 추가 | 정보가 늘어나는가, 특정 자세의 반사나 시뮬레이터 영상 특성에만 반응하는가? |
| ④ 군집 알고리즘 비교 | 개발 자료에서 고른 동일 특징, 동일 표준화·분할·K·시드 목록 | k-means++ 초기화의 KMeans, MiniBatchKMeans, 공식 CPU e-means | 배정 재현성, 새 위치의 환경 구분, 학습 시간·메모리에서 실익이 있는가? |

K는 **2·4·8**, 난수 시드는 **0·1·2**를 첫 후보로 둔다. 밝기 기준선도 같은 K를 쓰고 구간 경계는 학습 밝기의 분위수로 고정한다. 중복 경계로 실제 구간 수가 줄면 기록한다. 상수 열 제거와 표준화는 매 분할의 학습 행에서만 적합한다. ②·③은 우선 K=4에서 보고 유망한 구성만 K 민감도를 확인한다. 시드별 반복에서 초기화 횟수, 처리한 데이터 양, CPU 스레드 수와 시간도 기록한다. 표준화된 제곱거리의 절댓값 비교는 같은 특징 공간 안에서만 한다.

e-means는 주어진 K개의 중심을 학습한다. 학습은 오프라인에서 하고 새 RGB에는 고정된 전처리와 최근접 중심 배정만 적용한다. 공식 CPU 구현은 별도 실험 환경에서 작은 입력으로 먼저 확인하고 버전과 소스 revision을 고정한다. 논문은 작은 저차원 데이터에서 제안 설정이 최적이 아닐 수 있다고 밝힌다. 이 자료에서의 속도·정확도 이득은 직접 측정한다. 도로·하늘·좌우 영역을 별도로 관찰한 주행 영상 연구는 ROI 설계 근거로 사용한다. ## 4. 평가와 선택

- **환경과 장소의 영향.** 주 지표는 검증 자료에서 ㉠ 같은 날씨·시각, 다른 자세의 두 영상이 같은 군집에 속한 비율과 ㉡ 같은 자세, 서로 다른 조건의 두 영상이 다른 군집에 속한 비율이다. 조건 또는 조건 쌍별 비율을 먼저 구한 뒤 동일 가중치로 평균한다. 서로 다른 설정이라도 영상이 비슷할 수 있으므로 조건 쌍별 표와 대표 영상을 함께 본다. 하나의 큰 군집이 ㉠만 높이거나, 장소별 분할이 날씨 구분처럼 보이는 사례를 확인한다.
- **안정성과 사용 가능 범위.** 같은 검증 행을 시드별로 배정해 ARI(군집 번호 순서에 무관한 일치도), 군집별 프레임·자세·부모 그룹 수, 비어 있는 군집을 보고한다. 주행에서는 조건이 일정한 구간의 연속 배정 전환율을 표본 간격과 함께 제시한다. 전환 장면을 열어 실제 조명 변화와 배정 흔들림을 구분한다.
- **후보 선택.** 같은 K에서 ㉠·㉡를 밝기 기준선과 비교한다. 어느 한 지표만 좋아지면 그 조건 쌍과 장소를 남긴다. 두 지표가 모두 동등 이상이고 적어도 하나가 개선된 후보를 우선하며, 이 경향이 분리한 구간과 시드에서 반복되는지 본다. 표본이 적어 우열이 흔들리면 단순 기준선과 함께 인계한다. 학습 시간과 프레임당 특징 추출·배정 지연(p50/p95)은 같은 장비에서 따로 측정한다. 전체 경보 개선 여부는 단위 2에서 검증한다.
- **새 환경 처리.** 학습 중심에서 먼 사례의 RGB와 거리 분포를 점검한다. 필요하면 검증 자료에서 거리 기준을 정해 ‘배정 신뢰 낮음’을 표시하고 후속 단계는 전역 기준을 사용한다. 거리는 미지 날씨의 확률이 아니다. 군집별 경보 보정에 충분한 정상·저품질 표본이 있는지는 군집을 고정한 뒤 GT를 결합해 확인한다.

| 평가·인계 | 영역 포함·제외 비교표, 군집×조건 표, 대표·실패 영상 모음, 지연표, 선택 또는 보류 근거 | 단위 2·3에 행 ID, 환경 특징 버전, 군집 모델 버전, 군집 ID, 배정 상태를 전달한다. 중심 기반이면 최근접 거리도 함께 전달한다. |

첫 인계 시점은 **독립된 위치에서 보닛을 더했을 때의 변화와, 같은 특징에서 e-means를 썼을 때의 변화를 각각 설명할 수 있을 때**다. 개선이 재현되지 않으면 단순한 기준선과 미해결 조건을 인계한다. 팀 레포에는 재현 절차·명세·집계 결과를 두고, 원본 프레임·실행별 특징 배열·모델 파일은 실험 저장소에서 관리한다.
