# 팀 운영과 공통 인계 기준

> 2026-11-22 문서 검토 · 실험 기준 2026-11-16 · 기술 역할은 11/3 논의, 계획은 11/4 ML 중간발표 슬라이드·발표자 노트를 반영

기계학습과 캡스톤디자인은 개발 결과를 공유하는 통합 프로젝트다.
기계학습 팀원은 **안승현·손재호·장원태**, 캡스톤 팀원은 **안승현·장원태**다.
개발은 이 저장소에서 수행하고, 과목별 발표·제출 자료는 로컬 워크스페이스에서 작성한다.

현재 구현·남은 과제는 [개발 현황](개발현황.md)을 먼저 확인한다.
안승현은 오프라인 통합 개발과 최종 채택 판정, 장원태는 야간 조건 대조, 손재호는 검수 순위 평가와 프로젝트 웹페이지를 담당한다. 실험 우선순위와 결과 PR 작성법은 [통합 실험 계획과 3인 분담안](데이터플라이휠_통합실험계획_3인분담.md)을 따른다.

## 공통 합의와 결정 상태

M v6를 고정하고 전방 영상의 출력+RGB 특징으로 통합 Lane IoU를 추정한다.
전체+3행×2열 ROI와 OLS/Ridge/RF·clipped MAE·예산별 Recall 비교는 최신 발표의 채택 계획이다.
X/y 특징 열·차원·계산 규칙은 [실행 스키마](../contracts/quality_xy_v2.json)에 고정했다.
11/16 후속 개발 요청으로 X/y 생성·검증, 회귀 학습·GT 없는 선별, 통제된 인지 재학습의 개발 실험을 실행했다.
예약한 주 평가·추가 조건 평가를 완료했다. 갱신 후 버전 쌍의 새 주행 재검증까지 실행했다. 기존 성능 유지·경보 오경보·독립 환경 등 남은 검증은 [프로젝트 설계](./프로젝트_확정설계_20261103.md)를 따른다.
이전 v1을 현재 실행 계약으로 사용하지 않으며 [현재 계획 JSON](../contracts/quality_plan_v2.json)을 참고한다.

현재 우선순위는 [오프라인 통합 실험 계획](데이터플라이휠_통합실험계획_3인분담.md)을 따른다. 11월 16일의 통합 목표와 첫 실험은 [당시 개발 현황](통합_데이터플라이휠_개발현황_20261116.md)에 보존한다.
과목별 범위를 별도 개발 목표로 나누지 않고 동일 파이프라인의 근거를 함께 사용한다.

## 역할과 파일 소유권

A/B/C는 기술 역할 ID다. 기존 기록에서 실명이 연결되지 않았으므로 여기서 임의 배정하지 않는다.

| 역할 | 담당 | 인수 기준 |
|---|---|---|
| A — 입력·정답 | 수집·동기화·GT, 출력+RGB·3행×2열 특징, 통합 Lane 정답 생성 | GT 없는 X와 별도 Y, 열 정의·순서, sample_id, 유효성 규칙 |
| B — 모델·학습 | v6 로더·확률 export, OLS/Ridge/RF 학습·추론·bundle | M 출력 기하·클래스·EMA 일치, sample_id별 예상 품질·모델 버전 |
| C — 선별·평가 | 계약 검증·metric·선별·조건 분석·시각화 | 예산·중복 규칙, 누수 검사, 기준선·조건별 결과, 개선 비교 |

공유 스키마는 공동 검토하되 한 번에 한 담당자가 변경한다.
구체적인 이식 대상과 인수 기준은 [코드 이식 계획](../development/코드이식_분담계획.md)을 따른다.

## 팀원 인계

| 연결 | 전달 내용 |
|---|---|
| 공통 → A/B/C | checkpoint·정밀도·전처리·GT 정책·카메라 매핑·데이터 역할 |
| A → B | 특징 열·순서·정의, 별도 target와 label_defined, 예시 X/Y |
| B → C | sample_id별 예상 Lane IoU·모델 버전, 검증 MAE로 선택한 bundle |
| C → A/B | 검수 예산·중복 정책·필요 조건·실패 사례·추가학습 통제 조건 |

데이터·GPU가 없는 팀원도 작은 feature/label 표와 정의로 모델·평가 작업을 할 수 있게 인계한다.
공통 인터페이스의 정본은 [입출력 규약](../contracts/품질추정_입출력규약.md)이다.

## 검토 기준

- 같은 sample_id로 입력·정답·예측·선별 결과를 연결한다.
- 특징에는 출력과 RGB 관측값을 사용한다. GT·실제 IoU·환경 정답·장소 식별자는 넣지 않는다.
- 인접 프레임을 무작위로 나누지 않고 수집 세션·부모 묶음으로 분할한다.
- 예상 IoU와 실패 확률을 구분한다. 회귀 점수를 확률로 부르지 않는다.
- 설계 완료·구현 완료·실험 완료를 구분하고 독립 test를 개발에 사용하지 않는다.
- 문서별 확정 여부와 근거를 보존한다. 세부 평가 기준은 [평가 계획](./평가_수집_재학습계획.md)을 따른다.

## 문서 관리

공통 설계·규약·베이스라인·개발 환경은 팀 docs에서 관리한다.
개인 분석·연구 과정·강의자료·공지 원문·발표 대본은 로컬에 보존하고, 채택한 결론을 공통 문서에 반영한다.
과목별 발표는 같은 코드·실험 근거를 참조하며 작성 당시 모델·데이터·측정 범위를 명시한다.
