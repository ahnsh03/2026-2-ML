# 개발 환경과 현재 버전 쌍 재생

현재 시뮬레이터는26R1이며, **5070Ti용 rtx50과40계열용 rtx40을 분리**한다. 원본 D 자료는 읽고 큰 캐시·학습·수집 출력은 외부 실험 볼륨에 쓴다. 이번 작업은 E 드라이브를 사용한다. 개인 경로·이미지 이름은 Git에서 제외한 `config/local.env`에 설정한다.

## 세 가지 실행 환경

| 환경 | 정의와 확인 범위 |
|---|---|
| rtx40 | [Dockerfile](../../docker/perception/Dockerfile.rtx40), Torch2.1.2/cu118와 [기존 패키지](../../config/requirements-quality.txt). 여기서는CPU 재생/테스트를 확인하며 실제40GPU는 팀원 PC에서 확인한다. |
| rtx50 | [Dockerfile](../../docker/perception/Dockerfile.rtx50), Torch2.7.1/cu128와 [고정 패키지](../../docker/perception/requirements-rtx50.txt).5070Ti의 실제 추론·역전파·24k 학습을 사용한다. |
| CPU 연구 | Python3.12.13과 [고정 의존성](../../config/requirements-spatial-study.txt). GP/RF·BO·공식 Faiss1.16 e-means와 과학 그림을 실행한다. Torch 영상 학습은 GPU 이미지에서 실행한다. |

Torch2.1.2/cu118의5070Ti kernel 오류 때문에50 이미지를 분리했다.40환경을 업그레이드하거나 동일 이미지 이름으로 덮어쓰지 않는다. [PyTorch2.7 Blackwell 지원](https://pytorch.org/blog/pytorch-2-7/)과 [당시 실측](../experiments/ROI9_GP와_26R1_검증_20261126.md#7-rtx4050과-26r1-인수-범위)을 따른다.

```bash
git submodule update --init
cp config/local.env.example config/local.env
scripts/build_perception_image.sh rtx50
#40GPU 팀원은 rtx40으로 빌드한다.
ML_GPU_PROFILE=rtx50 scripts/run_container.sh python3 -m visualization.visualize_inference --help
```

`PERCEPTION_DATA`, `PERCEPTION_CKPT_ROOT`, `ML_OUTPUT_ROOT`, 프로필별 이미지 이름을 설정한다. 명시한 `ML_GPU_PROFILE`은local.env보다 우선하며 auto는8.9→40,12.*→50으로 고른다.50에서는 이전 `PERCEPTION_IMAGE` fallback을 재사용하지 않는다. 표준 runner의 코드/데이터/체크포인트는 읽기 전용, 출력만 쓰기 가능하다. [설정 예시](../../config/local.env.example)

CPU 연구 환경은 별도로 준비한다. 아래 명령은Python3.12가 설치된 상태에서 실행한다. 기존40/50 이미지에 Faiss를 추가할 필요는 없다.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r config/requirements-spatial-study.txt
PYTHONPATH=src:ros/src/data_collection/src .venv/bin/python -c 'import faiss; from faiss.contrib.e_means import NumpyEmeans; print(faiss.__version__)'
```

[별도 CPU 의존성 목록](../../docker/research/requirements-cpu.txt)도 같은 주요 버전을 사용한다. `.venv/`는 Git에서 제외한다. CPU 연구 환경에는 Torch가 없을 수 있으므로 전체 영상/학습 테스트를 이 환경에서 실행하지 않는다.

## 현재 Q·환경 번들

현재 [Q·환경 계약](../contracts/environment_review_bundle_v1.md)은 GP/RF 중 선택한 Q 모델, RGB 날씨/조명 분류기, e-means 중심, Cal 잔차와 검수 정책을 묶는다. [최신 실험](../experiments/환경검증_전체원본재생_20261128.md)의 `candidate_pair.json`과 번들 manifest에서 정확한 인지 버전·열·채택 여부를 확인한다.9영역은 공통이며28/34/52/49열 중 버전별 선택을 따른다.

GP/RF와 RGB 분류기는 NPZ로 내보내40/50에서 pickle 없이 읽는다. 추론에서 Faiss를 실행하지 않고 고정 중심의 최근접 배정을 쓴다. 기존 joblib 모델을 다른 scikit-learn 버전에서 직접 읽지 않는다. 인지 가중치가 바뀌면 새X/y·품질모델·Cal/정책을 다시 만들고 다른 신원 조합은 거부한다.

```bash
PYTHONPATH=src:ros/src/data_collection/src python3 -m quality_estimation.infer_versioned_review \
  --bundle "$REVIEW_BUNDLE" --adaptation-run "$PERCEPTION_RUN" \
  --manifest "$RGB_MANIFEST" --data-root "$RGB_ROOT" \
  --output "$NEW_OUTPUT" --device cuda --batch-size 4 --budget 8
```

기준 v6는 `--adaptation-run` 대신 정확한 `--checkpoint`를 전달한다. 출력은GT 없는 특징·예측·선택 목록과 버전/입력 해시다. `join_spatial_gt`로 나중에 GT를 연결해도 Dev/Cal/확인의 학습 금지 역할은 유지한다. 현재는 오프라인 버퍼 재생이며 liveROS·자동 입학은 별도다.

## 독립 추론 인계

현재 형식의 [패키징](../../scripts/package_environment_release.py)은 커밋한 코드·독립 TwinLiteNet+ checkout·정확한 인지 계보·Q/환경 번들과 RGB 예시를 묶는다. 인지 버전 신원을 유지하기 위해 필요하면 학습 목록/원장 메타데이터도 그대로 포함하며 GT 원본 이미지는 포함하지 않는다. 이 묶음은 실험 볼륨의 연구팀 인계물이고 공개 Git 근거와 구분한다. [표준 라이브러리 검증기](../../scripts/verify_environment_release.py)와 패키지 README를 따른다.

실제 독립 실행은 원래 작업공간·D/E 원본을 마운트하지 않고 인계 폴더 하나와 빈 결과 폴더만 연결하여 확인한다.40CPU/50GPU의 예측·군집·선택과 버전 거부를 비교한다. 검증 수치는 최종 실험 영수증에 기록하며 파일 검증만으로 실제 추론·채택을 대신하지 않는다.

기존 `team_inference_release_v2`와28+31공간 진단 번들은 이전 실험용이다. 당시 파일·명령·검증은 [환경 가이드 원문](../archive/guides_20261127/개발환경.md), [이전 인계](../baselines/roi9_gp_20261126/inference_release_verification.json)에 보존했다. 새Q·환경 번들을 이전 spatial_bundle 명령으로 열지 않는다.

## 26R1 수집과 검증

[통신 프로파일](../../config/morai/README.md)과 [버전 정의](../../config/simulator_release_profiles.json)를 따른다.26R1 UDP payload27/전체59바이트, 이전은23/55이며 wheel필드와 조향 부호가 다르다. 내부 steering rad의 정규화 후26R1에서 한 번 부호를 반전한다. Windows UDP/native 저속 수집은 실제 상태·4채널 해시·복원을 검증한다. ROS 직접 토픽과 종단 추론 인수는 남아 있다.

외부 proto는 로컬에서 제공하고 Git에 복사하지 않는다. 수집ROS 이미지와 인지GPU 이미지는 별도다. [현재 실험 순서](../../scripts/experiments/environment_cycle_20261127/README.md)와 [데이터 역할](데이터_등록과_특징정답.md)을 먼저 읽는다. 카메라 노출 시각이 없는 자료는 RGB/GT 경계 정합 증거와 시간동기화 보장을 구분한다.

전체 회귀 테스트는 두 인지 이미지의CPU에서 `python -m unittest discover -s tests`로 실행한다. 현재274개 회귀 검사와 실제 standalone 재생의 완료 여부는 최신 근거 모음의 영수증으로 확인한다. 실제40GPU·실시간 ROS 성능은 해당 하드웨어/통신으로 별도 확인한다. 이전 환경 원문은 [보존 폴더](../archive/guides_20261127/README.md)에 있다.
