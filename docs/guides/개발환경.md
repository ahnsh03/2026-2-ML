# 개발 환경과 실행 준비

담당은 전원이다. 원본·가중치가 있는 환경은 영상·추론에, 저장한 특징·정답표만 있는 CPU 환경은 회귀·검수 정책 재생에 사용한다. 첫 입력과 인계 형식은 [일정과 역할](일정과_역할.md)에서 확인한다.

## 시작 입력

| 자산 | 사용처와 준비 방법 |
|---|---|
| v6 가중치 | 기본 모델은 TwinLiteNet+ Medium v6 EMA epoch 11이다. [근거 JSON](../baselines/medium_v6_baseline_evidence.json)의 해시와 비교한다. |
| RGB와 Semantic | 학습·평가에는 같은 프레임의 짝을 준비한다. 온라인 점수 입력은 RGB 목록이다. [데이터 등록](데이터_등록과_특징정답.md) |
| 실험 출력 볼륨 | 원본·가중치·상세 로그는 Git 밖에서 보관한다. 수집·대용량 실험은 E 드라이브 볼륨을 사용하고 각 PC에서 마운트한 실제 경로를 설정한다. |
| 패키지 | 기존 검증 환경은 Python 3.8.10, PyTorch 2.1.2와 CUDA 11.8이다. 수치·영상 패키지는 [requirements-quality.txt](../../config/requirements-quality.txt)를 참고한다. 환경 차이는 실행 기록에 남긴다. |

```bash
git submodule update --init
cp config/local.env.example config/local.env
```

`config/local.env`에서 `PERCEPTION_DATA`, `PERCEPTION_CHECKPOINT`, 출력 루트를 자신의 데이터에 맞춘다. 컨테이너 안에서 dataset_versions와 datasets를 함께 찾을 수 있는 실제 루트를 마운트한다. [환경변수 예시](../../config/local.env.example)

## 실행 경로

영상 추론에는 기존 컨테이너 래퍼를 사용한다. 수집·ROS 래퍼의 설치별 설정과 센서 항목은 [기존 환경 명령 원문](../archive/개발환경.md)에 있다.

```bash
scripts/run_container.sh python3 -m quality_estimation.build_native_dataset --help
scripts/run_container.sh python3 -m quality_estimation.roi10_study --help
```

저장한 표로 수행하는 작업은 저장소 루트에서 `PYTHONPATH=src`를 설정한다. GPU를 여는 명령과 특징표만 읽는 명령은 각 가이드에서 표시한다. e-means 중심 학습에는 공식 Faiss e-means 구현이 필요하고, 고정 중심의 추론은 NumPy로 가능하다. [군집 실행](환경군집과_검수정책.md)

## 준비 확인과 문제 해결

1. 체크포인트·입력 목록 해시, 카메라 해상도·화각·ROI 프로파일을 확인한다. 코드·의존성·인지모델·특징 버전과 실행 명령을 기록한다.
2. GPU가 필요한 영상 빌드는 작은 개발용 입력에서 먼저 확인한다. 회귀·정책 재생은 기존 표에서 시작할 수 있다. 같은 출력 폴더의 완료 산출물은 새 실험 이름으로 구분한다.
3. 원본 파일을 찾지 못하면 호스트 절대 심볼릭 링크와 컨테이너 마운트를 확인한다. 번들의 스키마 불일치는 인지모델·특징 버전을 먼저 대조한다.

기존 로더·시각화·수집·CPU 회귀 검증과 당시 명령은 [환경 검증 원문](../archive/개발환경.md), [코드 이관 근거](../archive/외부코드_선별.md)에 보존돼 있다. 세부 실행은 [데이터](데이터_등록과_특징정답.md) → [품질모델](품질모델_학습과_불확실성.md) → [검수](환경군집과_검수정책.md) 순서로 따른다.
