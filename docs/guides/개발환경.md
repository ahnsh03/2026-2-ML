# 개발 환경과 실행 준비

현재 시뮬레이터는 **26R1**, 인지 기본값은 **TwinLiteNet+ Medium v6 EMA**다. 40·50 GPU 환경을 각각 유지한다. 원본·가중치·상세 출력은 Git 밖 실험 볼륨에서 관리하고, 용량이 큰 수집·실험은 E 드라이브에 저장한다. 팀원은 자신의 실제 마운트 경로를 설정한다.

## GPU 프로파일과 CPU 학습

| 프로파일 | 정의와 확인 범위 |
|---|---|
| `rtx40` | [Dockerfile](../../docker/perception/Dockerfile.rtx40), Torch 2.1.2/cu118와 [기존 패키지](../../config/requirements-quality.txt). 이번 환경에서 CPU 로딩·v6 순전파·RGB 재생·동결 GP 추론 확인. 실제 40 GPU 재검증은 해당 팀원 PC에서 수행 |
| `rtx50` | [Dockerfile](../../docker/perception/Dockerfile.rtx50), Torch 2.7.1/cu128와 [고정 패키지](../../docker/perception/requirements-rtx50.txt). RTX5070Ti(sm_120)의 v6 추론·합성 역전파·optimizer 확인 |
| CPU 실험 | Python 3.12.13과 [requirements-spatial-study](../../config/requirements-spatial-study.txt). 저장한 특징에서 RF·GP·BO·평가 수행. 이 환경만으로 Torch 영상 추론 테스트를 실행하지 않음 |

Torch 2.1.2/cu118에서 5070Ti를 열면 CUDA kernel 실행 오류가 발생했다. 40 프로파일을 덮어쓰지 않고 50용 이미지를 분리했다. [PyTorch 2.7 Blackwell 지원](https://pytorch.org/blog/pytorch-2-7/) · [측정과 환경 비교](../experiments/ROI9_GP와_26R1_검증_20261126.md#7-rtx4050과-26r1-인수-범위)

```bash
git submodule update --init
cp config/local.env.example config/local.env
scripts/build_perception_image.sh rtx50
# 40 GPU 팀원은 rtx40으로 빌드한다.
ML_GPU_PROFILE=rtx50 scripts/run_container.sh python3 -m visualization.visualize_inference --help
```

`local.env`의 `PERCEPTION_DATA`, `PERCEPTION_CKPT_ROOT`, `ML_OUTPUT_ROOT`를 채운다. 이미지 이름은 `PERCEPTION_IMAGE_RTX40`, `PERCEPTION_IMAGE_RTX50`로 따로 설정한다. `ML_GPU_PROFILE=auto`는 compute capability 8.9→40, 12.*→50으로 선택한다. 재현 실험에서는 프로파일을 명시한다. 명령 앞의 명시 프로파일은 local.env보다 우선한다. 40에서는 이전 `PERCEPTION_IMAGE` fallback을 유지하고 50에서는 이 값을 재사용하지 않는다.

컨테이너의 저장소 `/ml`, 데이터 `/data`, 체크포인트 `/ckpt`는 읽기 전용이고 결과 `/outputs`만 쓴다. `ML_OUTPUT_ROOT`가 출력 볼륨에 연결됐는지 먼저 확인한다. [설정 예시](../../config/local.env.example)

## 동결 번들과 의존성

새 품질 모델은 [v3 명세](../../config/region_feature_recipe_v3.json)의 9영역·28열이다. 공유받은 번들의 `feature_recipe.json`, `quality_spatial_gp.npz`, `calibration_26r1.json`, 학습 구성원·역할·해시 manifest를 함께 사용한다.

```bash
PYTHONPATH=src python3 -m quality_estimation.spatial_bundle \
  --bundle "$FROZEN_BUNDLE" --simulator-release 26.R1
```

GP는 pickle 없는 NPZ이며 40·50 패키지 환경에서 추론을 대조했다. RF joblib은 **학습 때의 scikit-learn 1.9.1**을 사용한다. 40의 기존 scikit-learn 1.3.2로 직접 로딩하지 않는다. 40·50 공통 추론에는 [RF 호환 NPZ와 내보내기 절차](../baselines/roi9_gp_20261126/portable/README.md)를 사용할 수 있다. 학습된 트리를 유지한 내보내기이며 품질96장·환경432장에서 예측/확률 차이0을 확인했다. X56·24열 v1·27열 v2·28열 v3는 서로 다른 번들이다. 열 개수만 맞추지 말고 프로파일·열 순서·모델·인지 체크포인트 해시를 대조한다.

RF 호환 추론은 여러 트리를 함께 탐색하고256행 단위로 메모리를 제한한다. 기존 모델/예측은 유지하면서 단건 forest 계산을 줄였다. [측정 범위와 결과](../baselines/roi9_gp_20261126/portable/README.md#추론-반복-계산-보완)는 영상 처리·통신을 제외한CPU 추론이며 라이브 시스템 FPS가 아니다.

## 팀원에게 독립 추론 묶음 전달

실험 볼륨의 **team_inference_release_v2.tar.gz**는 약89MiB의 추론 인계물이다. ML 코드·고정 TwinLiteNet+ checkout/라이선스·f0·주28열 GP/보정·RF/환경 NPZ·ROI·RGB8장·상대경로 명령과 전체 파일 해시를 함께 묶었다. GT 원본과 학습 구성원은 별도 연구 번들에 남긴다. 공통 팔레트의 순수 Python 소스도 포함한다.

원래 워크스페이스와 데이터 드라이브를 연결하지 않고 이 묶음과 빈 출력 폴더만 마운트해 실제 재생했다.40 이미지CPU8장·5070Ti8장이 완료됐고, 원래 재생 대비 최대 예측 차이는 각각1.59e−7·0이었다. 실제40 GPU와 라이브 ROS는 별도 인수한다. [소스·전송 파일 SHA·실행 범위](../baselines/roi9_gp_20261126/inference_release_verification.json)

```bash
python3 "$RELEASE_ROOT/code/scripts/verify_inference_release.py" --root "$RELEASE_ROOT"
# 압축을 푼 묶음의 README.md에서 CPU/50GPU 재생 명령을 실행한다.
```

새 묶음은 [package_inference_release.py](../../scripts/package_inference_release.py)로 만든다. 커밋된 깨끗한 소스와 동결 모델·RGB 원본 목록이 입력이다. 초기 `team_inference_release`는 공통 모듈 누락을 찾은 실행 이력이고, 현재 전달 정본은 **v2**다. 추론 묶음의 검증을 모델/정책의 최종 채택이나 학습 이력 전체 검증으로 대신하지 않는다.

## 26R1 통신·수집

[시뮬레이터 프로파일](../../config/simulator_release_profiles.json)과 [MORAI 설정 안내](../../config/morai/README.md)를 따른다. 26R1의 UDP 명령은 payload27/전체59바이트, 이전 버전은 23/55다. JSON 운전 모드와 UDP 모드 열거형을 혼동하지 않는다. 내부 `CtrlCmd.steering`의 rad 값을 정규화한 뒤 26R1에서 한 번 부호 반전한다. 이전 버전은 launch의 `simulator_release:=molitcomp03`으로 선택한다.

수집용 [ROS Noetic 이미지](../../docker/ros-noetic/Dockerfile)는 새 인지 GPU 이미지와 별개다. ROS의 직접 메시지·토픽·휠 필드와 저속 좌우 회전 인수는 아직 남아 있다. 새 GP가 라이브 ROS에 연결됐다고 가정하지 않는다.

외부 proto는 실행 환경에서 제공하고 Git에 복사하지 않는다. 새 정지 수집기는 [capture_stationary.py](../../scripts/experiments/roi9_gp_20261125/capture_stationary.py)다. 26R1의 SaveSensorData 응답 타임아웃을 파일 생성 성공과 구분하고 고유 파일명·4채널·전후 상태를 검증한다. 이는 정지 수집의 제한된 인수이며 주행 중 동기화 보장이 아니다. 실행 전 `--help`와 [수집·등록 기준](데이터_등록과_특징정답.md)을 읽는다.

## 검증과 이력

프로파일 변경 후 고정 체크포인트 소량 입력으로 CUDA 순전파를 먼저 확인하고, GT 없는 재생과 기존 특징표를 대조한다. 전체 테스트는 인지 패키지가 있는 이미지에서 `python3 -m unittest discover -s tests`로 실행한다. 최종208개 테스트를40·50 이미지의CPU에서 각각 통과했다. 실제5070Ti CUDA 호환성은 별도 순전파·합성 역전파/optimizer로 확인했다. 실제40 GPU·실시간 ROS 성능은 아직 확인하지 않았다.
