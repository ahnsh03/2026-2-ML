# 온라인 연결과 영어 발표·프로젝트 페이지

11월 30일 오프라인 모델·정책을 판정한 뒤 12월 1–4일에 온라인 시연과 최종 발표물을 병행한다. 12월 4일까지 영문 슬라이드·대본·8분 리허설, 확정 수치·영상, 영어 공개 사이트와 제출 URL을 준비한다. 공식 발표는 12월 9일 기존 장소, 페이지 제출 마감은 12월 13일이다. [전체 일정](일정과_역할.md)

직전27일 단위는 g1 품질 유지성 실패로 교체를 보류했다. [28일 전체 원본 재생·환경 검증](../experiments/환경검증_전체원본재생_20261128.md)은8학습·새 확인·standalone 재생까지 완료했으나 **검수 실패로 통합 교체와 ROS 이행을 보류**했다. 새 장면/검수 정답과 독립 확인을 보완해 오프라인 기준을 먼저 통과한다. 재생 후보가 정상 실행되는 것과 운영 채택은 구분한다. 아래 온라인 분담은 그 조건 이후의 작업이다.

## 시작 입력과 담당

| 담당 | 온라인 작업 | 발표·사이트 인계 |
|---|---|---|
| 승현 | RGB 수신·프레임 ID·시각과 v6 추론을 연결하고 한 세션을 녹화한다. | 단일 확정 결과표, 주장·분모·모델 버전, 최종 영상·영어 대본과 리허설을 총괄한다. |
| 재호 | 라이브 RGB·출력에서 특징을 계산하고 같은 영상의 오프라인 열·값과 대조한다. | 영어 웹페이지 제작을 맡고 ROI·대표 사례, 자막 영상, 코드·재현 링크를 배치한다. |
| 원태 | 채택 추정기·군집·보정·검수 정책을 연결한다. 같은 입력의 점수·선택 ID, 지연·드롭·저장량을 측정한다. | RF·GP, 검수, 재학습 결과 그림에 분모·단위·영문 캡션을 붙이고 공개 수치를 대조한다. |

입력은 [최신 실험](../experiments/환경검증_전체원본재생_20261128.md)의 판정과 정확한 인지/품질 버전 쌍, `deployment/candidate_pair.json`이 가리키는 Q·환경 번들, RGB 재생 예제다. 원본과 점수·선택을 같은 프레임 ID로 연결한다. ROS 센서 시각과 호스트 수신·추론·선택 시각은 단위·출처를 기록한다.

## 현재 재생 구현과 온라인 인수 범위

새 버전 쌍은 [RGB 재생](ROI와_특징추출.md#버전-쌍의-현재-실행) → [검수큐](환경군집과_검수정책.md#실행과-사후-검수) → [사후GT](데이터_등록과_특징정답.md#gt-없는-선별-후-정답-연결)로 연결한다. `infer_versioned_review`는 현재 `EnvironmentReview`와 이전 `VersionedReview`를 번들 형식에 따라 읽는다. 이를 재사용할 수 있지만 기존ROS 스트림이 이 새 번들을 이미 읽는 것은 아니다. 보조 공간 확률은 진단용이며 자동 재학습 승인에 쓰지 않는다. 실제 RGB/GT 재생·호환 측정은 통합 결과에서 확인한다.

현재는26R1이다. [통신 프로파일](../../config/morai/README.md)의 메시지·포트·wheel필드·정지 명령·저속 좌우 회전·상태 피드백 부호를 먼저 인수한다. Windows UDP/native 경로에서는 실제 저속 좌우 조향·별도 구간237회 주행과 heartbeat 중단 시 Park 전환을 확인했다. [실측과 한계](../experiments/ROI9_저속주행과_검수보정_20261126.md)는 직접ROS 토픽·종단 실시간 추론·충돌 피드백 인수와 구분한다. 수집ROS 이미지와40/50인지 이미지는 분리되어 있으며 라이브GPU/ROS 결합은 별도다.

오프라인 채택 버전에서 동일RGB의 특징·점수·후보ID가 일치하는지 확인한 다음, 입력유실/지연·세션 종료/복구·프레임 시각·원본보존을 검사한다. f0→f1이면 같은 열이라도 출력이 바뀌므로 X/y·GP/RF·환경기준/보정을 다시 적합하고 번들 계보를 기록한다. 현재 f0 기준28열과 f1 후보52열을 혼용하지 않는다.

## 기존 스트림 연결과 추가 구현

기존 `stream_front_rgb.py`는 ROS 압축 전방 RGB를 원래 바이트·헤더 시각·수신 시각과 함께 저장하고 RGB 경로 행을 내보낸다. `stream_review`는 이 경로 행을 순서대로 읽어 기존 품질모델로 채점하고 창별 선택 원본을 저장한다. 아래 예시는 기존 X56 경로다. 새 버전별 GP·환경 중심·검수 정책을 이 시간 창에 연결하는 일은 원태·재호가 구현할 대상이다. σ 순위와 환경 할당은 추론 미니배치가 아니라 닫힌 검수 창 전체에서 계산한다. 실제 26R1 토픽·압축 설정·수신률은 시뮬레이터에서 확인한다. [ROS 입력·수신기 원문](../archive/회귀학습_선별평가.md#ros-1-전방-압축-영상-입력)

기존 저장 RGB로 일괄·스트림 출력을 대조할 때는 다음 명령을 사용한다. 변수는 같은 프레임과 완료 모델의 실제 경로로 설정한다.

```bash
PYTHONPATH=src python3 -m quality_estimation.stream_review \
  --data-root "$RGB_ROOT" --model-run "$QUALITY_RUN" --alarm-calibration "$ALARM_RUN" \
  --window-frames 64 --budget-percent 10 --audit-fraction 0.2 \
  --output-dir "$LIVE_RESULT" < "$RGB_MANIFEST"
```

`stream_review`는 표준 입력의 JSON 행마다 RGB를 읽는다. `scores.jsonl`, `windows.jsonl`, `queue.jsonl`, `selected_rgb/`와 `_SUCCESS`를 확인한다. 창이 닫힐 때까지 원본이 같은 경로에서 읽혀야 한다. 스트림 공급·관측 예제는 [기존 실행 기록](../archive/회귀학습_선별평가.md#들어오는-rgb를-바로-채점하고-검수-이미지를-저장하기)에 있다.

같은 입력 순서에서 선택 ID·특징값·점수를 오프라인과 대조한다. 프레임 수·수신률·p50/p95 추출/추론/전체 지연·드롭·기록 용량과 종료 후 재처리 가능 여부를 남긴다. 원본 수집의 보존 범위는 [데이터 등록](데이터_등록과_특징정답.md)에서 확인한다.

## 영어 발표와 보고서 대체 페이지

8분 구성은 문제·목표 1분, 방법·비교 조건 2분, 정량 결과·실패 사례 3분, 시연 1분, 한계·결론 1분이다. 첫 장면으로 RGB·차선 예측·정답을 설명하고, 처음 듣는 청중이 검수와 IoU를 이해할 수 있게 한다. 핵심 결과는 ROI·특징 선택, RF·GP와 검수 비교, 실제 재학습 전후를 같은 데이터 범위와 함께 제시한다.

영어 페이지는 저장소의 `site/`에 구현한다. 첫 화면의 제목·한 문장 성과·대표 영상에서 방법 그림·결과·한계·코드·재현 절차·팀·참고문헌으로 이어지게 한다. 최신 연구 페이지의 영상·코드 접근 방식을 참고한다. [CVPR 2026 LFG 페이지](https://lfg-ai.github.io/)

공개할 표와 그림은 `docs/baselines/`의 공개 집계 또는 문서와 함께 검토한 자산에서 사용한다. 원본 영상의 공개 범위를 확인하고, 영상에는 실제 촬영·재생 방식과 영문 자막을 붙인다. 공개 페이지에서는 개인 경로 대신 코드·결과·영상의 실제 링크를 사용한다.

[최신16개 그림](../baselines/environment_cycle_20261128/README.md)에는 기존 구성 보존·GP/RF·환경 혼동행렬·같은 예산 재학습·정확한 GT 사례·검수 실패 원인을 모았다. 좋은 사례와 나쁜 사례를 함께 보여주며, 사후에 고른 큰 개선 이미지를 평균 성과로 설명하지 않는다. 현재 확인에서 RF가 GP보다 낮은 MAE였고 위험 선별 재학습이 무작위를 앞서지 못했다는 한계를 공개한다. 일정상 온라인 인수를 못 마치면 검증된 오프라인 재생의 범위를 명시한다.

## 12월 4일 완료 점검

- 세 사람이 슬라이드·영상·페이지의 수치, 분모·모델·예산·독립 평가 범위를 같은 확정표와 대조한다. ROS 실측과 오프라인 재생의 관측 범위를 영상에 표시한다.
- 영어 8분 전체 리허설을 마치고 최종 슬라이드·대본·영상을 보관한다. 검증된 재생 영상은 발표 환경에서도 열어 본다.
- 공개 URL에서 모바일·데스크톱의 그림·영상·자막·코드·재현 링크를 확인한다. 재호가 페이지를 완성하고 승현이 제출용 URL과 최종 파일 버전을 보관한다.
