# RGB 환경 구분과 버전별 검수 정책

환경 구분과 품질 회귀를 분리한다. 현재 후보는 **RGB400 히스토그램 감독 분류→확률9차원→공식 e-means16군집**이며 순수 비지도 환경 발견이 아니다. 환경을 잘 구분하는지, 환경별 임계가 같은 예산의 취약 데이터 선별을 개선하는지, 그 선별이 재학습에 유리한지는 각각 확인한다. 최신 진행·채택 여부는 [28일 실험](../experiments/환경검증_전체원본재생_20261128.md)을 따른다. 직전 RGB27/K8 및 공통정책 판정은 [보존 가이드](../archive/guides_20261127/환경군집과_검수정책.md)에 남긴다.

## 왜 환경 표현을 바꾸었나

RGB27 요약의 군집은 이동 Dev에서 날씨 balanced accuracy 약0.732, 조명0.899였다. 지역별 색·명암 분포의 정보를 더 남기기 위해 최소 밝기·대비·hue·채도10-bin 히스토그램을9영역+전체에서 계산한다. 총400열이다. 원본의10×10 블록을 사용하며 품질 GP/RF의28/34/52/49열과 목적·입력을 구분한다.

후보400열·이전 선택 히스토그램·상부/보닛120열을 지리 분리 CV로 비교했다. 선택한 RGB 분류기는 날씨6종과 조명3종(day/transition/night)을 예측한다. 수집 당시 시뮬 태그는 **오프라인 학습/평가 정답**이고 온라인 입력에는 없다. 환경 클래스가 없는 원본 학습 자료에 추정 태그를 정답처럼 채우지 않는다.

원 논문 [Roser·Moosmann IV2008](https://www.mrt.kit.edu/z/publ/download/Roser_al2008iv.pdf)은 지역 블록의 밝기·대비·선명도·hue·채도 분포와 SVM을 사용한다. 현재는 선명도를 제외한4종, 고정9영역+전체와 RF 분류기를 쓰는 적용 변형이다. 원문 전체 재현이나 모든 실제 날씨에 대한 성능을 주장하지 않는다.

## e-means 비교와 해석

원 RGB·히스토그램/PCA·학습한 분류 확률 표현에 공식 [Faiss e-means](https://github.com/facebookresearch/faiss/blob/main/contrib/e_means/README.md)를 적용하고 Lloyd/GMM, 군집 수와3시드의 안정성을 비교한다. 선택 표현은 날씨6확률+조명3확률의 제곱근 변환이다. 최종 중심에 최근접 재배정하며 실행에는 Faiss를 요구하지 않는다.

현재16군집은 이동 Dev 환경 태그와 잘 대응했고 시드 ARI는 약0.946이다.24군집의 극소 군집을 피했다. 군집의 날씨/조명 해석은 훈련 라벨의 빈도 보정 매핑으로 고정하고 새 확인에서 balanced accuracy·혼동행렬로 검사한다. RGB 분류기 자체의 정확도와 군집 매핑 정확도를 따로 보고한다. 개발에5/6날씨만 있으므로 새 확인은6날씨와 새벽을 포함한다.

같은 학습 확률 표현·K16의 추가 대조에서 e-means와 Lloyd 모두 이동 Dev 날씨/조명 balanced accuracy1.0이었다. 대각 GMM은 약0.714/0.689였다. 이 결과는 이 표현에서 e-means가 Lloyd보다 우월하다는 증거가 아니며, 테스트한 GMM 설정 전체의 한계로 일반화하지 않는다.

이는 **감독된 환경 표현을 군집화**한 것이다. 높은 정확도만으로 e-means가 분류기보다 유리하거나 실제 재학습을 개선했다고 말하지 않는다. 현재 작은 CPU 문제에서 원 논문의 속도 배수를 재현했다고 주장하지 않는다. 최근접 거리/저신뢰 표시는 OOD 감사 단서이며 확률 보장은 아니다.

## 공통 기준과 환경별 참조

비교 정답은 모든 환경에서 **전체 Q<0.7**로 유지한다. 환경별 참조는 검수 우선순위를 바꿀 뿐 야간 저IoU를 운행 정상으로 재정의하지 않는다. 정상 야간·가시성의 별도 정답이 없으면 운행 오경보율을 주장할 수 없다.

Cal에서 환경별 Q 분위수를 구하고 전체 분위수와의 차이를 공간 셀 수에 따라 축소한다. 참조는0.45–0.85로 제한한다. 군집마다 최소30행·2도로·10개5m 셀이 필요하며 미지원·RGB 저신뢰·중심 거리 초과는 공통0.7로 돌아간다. 시뮬 oracle은 정확한 환경 정보를 쓰는 오프라인 상한 대조여서 RGB 저신뢰 제한을 적용하지 않는다.

| 기준 후보 | 목적과 사용 |
|---|---|
| 공통 Q0.7 | 기본 보정 확률순 검수 |
| 시뮬 날씨×조명 / 조명 | 태그가 정확하다고 가정한 오프라인 대조 |
| RGB 날씨 / 조명 / 날씨×조명 | 추정 환경별 기준 |
| RGB e-means 군집 | 외관 군집별 기준 |

새 f1에서는 각 후보를 Cal 참조·Dev BO16회와 같은 초기4점의 무작위16회로 비교한다. 분위수0.1/0.25/0.4, 축소20/100, 균형 예약0/0.25/0.5, 불확실성 혼합0/0.1, 근거리 precision/recall 양호 표본만의 참조 여부를 조합한다.10%/25%/41.3% 검수 예산의 도로·환경별 근거리 결함 검색과 양호 표본 비용을 평균한 대리 목적이다. **실제 재학습 이득을 BO로 직접 최적화한 것은 아니다.**

RGB 정책은 충분한 결함 지원과 공통 대비 목적함수0.01 이상 개선이 있어야 채택한다. 새 확인 전 정책을 고정하고 모든 고정 정책의 전이 성적을 함께 보고한다. 새 확인 수치로 임계값을 다시 고르지 않는다. 시뮬 oracle은 배포 정책으로 선택하지 않는다.

## 같은 버퍼·예산의 선별

GP는 관측 표준편차로 나눈 Cal 부호 잔차 CDF, RF는 단위 scale의 잔차 CDF로 검수 확률을 만든다. 탐색 혼합은 닫힌 **전체 검수 버퍼**의 관측 scale 순위이며 미니배치별로 다시 순위를 매기지 않는다. RF의1은 GP 표준편차가 아니다.

일부 슬롯만 환경 균형으로 예약하고 나머지는 전체 위험 순위로 채운다. 전체 할당을 환경별로 고정해 임계값 효과가 사라지는 것을 피한다. 감사는 `floor(예산×0.1)`장을 미선택 자료에서 중복 없이 뽑는다. 같은 ID·창·예산·시드·동점 규칙으로 비교한다. 검수 precision은 실제 저IoU 수/**전체 선택 장수**이며 IoU 미정의 장수·정의된 표본만의 precision도 함께 남긴다.

기존 v6용 환경 임계 BO는 공통 GP와 같은3,072장 순서를 골랐다. 그 결과를 별도 독립 학습으로 세지 않는다. 시뮬 균형 무작위는 별도 대조다. 정확한 기존26,001장 재생은 원래 구성 유지, 새 bank의 균형/위험도 조정은 신규 선별의 효과를 시험한다.

## 한계와 실행

현재 이동 Dev는 낮242장이 모두 근거리 양호, 밤119장이 모두 결함이고 Cal에는 지원되는 야간 양호 표본이 없다. 환경 분류 정확도가 높아도 이 자료만으로 정상 야간과 실제 결함을 구별했다고 주장할 수 없다. 새 확인의 근거리 precision/recall·오검출 지원을 따로 확인하고 부족하면 해당 주장을 보류한다.

[번들 계약](../contracts/environment_review_bundle_v1.md)과 [실행 순서](../../scripts/experiments/environment_cycle_20261127/README.md)를 따른다. `infer_versioned_review`에 일치하는 `--bundle`, `--adaptation-run` 또는 `--checkpoint`, RGB `--manifest`, `--data-root`, 새 `--output`, 닫힌 버퍼의 `--budget`을 전달한다. 환경 분류·품질 예측은 RGB와 인지 출력만 사용한다.

선택 후 `join_spatial_gt`로 원본 바이트·픽셀·모델·역할을 확인한다. 예약 Dev/Cal/확인은 학습 승인 없이 원래 역할을 보존한다. RGB 재생이 live ROS·자동 입학을 의미하지 않는다. 오프라인 판정 뒤 [온라인 연결](온라인_연결과_최종제출.md)을 진행한다.
