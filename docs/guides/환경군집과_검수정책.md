# 환경 군집과 버전별 검수 정책

**9영역의 환경 RGB27열·공식 e-means 8군집**을 사용한다. 품질 회귀 입력과 환경 표현을 분리하고, 선택한 인지모델 버전의 GP·보정·정책을 함께 읽는다. 채택 결과와 수치는 [통합 실험](../experiments/군집_검수_동일예산_재학습_20261127.md), 산출물은 [공개 집계](../baselines/selection_cycle_20261127/README.md)를 따른다.


**27일 판정:** 환경 RGB27열/K8을 유지하되 개발 BO혼합은 확인에서25/39장, 공통확률+감사는35/39장의 저품질을 찾았다. 새f1 후보 정책은 공통Q0.7확률+ceil10%감사·σ혼합0·환경 강제할당 없음이다. 환경 상대 임계는 미채택이다. f1/g1 교체 자체는 품질 유지성 실패로 보류했다.


## 환경 표현과 군집

상부 위층 좌우와 보닛에서 각각 밝기 평균·표준편차, glare/어두운 픽셀 비율, 밝기 p90−p10, 채도 중앙값, blue−red, hue cos/sin을 추출한다. 총27열 중 현재 후보에서 변하는24열을 표준화해 군집에 사용한다. 나머지3개 glare열의 새로운 변화도 참조 이탈 표시로 남긴다. ROI9의 모든 영역에서 같은 특징을 사용할 필요는 없다.

공식 [Faiss e-means](https://github.com/facebookresearch/faiss/blob/main/contrib/e_means/README.md)의 `NumpyEmeans`로 RGB4종×K8/16/32×3시드를 비교했다. 후보7,442장의 환경 정보량, 시드 안정성, 복잡도를 보고27열/K8을 골랐고 첫 시드를 사용한다. 날씨·시각 메타데이터는 표현 선택의 오프라인 진단에 사용했다. 중심 적합과 실제 배정 입력은 RGB다. 실행에서는 표준화와 최종 중심의 최근접 배정만 수행하므로 Faiss가 필요하지 않다.

C0–C7은 외관 군집이다. 같은 날씨가 여러 군집에 나뉘거나 다른 날씨가 함께 묶일 수 있다. NMI는 분류 정확도가 아니다. 최근접 거리와99% 참조 반경은 감사 표시이며 OOD 확률을 보장하지 않는다. 새로운 카메라 배치는 ROI/중심/품질모델을 함께 재검증한다.

## 품질 점수와 검수 예산

주 목표는 전체 프레임 white/yellow 차선 IoU Q다. 공통 저품질 벤치마크는 Q<0.7이다. 정책 후보는 다음 점수와 혼합·할당을 개발 자료에서 비교한다.

| 요소 | 의미 |
|---|---|
| 낮은 평균 | `1−clip(μQ,0,1)` |
| 저품질 확률 | 보정 사용 여부를 고정한 `P(Q<0.7)` |
| 기대 부족분 | `E[(0.7−clip(Q,0,1))+] / 0.7` |
| 탐색 혼합 | 위 점수와 전체 검수 버퍼의 잠재함수 σ 순위 혼합 |
| 환경 할당 | 군집 크기의 지수0/0.5/1에 따른 균등/중간/비례 할당 |
| 무작위 감사 | `ceil(검수 예산×0.1)`장을 우선순위 선별 후 남은 자료에서 추출 |

BO16회와 같은 초기4점·16회 무작위 탐색을 비교한다. 목적함수는 개발 자료의10%/41.3% 검수 예산에서 도로·군집별 저품질 검색과 검수 비용이다. 재학습 이득을 직접 최적화한 값은 아니다. 채택된 점수·혼합·할당은 번들의 `policy.json`이 정한다.

σ 순위는 추론 미니배치를 합친 **전체 검수 버퍼**에서 계산한다. 동점에는 평균 순위를 준다. 출력에는 `priority`/`random_audit`, 조건부 포함 확률, 모집단·예산·시드·모델 식별자를 남긴다. 같은 창·분모·동점 규칙으로 비교한다. 예산 반올림으로 실제 비율이10%보다 커질 수 있다.

첫 인지 재학습의 `ClusterBO` bank는 f0/g0로 미리 고른3,072장이다. 새 g1 정책과 이 bank의 정책을 구분한다. 새 인지모델로 다시 만든 정책은 다음 선별 회차에 사용한다.

## 환경별 상대 기준

`versioned_relative_study.py`는 선택된 f1의 별도26R1 보정612행으로 참조를 다시 적합한다. 전체 지원 자료와 근거리 precision/recall이 보존된 자료를 나누고, 분위수·축소 강도·혼합·할당을 비교한다. 군집별 최소30행·2도로·10개5m 셀이 필요하다. 지원이 부족하거나 참조에서 벗어나면0.7로 돌아간다.

이는 환경 안의 상대적 검수 우선순위 실험이다. 낮은 야간 IoU를 운행 정상으로 바꾸는 기준은 별도의 가시성·정상 라벨이 필요하다. 이번 주 정책은 절대 Q0.7과 별도 검수 채택 기준으로 고정한다. 상대 참조의 개발·확인 이득과 미채택 사유는 결과 문서에 남긴다.

## 실행과 사후 검수

선택한 GPU 환경에서 `quality_estimation.infer_versioned_review`에 **같은 버전의** `--bundle`, `--adaptation-run`, RGB `--manifest`, `--data-root`, 새 `--output`을 전달한다. `--batch-size 4 --budget 12`처럼 검수 장수를 명시할 수 있다. [환경 준비](개발환경.md) · [입력과 특징](ROI와_특징추출.md)

그 다음 `quality_estimation.join_spatial_gt`로 원본 RGB/Semantic 바이트·디코딩 픽셀·인지 버전·ROI·정답을 대조한다. 예약된 development/calibration/heldout 역할은 GT 연결 뒤에도 보존하고 학습 승인은 false로 둔다. [데이터와 역할](데이터_등록과_특징정답.md)

검수 순위에는 모든 RGB를 넣는다. 선별 후 GT≥100과 union≥100의 지원 집계를 따로 남겨 GT가 적은 오검출 장면도 확인한다. 검수 precision은 선별 장면 중 실제 저품질 비율이며, 세그멘테이션의 픽셀 precision과 다르다. 운행 오경보율은 가시성 정상 라벨로 따로 정의한다.

현재 소스는 오프라인 버퍼 재생이다. ROS의 시간 창·세션 경계·원자적 버전 전환은 [온라인 연결](온라인_연결과_최종제출.md)의 다음 단위다. 원태는 새 구현을 처음부터 반복하기보다 동결 번들·동일 예산 표·확률 보정과 실패 사례를 독립 재현해 인계한다.

이전 RGB54/K16·날씨80/시각160·공간 혼합·조건부 GP 실험은 [통합 전 가이드](../archive/guides_20261126/환경군집과_검수정책.md)와 날짜별 실험 문서에 보존한다.
