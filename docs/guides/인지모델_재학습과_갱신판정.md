# 동일 예산 인지 재학습과 버전 쌍 판정

이번 비교는 신규3,072장과 원래 학습 자료4,096장을 함께 사용하는 장시간 추가학습이다. 인지 성능 개선, 품질 추정 성능, 검수 검색 성과를 각각 판정한다. 실제 완료 수치와 선택한 모델은 [통합 결과](../experiments/군집_검수_동일예산_재학습_20261127.md), 실행·그림·해시는 [근거 모음](../baselines/selection_cycle_20261127/README.md)을 따른다.


**27일 판정:** 8학습·24파생·50평가를 완료했다. 개발에서 고른 QualityRank alpha0.5는 주 확인IoU0.57891→0.64997·기존lane 손실0.00294로 인지 기준을 통과했지만 g1 유지성은 실패했다. 통합 교체는 보류하며 선별의 무작위 대비 학습 이득도 확인하지 못했다. 다음 수천장/온라인 이전에 g1을 보완한다.


## 고정 비교

| 방법 | 새 슬롯3,072장 | 공통 replay4,096장 |
|---|---|---|
| Random | 보유 후보에서 무작위 | 원래 train, 전·좌·우 카메라 |
| QualityRank | f0/g0 저품질 점수순 | 동일 목록·시드 내 동일 순서 |
| ClusterBO | e-means 환경별 할당과 품질/불확실성 점수 | 동일 목록·시드 내 동일 순서 |
| ReplayOnly v2 | 새 슬롯을 다른 original train 전방3,072장으로 대체 | 동일 목록·시드 내 동일 순서 |

모두 같은 Medium v6 EMA f0에서 시작한다. 세 신규자료 방법은 각2개 optimizer 시드, 대조도2개로 총8학습이다. 방법마다 선별 bank는 고정하므로 두 시드는 선별 자료 변화의 반복이 아니다. continuation 대조는 새로운 이미지 없이 최적화를 더 한 효과를 구분한다.

보관된 v6 manifest의 train은26,001카메라 표본(전방8,667), validation은1,404장이다. 새 후보7,442장은 원래 train/val 전체27,405장과 디코딩RGB가 겹치지 않는다. 새 수집·원본 복사 없이 D/E 보관 자료를 재가공한다.

## 충분한 학습과 캐시

배치16=새8+replay8,24,000업데이트, LR1e-5에서cosine으로1e-6까지 낮춘다. warmup200, AdamW decay1e-4, gradient clip10을 사용한다. BF16 forward와 FP32 loss reduction, 고정BN 통계·학습 가능한 affine을 사용하며 공통replay에 f0 teacher KL0.25/T2를 적용한다. 새 bank62.5회·replay46.875회분을 제시한다. 실제 소요 시간·메모리·손실은 실행별로 기록한다.

[공유 캐시](../../src/quality_estimation/adaptation_cache.py)는 RGB/Semantic/정답정책 해시로 주소를 정한다. 원본을 보존하고 축소 입력·두 헤드 정답·valid mask를 한 번 생성한다. 원래 replay/val/control 총8,572장의 두 헤드와padding은 원래 학습 캐시와 비트 단위로 일치했다. 전처리 규격을 바꿀 때에는 새 캐시 규격/이력을 만든다.

`input_rgb.png`는 cv2로 색변환 없이 읽는 학습텐서, `targets.png`는 drivable/road_marking/valid 채널이다. 발표용 자연색 이미지로 바로 사용하지 않는다. 결과 그림은 실제 GT·두 모델의 카운트/IoU 일치를 확인한 별도 PNG다.

## 원래 성능 유지와 보간

첫 Random 원시 endpoint가 개발 성능을 높였지만 기존 성능 유지 기준을 실패한 뒤, 다른 f1 개발 결과와 확인 자료를 열기 전에 모든 방법·시드·대조에 같은 alpha0.25/0.5/0.75 추가 비교를 등록했다.

`θα=(1−α)θf0+αθtrained`로 파라미터를 보간하고 고정 buffer가 같은지 검사한다. 이는 추가 gradient 학습 없이 한 네트워크를 만드는 작업이다. **8회 학습과24개 파생 가중치 평가를 구분한다.** 개념 근거는 [WiSE-FT](https://github.com/mlfoundations/wise-ft)의 가중치 보간이며 모델·과제·자료가 다른 적용 실험이다.

선별 자체의 대조는 원시alpha1.0과 미리 정한 공통alpha0.5에서 수행한다. 방법별로 개발에서 고른 계수가 다른 경우에는 전체 파이프라인 비교로 따로 보고한다. 확인 도로에서 계수를 다시 고르지 않는다. g1 재적합에 사용한 정확한 방법·계수도 최종 판정까지 유지한다.

## 데이터 역할과 판정

추가학습에 사용한 ID·픽셀은 quality-fit·예약 평가와 겹치지 않는다. 후보와 예약 개발/보정/확인 위치는25m 이상 분리한다. quality-fit2480행과 추가학습 자료는 가까운 위치가 많으므로 위치까지 전부 독립됐다고 주장하지 않는다. 이미 열었던 f0 자료를 이번 갱신에서 배제한 paired 진단이며, 새로운 지도나 처음 공개한 최종 시험은 아니다.

| 판정 | 이번 고정 조건 |
|---|---|
| 신규 주 도로 | macro IoU 이득≥0.005,3도로 중2개 이상 향상, 개별 손실≤0.02 |
| 기존 validation | 전체 lane/drivable pooled 손실 각각≤0.005 |
| 기존 클래스·시야 | white/yellow/stopline 각 손실≤0.01, 전·좌·우 lane/drivable 각 손실≤0.01 |
| 반복 | 방법의 두 optimizer 시드가 함께 통과 |
| 품질모델 | GP 개발 MAE≤RF+0.005, 새 확인 MAE≤기존 f0/g0+0.010 |
| 검수 혼합 | 주 확인 저품질20장·2도로 이상, 공통확률+감사 대비 macro recall 손실≤0.02, precision≥무작위 평균 |

이는 연구 채택 기준이다. 선택한 모델과 시드는 개발에서 고정하고 확인 뒤에는 채택/보류만 판정한다. 혼합 검수가 실패하면 미리 정한 공통 Q0.7 확률순+10%감사로 돌아간다. 과거 [cycle_acceptance_v1](../../config/cycle_acceptance_v1.json)의 신규이득≥0은 이전 재현 기준이며, 이번에는 위의 더 엄격한 조건을 사용한다.

## f1/g1 연결과 실행

[실험 순서](../../scripts/experiments/selection_cycle_20261126/README.md)는 준비/감사→GT없는 선별→공유캐시→장시간학습/대조→개발 보간→정확한 f1 고정→새X/y·GP/RF·보정/정책→확인 평가→RGB단독/GT연결/호환 검증이다. [retrain_streaming](../../src/quality_estimation/retrain_streaming.py)은 optimizer/RNG와 `latest.pt`를 보존하고 완료된 체크포인트·목록·정책·코드·해시를 함께 기록한다.

인지 가중치가 바뀌면 같은 GT에서도 출력·특징과 IoU 정답이 바뀐다. 선택된 f1으로 품질 학습·개발·보정 자료를 다시 계산하고 g1을 새로 적합한다. RGB 환경 중심은 재사용할 수 있지만 해당 버전의 IoU 상대 참조·확률 보정은 다시 확인한다. `deployment/candidate_pair.json`과 버전별 `review_bundle`이 인계 단위다. 원래 f0 파일을 덮어쓰지 않는다.

실행은 맞는 `--adaptation-run`과 `--bundle`을 명시한다. 새 RGB 후보의 GT 연결 뒤에도 데이터 역할과 입학 허용 여부를 검토한다. 이번 확인용 후보는 예약 역할을 보존하고 자동 학습하지 않는다.
