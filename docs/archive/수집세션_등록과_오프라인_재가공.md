# 수집 세션 등록, 원본 복원 검증과 오프라인 GT 연결

**`capture_session.json`이 어떤 모집단의 어떤 원본을 보존했는지 기록한다.** 팀 Capture Mode 동기화와 ROS 압축 RGB 수집기는 정상 종료 시 세션 기록을 발행한다. 기존 전방 4채널 연구 수집본은 원본 파일을 복사하지 않고 등록할 수 있다. 기록에 매니페스트 해시, 상대경로, 채널, 프레임 수, 보존 범위, 시각의 출처, 실험 맥락이 남는다. 완료 표식은 이 기록의 해시에 연결된다. [등록·검증 도구](../../scripts/capture_sessions.py) · [공통 기록 구현](../../ros/src/data_collection/src/data_collection/session_archive.py)

| 입력 경로 | 등록 시점과 보존 범위 | 복원 근거 |
|---|---|---|
| Capture Mode ROS/gRPC → 기존 동기화 명령 | 촬영 시도는 트리거 원장에 기록한다. 동기화가 끝나면 성공 중 명시적으로 제외된 프레임을 뺀 모집단을 등록한다. 4개 카메라 × 4채널과 GPS·IMU를 저장한다. | 프레임별 18파일의 SHA-256, 카메라·모달리티 상대경로, 요청·ROS·시뮬레이터 시각, 원래 시도 원장과 제외 목록을 보존한다. 같은 크기의 손상도 재동기화에서 검출한다. |
| ROS 압축 전방 RGB 수집기 | 실제 수신한 RGB 전량과 원래 압축 바이트를 보존한다. 수신 전에 빠진 메시지는 시퀀스 통계에 나타날 수 있다. | 헤더 시각·수신 시각·파일 해시·디코딩 RGB 해시를 전송 원장에 저장한다. 추론용 RGB 목록은 기존 4개 필드를 유지한다. 이 수집 경로의 GT 가용 수는 0이다. |
| 기존 native 전방 연구 수집본 | `register-front`가 주어진 원장 전 행의 RGB·Semantic·Instance·Depth의 파일 해시와 네 PNG의 해상도 일치를 검증한다. 원장의 `files` 목록 형식과 채널별 `sha256` 형식을 받는다. | 원본 원장 사본·행 번호와 프레임 ID를 보존한다. 세션 디렉터리에는 원장과 해시만 있으며 카메라 파일은 별도 미디어 루트에 있다. 원장 밖 프레임의 존재는 이 도구로 확인할 수 없다. |

## 실행

촬영 전에 팀이 확인한 맥락은 별도 JSON 파일로 전달한다. 예시는 `{"purpose":"offline_policy_evaluation","parent_session_id":"session-B","road_id":"road-B","split_role":"final_test","camera_profile":"front-v1","condition_source":"simulator_readback"}`이다. `site_id`, `root_alias`, `sampling_policy`도 기록할 수 있다. 모델·ROI·GT·검수 정책이 적용된 단계에서만 해당 버전 필드를 채운다. 알 수 없는 값은 생략한다. 역할을 생략한 기존 자료도 등록할 수 있으며, 훈련 사용에는 별도 분할 근거가 필요하다.

- 통상 수집에는 `capture_mode_collector.launch`의 `session_context:=<JSON 파일>`과 기존 `scripts/sync_capture_mode_data.py`를 사용한다. 촬영 메타데이터가 동기화 결과에 계승된다. 단순 ROS RGB 기록에는 기존 `stream_front_rgb.py`에 `--session-context <JSON 파일>`을 추가할 수 있다. 온라인 품질모델 연결 전에도 원본 수집과 오프라인 재생은 독립적으로 가능하다.
- 다음 예시는 이미 보관한 연구 수집본의 **한 세션**을 등록한 뒤 원본 해시를 확인하고 ML 입력 두 벌을 만드는 명령이다. 변수는 각자 실험 볼륨의 실제 경로로 설정한다. `CAPTURE_STORE`는 세션 목록을 모으는 폴더다. `RAW_ROOT` 아래에서 상대경로로 카메라 파일을 찾으며, 기본 전방 폴더는 `captures/CAMERA_1`이다. 다른 배치는 `--camera-dir`로 지정한다. `--population`에는 원래 수집 설계에 따라 `all_captured`, `selected_only`, `unknown`을 기록한다.

```bash
python3 scripts/capture_sessions.py register-front \
  --manifest "$RAW_MANIFEST" --media-root "$RAW_ROOT" --session-id "$SESSION_ID" \
  --context "$SESSION_CONTEXT" --population all_captured --output "$CAPTURE_STORE/$SESSION_ID"
python3 scripts/capture_sessions.py list "$CAPTURE_STORE"
python3 scripts/capture_sessions.py verify "$CAPTURE_STORE/$SESSION_ID" --media-root "$RAW_ROOT"
python3 scripts/capture_sessions.py export "$CAPTURE_STORE/$SESSION_ID" \
  --media-root "$RAW_ROOT" --output "$EXPORT_DIR"
```

내장 수집기의 동기화 결과·RGB 세션은 미디어도 해당 세션 아래에 있으므로 `--media-root`를 생략한다. 복원본을 검사할 때는 같은 상대경로를 가진 다른 미디어 루트도 사용할 수 있다. `list`는 완료 기록과 미등록·무결하지 않은 기록을 구분한다. 원본 전체의 무결성은 `verify`로 확인한다. `register-front`와 `export`는 새 출력 디렉터리에 완성된 결과만 발행하므로 실패 후 같은 경로로 재시도할 수 있다. 이미 성공한 출력 디렉터리는 보존한다.

## 데이터 사용 규칙

1. `export/rgb.jsonl`은 ID·view·RGB 경로·RGB 바이트 해시만 갖는다. 모델·선별 정책은 이 목록을 촬영 순서대로 재생해 점수와 검수 목록을 먼저 저장한다.
2. `export/paired.jsonl`에는 같은 ID의 RGB·Semantic 상대경로와 두 바이트 해시, 디코딩한 RGB 픽셀 해시가 들어간다. RGB만 받은 세션은 빈 paired 목록과 `paired=0`을 명시한다. 파일은 원본 미디어 루트에 있으므로 후속 CLI의 `--data-root`도 그 루트를 가리켜야 한다. 예측과 정답은 ID·픽셀 해시 둘 다 일치할 때 접합한다. [기존 ROI10 점수·지연 GT 실행법](전방_10영역_실험_재현.md)
3. 역할·노출·부모 그룹은 원래 수집/분할 설계와 대조한다. 잘린 원장 또는 선별 영상만 있는 세션을 전체 후보 모집단으로 사용하면 미선별 실패의 분모가 빠진다. 원래 역할이 섞인 세션은 원본 행의 역할을 유지한다. 전역 물리 세션이나 위치를 알 수 없는 가공본은 분할 근거를 보강한 뒤 독립 평가에 사용한다.
4. 검수 정책·모델 버전은 실제 점수 실행의 `run.json`, 선별한 ID·사유·예산은 검수 원장, 파생 입력 해시는 `export.json`에 보관한다. 원본 세션의 해시는 그 목록의 부모 식별자로 사용한다. 해시 검사는 현재 읽은 원본의 일치 여부를 보여준다. 장기 보존 시 별도 장치로 복원해서 같은 명령을 실행한다.

## 11월 23일 검증 범위

기존 전방 원장 8개의 3,233장과 네 채널 12,932파일을 등록·검증하고 GT 격리 입력을 내보냈다. 두 주행 273장의 ID, 파일·디코딩 픽셀 해시를 이전 원장과 맞춘 뒤 실제 ML 빌드로 영역별 TP·FP·FN 8,190개의 정수 일치를 확인했다. 별도 디렉터리에 복원한 다중 센서 한 프레임의 18파일과 전방 GT 짝도 점검했다. 팀 컨테이너에서 수집 패키지 32개와 ML 파이프라인 145개 테스트를 통과했다. 수집 테스트에는 같은 크기 손상 복구, 변경된 원본 거부, 쓰기 중단 후 재개, 빈 GT, 역할 보존과 불완전 입력 거부를 포함한다. 이전 세션 중 해시·완료 표식이 없는 자료는 원래 입력 목록으로 사용하거나 원본과 대조한 뒤 등록한다.
