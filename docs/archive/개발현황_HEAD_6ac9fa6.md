# 통합 프로젝트 개발 현황

**11월 23일 저녁.** 검수 후보 576장 중 116장을 선별해 실제 재학습했다. 위험순 검수 정밀도 100%와 인지모델 교체 효과를 분리해 측정했다. f0의 추정 IoU가 0.7 미만일 때만 갱신 모델을 사용하는 후보는 과거 회로의 평균 차선 IoU를 0.4026에서 0.5293으로 높였고 기존 IoU 하락은 0.0020이었다. 별도 품질 학습분 288장을 보강한 뒤 품질 MAE 증가는 0.0073이었다. 다음 도로 검증 전까지 기본 운용 쌍은 f0/g0다. [동일 예산 비교·야간 정상 분모·팀용 점수표](../experiments/오프라인_검수와_동일예산_재학습_20261123.md)

**현재 진행 순서 · 11월 23일.** 수집기가 세션별 원본·채널·보존 범위·목록 해시를 기록하고, 기존 전방 4채널 자료를 원본 복사 없이 등록해 RGB 단독 입력과 지연 GT 입력을 내보낸다. 기존 데이터로 품질모델과 검수 정책을 고정하고, GT 평가·f1/g1 재학습·채택 또는 보류 결정을 마친 뒤 단위 2·3을 26R1에 연결한다. 기준 쌍은 f0/g0다. [수집 세션 등록·재가공 명령](수집세션_등록과_오프라인_재가공.md) · [오프라인 단계와 팀원별 실험·웹페이지 분담](데이터플라이휠_통합실험계획_3인분담.md)

**수집기 검증.** 기존 8개 전방 수집 세션 3,233장(4채널 12,932파일)을 해시 검증해 RGB 단독 목록과 사후 GT 목록으로 내보냈다. 별도 도로 273장을 이 목록으로 팀 ML 실행 경로에서 다시 처리한 결과, 10영역의 TP·FP·FN 8,190개가 기존 결과와 모두 일치했다. 다중 카메라 동기화는 실제 보관 프레임 1개의 18파일로 복원·GT 내보내기를 점검했다. 이 수치는 데이터 경로 재현 검사다. 이어서 동일 예산 검수로 인지모델을 실제 재학습하고 f1별 10영역 품질 추정기를 다시 적합했다. [후속 비교 결과](../experiments/오프라인_검수와_동일예산_재학습_20261123.md)



11월 23일 오후에는 화면 전체를 10영역으로 분할해 환경 분류·공간 관계·차선 품질 회귀·경보를 다시 검증했다. 공용 명령에서 10영역 품질 회귀와 띠별 날씨 분류를 다시 학습·평가할 수 있다. 새 주행 3회에서 영역별 추정의 IoU MAE는 0.0607이었다. 아래의 수치는 각각 표기된 시점의 기준 실험이다. [10영역 결과와 다음 개발 순서](../experiments/전방_10영역_특징과_품질추정_20261123.md)

반복주행에서 GT 없는 검수와 선별 재학습을 연결했다. 새 도로의 실제 RGB·Semantic 288장을 추가해 갱신 인지모델의 품질 추정기도 다시 학습했다. 별도 위치의 144장에서 IoU 예측 MAE는 0.1299에서 0.0823으로 줄었다. [주행 검수와 인지모델 갱신 실측](../experiments/주행검수와_인지모델갱신_20261123.md)

2026년 11월 23일 기준. 아래 기준 모델·갱신 수치는 11월 16일 실험에서 얻었다. 이후 공간 분할에서 환경 특징과 품질 추정을 다시 평가했다. [11월 23일 환경 ROI·e-means·GP 검증](../experiments/환경_ROI와_품질추정_20261123.md)

목표는 **기계학습 기반 인지 품질 추정을 통한 딥러닝 인지모델 개선 데이터 플라이휠 구축**이다.
기계학습과 캡스톤디자인은 개발 결과를 공유한다. 기계학습 팀원은 안승현·손재호·장원태,
캡스톤 팀원은 안승현·장원태다. 개발 기준은 현재 코드와 검증된 실험 기록이며,
11월 4일 발표의 계획·주차·선택 과제 표시는 당시 이력으로 구분한다.

## 11월 23일에 확인한 범위

- MORAI 시뮬레이터에서 6개 날씨·8개 시각의 정지 자세를 교차하고 다른 도로와 실제 반복주행에서 같은 인지모델을 평가했다. 다른 도로 960장에서 RF와 GP의 차선 IoU MAE는 모두 약 0.082였다. 환경 분류는 별도 RF로 날씨와 촬영 시각을 예측한다.
- 주행 중 전방 RGB를 전달해 품질 점수와 경보를 계산하고, 64장 검수 창마다 선별한 원본을 저장했다. 안개 13시 주행의 49장 검수에서 실제 저품질 25장을 찾았고 같은 예산의 무작위 기대는 8.1장이었다. 같은 안개 20시에는 검수 가능 영상 전부가 저품질이었다.
- 예측 차선 면적별 검수 예산, 실제 GT 면적별 발견 수, 신규 라벨 장수·학습 횟수별 재학습, 기존 성능 손실 제약을 둔 BO와 무작위 탐색을 비교했다. 공용 명령으로 고정 격자에서 탐색을 재생할 수 있다. [11월 23일 실험 결과](../experiments/환경_ROI와_품질추정_20261123.md)

## 11월 16일의 기준 모델과 첫 갱신 검증

| 단계 | 구현·실행 상태 | 근거와 판단 |
|---|---|---|
| 인지 기준 모델 | TwinLiteNet+ Medium v6 EMA epoch 11 연결 | v6는 학습 버전이다. 기본 인지모델 f0와 품질모델 g0를 유지한다 |
| 특징·정답 | 출력·RGB 8통계 × 전체 및 6개 ROI = 56차원 X, 단일 차선 IoU y | 흰·노란 차선 합집합, 정지선·padding 제외. GT는 X에 넣지 않는다 |
| 품질 회귀 | OLS·Ridge·Random Forest 학습·비교·고정 | RF MAE: 개발 0.0566, 정지 최종 0.0913, 주행 보조 0.0800. 평가군을 구분한다 |
| GT 없는 선별 | RGB 추론, 중복 제거, 예산별 순위·기준선 평가 | 원래 후보 296장 중 30장 예산에서 품질 순위·Confidence 모두 저품질 30장 발견. 두 방법의 우위는 확인하지 못함 |
| 인지모델 추가학습 | 동일 신규 정답 수·업데이트 수와 replay-only 대조군 비교 | 원래 두 시드 평균의 새 정지 IoU 0.6379→0.7102, 기존 조건 0.8006→0.7734. 개선과 성능 유지는 별개 |
| 버전 쌍·경보·갱신 판단 | f1/g1 연결, 개발 전용 경보 보정, 검수 대기열, 채택 판정 CLI 실행 | 새 주행 1,371행과 추가 661행 검증 완료. 기존 성능 유지 기준 미달로 갱신 후보 채택 보류 |

위의 11월 16일 비교에서는 같은 지도에서 얻은 자료와 일부 위치를 공유한다. 프레임 수를 독립 환경의 반복 수로 해석하지 않는다.
낮은 IoU 정의와 운용 경보 cutoff는 구분한다. 높은 저품질 Recall만으로 야간 오경보 문제가 해결됐다고 보고하지 않는다.
데이터 선별 효과, 회귀 오차, 재학습 효과, 기존 성능 유지도 각각 검증한다.

## 구현과 실험 자산의 경계

- 유지보수할 코드는 이 저장소의 [`src/quality_estimation/`](../../src/quality_estimation),
  [`src/common/bridge.py`](../../src/common/bridge.py), [`src/visualization/`](../../src/visualization)에 있다.
- 실행 프로토콜은 [`config/`](../../config), 공유 결과·절차는 이 저장소의 `docs/`에서 관리한다.
- 원본 RGB/Semantic, X/y 배열, 모델 bundle·checkpoint, 상세 로그·시각화·실험별 실행기는 Git 밖에 보존한다.
  각 완료 run의 source snapshot과 해시가 실제 실행 코드를 식별한다. 이후 커밋이 과거 run의 실행 revision이었다고 소급하지 않는다.
- 발표 전 사용한 UDP 수집 어댑터는 로컬 실험 기록이다. 공개 품질 파이프라인은 다른 프로젝트 저장소를 import하지 않는다.
  기존 수집 부품의 존재와 MORAI 26R1 ROS 통합 검증 완료를 구분한다.
- 발표 파일·강의 원문·개인 분석은 로컬 워크스페이스에서 관리하고, 개발에 필요한 결론과 명령은 공통 문서에 남긴다.

## 남은 개발과 우선순위

2026-11-23에 네 세부 계획을 [데이터 플라이휠 통합 실험 계획과 3인 분담안](데이터플라이휠_통합실험계획_3인분담.md)으로 정리했다. 안승현이 오프라인 전체 주기를 진행하는 동안 장원태는 야간 정상과 조건별 경보를, 손재호는 검수 순위 평가와 논문 프로젝트 웹페이지 초안을 담당한다.

1. **품질 추정의 신뢰성:** 정상·저품질을 함께 확보하고 조건별 MAE·오경보를 검증한다. 특징·경보 기준은 개발 자료로 정하며 새 평가를 보고 다시 맞추지 않는다.
2. **기존 성능을 유지하는 갱신:** 취약 조건 데이터, replay 대표성·비율, 학습률·학습량과 유지 제약을 비교한다. 새 조건 개선과 기존 조건 유지를 함께 통과해야 한다.
3. **독립 환경:** 다른 지도·날짜·객체 배치의 평가 역할을 수집 전에 고정한다. 같은 경로 반복으로 독립성을 대신하지 않는다.
4. **26R1 ROS 연계:** 오프라인 채택·보류 결정을 기록한 뒤 센서/수신 시각·지연·드롭·저장 예산을 측정하고 GT 없는 로깅을 연결한다. 현재 실시간 폐루프·자동 배포 성과는 없다.
5. **다음 세대 누적 주기:** 현재 재학습 CLI는 고정 f0에서 시작하는 한 번의 갱신이다. f1→f2에는 부모 모델 계보·누적 노출·새 잠금 평가 연결이 필요하다.
