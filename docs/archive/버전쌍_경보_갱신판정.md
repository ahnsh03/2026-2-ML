# 인지·품질 버전 쌍, 경보 보정, 갱신 채택 판정

2026-11-16 구현. 파일 기반 오프라인 데이터 플라이휠의 다음 주기를 검증하는 방법이다.
[통합 목표·현재 근거](통합_데이터플라이휠_개발현황_20261116.md)와
[X/y](X_y_데이터셋.md)·[회귀](회귀학습_선별평가.md)·[인지모델 갱신](선별자료_인지모델_재학습.md)을 함께 본다.

## 버전 쌍을 명시한다

`perception_identity.py`는 baseline f0와 검증된 adaptation f1을 구분한다.
f0는 기존 기본값을 유지한다. f1은 완료된 재학습 run의 artifact·checkpoint·초기 f0·정답 정책 해시를 확인한다.
bundle·dataset의 인지 checkpoint와 이력이 호출자가 지정한 버전과 다르면 거부한다.
이전 f0 산출물에 새 identity 필드가 없어도 기존 f0 해시가 맞으면 읽을 수 있다.
임의 checkpoint를 기본 검사를 우회해 연결하는 용도가 아니다.

아래 경로는 예시다. 데이터·run은 사용자의 출력 볼륨에 준비한다.

```bash
# f1로 이전 품질 학습/개발 프레임의 X/y를 다시 생성한다.
scripts/run_container.sh python3 -m quality_estimation.build_native_dataset \
  --manifest /outputs/catalog/meta_train_dev.jsonl --data-root / \
  --adaptation-run /outputs/experiments/f1_update \
  --output-dir /outputs/datasets/f1_meta_xy

scripts/run_container.sh python3 -m quality_estimation.verify_dataset \
  --dataset-dir /outputs/datasets/f1_meta_xy --data-root / \
  --adaptation-run /outputs/experiments/f1_update \
  --report /outputs/reports/f1_meta_validation.json
```

`splits`·`train_models`·`freeze_models`·`evaluate_models`·`infer_images`도 f1에는 같은
`--adaptation-run`을 받는다. f1 학습 프레임·부모 그룹·RGB 픽셀이 품질 학습/개발에 섞이지 않도록 검사한다.
정답의 의미와 56차원 특징 계산은 f0/f1에서 같다. 인지 출력과 그 출력의 실제 IoU 값은 버전마다 다시 계산한다.
전처리를 다시 fit할 때도 meta_train만 사용한다.

## 실제 저품질과 경보 임계값을 분리한다

- 정답 정의: 실제 차선 IoU **<0.7**. 연구용 기준이며 안전 기준이 아니다.
- 경보: 예상 IoU **<개발 자료로 정한 별도 cutoff**.
- 순위 선별: 같은 예산에서 예상 IoU 오름차순. 경보 임계값과 독립된 평가다.

```bash
scripts/run_container.sh python3 -m quality_estimation.alarm \
  --dataset-dir /outputs/datasets/f1_meta_xy \
  --split /outputs/protocols/f1_meta_split.json \
  --model-run /outputs/experiments/g1 --model RandomForest \
  --adaptation-run /outputs/experiments/f1_update \
  --target-iou 0.7 --maximum-fpr 0.1 \
  --output-dir /outputs/experiments/g1_alarm

scripts/run_container.sh python3 -m quality_estimation.infer_images \
  --manifest /outputs/catalog/new_rgb_only.jsonl --data-root / \
  --model-run /outputs/experiments/g1 --model RandomForest \
  --adaptation-run /outputs/experiments/f1_update \
  --alarm-calibration /outputs/experiments/g1_alarm \
  --output-dir /outputs/experiments/new_g1_rgb_only
```

Calibration은 meta_dev의 정상 행에 대한 경험적 FPR 예산을 적용한다. strict `<`와 보수적인 동점 처리를 사용한다.
정상 개발 행이 부족하면 거부한다. 새 자료의 분포가 바뀌면 실제 FPR은 예산보다 높을 수 있다.
경보 산출물은 품질 모델·인지 identity·정의·source dataset/split 해시에 묶이며 다른 모델에 재사용할 수 없다.
RGB 단독 추론 결과는 실제 IoU 없이 예상 IoU·경보 여부·임계값·RGB 해시를 남긴다.

## GT 없는 검수 대기열

`review_queue`는 완료된 RGB 단독 추론과 그 입력 manifest의 해시를 확인하고, 예상 IoU가 낮은 RGB를 우선 제안한다.
현재 추정기가 놓치는 사례를 검토할 수 있도록 예산 일부는 우선 선별되지 않은 나머지에서 무작위로 고른다.
GT·실제 IoU를 열지 않으며, manifest도 전방 RGB 참조·RGB 해시만 허용한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.review_queue \
  --inference-run /outputs/experiments/new_g1_rgb_only \
  --rgb-manifest /outputs/catalog/new_rgb_only.jsonl \
  --budget 30 --audit-fraction 0.2 --seed 20261116 \
  --purpose candidate_pool --output-dir /outputs/experiments/review_queue
```

30장 예산에서는 낮은 예상 IoU 순 24장과 나머지의 무작위 6장을 뽑는다.
정확히 같은 decoded RGB 픽셀은 하나로 묶고, 시간·위치 간격 필터는 입력 후보를 만들 때 먼저 적용한다.
`queue.jsonl`·`queue.csv`는 원본 참조, 점수, 선별 이유, 모델 이력을 기록한다. RGB·GT 복사나 학습 편입은 수행하지 않는다.
추론 manifest가 평가 자료인지 스스로 판별할 수 없으므로 호출자는 데이터 역할을 확인해야 한다.
평가 자료로 기능을 확인할 때는 `--purpose demonstration_only`를 쓰고 학습에 편입하지 않는다.
이 혼합 대기열은 운영 연결을 위한 기능이며, 기존에 고정한 순위 선별 실험의 방법·예산을 사후 대체하지 않는다.

### 검수한 장면만 라벨링했을 때의 모집단 추정

완료된 검수 목록의 프레임만 RGB·Semantic으로 가공하면, 실제 IoU 0.7 미만이 같은 주행의 적격 영상에 얼마나 있었는지 추정할 수 있다. `--dataset-dir`의 ID·RGB 해시·픽셀 해시·인지모델은 검수 목록과 일치해야 한다. 원래 전방 RGB를 압축했다면 실제로 검수한 인코딩으로 인지 출력과 IoU를 다시 계산한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.review_audit \
  --review-run /outputs/relative_queue --dataset-dir /outputs/reviewed_native_xy \
  --output /outputs/reports/review_population.json
```

창마다 우선 선별한 장면의 실제 저품질은 그대로 센다. 나머지 후보가 R장이고 그중 균일하게 감사한 A장에서 저품질 L장을 찾았다면, 나머지 전체의 저품질 추정치는 R × L / A다. 창별 값을 합쳐 전체 저품질 추정치와 검수에서 놓친 추정 장수를 구한다. 미정의 IoU는 별도로 센다. `lower_low`와 `upper_low`는 미검수 장면의 가능한 정답 전체를 포함하는 경계다. 미검수 장면이 남은 창에 감사 0장이면 모집단 점 추정은 `null`로 기록한다.

실제 주간 세 주행에서 각 49장 중 무작위 감사 10장만 사용한 모집단 추정치는 안개 111.5장, 눈 265.5장, 흐림 110.5장이었다. 전체 GT로 확인한 값은 80·148·58장이었다. 같은 영상과 검수 예산에서 감사 시드만 64번 바꾼 안개 주행의 추정치 10~90백분위는 감사 비율 20%에서 25~142장, 40%에서 44~111장이었다. 감사 비율을 늘리면 우선 선별에 쓸 장수도 줄어든다. 한 주행의 소량 감사만으로 정밀한 누락률을 주장하기 어렵다.

## 갱신은 비교한 뒤 판단한다

`quality_estimation.cycle_gate`는 완료된 f0/g0와 f1/g1 평가를 입력받는다.
각 run의 완료/파일 해시, 같은 행·RGB·GT·GT support, 품질 정답과 인지 IoU의 일치,
새 평가와 기존 조건 자료의 ID/픽셀 비중복을 확인한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.cycle_gate \
  --incumbent-new-perception /outputs/experiments/new_f0_perception \
  --candidate-new-perception /outputs/experiments/new_f1_perception \
  --incumbent-retention /outputs/experiments/retention_f0 \
  --candidate-retention /outputs/experiments/retention_f1 \
  --incumbent-quality-evaluation /outputs/experiments/new_g0_quality \
  --candidate-quality-evaluation /outputs/experiments/new_g1_quality \
  --incumbent-model-run /outputs/experiments/g0 \
  --candidate-model-run /outputs/experiments/g1 \
  --candidate-adaptation-run /outputs/experiments/f1_update \
  --policy /ml/config/cycle_acceptance_v1.json \
  --output-dir /outputs/reports/cycle_decision
```

각 평가 인자는 반복해서 여러 조건의 run을 지정할 수 있다. 양쪽에 같은 순서로 전달한다.
현재 정책은 프레임 IoU의 정의된 행 평균과 clipped MAE를 사용한다. 조건별 결과도 별도로 확인해야 한다.
보고서의 `new_condition_deltas`에는 날씨·시각별 평가 장수, 평균 실제 IoU와 두 버전의 품질 MAE가 함께 기록된다. `quality_mae_delta`가 양수이면 해당 조건에서 갱신한 품질 추정기의 절대 오차가 커졌다. 각 추정값은 짝지은 인지모델의 실제 IoU와 대조한다. 기존 성능 유지 자료는 조건별 인지 IoU를 기록한다. 전체 평균이 좋아져도 일부 조건은 나빠질 수 있다.
현재 사전 정책은 조건별 최대 손실을 따로 제한하지 않는다. 후속 채택 정책에서 조건별 제한을 쓸 때는
다음 평가를 보기 전에 정해야 한다. IoU가 전부 미정의인 조건은 정의된 행 0개와 null로 표시한다.
현재 재학습 CLI는 고정 f0에서 시작하는 한 번의 갱신을 지원한다. f1에서 다시 시작하는 f2 누적 학습은 아직 지원하지 않는다.
결과에는 각 지표의 변화, 통과 여부와 실패 항목을 남긴다. 새 조건 개선·기존 조건 유지·품질 MAE를 함께 확인하며,
통과 여부는 연구용 채택 적격 판단이다. 자동 배포·주행 제어 변경을 수행하지 않는다.
정책은 평가 전 고정하고 결과를 본 뒤 허용 손실을 넓히지 않는다.

## 검증 범위

기존 f0 동작, 명시적 f1 이력·불일치·변조 거부, legacy run checkpoint inventory,
개발 FPR cutoff·동점·float32 정답 경계, 서로 다른 정답/경보 임계값,
새 조건 개선만으로 기존 조건 하락을 무시하지 않는 채택 판정을 검사한다.
실제 f1 X/y 생성·g1 학습·모델 고정·새 RGB 단독 추론과 paired 평가로 통합 경로도 실행한다.
동일 지도·경로의 반복 주행은 다른 지도·날짜 일반화 검증을 대신하지 않는다.
