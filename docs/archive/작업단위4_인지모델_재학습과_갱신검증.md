# 작업 단위 4. 취약 장면을 이용한 인지모델 재학습과 갱신 검증

**11월 23일 적용 순서.** 기존 데이터로 RGB 점수·검수 정책을 고정하고 사후 GT 평가와 인지모델 재학습·짝 품질모델 검증을 마친 뒤 단위 2·3의 온라인 연결에 착수한다. [오프라인 단계와 팀원별 실험·웹페이지 분담](데이터플라이휠_통합실험계획_3인분담.md)

2026-11-23 팀 개발·실험 계획. **같은 라벨 예산에서 단위 3이 선별한 장면으로 차선 인식을 더 개선할 수 있는가? 그 개선을 기존 조건의 성능과 품질 추정기의 정확도를 유지하면서 얻을 수 있는가?** 기준 인지모델은 고정된 TwinLiteNet+ Medium v6(f0), 기준 품질모델은 그 출력으로 학습한 g0다. 각 후보 f1은 f0에서 독립적으로 시작한다.

**2026년 11월 23일 실행 결과.** 신규 라벨 58·116장과 240·1,200회 업데이트를 교차해 RF 선별·무작위 선별을 두 시드로 비교했다. 경로 밖 960장에서는 RF 58장으로 재학습해 최초 인지모델보다 IoU가 올랐지만, 같은 장수의 무작위 학습과 차이가 작았다. [신규·기존 조건의 짝비교](../experiments/환경_ROI와_품질추정_20261123.md)

## 2. 데이터를 먼저 고정한다

- **신규 학습 자료.** 단위 3에서 같은 후보 풀의 품질 선별·무작위 대조 목록을 함께 받는다. 각 행의 선택 이유·순위·선별 시드·부모 세션·RGB 해시를 보존하고 대응 Semantic, 촬영 시각, 기하, 라벨 정책을 확인한다. 저품질·정상·무작위 감사로 선택된 장면을 GT를 본 뒤 임의로 교체하지 않는다. 정책별 검수 장수와 실제 라벨 확보 수를 따로 기록한다. 유효 장수가 다르면 GT 점수와 무관한 사전 순서로 같은 유효 장수까지 자르고 원래 비용도 보고한다. 정책 간 선택 ID 겹침은 그대로 허용하고 수를 기록한다. [단위 3 인계](작업단위3_취약장면_선별과_온라인수집.md)
- **기존 학습 자료(replay).** f0 학습에 사용한 것으로 확인된 자료만 허용한다. 원래 256장 풀을 기준선으로 두고, 기존 조건의 날씨·시간·노선·차선 유형이 얼마나 포함됐는지 점검한다. 대표성 비교에서는 같은 풀 크기와 같은 배치 비율로 구성만 바꾼다. BO에서 배치 비율을 바꿀 때는 풀 구성을 고정한다.
- **개발·잠금 평가.** BO용 신규 조건 개발셋과 기존 조건 유지 개발셋을 따로 지정한다. 최종 판단용으로 그와 별개인 신규 조건·기존 조건의 세션을 각각 예약한다. 같은 자세·인접 경로·세션·픽셀 중복을 역할 간 검사한다. 평가에는 저품질과 정상 프레임을 모두 포함한다. 기존 1,997행은 이미 반복 진단에 썼고 f0 학습 노출도 완전히 배제할 수 없어 새 독립 평가로 세지 않는다. 각 분할에서 고정 f0 점수를 다시 계산한다.
- **품질모델용 자료.** g1의 학습·모델 선택·경보 보정 자료도 f1 신규 학습 및 잠금 평가와 분리한다. 단위 1의 환경 표현과 단위 2의 경보 정책을 썼다면 버전·학습 그룹을 대조한다. 원본·가중치·실행별 산출물은 실험 저장소에, 공유 프로토콜과 집계 결과는 팀 레포에 기록한다.

첫 재현은 기존 프로토콜의 AdamW, 학습률 1e−5, 배치 8(신규 4+replay 4), 240회, BatchNorm running 통계 고정, 마지막 step 평가다. 이때 신규 30장은 총 960회 추출되므로 1장당 평균 32회 노출된다. 같은 240회에 고유 자료를 60장으로 늘리면 평균 16회가 된다. 증가분은 같은 위치를 연속 촬영한 복사본보다 **서로 다른 구간·방향·객체 배치의 취약 환경**에서 확보한다. 30장이 60장의 부분집합인지, 추가분에서 조건·구간 분포도 달라졌는지 기록한다. ## 4. GP 기반 제약 베이지안 최적화

보관 목록 점검에서 기존 품질 선별 30장이 같은 풀의 품질 상위 60장에 포함됐고, 60장·240회 Quality/Random 각 두 시드의 완료 기록을 확인했다. 2×2 비교를 시작할 때 실제 목록·시드·평가 행·프로토콜이 맞는 기존 실행은 재사용한다. 같은 풀에서 선별 비율을 늘리면 경계 순위의 사례도 들어가므로 고유 장수와 사례 구성이 함께 변한다. 추가 촬영 효과를 주장할 때에는 새 구간에서 선별 규칙과 조건 구성을 맞춘 비교가 필요하다.

BO는 **다음 오프라인 재학습 설정**을 고른다. 한 번의 관측은 f0에서 후보 모델 하나를 학습해 두 개발셋을 평가한 결과다. 목적값은 신규 개발셋의 평균 차선 IoU 이득 `IoU(f1) − IoU(f0)`, 제약은 기존 개발셋의 평균 손실 `IoU(f0) − IoU(f1) ≤ 0.005`로 둔다. 단위 2 GP는 프레임 특징으로 IoU를 예측하고, 여기의 GP는 학습 설정으로 개발 성능을 예측한다. [제약 있는 BO의 방법 근거](https://proceedings.mlr.press/v32/gardner14.html)

| 탐색 변수 | 첫 탐색 범위 제안 | 통제 사항 |
|---|---|---|
| 학습률 | 1e−6~3e−5, 로그 척도 | AdamW와 weight decay 고정 |
| 배치 내 replay 수 | 배치 8에서 2·4·6장 | 신규 슬롯은 각각 6·4·2장. 업데이트 수는 240으로 고정하고 실제 신규 노출량을 기록 |
| 출력 유지 가중치 λ | 0·0.25·1·4 | λ=0은 제약 비활성, 양수이면 기존 자료의 유효 영역에서 f0 두 출력 head와의 KL 사용. 온도 1 고정 |

1. 개발 전용 목록 하나와 replay 풀을 고정한다. BO와 **무작위 하이퍼파라미터 탐색**에 동일 탐색 범위·학습 시드·평가 자료를 준다. 데이터 선별 대조군인 ‘무작위 30장’과 별개의 비교다. 탐색 설정이 특정 선별법에만 유리해지는지 확인하려면, 최종 선별법 비교에서는 두 방법에 동일하게 사전 고정한 설정을 적용하고 원래 설정의 결과도 함께 낸다.
2. 첫 제안은 방법당 **공통 시작 설정 4개를 포함한 총 20회 평가**다. 원래 설정을 시작점에 포함하고 공통 관측은 한 번 계산해 양쪽에 같이 제공한다. 짧은 재현 런으로 가용 GPU 시간을 확인한 뒤 최종 예산·공통 시드·초기 설정을 고정한다. 모델 학습, 교사 출력 준비, 개발 평가를 포함해 실제 GPU 시간도 비교한다.
3. BO는 목적과 제약을 각각 GP로 적합한다. 실행 가능한 설정에서 기대 개선량과 제약 충족 확률을 고려해 다음 점을 고른다. 초기 관측에 제약 충족점이 없으면 먼저 충족 가능성이 높은 점을 탐색한다. 정수 슬롯·이산 λ만 제안하고 같은 설정의 우발적 중복 평가는 제거한다. 실행마다 설정·시드·두 점수·비용과 실패 사유를 남긴다.
4. 시행 횟수 및 누적 GPU 시간에 따른 **제약 충족 후보 중 최고 신규 이득**, 충족 건수, 시드별 변동을 보고한다. 유망 설정은 사전 지정한 추가 학습 시드에서 반복한다. 비교군에도 같은 반복 예산을 준다. 충족 후보가 없으면 개발 결과를 그대로 보고하고 f0/g0를 유지한다. 제약을 완화해 결과를 소급 채택하지 않는다.

## 5. 갱신한 인지·품질 모델을 한 쌍으로 검증한다

**탐색 규모 산정.** 방법당 20회에 공통 시작 4회를 한 번만 계산하면 후속 시드 반복 전 최대 36개 고유 설정을 실행한다. 기존 240회 Quality/Random 두 시드씩에서 학습 루프 시작부터 체크포인트 저장 직후까지 기록된 시간은 약 61~63초였다. 데이터 로딩·교사 캐시 준비·별도 개발 평가는 이 수치에 포함되지 않는다. 첫 런에서 이 단계까지 측정한 후 양쪽에 같은 시행 예산을 확정한다. 학습에 불리한 설정이나 제약 미충족도 탐색 이력에 보존한다.

1. **인지 평가.** 개발 자료로 설정·시드 선택 규칙을 고정한다. 잠금 평가에서는 f0와 고정 f1을 동일한 RGB·GT 행에 적용한다. 프레임 차선 IoU 평균과 유효 행 수, 조건·경로별 변화, `IoU < 0.7`에서 정상으로 회복한 수 및 새로 저품질이 된 수를 함께 본다. 주행가능영역과 흰색·노란색·정지선 결과도 두 head 학습의 부작용 진단으로 남긴다. 여러 시드를 독립 주행 세션처럼 세지 않는다.
2. **품질 평가.** 잠금 자료를 열기 전에 선택한 f1을 고정하고 품질 학습·개발 프레임에서 f1의 출력 특징과 실제 IoU를 다시 계산한다. 그 X/y로 g1을 학습하고, 별도 보정 그룹에서 g1 경보 cutoff를 고정한다. 잠금 평가에서 g0의 MAE는 f0의 실제 IoU에, g1의 MAE는 f1의 실제 IoU에 대해 구한다. 경보 FPR·Recall도 조건별로 보고한다. [단위 2 품질 평가](작업단위2_인지품질_추정과_경보보정.md) · [버전 쌍 검증 절차](버전쌍_경보_갱신판정.md)
3. **채택 판단.** 새 조건 평균 차선 IoU 변화 **≥ 0**, 기존 조건 평균 차선 IoU 손실 **≤ 0.005**, 짝 품질 MAE 증가 **≤ 0.01**을 모두 통과해야 연구용 채택 적격이다. 예를 들어 기존 조건 f0 IoU가 0.8006인 평가에서는 f1이 최소 0.7956이어야 한다. 새 분할은 그 분할의 f0 점수로 계산한다. 이 기준은 평균에 적용되므로 야간 이득·주간 손실이 상쇄되면 조건별 표에 명시한다. 적격 여부와 실제 배포 결정은 별도 기록한다. [현재 채택 기준](../../config/cycle_acceptance_v1.json) · [판정 코드](../../src/quality_estimation/cycle_gate.py)

## 6. 개발 순서와 완료 기준

| 순서 | 개발·실험 산출물 | 인수 시 확인할 항목 |
|---|---|---|
| ① 기준선 재현 | f0·ReplayOnly·Random·기존 품질 선별의 설정 및 결과표, 목록·체크포인트 해시 | 과거 두 시드 평균과 첫 시드 결과를 구분하고, 업데이트·배치 노출 수·평가 행을 대조한다. 기존 CUDA 비결정 연산에 따른 차이는 기록한다. |
| ② 단위 3 연결 | 신규 선별 방법·감사 사유·선별 시드·학습 시드를 보존하는 학습 목록과 검증 | 현재 학습 CLI는 정해진 방법만 허용하고 Random의 선별 시드를 학습 시드에 묶는다. 신규 정책 식별과 두 시드 분리를 확장하고 기존 목록 호환성을 검사한다. ReplayOnly의 현재 공통·대체 슬롯은 4+4다. 2+6 등 새 비율의 짝 대조까지 비교할 때에는 공통 replay 추출을 일반화하고 검증한다. [학습기](../../src/quality_estimation/retrain_perception.py) · [목록 검사](../../src/quality_estimation/perception_data.py) |
| ③ 탐색과 가설 비교 | 설정별 BO·무작위 시행 이력, 데이터 장수×업데이트 비교표, 신규 이득·기존 손실 그래프 | 잠금 평가 접근 없이 개발 자료로 비교한다. 출력 유지 비활성은 기존 구현에서 해당 옵션을 생략한다. 완료·실패·재시작 이력을 보존한다. [출력 유지 구현](../../src/quality_estimation/distillation.py) |

첫 작업은 **기존 30장·240회 실험에서 신규 이득과 기존 손실을 한 표로 재현하고, 같은 역할표에 다음 학습 후보·replay·신규 및 기존 조건의 개발·잠금 평가 그룹을 배치하는 것**이다. 이후에야 추가 데이터 확보와 학습 설정 변경의 기여를 구분해 설명할 수 있다.

## 11월 23일 개발 자료에서 BO와 무작위 탐색 재현

팀 명령은 같은 초기 네 점에서 시작해 각 방식이 고른 시험의 결과만 읽는다. 신규 개발 IoU의 기대개선량과 기존 조건의 유지 제약을 만족할 확률을 곱한다. 관측된 설정 중 유지 제약을 만족한 점이 없으면 제약 충족 확률로 다음 설정을 고른다. 두 방식의 결과를 한 볼륨에 저장해도 각각 20회 예산을 적용한다. [고정 탐색 격자](../../config/adaptation_search_v1.json) · [다음 설정 계산](../../src/quality_estimation/search_adaptation.py) · [11월 23일 결과](../experiments/환경_ROI와_품질추정_20261123.md)

```bash
python -m quality_estimation.search_adaptation --runs "$SEARCH_RUNS" \

```

`SEARCH_RUNS`에 초기 모델의 두 평가 폴더 `f0_development`와 `f0_retention`을 둔다. 각각 `evaluate_perception`의 `meta_dev`와 유지 진단용 `diagnostic_only` 결과다. 명령이 `next_trial`을 반환하면 `settings` 순서대로 학습률·배치 내 replay 장수·출력 유지 손실 가중치를 적용한다. `name`에 해당하는 폴더에 `retrain_perception` 결과를, 같은 이름에 `_development`와 `_retention`을 붙인 폴더에 동일 두 명세로 평가한 결과를 둔다. 다시 실행하면 다음 설정 또는 완료된 탐색 이력이 나온다. 최대 허용 손실은 0.005다. 제약과 양의 신규 이득을 함께 만족하는 개발 설정이 없으면 `selected`는 비어 있다. 실제 갱신 판단에는 별도로 예약한 주행과 해당 인지모델에 맞춰 학습한 품질 추정기가 필요하다.
