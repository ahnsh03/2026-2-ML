## 기본 ROI와 특징 추출 실험

**11월 24일 후속 결정으로 기본 ROI를 `roi9-front-v1`로 정한다.** 상부를 y=169에서 높이로 반반 나눈 두 층·원거리·근거리 각 좌우와 보닛 하나다. 안승현·손재호는 이 마스크에서 특징을 공동 선정하고 장원태는 같은 특징표로 RF·GP와 군집·정책을 비교한다. 27일 첫 결합, 30일 오프라인 판정 일정은 유지한다. [비교 결과와 한계](../experiments/ROI_7영역_10영역_비교_20261124.md) · [일정과 역할](../guides/일정과_역할.md)

재호가 병행한 7영역 연구는 전체 화면의 상위 엔트로피·최대 구간 엔트로피·확률 마진을 더한 99열을 해당 실험의 기본값으로 선택했다. 이 결과와 7영역 전용 추출 경로는 [7영역 최종 기록](../experiments/ROI7_최종_피처_판정_20261124.md)과 [99열 명세](../baselines/roi7_final_20261124/selected_features.json)에 보존한다. 영역 공통인 세 불확실성 요약을 9영역에서도 대조했고 현재 27열에 포함했다. 두 연구의 모델·열 순서는 각각 보존한다.

### 고정한 영역과 비교 이력

| 구성 | 픽셀 배정과 용도 |
|---|---|
| **9영역 기본** | 상부 위·아래, 원거리·근거리 각 좌·우와 보닛. 가로선 y=169, 좌우선 x=640이다. [프로파일](../../config/roi9_front_v1/profile.json) |
| **7영역 이력** | 상부가 한 층인 이전 정의와 결과를 재현할 수 있다. [프로파일](../../config/roi7_front_v1/profile.json) |
| **전체 화면 통계 추가** | 보닛을 포함한 화면 전체에서도 같은 12개를 계산한다. 현재 시작 기준선은 `(9+1)×12=120`열이다. 전체 화면 통계는 별도의 집계 범위다. |
| **10영역 보존** | 세 띠를 좌·중앙·우로 나눈 마스크와 기존 실험은 재현용으로 유지한다. 기존 영역별 모델은 이 프로파일로 실행한다. [프로파일](../../config/roi10_front_v1/profile.json) |

고정 전방은 1280×720, 수평 화각 90°, 피치 2°이며 수평선은 y=338이다. 수평선과 보닛 사이를 1대2로 나눈다. 원·근거리는 영상의 띠를 뜻한다. 상부 위층은 0≤y<169, 아래층은 169≤y<338이며 세 프로파일의 원·근거리와 보닛 경계는 픽셀 단위로 같다. 공간 구획이므로 건물·하늘의 실제 의미론적 마스크를 보장하지 않는다. 7영역 경계는 10영역의 중앙 칸 내부를 지나므로 10영역 통계만으로 7영역을 정확히 복원할 수 없다.

현재 9영역 결정은 상부의 조명·색과 지평선 주변 구조물을 나누어 실험하자는 프로젝트 결정이다. 이전 7영역 선택은 과거 비교 근거로 보존한다. 일부 주행과 같은 특징을 사용한 GP에서는 10영역이 더 좋았다. 선택에 사용한 도로는 개발·진단 자료로 남기고 최종 미사용 도로를 별도로 확보한다. RF·GP의 최종 채택과 환경별 검수 기준은 후속 판정이다.

### 이전 7영역 연구의 99열 재현

동일 프레임의 전방 RGB, 4×180×320 uint8 인지 맵, 고정 `f0`의 4×384×640 float32 마킹 softmax를 사용한다. 입력의 위아래 패딩 12픽셀씩은 추출기가 제외한다. 출력 JSON의 열 순서를 [확정 목록](../baselines/roi7_final_20261124/selected_features.json)과 대조할 수 있다.

```bash
PYTHONPATH=src python3 -m quality_estimation.spatial_features \
  --features roi7-iou99 --roi-profile config/roi7_front_v1 --image front.png --head-maps heads.npy \
  --marking-probability marking_probability.npy --output roi7_iou99.json
```

### 피처 선정 당시의 후보와 담당

| 담당 | 비교할 후보 | 참고와 측정 목적 |
|---|---|---|
| **재호** | 이번 RGB 5개와 색상·채도·대비·선명도의 분포, 다크 채널 | Roser·Cheng·Lu의 환경 단서. 다른 도로에서도 환경을 안정적으로 구분하는지 본다. |
| **승현** | 예측 차선 확률 마진, 성분 크기·연결성분, 경계·내부 엔트로피, 필요 시 raw logit energy | MetaSeg·SEE의 품질 단서. 같은 환경 내 정상·저하를 구분하는지 본다. |
| **공동** | 보닛–노면 밝기차, 원–근거리 대비차, 좌우 비대칭과 영역 통합 | 남은 독립 특징에 관계를 더하고, 가로 분할을 합쳐도 선별 능력이 유지되는지 본다. |

논문별 원래 과제·정의와 재현 범위는 [논문 목록](../baselines/참고논문_베이스라인.md), [적용 분석 원문](../archive/수집데이터_재가공과_논문활용_20261123.md)에 있다. RGB 환경군 입력과 품질 회귀 입력은 각각 선정한다. 필터 잔차에는 재질·반사·압축 효과도 섞인다.

1. **9영역에서 후보를 일괄 계산한다.** 120열 기준선을 남기고 모든 ROI에 같은 후보를 계산한다. RGB만·출력만·결합 입력과 후보군 하나씩 추가를 같은 데이터·튜닝 예산의 RF·GP로 비교한다.
2. **영역별 특징을 줄인다.** 상부·보닛의 출력 4개 → 차선 면적 1개 → 0개를 비교하고 도로의 RGB·출력도 묶음별 제거한다. 남은 열만 연결하므로 차원이 줄어든다. RF 중요도와 다시 학습한 제거 실험을 함께 본다. 최종 추출기에서 불필요한 통계 계산도 제거한 뒤 비용을 다시 잰다.
3. **남은 특징에 관계를 추가한다.** 보닛–노면·원–근거리·좌우 차이를 하나씩 더한다. 직접 입력에서 빠진 열도 관계 계산 재료로 남길 수 있다. 관계의 효과와 영역 통합의 효과는 각각 대조한다.
4. **좌우를 통합하는 후보를 비교한다.** 9영역의 좌·우를 띠별로 합쳐 상부 위·아래·원거리·근거리·보닛 5영역으로 집계하거나 일부 띠만 합친다. 전체 화면 옵션은 동일하게 둔다. 파생 마스크·열 이름·버전을 기록하고 고정 9영역 기준선과 비교한다. 기존 10영역 좌·중앙·우 통합은 과거 결과 해석이 필요할 때 보조 대조로 둔다.
5. 개발 도로에서 최종 열을 고정하고 별도 보정 자료에서 GP 불확실성·환경군·검수 정책을 조정한다. 미사용 도로 GT 평가와 동일 예산 재학습까지 오프라인으로 마친 뒤 온라인에 연결한다.

영역을 합칠 때 원본 RGB·예측 맵과 파생 마스크로 다시 집계한다. 평균은 픽셀 수 가중, 분산은 모멘트 결합이 가능하지만 분위수·중앙값·선택 픽셀 통계는 기존 값의 평균으로 대체할 수 없다. 관계 추가·열 제거·영역 통합을 한 번에 바꾸면 원인을 구분하기 어려우므로 각각의 기준선 비교표를 남긴다.

한 프레임은 한 행이고 열은 `영역.특징`이다. 예측 픽셀 위 통계는 예측이 없을 때 대체값·면적·유효 여부를 함께 기록한다. 필터·경계는 전체 영상에서 계산한 뒤 집계해 ROI 테두리가 특징이 되는 것을 막는다. 회귀 정답과 최종 출력은 **전체 차선 IoU 하나**이며 ROI별 IoU를 온라인 목표로 추가하지 않는다.

### 11월 24일 특징 선정 인계

품질 회귀는 **RGB 10열+인지 출력 요약 14열+원본 확률 요약 3열의 공통 27열**을 RF·GP에 제공한다. 날씨 분류는 80개 히스토그램 성분, 지정 시각 분류는 160개 성분, e-means 문맥은 상부 위층 좌우·보닛 RGB 54열을 사용한다. [실험 결과와 선정 근거](../experiments/ROI_9영역_특징선정_20261124.md), [순서 있는 열·모델 해시](../../config/region_feature_recipe_v2.json)가 현재 인계 기준이다.

공통 120열은 후보 비교의 시작점이며, 기본 27열은 아래 별도 추출 경로로 실행한다. 후보 통계와 모델 입력은 이름·순서·프로파일 해시를 함께 대조한다. RGB 후보는 기존 8개+분위수·채도 5개+색차·채도 IQR·채도 가중 원형 hue 두 성분·경계 밀도 5개로 18개다. 출력 후보는 기존 4개와 차선 가중 엔트로피·확률·차선/주행가능 불일치·예측 지원 여부의 총 8개다.

```bash
# FROZEN_MODEL_ROOT는 공유받은 export/selected_v2/models 디렉토리다.
PYTHONPATH=src python3 -m quality_estimation.region_inference \
  --image front.png --head-maps heads.npy \
  --marking-probability marking_probability.npy \
  --recipe config/region_feature_recipe_v2.json --task quality_gp \
  --model "$FROZEN_MODEL_ROOT/quality_gp.joblib" --output quality.json

# 환경 특징과 태그는 RGB만으로 계산한다.
PYTHONPATH=src python3 -m quality_estimation.region_inference \
  --image front.png --recipe config/region_feature_recipe_v2.json \
  --task weather --model "$FROZEN_MODEL_ROOT/weather.joblib" --output weather.json
```

`--task quality_rf`, `hour`, `environment`도 지원한다. 환경 군집 아티팩트는 `environment.npz`다. 모델 파일을 생략하면 선정한 특징값을 JSON으로 저장한다. 입력 RGB는 원래 1280×720이며, 품질 입력은 고정 v6와 기존 전처리에서 만든 4×180×320 uint8 요약 맵과 같은 프레임의 4×384×640 float32 마킹 softmax다. 원본 확률은 추출기 안에서 패딩 12행씩을 제외한다. 원본 확률 통계는 엔트로피 상위 10% 평균·최대 32×32 구간 평균·예측 차선 확률 마진이다. 전체 화면 통계이므로 상부·보닛의 출력도 포함한다. CLI는 아티팩트·프로파일·입력 차원과 출력 파일 충돌을 검사하고 입력 해시를 기록한다. NPY의 생성 버전은 데이터셋의 검증 영수증과 연결한다. 24열 v1과 27열 v2의 모델·명세를 함께 묶어 사용한다. 추가 독립 도로에서 정상 장면 과소추정과 GP 구간의 과소포함이 남아 있어 27열은 27일 결합 기준선으로 인계한다.

후보 표를 새로 만들 때의 실행 경로는 다음과 같다.

```bash
PYTHONPATH=src python3 scripts/extract_region_candidates.py \
  --source-dir "$RECORDED_SOURCE" --reference-packs "$VERIFIED_REFERENCE_PACKS" \
  --media-root "$RGB_ROOT" --output-dir "$CANDIDATE_PACKS" \
  --uncertainty-packs "$RAW_UNCERTAINTY_PACKS"
```

| 입력 | 구조 |
|---|---|
| `RECORDED_SOURCE/protocols/<key>.jsonl` | `sample_id`, `image`, `expected_sha256.rgb`, `pixel_sha256`를 가진 RGB 목록 |
| `RECORDED_SOURCE/maps/<key>.npz` | 같은 순서의 `ids`, `maps`와 `checkpoint_sha` |
| `VERIFIED_REFERENCE_PACKS/<key>.npz` | 같은 순서의 `y`, `ids`, `pixel_sha256`, `group`, `site`, `cohort`, `weather`, `hour`, `xy` |
| `RAW_UNCERTAINTY_PACKS/<key>.npz` | 같은 `ids`, float32 `values` N×3, `ordered_features`, `checkpoint_sha`와 NPZ SHA-256 JSON 영수증 |
| reference JSON 영수증 | NPZ·manifest·출력 맵의 SHA-256 |

reference는 정답과 역할 메타데이터를 연결하는 자료다. 특징은 RGB와 인지 맵에서 9영역으로 다시 계산한다. 출력은 `rgb` 180열·`output` 80열·`relations` 88열·`histograms` 500열, 선택 옵션의 원본 확률 요약 3열과 별도 정답·메타데이터다. 원본 확률 요약은 같은 전처리·가중치·프레임에서 계산하고 값과 ID·열 순서·가중치·영수증 해시를 대조한다. 옵션을 생략하면 원래 848열 후보 캐시를 재현한다. 스키마와 원본·모델·팩의 해시를 보존한다.

비교는 `compare_region_candidates.py`, 내부 순위 기반 축소는 `reduce_region_candidates.py`와 `reduce_region_environments.py`, 축소 후 관계 비교는 `compare_compact_relations.py`를 사용한다. 환경 군집은 `compare_region_environments.py`, 고정 후보 평가는 `evaluate_region_candidates.py`다. 각 명령의 `--help`와 결과 문서의 데이터 역할·설정 예산을 함께 따른다. 이후 보정·검수 정책의 인계는 [환경 군집과 검수 정책](../guides/환경군집과_검수정책.md)에 연결한다. 실제 설정과 27열 재적합 경로는 [프로토콜 묶음](../baselines/roi9_features_20261124/protocols/README.md)에 있다.

## 품질모델 학습과 GP 불확실성

원태가 GP·튜닝·불확실성 평가를 맡고 승현이 RF 기준선을 연결한다. 27일에는 첫 결합용 점수표를, 30일에는 최종 입력으로 재학습·보정한 모델과 비교표를 전달한다. [일정과 역할](../guides/일정과_역할.md)

11월 24일의 현재 인계 입력은 **RF·GP 공통 27열**이다. [9영역 특징 선정](../experiments/ROI_9영역_특징선정_20261124.md)과 [고정 열·파라미터·해시](../../config/region_feature_recipe_v2.json)를 사용한다. GP는 Matern 1.5·스칼라 길이 배수 2.8·정규화 타깃 공간의 관측 잡음 분산 0.05로 적합했다. 반환 표준편차는 관측 잡음을 포함한 IoU 단위다. 첫 8위치 480장의 관측 MAE는 RF 0.0587·GP 0.0596, 추가 독립 3링크 144장은 RF 0.1628·GP 0.1703이었다. 도로 구조가 달라지면 정상 장면의 과소추정이 남는다.

27열 GP의 보정 전 명목 90% 구간 포함률은 첫 480장 81.67%, 추가 144장 44.44%다. 평균순 검수와 σ 활용을 별도로 대조하고 별도 정상 장면·보정 도로로 적용 범위를 확인한다. 1차 24열·잡음 분산 0.15 모델은 [v1 명세](../../config/region_feature_recipe_v1.json)에 보존한다. 현재 27열 단일 이미지 추출·예측은 [실행 가이드](../guides/ROI와_특징추출.md#11월-24일-특징-선정-인계)를 따른다.

### 입력과 기존 구현

입력은 같은 프레임의 버전 있는 특징 X와 전체 차선 IoU y다. 학습·개발·보정·평가 그룹, ROI·인지모델·열 순서를 확인한다. RF·GP는 같은 입력 열과 같은 정답을 사용한다.

| 구현 | 현재 기능과 이번 개발의 연결 |
|---|---|
| [모델 학습 CLI](../../src/quality_estimation/train_models.py) | X56 실행 스키마와 데이터 로더를 사용한다. 기존 OLS·Ridge·RF 및 선택적인 GP를 재현한다. |
| [GP 클래스](../../src/quality_estimation/gaussian_process.py) | 유한한 X와 0~1의 y로 학습하고 평균·표준편차를 반환한다. 정확 GP의 현재 행 상한은 2,500이다. |
| [10영역 모델](../../src/quality_estimation/roi10_quality.py) | 영역별 정밀도·누락 면적을 RF로 추정해 합산한다. 과거 성적표의 영역별 모델이다. |
| [공간 특징 직접 회귀](../../scripts/compare_roi_features.py) | 7·10영역 세 특징 구성과 RF·GP를 같은 학습 그룹 CV·개발 자료로 비교한다. 이 경로는 앞선 ROI 비교를 재현한다. 현재 기본 ROI는 9영역이며 선정한 열과 새 실행 방법은 [ROI와 특징 추출](../guides/ROI와_특징추출.md)을 따른다. [ROI 선택 결과](../experiments/ROI_7영역_10영역_비교_20261124.md) |

앞선 ROI 비교의 96열은 `(7영역+전체 화면)×12`의 새 스키마다. 과거 `X56+output10`의 96열과는 이름·순서·프로파일이 다르다. 열 수가 같아도 모델 번들에서 이 식별자가 모두 일치해야 재사용한다.

기존 X56의 스키마 검사는 [dataset_io](../../src/quality_estimation/dataset_io.py)에 있다. 새 특징을 56열로 가장해 기존 로더에 전달하면 스키마가 달라진다. 새 공간 특징의 연구용 학습·저장 경로가 추가됐다. 배포용 특징 스키마·모델 번들과 기존 스트림 추론 연결은 승현과 함께 구현하고 버전의 일치를 검증한다.

새 공간 특징 비교는 해시 영수증이 있는 연구 팩을 준비한 뒤 아래와 같이 재현한다. 팩은 같은 프레임 ID의 `x7_base12`, `x7_base12_global`, `x7_robust17`과 10영역 대응 열, `y`, `group`, `pixel_sha256` 등을 담는다. 스키마 JSON의 열 순서를 함께 전달한다. 원본 팩·모델은 실험 볼륨에서 인계한다.

출력은 후보별 학습 그룹 교차검증, 개발 MAE, joblib 모델과 `frozen_models.json`이다. 출력 디렉토리는 새 경로를 쓴다. 위 프로토콜은 ROI 비교 당시의 세 구성·12개 설정 예산을 보존한다. 이후 팀 실험에서는 9영역에서 선정한 같은 열로 RF·GP를 대조하며, 기존 진단 도로를 최종 미사용 평가 자료로 재지정하지 않는다.

### RF·GP 비교와 튜닝

1. 학습 자료에서만 상수 열 제거·표준화를 적합한다. X56 재현과 새 ROI 결과의 데이터·특징 버전을 표에 표시한다.
2. 선택된 같은 열에서 RF와 GP를 학습한다. GP의 행 예산 때문에 부분집합이 필요하면 위치·환경을 고려해 먼저 고정하고, 같은 부분집합의 RF 결과도 함께 낸다. 별도 전체 학습분 RF는 표본 수를 표시한다.
3. 같은 도로 분할·시드·평가 횟수에서 GP 길이척도와 잡음, 이후 RGB/출력/관계별 가중 커널을 튜닝한다. 가중 커널은 확장 구현 과제다. 개발 도로 MAE와 검수 성과로 선택한다.
4. BO의 입력은 튜닝 설정, 목표는 해당 설정의 그룹 교차검증 MAE다. 같은 초기 관측·평가 횟수의 무작위와 비교한다. 개별 프레임 IoU를 예측하는 GP와 BO 내부의 대리모델은 각각 기록한다.

현재 GP는 Matérn 3/2와 WhiteKernel을 사용하고 내부 optimizer는 꺼져 있다. 길이척도는 표준화 후 유효 차원 수에 맞춰 조절하며 잡음 분산은 정규화된 y 공간의 값이다. 같은 도로 평가 결과에서 모델을 다시 고르면 해당 도로를 개발 자료로 표시한다. [기존 커널·BO 결과](../experiments/전방_10영역_특징과_품질추정_20261123.md#5-군집gp베이지안-최적화의-사용처)

### 불확실성 평가

- 점 예측은 원래 IoU 단위 평균과 [0,1] 제한값을 저장하고 MAE·편향·조건별 오차를 낸다. GP 표준편차는 관측 잡음을 포함한다.
- 명목 90% 구간은 원시 평균 ± 1.645σ로 시작한다. 별도 보정 도로에서 조정하고 미사용 도로에서는 실제 포함률과 평균 폭을 함께 측정한다. 분포 경계에서 구간을 잘랐다면 원시 구간과 표시 구간을 명시한다.
- σ가 큰 장면에 실제 오차가 모이는지, 야간에서 좁은 구간으로 틀리는지 본다. 같은 GP 평균 순위에 σ를 더했을 때 새로 찾거나 놓친 장면을 비교한다.
- 예측 저품질 확률을 쓸 때는 분포·보정 방법을 기록하고 실제 저품질 비율과 대조한다. 실패 확률의 해석은 이 검증 결과와 함께 제시한다.

기존 273장 도로에서 한 GP의 90% 구간 포함률은 98.2%였지만 평균 폭은 0.644였고, σ와 절대오차의 순위상관은 −0.251이었다. 이 모델의 σ 단독 검수는 평균순보다 적은 실패를 찾았다. 새로운 입력에서는 같은 검증을 다시 한다. [불확실성 실측](../experiments/오프라인_검수와_동일예산_재학습_20261123.md#gp의-평균-예측과-불확실성-순위)

추가 수집에서는 차선 GT가 매우 적은 장면을 포함해 GP의 전이 오차를 따로 확인한다. 같은 특징의 ROI 대조와 개발 자료에서 각각 선정한 특징 구성의 대조를 구분한다. 전자는 영역 효과, 후자는 전체 설정의 전이 성능을 보여준다. GT 차선 면적은 사후 진단에만 사용하고 RGB 단독 모델 입력에는 넣지 않는다. [GT 픽셀 수와 전이 결과](../experiments/ROI_7영역_10영역_비교_20261124.md)

### 인계와 완료 기준

프레임 ID별 원시 평균·예상 IoU·σ, 모델·특징·분할 해시, 개발 비교표, 예측구간 보정값과 조건별 포함률·폭, 추출과 추론 p50/p95 시간을 넘긴다. 유효·미정의 y 수, 표본 수와 독립 위치 수도 적는다. 재로딩한 같은 표의 예측이 일치하고 [검수 정책](../guides/환경군집과_검수정책.md)이 같은 점수표를 읽으면 첫 결합이 가능하다.

## 데이터 등록과 특징·정답 생성

승현이 원본·역할 목록을 준비하고 재호·원태가 같은 ID의 특징표를 사용한다. 11월 24일에는 ROI 비교용 입력을, 27일에는 첫 결합용 회차를 전달한다. [일정과 인계](../guides/일정과_역할.md)

### 기존 구현과 추가 개발

| 경로 | 현재 가능한 것 | 이번 작업에서 이어갈 것 |
|---|---|---|
| `capture_sessions.py` | 기존 4채널 원장을 해시 검증해 등록하고 RGB 단독·paired 입력을 내보낸다. | 역할과 물리 세션·도로를 확정하고 팀원이 읽을 입력 목록을 만든다. |

새 특징표에는 프레임 ID, 입력 해시, 인지모델·ROI·추출기 버전, 순서 있는 특징명과 값이 필요하다. 실제 IoU와 평가용 날씨·시각·위치는 별도 정답·메타데이터로 연결한다. [입출력 규약과 기존 구현](../contracts/품질추정_입출력규약.md)

### 원본 등록과 내보내기

다음 변수는 자신의 실험 볼륨의 원본·목록·새 출력 경로로 설정한다. `SESSION_CONTEXT`에는 물리 세션, 도로, 학습/개발/보정/평가 역할, 카메라 설정과 관측 출처를 기록한다.

```bash
python3 scripts/capture_sessions.py register-front \
  --manifest "$RAW_MANIFEST" --media-root "$RAW_ROOT" --session-id "$SESSION_ID" \
  --context "$SESSION_CONTEXT" --population all_captured --output "$CAPTURE_STORE/$SESSION_ID"
python3 scripts/capture_sessions.py verify "$CAPTURE_STORE/$SESSION_ID" --media-root "$RAW_ROOT"
python3 scripts/capture_sessions.py export "$CAPTURE_STORE/$SESSION_ID" \
  --media-root "$RAW_ROOT" --output "$EXPORT_DIR"
```

출력의 `rgb.jsonl`은 점수화 입력, `paired.jsonl`은 사후 정답 입력이다. RGB만 수신한 세션은 paired가 0이며 실제 IoU는 미정의다. 원본 미디어는 `RAW_ROOT`에 있고 후속 `--data-root`도 그 루트를 사용한다. 누락 채널·잘린 원장·선별본의 모집단 범위는 그대로 기록한다. [세션 기록 형식과 복원 절차 원문](../archive/수집세션_등록과_오프라인_재가공.md)

### 특징과 정답

- 원해상도 RGB와 같은 버전의 인지 출력에서 특징을 계산한다. 흰색·노란색 차선은 4클래스 argmax 결과의 합집합으로 정의하고 모델 letterbox padding을 제거한다.
- 정답은 `TP / (TP + FP + FN)`으로 계산한 프레임 전체 IoU 하나다. 합집합이 빈 장면은 미정의로 기록한다. 회귀 적합·MAE에는 정의된 정답을 쓰고, 검수 후보와 예산에는 미정의 장면도 남겨 선택 수를 보고한다.
- ROI별 TP/FP/FN은 누락·오검출 사례를 해석하고 전체 IoU를 대조하는 데 사용한다. 이번 직접 회귀의 목표는 전체 IoU다.
- 인지모델을 갱신하면 같은 RGB에서도 출력 특징과 실제 IoU를 다시 계산한다. 인지모델·품질모델의 짝과 학습 이력을 함께 기록한다.

기존 X56을 재현할 때는 아래 명령을 사용한다. `NATIVE_MANIFEST`에는 RGB·Semantic 짝과 출처 역할이 있어야 한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.build_native_dataset \
  --manifest "$NATIVE_MANIFEST" --data-root /data \
  --output-dir /outputs/datasets/native_front --audit-per-run 2
```

기존 10영역 연구 팩은 다음 명령으로 만들 수 있다. `--paired`는 학습·사후 정답용 입력에서 사용한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.roi10_study build \
  --manifest /outputs/manifests/train.jsonl --data-root /data \
  --paired --purpose training --output /outputs/roi10/train
```

새 [공간 추출기](../../src/quality_estimation/spatial_features.py)는 7·9·10영역을 같은 RGB·출력 맵에서 재집계한다. 현재 9영역 공통 대조는 전체 화면 포함 120열이며, 품질 입력은 RGB 10열·출력 요약 14열·원본 softmax 통계 3열의 27열이다. 환경 쪽은 RGB만으로 날씨 80·시각 160·군집 54열을 각각 쓴다. [현재 명세](../../config/region_feature_recipe_v2.json)를 입력·모델·인지 버전과 함께 인계한다. [현재 열과 사용법](../guides/ROI와_특징추출.md) · [비교 결과](../experiments/ROI_9영역_특징선정_20261124.md)

### 분할과 재가공

학습·개발·보정·미사용 평가 도로는 모델과 정책을 선택하기 전에 정한다. 물리 세션, 인접 위치·프레임, 디코딩 RGB 중복과 인지모델의 과거 노출을 확인한다. 이미 본 273장 도로는 진단 자료다. 미사용 평가 GT는 예측·선택 목록을 고정한 뒤 연결한다.

ROI·분위수·연결성분을 바꿀 수 있도록 원본 RGB, 픽셀 예측을 재생성할 체크포인트·코드·전처리를 보관한다. 원해상도 연결성분이나 logit energy가 필요하면 같은 RGB를 재추론한다. 축소 요약 맵에서 사라진 경계나 raw logit은 원래 의미로 복원할 수 없다. [원본 복원 범위와 누락 1,802장 기록](../archive/수집데이터_재가공과_논문활용_20261123.md)

## 환경 군집과 동일 예산 검수

원태가 RGB 기반 환경 군집과 검수 기준을 구현한다. 27일에는 같은 개발 회차의 선택 표를 만들고, 30일에는 별도 보정 자료로 최종 정책을 고정한다. 승현은 모델·입력을 제공하고 재호는 실제 장면과 분모를 확인한다. [일정과 역할](../guides/일정과_역할.md)

### 입력과 출발점

입력은 프레임 ID·시간 순서·예상 IoU·모델 버전, GP 사용 시 σ, RGB 환경 특징이다. 실제 IoU와 시뮬레이터 날씨·시각은 사후 검증용으로 연결한다. 온라인 추출값과 실제 설정 라벨의 출처를 구별한다.

GPU 없이 먼저 시작할 때는 [849행 점수표](../baselines/offline_review_20261123/scores.csv)와 [사후 GT](../baselines/offline_review_20261123/delayed_gt.csv)를 `id`로 연결한다. `candidate` 576장과 `road` 273장은 각각 별도 모집단으로 계산한다. `roi10`은 과거 영역별 합산 모델, `gp_raw_mean`과 `gp_std`는 기존 GP의 값이다. 두 모델은 학습 조건도 다르므로 이 표는 기존 검수 재생에 사용한다. 새 RF·GP의 주 비교에는 같은 특징·학습분으로 만든 점수표를 사용한다. [전체 열 정의](../archive/전방_10영역_실험_재현.md#팀원이-cpu로-재생할-표)

### 11월 24일 입력 인계

현재 9영역의 품질 추정 입력은 RF·GP 공통 27열이다. 환경 입력은 날씨 분류 80개·지정 시각 분류 160개 히스토그램 성분, e-means RGB54로 나뉜다. [선정 결과](../experiments/ROI_9영역_특징선정_20261124.md)와 [열·아티팩트 해시](../../config/region_feature_recipe_v2.json)를 사용한다. RGB54는 상부 위층 좌우와 보닛에서 18개씩 추출한다. 센터 적합은 공식 e-means, 실행은 저장된 표준화와 최근접 중심 배정이다. K=16은 현재 기본 후보이고 170열 문맥 히스토그램도 정책 비교의 대조군으로 보존한다. RGB54의 확인 범위는 조명·날씨 문맥이다. 좁은 도로·급커브 등 주행상황 태그의 정의와 검증은 별도 항목으로 다룬다.

새 위치 480장의 실제 IoU≥0.7 정상 279장 중 공통 경보 기준에서 RF 34장·GP 48장의 오경보가 있었다. 추가 독립 3링크 144장에서는 정상 60장 중 RF 49장·GP 48장이 오경보였다. 날씨 분류가 약 96.5%여도 품질 회귀는 정상 장면을 과소추정했다. GP의 보정 전 90% 구간 포함률도 이 자료에서 44.44%였다. 원태는 이 예측과 군집을 별도 보정 자료의 정상·저품질 사례에 연결해 공통/환경 기준을 비교한다. 미학습 시각 15·17시는 시각 분류의 별도 범위로 기록하고 품질 회귀·날씨 평가에는 포함한다.

### e-means 환경 표현

1. 학습 도로 RGB의 색차·다크 채널·국소 대비에서 시작하고 재호의 밝기·색상·대비 분포를 추가한다. 품질 회귀용 열과 환경 군집용 RGB 열을 각각 선정한다.
2. 상수 열 제거·표준화·중심 적합은 학습 도로에서만 수행한다. 현재 RGB54에서 K=8·16·32와 3시드 비교를 수행했고 K=16을 첫 결합 후보로 인계했다. K=2·4·8은 초기 계획의 탐색 범위였다. 유망한 표현부터 비교하고 같은 표현·K·초기조건에서 KMeans 대조를 남긴다.
3. 다른 장소의 같은 조명이 함께 묶이는지, 같은 장소의 다른 조건이 구분되는지, 군집이 한곳에 몰리는지 본다. 시드 간 ARI, 군집별 프레임·장소 수, 일정 조건 주행 중 배정 전환도 기록한다.
4. 군집은 환경 태그와 검수 예산 배분·보정에 적용한다. 정상 위치가 적거나 배정 신뢰가 낮은 군집에는 공통 보정값을 적용한다. 중심 거리와 관측 조건은 서로 다른 열로 남긴다.

기존 10영역 학습 팩에서는 다음 명령으로 공식 e-means 중심을 만들 수 있다. 학습에는 Faiss의 e-means 구현이 필요하다. 고정 중심의 배정은 저장된 평균·표준편차·중심으로 실행한다.

```bash
PYTHONPATH=src python3 -m quality_estimation.roi10_study fit-centers \
  --data "$TRAIN_PACK" --method emeans --clusters 8 --seed 0 \
  --output "$ENVIRONMENT_RUN"
```

현재 명령은 고정 10영역의 haze30 표현을 사용한다. 현재 9영역 RGB54 군집은 `compare_region_environments.py`로 적합했고 `region_inference --task environment`로 고정 중심을 배정한다. [실행 가이드](../guides/ROI와_특징추출.md#11월-24일-특징-선정-인계)를 사용한다. 원태는 이 아티팩트와 27열 품질 점수를 같은 프레임 ID의 검수 정책에 연결한다. 환경군의 입력·중심·표준화와 품질모델의 열 목록을 각각 기록한다. [기존 군집 코드](../../src/quality_estimation/environment_clusters.py) · [공간·시드 평가 원문](../archive/작업단위1_주행환경_특징과_군집화.md)

| GP 불확실성 활용 | 동일 GP의 평균순을 기준으로, 불확실성에 배분한 장면 또는 보정한 저품질 확률의 이득을 본다. |
| 환경 내 상대 품질 | 비슷한 환경에서 통상 얻는 품질보다 낮은 장면을 우선한다. |
| 혼합 | 절대 품질·환경 내 상대 품질과 무작위 점검에 예산을 배분한다. |

실제 전체 IoU < 0.7은 공통 비교 분모다. 환경별 예상 IoU 경보값은 별도 보정 자료에서 고른다. 환경 내 이례적인 저하·근거리 누락도 보조 집계한다. 모델·정책에 같은 모집단, 시간 창, 중복 규칙·동점·무작위 시드를 적용하고 GT를 보기 전에 선택 ID를 고정한다. 미정의 정답을 고른 장면도 검수 예산에 포함한다.

기존 RGB 단독 추론에서 검수 목록을 재생하는 명령은 다음과 같다. 역할이 평가·시연인 입력은 `demonstration_only`로 구분한다.

```bash
PYTHONPATH=src python3 -m quality_estimation.review_queue \
  --inference-run "$RGB_INFERENCE" --rgb-manifest "$RGB_MANIFEST" \
  --window-frames 64 --budget-percent 10 --audit-fraction 0.2 --seed 20261116 \
  --purpose demonstration_only --output-dir "$QUEUE_RUN"
```

현재 `quality_uncertainty`는 무작위 감사 몫을 확보한 뒤 우선 선별 몫의 3/4를 낮은 GP 평균, 나머지를 큰 σ로 채운다. `environment_relative`는 군집 학습 IoU 하위 20% 기준과 현재 예상값의 차이를 쓴다. 정책 이름·정렬·기존 보정 실행은 [재생 원문](../archive/회귀학습_선별평가.md), [경보 원문](../archive/버전쌍_경보_갱신판정.md)에 있다. 새 혼합 비율과 보정한 실패 확률은 후속 비교 항목이다.

군집별 경보의 기존 구현은 정상 20장·정상 자세 그룹 2개 이상을 요구하고 부족하면 전체 cutoff를 쓴다. 공통·군집 기준을 결합한 정상 오경보 예산도 검사한다. 원태는 다른 도로에서 실제 오경보·누락을 함께 보고 이 기준의 적용 범위를 기록한다. 기존 273장에서는 공통 보정의 오경보/누락이 1/5, 조명 보정은 8/1이었다. [기존 실측](../experiments/오프라인_검수와_동일예산_재학습_20261123.md#야간-오경보를-평가할-수-있는-범위)

기존 주행의 64프레임 창에서는 27열 GP·RF가 648개 슬롯에서 각각 565·561개의 IoU<0.7 장면을 찾았고 단독 마진은 552개였다. 추가 3링크의 동일 조건 소그룹에서는 학습모델이 마진보다 적게 찾았다. 고유 위치·창·올림된 실제 예산을 함께 보고, 전체 풀만 섞은 결과로 정책을 채택하지 않는다. [창별 비교](../baselines/roi9_features_20261124/window_review.json)

### BO와 결과표

저장 점수표의 소수 임계값은 직접 비교한다. 절대/상대 예산 비율과 군집 보정 강도 등 여러 변수를 함께 고를 때 BO를 적용하고 동일 초기 관측·횟수의 무작위 탐색과 대조한다. 개발 자료 안에서 정책 보정과 검증 그룹을 나눈다. 목표는 고정 예산의 실패 발견·고유 위치, 함께 확인할 제약은 정상 오경보와 근거리 누락이다. 설정과 허용 손실은 평가 전에 고정한다. [GP 커널 튜닝](../guides/품질모델_학습과_불확실성.md)

주 예산 10%, 보조 5%·20%에서 Recall·Precision, 실제 저품질 분모, 고유 실패 위치, 야간 정상 수와 오경보, 원·근거리 누락을 보고한다. risk–coverage와 AURC는 같은 정의된 전체 후보에서 계산한다. 프레임 간 의존성은 도로·위치별 재표집으로 확인한다. 전체 GT가 없을 때의 무작위 감사 모집단 추정과 그 넓은 변동 범위는 [원문](../archive/버전쌍_경보_갱신판정.md#검수한-장면만-라벨링했을-때의-모집단-추정)을 따른다.

모델·중심·보정값·입력 목록 해시, 선택 ID와 사유, 평가표·실패 사례·지연표를 넘기고 [동일 예산 재학습](../guides/인지모델_재학습과_갱신판정.md)에 연결한다.

### 함께 판정할 기준

회귀 정답과 출력은 전방 프레임 전체의 흰색·노란색 차선 IoU 하나다. 실제 IoU < 0.7을 공통 비교 지표로 쓰고, 환경별 상대 저하와 근거리 오류도 사후 분석한다. 모델·특징을 개발 도로에서 정하고 별도 보정 자료로 정책을 고정한 뒤 미사용 도로에서 평가한다. 이미 분석한 273장은 진단에 사용한다.

주 검수 예산은 10%다. 품질 MAE, 같은 예산의 Recall·Precision, 고유 실패 위치, 야간 오경보와 정상 분모, 처리비용을 함께 보고한다. 갱신 채택은 신규 인지 IoU 변화 ≥ 0, 기존 IoU 손실 ≤ 0.005, 짝 품질 MAE 증가 ≤ 0.010을 함께 확인한다. [정책 파일](../../config/cycle_acceptance_v1.json)

### 기존 스트림 연결과 추가 구현

기존 `stream_front_rgb.py`는 ROS 압축 전방 RGB를 원래 바이트·헤더 시각·수신 시각과 함께 저장하고 RGB 경로 행을 내보낸다. `stream_review`는 이 경로 행을 순서대로 읽어 기존 품질모델로 채점하고 창별 선택 원본을 저장한다. 기존 X56 모델·환경 중심과 새 ROI 직접 회귀의 번들 연결은 원태·재호가 구현할 대상이다. 실제 26R1 토픽·압축 설정·수신률은 시뮬레이터에서 확인한다. [ROS 입력·수신기 원문](../archive/회귀학습_선별평가.md#ros-1-전방-압축-영상-입력)

기존 저장 RGB로 일괄·스트림 출력을 대조할 때는 다음 명령을 사용한다. 변수는 같은 프레임과 완료 모델의 실제 경로로 설정한다.

```bash
PYTHONPATH=src python3 -m quality_estimation.stream_review \
  --data-root "$RGB_ROOT" --model-run "$QUALITY_RUN" --alarm-calibration "$ALARM_RUN" \
  --window-frames 64 --budget-percent 10 --audit-fraction 0.2 \
  --output-dir "$LIVE_RESULT" < "$RGB_MANIFEST"
```

`stream_review`는 표준 입력의 JSON 행마다 RGB를 읽는다. `scores.jsonl`, `windows.jsonl`, `queue.jsonl`, `selected_rgb/`와 `_SUCCESS`를 확인한다. 창이 닫힐 때까지 원본이 같은 경로에서 읽혀야 한다. 스트림 공급·관측 예제는 [기존 실행 기록](../archive/회귀학습_선별평가.md#들어오는-rgb를-바로-채점하고-검수-이미지를-저장하기)에 있다.

같은 입력 순서에서 선택 ID·특징값·점수를 오프라인과 대조한다. 프레임 수·수신률·p50/p95 추출/추론/전체 지연·드롭·기록 용량과 종료 후 재처리 가능 여부를 남긴다. 원본 수집의 보존 범위는 [데이터 등록](../guides/데이터_등록과_특징정답.md)에서 확인한다.

### 영어 발표와 보고서 대체 페이지

8분 구성은 문제·목표 1분, 방법·비교 조건 2분, 정량 결과·실패 사례 3분, 시연 1분, 한계·결론 1분이다. 첫 장면으로 RGB·차선 예측·정답을 설명하고, 처음 듣는 청중이 검수와 IoU를 이해할 수 있게 한다. 핵심 결과는 ROI·특징 선택, RF·GP와 검수 비교, 실제 재학습 전후를 같은 데이터 범위와 함께 제시한다.

영어 페이지는 저장소의 `site/`에 구현한다. 첫 화면의 제목·한 문장 성과·대표 영상에서 방법 그림·결과·한계·코드·재현 절차·팀·참고문헌으로 이어지게 한다. 최신 연구 페이지의 영상·코드 접근 방식을 참고한다. [CVPR 2026 LFG 페이지](https://lfg-ai.github.io/)

공개할 표와 그림은 `docs/baselines/`의 공개 집계 또는 문서와 함께 검토한 자산에서 사용한다. 원본 영상의 공개 범위를 확인하고, 영상에는 실제 촬영·재생 방식과 영문 자막을 붙인다. 공개 페이지에서는 개인 경로 대신 코드·결과·영상의 실제 링크를 사용한다.
