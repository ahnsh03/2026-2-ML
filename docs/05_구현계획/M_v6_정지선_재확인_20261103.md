# TwinLiteNet+ M v6 — 정지선 학습 이력 재확인

> 2026-11-03 · 원본 config·18행 history·result·checkpoint SHA를 직접 대조했다.
> **M v6는 정지선을 포함해 본학습을 완료했다.** 이전에 v5 binary 모델만 확인해 M 전체가
> 정지선을 출력하지 않는다고 설명한 것은 잘못이다. 이 문서가 이전 M 클래스 설명보다 우선한다.

| road_marking 클래스 | background / white_lane / yellow_lane / stopline |

| 초기화 | v5 M의 EMA에서 공통 가중치 이전, 노면표시 head 초기화, optimizer/scheduler reset |
| 사용할 후보 | best_mean, 선택 epoch **11**. 18은 완료한 학습 epoch 수 |

정지선을 추가하기 위해 새 M을 처음부터 학습해야 하는 상황은 아니다.
이 가중치를 품질 추정 대상 f0로 고정하는 것을 제안한다. 새 품질 추정기는 전방만 사용한다.
과거 인지 모델이 전방만으로 학습됐다고 설명하지 않는다.

**best_mean epoch 11의 과거 validation 누적 교집합/합집합 IoU**다.
frame별 IoU의 평균이나 새 독립 test 성능이 아니다.

| 클래스 | 3뷰 전체 | 전방만 |

| drivable | 98.34% | 97.75% |
| white_lane | 87.86% | 77.69% |

원본 validation의 노면표시 3개 foreground class 평균은 89.56%다.
발표에서는 이번 과제 범위에 맞게 전방 수치를 우선 보여준다.
클래스별 평균만으로 장면별 실패의 빈도·환경 원인을 주장하지 않는다.
숫자는 [근거 JSON](./contracts/medium_v6_baseline_evidence.json)에 별도로 보존했다.

10월의 다른 해상도·데이터 버전 재평가도 존재한다. 그 수치를 위 학습 validation 수치와 섞지 않는다.
기존 v5 그림의 lane IoU 0.165/0.940, 89/468 사례를 v6 결과로 재표기하지 않는다.

## 품질 모델 입출력에 반영할 점

```text
전방 RGB → 고정 M v6
             ├─ 도로 확률 [2,H,W]
             └─ 노면표시 확률 [4,H,W]
                      ↓ GT 없이 계산한 확률·형태·ROI 특징 X
학습 때만: 예측 마스크 + GT → 클래스/영역별 실제 IoU Y
                      ↓ 별도 회귀 모델 학습
새 전방 영상: X → 도로·차선·정지선의 예상 IoU → 검수 순위
```

- 노면표시 예측은 multiclass argmax를 기준으로 정의한다. 각 클래스를 독립 이진 threshold로 겹쳐 만들지 않는다.
- 흰/노란 차선 합집합을 쓸 수 있다. argmax class가 white 또는 yellow인 마스크와
  `p_white+p_yellow≥0.5` 마스크는 같다고 가정하지 않는다.
- 정지선 IoU는 별도로 유지한다. GT·예측 모두 없는 union=0은 undefined로 관리한다.
  정지선이 있는데 완전히 놓친 경우는 union>0, IoU=0이므로 평가에 포함한다.
- 정지선 존재 여부가 드물 수 있어 유효 표본 수·누락 사례를 함께 보고한다.
  IoU 추정치를 주행 안전도나 정지 위치 정확도로 해석하지 않는다.

기존 `quality_contract_v1.json`과 14/30/78개 특징, binary 정책·시각화 코드는 **v5 기반 초안**이다.
그대로 v6에 적용하면 안 된다. A/B가 4클래스 GT 변환·출력 차원·특징 순서·ROI target을 맞춘 뒤
새 계약으로 동결한다. 현재 ML 로더의 binary 전제도 점검할 이식 항목이다.
이번 확인 작업에서 모델 실행·새 학습·코드 이식·계약 JSON 교체는 하지 않았다.

실제 원본 경로는 공개 저장소 밖 `external/medium-v6-evidence.local.json`에 기록한다.
