## 1. 담당의 목표와 선택

**목표:** 고정 TwinLiteNet+의 전방 출력에서 만든 숫자 특징을 받아, 실제 전체·ROI IoU를 예측한다.
실제 GT가 없는 새로운 프레임에서도 예상 품질과 검수용 순위 점수를 출력하는 것이 B의 결과물이다.

| 설계 질문 | 제안 결정 | 이유 |
|---|---|---|
| 회귀/분류 | **IoU 회귀를 주 과제**, 직접 실패 분류는 선택 비교 | 품질 정도·ROI별 표시·검수 순위에 같은 출력을 활용 |
| 첫 구현 | `lane_full` 단일 target부터 완성 | 학습/평가/인계 오류를 작게 확인 |
| 확장 target | drivable_full, lane_road, drivable_road | 차선/도로와 전체/ROI를 구분해 평가 |
| 선형 기준선 | StandardScaler + Ridge | 선형 관계·정규화 효과, 상관된 특징에 대한 제어 |
| 비선형 비교 | RandomForestRegressor | 형태·불확실성·ROI 특징의 상호작용을 학습할 수 있는 비교 |
| 입력 | A가 제공하는 출력-only feature | RGB/환경/GT를 추가해 범위를 바꾸지 않음 |
| 저장/실사용 | target별 모델 + 전처리 + schema·f0 식별 정보를 함께 저장 | 다른 feature 순서·checkpoint를 잘못 적용하는 문제 방지 |

RF가 반드시 Ridge나 confidence를 이긴다고 가정하지 않는다. 실제 데이터에서 비교하고 이득과 실패를 보고한다.
실패 위험 점수는 실패 확률이나 안전도 점수가 아니다.

## 2. A로부터 받는 데이터와 C로 넘길 결과

### 입력

| 항목 | 모양·사용 |
|---|---|
| features | 전방 1 frame당 1행, float32/float64 `[N,d]` |
| ordered_features | 열 이름·순서·단위. 현재 초안 d=14/30/78 |
| labels | sample_id별 실제 IoU 4개와 target별 label_defined |
| metadata | sample_id, parent_session_id, meta 역할, f0 노출 여부, 조건 |
| versions | checkpoint·GT 정책·기하·ROI·feature schema·split 해시 |

metadata는 join·split·분석에만 사용하고 X에는 넣지 않는다. 입력 열은 feature allowlist로 선택한다.
같은 frame의 GT IoU·FN·FP·환경 조건이 features에 섞이면 거부한다.
같은 sample_id가 여러 번 있거나 feature/label join이 일대일이 아니면 중단한다.
정상적인 빈 마스크의 특징 값은 A가 empty flag와 함께 정의한다. 예상하지 않은 NaN/inf는
데이터 오류로 보고하고 임의로 0으로 덮지 않는다. target undefined와 입력 결측을 혼동하지 않는다.

### 출력

C에 `sample_id, model_bundle_id, target별 raw_estimate/estimated_iou, primary_target,
risk_score, dev_threshold, review_flag`를 전달한다. 저장 파일과 feature/model/schema 해시도 함께 제공한다.
실제 GT와 선별 효과 지표는 C가 평가할 때 join한다.

```json
{
  "example_only": true,
  "sample_id": "illustration/front/000001",
  "estimated_iou": {
    "lane_full": 0.62,
    "drivable_full": 0.94,
    "lane_road": 0.55,
    "drivable_road": 0.93
  },
  "primary_target": "lane_full",
  "risk_score": 0.38,
  "dev_threshold_example": 0.35,
  "review_flag": true
}
```

위 수치는 **출력 형식만 설명하는 가상 예시**다. 실제 성능·학습 결과가 아니다.
0.38은 `1-0.62`인 검수 점수이며 “38% 확률로 실패”라는 의미가 아니다.
모델이 학습되지 않은 target은 unavailable로 표시하거나 bundle 완성을 기다린다.
배포 시 해당 frame의 GT가 undefined인지 알 수 있다고 가정하지 않는다.

## 3. 회귀 문제와 모델의 의미

프레임 i의 출력 특징을 x_i, GT로 채점한 실제 IoU를 y_i라 두면
`g_theta(x_i) = raw_estimate_i`, `q_hat_i = clip(raw_estimate_i,0,1)`이다.
TwinLiteNet+ f0는 고정되며 g만 학습한다. GT는 y를 만드는 학습·평가 단계에서만 사용한다.

### 상수·확신도 기준선

- B0: target별 meta_train IoU 평균을 모든 frame에 예측한다.
- B1-raw: 높은 entropy 또는 낮은 confidence를 검수 점수로 쓴다. 이는 IoU 예측값이 아니다.
- B1-reg: 단일 confidence 또는 entropy에서 실제 IoU로의 1변수 회귀를 meta_train에서 학습한다.
  회귀 MAE는 B1-reg와 비교하고, 순위/검수 효과는 B1-raw도 비교한다.
- confidence가 낮으면 틀렸다는 가정을 성과로 쓰지 않고 GT로 관계를 확인한다.

### Ridge: 정규화한 선형 회귀

`g(x)=b+w^T z`, `z_j=(x_j-mu_train,j)/sigma_train,j`.
학습 목적은 `sum_i (y_i-b-w^T z_i)^2 + alpha*||w||_2^2`다. 절편에는 L2를 적용하지 않는다.
같은 확률·면적·ROI 통계는 서로 상관될 수 있으므로 정규화한 선형 비교를 둔다.
alpha가 클수록 계수를 더 강하게 줄인다. StandardScaler는 각 학습 fold의 X에서만 fit한다.
coef는 예측기의 선형 관계를 설명하지만 조명·날씨의 인과 효과는 아니다.
[공식 Ridge 설명](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html)

### Random Forest: 여러 회귀 트리의 평균

`g(x)=(1/T)*sum_t h_t(x)`로 설명한다. bootstrap 표본과 분할 후보 특징의 무작위성을 사용한다.
트리는 예를 들어 “차선 면적이 작고 특정 ROI의 불확실성이 높을 때 낮은 품질” 같은 결합 관계를
학습할 수 있다. 이는 가능한 관계의 예시이며 우리 데이터에서 발견한 규칙은 아니다.
기본 squared_error 회귀를 사용하고 트리 깊이·최소 leaf 수로 복잡도를 제한한다.
RF에는 표준화가 필수는 아니지만 같은 유효성·열 순서 검사를 적용한다.
OOB 점수는 세션 단위 평가를 대체하지 않는다. 인접 frame이 OOB/학습에 섞일 수 있기 때문이다.
[공식 RandomForestRegressor 설명](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.RandomForestRegressor.html)

### 회귀를 먼저 하는 이유와 한계

동일한 낮은 품질 기준에서도 IoU 0.69와 0.10은 다른 상황이다. 회귀는 그 차이를 보존하고 ROI별
품질 표시·검수 순위에 활용할 수 있다. 반면 평균 오차를 줄인 회귀가 드문 실패를 잘 찾는다고
보장하지는 않는다. MAE와 함께 실패 AP·검수 예산별 발견율을 평가한다.
회귀의 MAE가 낮아도 실패 선별이 약하면 직접 실패 분류를 후속 비교로 제안한다.

선택 분류 실험은 `z_i=1[y_i<tau]`, Logistic Regression으로 시작한다.
tau는 실패의 정의, lambda는 배포 경고 점수의 임계값이다. 두 값을 구분한다.
분류기 predict_proba도 새 조건에서 보정된 확률을 보장하지 않으므로 확률 주장은 별도 검증한다.
XGBoost·SVM·GP·MLP를 모두 추가하지 않는다.

## 4. 고정할 비교 행렬

| ID | 입력 | 모델/점수 | 답할 질문 |
|---|---|---|---|
| B0 | 없음 | train 평균 | 학습할 정보가 있는가? |
| B1 | confidence 또는 entropy 하나 | raw rank / 1변수 회귀 | 단일 확신도보다 나은가? |
| B2-OLS | F_conf 14 | Ordinary Least Squares | Lecture3의 최소제곱을 직접 적용한 기준선 |
| B2 | F_conf 14 | Ridge | 확률 통계의 조합이 도움이 되는가? |
| B3 | F_global 30 | Ridge | 형태·경계 정보의 추가 효과는? |
| B4 | F_grid 78 | Ridge | 단순 공간 분할 효과는? |
| B5 | F_camera_roi 78 | Ridge | 같은 차원에서 카메라 ROI 효과는? |
| B6 | F_camera_roi 78 | RF | 같은 입력에서 비선형 모델 효과는? |

B3→B4→B5는 같은 학습기로 입력 정보의 효과를 보고, B5→B6는 같은 입력으로 모델 효과를 본다.
B2-OLS→B2는 같은 전처리·입력에서 L2 정규화 효과를 본다. main_notes의 정규화와 연결한다.
ROI를 정하기 전에도 F_conf/F_global로 B0~B3를 먼저 완성할 수 있다.
시간이 허용되면 RF의 F_global/F_grid도 비교해 ROI 효과가 학습기에 따라 달라지는지 확인한다.
모든 방법은 동일 target의 동일 평가 가능 frame에서 비교한다. feature 수가 다른 방법의 수치만 보고
특정 알고리즘이 우수하다고 단정하지 않는다.

## 5. 분할·튜닝·모델 선택

1. **f0 고정:** checkpoint SHA·EMA/raw·preprocessing·GT 정책을 잠근다. 기본 후보는 기존 M이다.
2. **역할 분리:** A와 meta_train/meta_dev/candidate_pool/final_test의 부모 세션 중복을 검사한다.
   f0 학습 자료와 이미 개발에 쓴 val는 파일럿으로 구분한다.
3. **target별 학습:** 그 target의 label_defined=true인 meta_train 행만 회귀에 사용한다.
   union=0을 좋은 품질 1로 채우지 않는다. 사용/제외 수·세션 수·분포를 남긴다.
4. **내부 튜닝:** 충분한 독립 그룹이 있으면 meta_train 안에서 GroupKFold 최대 3-fold를 사용한다.
   각 fold마다 scaler를 새로 fit하며 final_test/candidate_pool을 열지 않는다.
5. **설정 확정:** 내부 CV에서 primary lane_full MAE로 하이퍼파라미터를 정하고 meta_train 전체로 적합한다.
   meta_dev에서 모델/feature 후보를 최종 선택한다. dev MAE를 우선하고 선별 지표를 함께 기록한다.
6. **적은 그룹:** target에 유효한 meta_train 그룹이 3개 미만이면 CV 결과를 과장하지 않는다.
   고정 설정 또는 제한된 dev 비교를 사용하고 더 많은 독립 세션 확보를 요청한다.
7. **경고 기준:** 선택한 g를 고정하고 meta_dev에서 정상 frame 오경보율 10% 이하를 목표로 lambda를 정한다.
   테스트에서 threshold를 다시 조정하지 않는다. 높은 confidence 기준도 dev에서 고정한다.
8. **최종 평가:** 잠근 final_test에 한 번 적용하고 C가 회귀·선별·조건별 결과를 채점한다.
   결과가 나쁘면 한계로 보고한다. test를 보고 규약을 고치면 새 test가 필요하다.

[GroupKFold 공식 설명](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html)

내부 CV 하이퍼파라미터 튜닝은 우선 primary target에 한정해 비용을 줄인다.
다른 target은 같은 설정을 먼저 적용하고, 별도 튜닝했다면 그 범위·예산을 명시한다.
모델/feature 선택에 쓴 meta_dev 수치를 독립 test 결과라고 쓰지 않는다.
candidate_pool에서 정답 유무로 후보를 거르거나 final_test를 추가학습에 편입하지 않는다.

### 초기 하이퍼파라미터 제안

| 모델 | 시작 설정 / 탐색 범위 |
|---|---|
| Ridge | alpha={0.1,1,10,100}, fit_intercept=True, solver=auto |
| RF | n_estimators=300, criterion=squared_error, bootstrap=True, random_state=2026 |
| RF 탐색 | max_depth={4,8,None}, min_samples_leaf={5,10,20}, max_features={sqrt,1.0} |
| 비용 제한 | RF 18조합 중 seed 고정 12조합을 뽑아 primary target에서 탐색 |
| 반복 | 최종 후보는 여유가 있으면 seed 2026/2027/2028 변동 확인. frame 독립 CI로 해석하지 않음 |

위 값은 측정으로 선정된 최적값이 아니다. 작은 데이터의 과적합을 제한하기 위한 시작점이다.
feature 표를 받은 뒤 RF 학습은 CPU로 먼저 실행한다. GPU는 주로 f0 추론에 사용한다.
공식 문서는 현재 버전 API를 참고했으며 실제 환경의 sklearn 버전을 bundle에 기록한다.
기존 환경을 임의로 업그레이드하거나 최신 RF의 NaN 처리를 전제로 구현하지 않는다.

## 6. 성공 기준과 C에 요청할 평가

| 지표 | 무엇을 의미하는가 | 주의 |
|---|---|---|
| MAE | 실제 IoU와 예상 IoU의 평균 절대 차이 | 0.05는 IoU 절대값 평균 0.05 차이. 현재 달성값/목표 보장 아님 |
| Spearman | 나쁜 품질을 낮은 순위에 두는가 | 값이 일정하면 NA |
| Failure AP | 실제 IoU<tau 장면이 상위 위험 순위에 모이는가 | 실제 실패 비율을 함께 보고 |
| Recall@Budget | 같은 검수량으로 전체 실패 중 얼마나 찾는가 | GT undefined도 선별 예산에서 빠지지 않음 |
| FPR/Recall | 고정 경고 기준에서 정상 경고·실패 검출 수준 | test에서 FPR을 다시 맞추지 않음 |

성공은 “RF를 만들었다”가 아니라 **기준선보다 품질을 잘 추정하거나 같은 예산에서 오류를 더 찾았는가**다.
평균 MAE 개선과 검수 효과가 충돌하면 둘 다 보고한다. 수치가 나오기 전에 개선율을 약속하지 않는다.
성공/실패가 공존하는 같은 환경 안의 성능도 평가해 단순 환경 구분인지 실제 품질 구분인지 확인한다.

```text
src/quality_estimation/
  features.py / labels.py      A 소유
  estimators.py                B: Ridge/RF 생성
  train.py                     B: target별 fit·튜닝·bundle
  predict.py                   B: GT 없는 입력 검증·예측
  bundle.py                    B: 모델·스키마·전처리 저장/확인
  evaluation / selection       C 소유, 세부 파일명은 취합 때 조정
```

B의 기본 인수 순서:

1. 기존 M 로더와 출력 adapter로 front 확률맵을 얻는 경로 확인.
2. A로부터 작은 실제 feature/label 표와 schema를 받아 B0와 Ridge 단일 target 완성.
3. 같은 입력의 RF 비교, ROI·여러 target 확장.
4. bundle을 저장/재로딩하고 같은 X의 예측이 일치하는지 확인.
5. GT 파일 없이 predict가 동작하고 GT/환경 열은 입력에서 거부하는지 확인.
6. feature 순서·ROI·f0 SHA 불일치가 오류가 되는지 확인.
7. sample_id별 예측, dev threshold, 설정/시간/학습 행·그룹 수를 C에게 전달.

bundle은 학습기뿐 아니라 scaler, feature 순서, target 정의, 입력 계약 해시, checkpoint/EMA,
데이터 역할, sklearn/Python 버전, seed, 튜닝 기록과 threshold를 담는다.
낮은 latency를 주장하려면 feature 추출·데이터 이동·g 추론을 포함해 측정해야 한다.
새 f0 checkpoint·정책·카메라/ROI에서 그대로 유효하다고 가정하지 않는다.

## 8. 논문에서 B가 차용할 것

| 참고 | 차용 | 차이 |
|---|---|---|
| [MetaSeg](https://arxiv.org/abs/1811.00648) | 출력 특징 위 별도 회귀/분류 | 우리는 frame/고정 ROI IoU, 원본은 segment adjusted IoU |
| [SEE, ISCAS 2026](https://epapers2.org/iscas2026/ESR/paper_details.php?paper_id=2485) | 이미지 품질 회귀와 RF | 원본의 RGB 품질·재구성 특징을 제외하므로 정확 재현 아님 |
| [Küchler 2024](https://arxiv.org/html/2401.09245v2) | 단순/비선형 학습기와 feature 묶음 비교 | 원본의 외장 부품 precision 분류·영역 삭제는 그대로 적용하지 않음 |
| [TCSR-Monitor](https://arxiv.org/html/2608.16748v1) | 조건 이동·과신 오류·고정 임계값 평가 | 주로 C와 협업. 의료 영상의 성능·보장을 도로로 이전하지 않음 |

SEE와 Küchler는 공식 전용 코드 확인 여부가 제한적이다. 확인한 내용은
[참고 범위 문서](./참고논문_베이스라인.md)에 따른다. 새 품질 모델이 학습 완료된 것처럼 발표하지 않는다.

## 9. 팀 취합 때 결정 요청할 항목

- A: 최종 feature 열·정의·ROI, target별 undefined 규칙, 실제 표 제공 시점.
- 공동: f0 체크포인트, primary target, 부모 세션 role split, freeze 시점.
- C: MAE/AP/검수 예산·중복 규칙, dev threshold와 final_test 접근 절차.
- B 제안: 회귀 우선, Ridge/RF 두 학습기, 같은 입력/같은 모델을 구분한 비교 행렬.
