## 1. 원본 위치를 찾는 방법과 경계

이 공개 저장소에는 비공개 원본 프로젝트의 이름·루트 경로·URL·컨테이너명을 넣지 않는다.
정확한 원본 절대경로와 파일 해시는 **저장소 밖** `external/source-path-map.local.json`에 기록했다.
이 문서의 `SOURCE_ROOT`는 해당 원본 루트, `SOURCE_CAMERA_PY`는 원본 카메라 Python 패키지다.
경로를 모르는 팀원은 소유자가 제공하는 로컬 대응표로 inventory ID를 해석한다.
`src/data_collection/`, `scripts/`, `tools/perception/`, `config/`는 SOURCE_ROOT 기준 상대경로다.

- 원본은 읽기만 한다. 원본 실행 파일을 호출하거나 sys.path로 import하는 방식으로 연결하지 않는다.
- 기존 ML 코드에 이미 이식된 파일이 많으므로 **통째로 덮어쓰지 않고 필요한 차이만 반영**한다.
- 변경 파일 머리에 원본 commit·정제한 source alias·변경 목적을 기록하고 로컬 대응표에 실제 경로를 둔다.
- 원본의 저장 경로·환경 변수·패키지 이름을 ML 계약으로 바꾼다. 특정 PC의 volume 관리 체계를 통째로 이식하지 않는다.
- 원본 데이터·가중치는 Git 밖에서 참조한다. 기존 source path와 root가 ML runtime의 의존성이 되어서는 안 된다.
- 이식 승인 범위는 이 프로젝트에 필요한 수집·분할·평가·추가학습 기능이다. 주행 제어·전체 ROS bring-up는 별도다.

## 2. 역할과 병합 순서

실명 배정은 팀에서 한다. [11/4 취합 분담](../03_팀운영/중간발표_3분할과취합공지_20261103.md)에 맞춰
역할 A/B/C를 **입력·정답 / 모델·학습 / 선별·평가·개선**으로 연결한다.

| 역할 | 주 소유 파일 | 넘겨줄 산출물 | 선행 의존성 |
|---|---|---|---|
| A — 입력 특징·학습 정답 | 수집·bake/dataset, ROI, feature extractor, label builder | 검증된 RGB/GT manifest, 고정 ROI, GT 독립 X와 별도 Y | Capture 샘플·센서 설정, B의 확률 export |
| B — 품질 모델·학습 | twinlite_morai, common loader, 예측 export, quality 학습/추론 | float32 PredictionRecord, Ridge/RF bundle, 예상 품질 | A의 sample/geometry·X/Y 계약 |
| C — 선별·평가·개선 | metric·계약 검증, 검수 manifest·보고서, 개선 비교 | 평가·선별 곡선, 조건별 분석, 추가학습 비교 protocol | A의 정답과 B의 예상 품질 |

순서: 계약·sample fixture 합의 → A/B 병행 parity 확인 → A ROI·X/Y → B 품질 모델 → C 평가·선별.
같은 shared 파일을 두 사람이 동시에 바꾸지 않는다. `src/common/bridge.py`의 model_id/해시는 B가 소유하고 A/C가 검토한다.
33개 모두를 새로 복사하는 작업이 아니다. P0도 **기존 구현이 계약을 만족하면 재사용**한다.
P1은 필수 결과를 통과한 뒤 선택한다.

## 7. 이번에 이식하지 않을 것

- 카메라 ROS 실시간 추론 노드·TensorRT backend·engine·주행 planner/fail-safe.
- LiDAR·지도·객체 detection 파이프라인과 광범위 ROS bring-up.
- `tools/perception/prepare_capture_training_data.py`는 BBox/teacher detection 의존성이 있어 현재 segmentation 경로로 가져오지 않는다.
- `prepare_twinlite_captures.py`, `finalize_twinlite_captures.py`는 대량 native/source 혼합과 4-class/L data 준비용이다.
  현재 v5 M 계약보다 범위가 크므로 통째로 가져오지 않는다. 필요한 provenance/무결성 아이디어만 A가 참고한다.
- `run_twinlite_training.py`의 긴 학습 세션 관리·리포터 전체, engine packaging·운영 배포 도구.
- 환경·객체 배치를 동시에 조작하는 route/layout coordinator 전체. 필요 시 독립 의존성 목록과 계획을 먼저 갱신한다.
- 외부 proto·대규모 데이터·학습 모델·원본 시각화의 공개 저장소 편입.

## 8. 각 이식 PR의 인수 기준

1. source ID/revision/SHA, 실제 변경 범위, ML 목적지를 기록한다. source snapshot이 바뀌면 해시를 갱신한다.
2. ML 저장소만으로 import·실행 가능하고 원본 경로·패키지에 의존하지 않는다.
3. 실제 작은 RGB/GT fixture에서 image/GT/valid/ROI 위치와 binary encoding을 확인한다.
4. M 같은 입력·가중치·정밀도에서 logits/probability parity를 비교한다. FP32 동일 연산은 max abs 1e-6을 초기 기준으로 하되
   장치·연산 차이가 있으면 근거와 허용 오차를 명시한다. threshold 인접 픽셀 차이도 별도로 센다.
5. GT를 제거해도 feature/predict 경로가 동작한다. GT를 바꿔도 feature는 변하지 않고 label만 바뀌어야 한다.
6. union=0, 전경 없음, 내부 없음, 빈 ROI, padding, shape mismatch를 확인한다.
7. 부모 세션·원본 해시의 역할 중복, final_test 후보 편입을 거부한다.
8. 이식한 의미 있는 데이터·기하·누수 계약 검증을 실행하고 실제 명령·환경·결과를 PR에 기록한다.
   외부 레포 clone/파일 존재만으로 실행 검증 완료라고 표시하지 않는다.

현재 이 문서의 체크 항목은 **미실행 인수 조건**이며 통과 결과가 아니다.
