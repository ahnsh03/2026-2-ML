## 0. 한 줄 정의

> **"우리 차는 자기 차선 인식이 언제, 어떤 식으로 틀리는지 알 수 있을까"**
> MORAI K-City에서 직접 수집한 데이터로, 카메라 차선 인지 모델이 **실패하는 프레임을 GT 없이 예측**하고,
> **실패가 어떤 유형으로 나뉘는지 라벨 없이 찾아낸다.**

| 제목안 | |
|---|---|
| 국문 | 우리 차는 자기가 언제 틀릴지 알 수 있을까 — 차선 인지 실패의 GT-free 예측과 실패 유형 발견 |
| 영문 | Can a Car Know When Its Lane Perception Fails? GT-free Failure Prediction and Failure-Mode Discovery |

인지 모델은 **학습된 블랙박스로 고정**한다. 이 프로젝트는 신경망을 새로 학습하지 않고, 그 출력과 입력 영상에서
뽑은 feature로 고전 ML 문제(분류·회귀·군집·불확실성)를 푼다.

## 1. 질문과 가설 — 정답이 정해지지 않은 지점

결과가 참이든 거짓이든 발표 결론이 되도록 가설 형태로 둔다.

| # | 가설 | 검증 방법 | 근거·예비 신호 |
|---|---|---|---|
| H1 | 차선 실패는 **날씨보다 태양 방향·시간대(역광·그림자)** 에 더 좌우된다 | 같은 장소를 조건만 바꿔 수집(§3.3)해 조건 효과를 분리 | val 조건별 lane IoU 중앙값: sunny 3pm **0.864** < foggy 0.881~0.905. 단 현재 val은 조건마다 다른 구간이라 장소와 교란됨 |
| H2 | 실패는 **소수(4~6개)의 공간 패턴**으로 요약된다 | 고유 오류맵 PCA + GMM (§6) | 기존 평가 기록의 정성적 관찰: 교차로·횡단보도·그림자 속 가는 차선, 안개, 15~20 m 원거리 |
| H3 | 모델 자기 확신(확률맵)만 쓰는 것보다 **영상 통계 + head 간 일관성**을 더한 예측이 낫다 | feature 그룹별 ablation (§7) | — |
| H4 | 전면과 측면 뷰는 **실패 원인이 다르다** | 뷰별 모델·군집 비교 | lane IoU < 0.7 비율: front **19.0%**, left 5.6%, right 6.8% |
| H5 | 학습 분포 밖 조건(cloudy 등)에서는 예측기의 **불확실성(GP 분산)이 커진다** | OOD 테스트셋 (§3.3, §7) | v1 모델을 학습에 없던 5pm에 돌리면 lane IoU 중앙값 **0.16** |
| H6 | 대상 모델이 **학습에 쓴 프레임**으로 예측기를 학습하면 held-out에서 과신한다 | train 프레임 학습 vs held-out 학습 비교 (선택 분석) | 학습 프레임 IoU는 부풀려져 있음 |

### 3.2 왜 새 held-out 데이터가 필요한가

1. **학습 프레임은 쓸 수 없다.** 대상 모델이 본 프레임의 IoU는 부풀려져 있어 실패 라벨로 쓰면 예측기가 과신한다(H6).
2. **val은 작고 약간 낙관적이다.** 468 frame뿐이고, 매 epoch 모델 선택에 쓰였기 때문이다(`twinlite_morai/README.md`).
3. **val은 조건과 장소가 교란되어 있다.** seg01 sunny 11am, seg02 foggy 1pm … 처럼 조건마다 다른 구간을 달렸다.
   "sunny 3pm이 제일 나쁘다"가 조건 때문인지 그 구간의 도로 때문인지 구분할 수 없다.
4. **기존 C 드라이브 Capture에는 쓰지 않은 run이 사실상 없다.** 남은 것은 ratepilot(각 20 frame)과 smoke 수준뿐이다.

### 3.3 수집 설계 — 같은 경로, 조건만 바꿔 반복

| 원칙 | 방법 |
|---|---|
| 조건 효과를 장소와 분리 | **같은 경로(샘플 경로)를 조건마다 한 바퀴씩** 반복한다. 가능하면 **자동주행**(MORAI autopilot `morai_auto` 또는 MPC)으로 궤적을 맞춘다 |
| in-distribution 조건 | sunny / foggy × 11am · 1pm · 3pm · 5pm (대상 모델 학습 조건과 동일) |
| OOD 조건 | **cloudy** — rosbag 8개(11am·1pm·3pm)에서 사용 이력 확인, 대상 모델 학습에는 없음. 다른 시각·날씨가 있으면 추가 `[조사]` |
| 수집 방식 | Capture Mode 1 Hz, `only_when_moving:=true`. 한 바퀴 약 400~750 frame, 시간당 약 2,500 frame |
| 센서셋 | GT 센서셋 (Semantic 카메라·Instance LiDAR 포함) |
| 시나리오 | 샘플 시나리오 고정 (NPC 가림 실패 모드 확보). 수집 대장에 시나리오 hash 기록 |

**수집 목록 (권장 최소안)**

| 묶음 | run 수 | 조건 | 예상 frame | 용도 |
|---|---:|---|---:|---|
| F (factorial) | 8 | sunny/foggy × 11am·1pm·3pm·5pm | 약 4,000 | 예측기 학습·교차검증, H1 |
| O (OOD) | 2~4 | cloudy × 11am·3pm (+ 가능한 추가 조건) | 약 1,000~2,000 | **최종 테스트 전용**, H5 |
| L (잠금 테스트) | 2 | F 조건 중 2개를 한 번 더 | 약 1,000 | **12월 최종 평가 전용**, 그 전에는 열지 않음 |

총 12~14 run, 약 6,000~7,000 frame(3뷰 합계 약 18,000~21,000 sample). 주행 약 3시간 + 처리.
F만 먼저 수집해도 교차검증은 성립하므로, 일정이 밀리면 O·L을 줄인다.

### 3.4 처리 파이프라인 — 기존 수집 스크립트를 그대로 쓴다

인지 코드 레포 클론에서 실행한다. 상세 옵션은 그 레포의 `src/data_collection/README.md`를 따른다.

```bash
# 2) Windows → WSL 동기화 (먼저 --dry-run)

python3 scripts/sync_capture_mode_data.py --run-id <run_id> --jobs 4

# 3) 정차 중복 선별 + 대상 모델 학습 데이터와 같은 정책으로 bake

  --run-id <run_id> --output-name curation_v2

  --run-id <run_id> --stage all \
  --policy config/perception_target_policy_v3_actor_negative.json \
  --curation-name curation_v2 \
  --native-output-name perception_targets_native_v3_actor_negative \
  --output-name twinlite_384x640_marking_actor_negative_v1

# 4) dataset version: 빌더는 train run이 최소 1개 필요하므로

  --test-run <신규 run 반복>
```

## 4. 라벨

| 라벨 | 정의 | 용도 |
|---|---|---|
| `lane_iou` | 프레임×뷰, valid mask 안에서 `intersection / union` | 회귀 타깃(GP), 분석 |
| `y_fail` | `lane_iou < τ` (초기 τ = 0.7 → val 전체 10.4%, front 19.0%) | **주 타깃** (이진 분류) |
| `lane_recall_{near,mid,far}` | 영상 행을 거리 대역 3개로 나눈 GT 차선 재현율 | 실패 유형 설명 |
| `drivable_iou` | 동일 | 보조 분석 (분산이 작아 타깃으로 쓰지 않음) |

**주의 — 기존 평가 스크립트의 0 처리**
`evaluate_twinlite.py`는 `intersection / max(1, union)`으로 계산해서, **GT 차선도 예측도 없는 프레임이 IoU 0**
(= 최악의 실패)으로 기록된다. 현재 val에는 이런 프레임이 없지만 교차로가 많은 새 데이터에서는 생길 수 있다.
export 단계에서 `lane_target_px`, `lane_union`을 함께 저장하고,
**GT 차선 픽셀이 N_min 미만인 sample은 실패 라벨에서 제외**한다(N_min은 히스토그램을 보고 결정, 초기값 500).

**τ 민감도**: τ ∈ {0.6, 0.7, 0.8}로 주요 결과를 다시 보고한다. 뷰별 분포가 달라 뷰별 τ도 비교한다.

## 5. 입력 feature — 전부 GT 없이 실행 시점에 계산 가능

| 그룹 | 접두사 | feature | 비용 |
|---|---|---|---|
| **A. 영상 통계** | `img_` | 밝기 평균·표준편차, RMS 대비, 엔트로피, Laplacian 분산(선명도), edge 밀도, **dark channel prior(안개)**, 채도 평균, 하늘 영역 밝기, 과노출·저노출 비율(역광), 도로 ROI 기울기 에너지(차선 대비), R/B 비(색온도) | 추론 불필요 |
| **B. 확률맵 통계** | `lane_`, `drv_` | 차선 max-prob 평균, 엔트로피 평균, 불확실 픽셀 비율(0.3 < p < 0.7), 예측 면적, 연결요소 수, 최대 요소 길이, **원거리/근거리 차선 비**, 좌우 균형, drivable 면적·엔트로피·경계 거칠기, **차선이 drivable 경계·내부에 놓인 비율(head 간 일관성)** | 추론 1회 (이미 필요) |
| **C. TTA 일관성** | `tta_` | 좌우 반전 입력의 예측을 되돌려 원 예측과 비교한 IoU (lane, drivable) | 추론 1회 추가 |
| **D. 주행 상태** | `ego_` | 속도, yaw rate(연속 capture 간 heading 차 / 시간), 조향각, 뷰 one-hot | 무료 |
| E. LiDAR 일치 (확장) | `lidar_` | 같은 capture의 LiDAR 도로 점을 카메라에 투영한 뒤 drivable 예측과 어긋나는 비율 | 확장 단계 ([A2](../02_주제후보/A2_센서불일치_인지실패예측.md)) |

**분석 축 (입력으로 쓰지 않음)**: 날씨, sim 시각, run, 경로상 위치(station), 지도 속성(교차로·횡단보도 근접·GPS 음영 구간).
실전에서 조건 라벨을 모른다는 전제이며, "영상 feature가 조건 정보를 얼마나 대신하는가"를 따로 본다.

> TTA(C)는 추론 비용이 두 배다. **"무료 feature(A+B+D)만으로 어디까지 가는가"** 와 **"C를 더하면 얼마나 오르는가"** 를
> 나눠 보고하면 실시간 예산과의 trade-off가 결과가 된다.

## 6. 실패 유형 발견 — 고유 오류맵 군집

H2를 검증하는 **군집 파트**다. 결과를 이미지로 바로 확인할 수 있도록 설계한다.

| 단계 | 내용 |
|---|---|
| 1. 오류맵 | sample마다 FN = GT ∧ ¬예측, FP = 예측 ∧ ¬GT (valid 영역) |
| 2. 축소 | 뷰별 valid 영역을 잘라 **24×40 격자**로 area pooling → 셀별 FN·FP 비율 → 1,920차원 벡터 |
| 3. PCA | 주성분을 24×40 이미지로 되돌려 그린다 → **"고유 오류맵"** (eigenfaces와 같은 원리). 예: "원거리 소실", "왼쪽 가장자리 과검출" |
| 4. 군집 | PCA 점수에 **GMM** (군집 수는 BIC로 2~12 탐색, full vs diag 공분산). K-means를 기준선으로 비교 |
| 5. 갤러리 | 군집마다 평균 오류맵 + 구성 sample 12장(RGB·GT·예측 overlay) + 조건·위치 분포를 한 페이지 HTML로 생성 |
| 6. 검증 | 아래 표 |

**군집 검증 — "군집이 그럴듯해 보인다"를 숫자로 바꾼다**

| 검증 | 방법 |
|---|---|
| 사람 분류와의 일치 | 팀원 2명이 저IoU sample 150개를 독립적으로 유형 분류(원거리 소실 / 그림자 / 교차로·횡단보도 오인 / 앞차 가림 / 노면표시 과검출 / 기타) → Cohen's κ로 사람 간 일치도 → 군집과 NMI·ARI |
| 안정성 | bootstrap 재표본에서 군집 할당 ARI |
| 조건·장소와의 관계 | 군집 × 날씨·시각 교차표(χ² 검정), 군집 × 경로 위치 → K-City 지도 위 분포 |
| 쓸모 | 군집 id를 feature로 넣었을 때 실패 예측 AUC 변화, "실패 유형까지 GT 없이 맞힐 수 있는가"(다중분류) |

**확장 (시간이 남으면)**
- **입력 공간 군집과 비교**: feature(A+B)로 따로 군집해 오류 공간 군집과 대조. 실패 유형이 입력 조건과 1:1로 대응하는지 본다.
- 뷰: front는 따로, left/right는 **right를 좌우 반전해 left와 합쳐** 표본을 늘리는 안을 검토.

## 7. 예측 모델 계단 — 베이스라인 → 개선

| 단계 | 모델 | 강의 주차 | 확인할 것 |
|---|---|---|---|
| 0a | **단일 feature 임계값** (차선 max-prob 평균, 엔트로피, 예측 면적 중 train fold 최고) | — | 베이스라인 |
| 0b | **조건 사전확률** (날씨×시각 칸별 실패율) | — | "조건을 알면 충분한가"의 기준. 이걸 못 넘으면 영상 feature가 무의미 |
| 1 | Logistic Regression (표준화, L2, class_weight=balanced) | 3 | 선형 한계 |
| 2 | SVM (linear vs RBF, Platt 확률) | 7 | 비선형 경계 |
| 3 | Random Forest / **HistGradientBoosting** + permutation importance | 11 | 주력 모델, H3의 feature 그룹 ablation |
| 4 | **앙상블** (soft voting, stacking) | 11 | 교수님이 권한 성능 향상 카드 |
| 5 | **Gaussian Process** 회귀 (Matern/RBF + WhiteKernel, 2~3k 층화 서브샘플) | 12 | IoU 예측 + **예측분산**, 90% 구간 포함률, OOD에서 분산 증가(H5). WhiteKernel 잡음 = aleatoric, 사후분산 = epistemic |
| 6 | **random search vs grid search** (같은 예산, GBM·SVM) | 14 | 예산 대비 최고 점수 곡선 |
| 공통 | calibration: reliability diagram, ECE, Brier, Platt·isotonic | 12 | 예측 확률이 실제 빈도와 맞는가 |

## 8. 평가 설계

### 8.1 분할 — 누수 방지와 도메인 시프트

| 프로토콜 | 학습 | 테스트 | 묻는 것 |
|---|---|---|---|
| P1 기본 | F 묶음 + 기존 val | **GroupKFold(run 단위)** | 일반 성능 |
| P2 날씨 이동 | sunny | foggy (역방향도) | 날씨가 바뀌어도 통하는가 |
| P3 시각 이동 | 11am·1pm | 3pm·5pm | 태양 각도가 바뀌어도 통하는가 |
| P4 장소 이동 | 경로 구간 일부 | 나머지 구간 (station 100 m 묶음 단위 GroupKFold) | 처음 보는 도로에서도 통하는가 |
| P5 OOD | F 전체 | **O 묶음(cloudy)** | 학습에 없던 조건 (H5) |
| 최종 | 전체 | **L 묶음** — 12월에 한 번만 연다 | 튜닝 과적합 없는 최종 수치 |

같은 frame의 front/left/right는 반드시 같은 fold에 둔다(run 단위 분할이면 자동으로 만족).

### 8.2 지표

| 축 | 지표 |
|---|---|
| 분류 | **PR-AUC**(주, 실패가 소수 클래스), ROC-AUC, 선택 임계값에서 F1·재현율 |
| 회귀 | MAE, Spearman 상관 (예측 IoU vs 실제) |
| 보정 | ECE, Brier, reliability diagram |
| **선택적 예측** | risk–coverage 곡선: 위험 점수 상위 x% 프레임을 거부하면 남은 프레임의 평균 lane IoU·실패율이 얼마나 개선되나. **planner 관점에서 가장 해석하기 쉬운 결과** |
| 군집 | BIC, NMI·ARI(사람 분류 대비), bootstrap ARI |
| 비용 | 프레임당 feature 계산 시간 (A+B+D vs +C) |

> **실주행 로그는 정량 테스트셋이 될 수 없다.** 실주행 raw bag에는 Semantic GT가 없어 IoU를 계산할 수 없다.
> (9/6 A1 문서의 "실주행 로그를 최종 테스트셋으로"는 정정한다.) 실주행 rosbag은 **위험 점수를 영상 위에 겹친 정성 데모**로만 쓴다.
> Capture는 프레임마다 시뮬이 약 0.5초 멈추므로 "실패 몇 초 전에 경보가 떴나(lead time)"도 정량으로 재지 않는다.

## 14. 다른 프로젝트와의 관계

| 프로젝트 | 관계 |
|---|---|
| **MORAI 프로젝트** | 대상 모델이 기존 프로젝트의 최신 후보다. 결과는 (1) 조건 중 위험 구간, (2) 추가 수집 우선순위(어느 실패 유형을 더 모을지), (3) planner가 받을 수 있는 실시간 신뢰도 신호 후보로 돌아간다. 기존 레포에는 없는 새 작업이다 |
| **캡스톤** | 카메라–HD맵 표현 불일치(측위)와 **다른 질문**이다. 이 프로젝트는 지도 정합 feature를 쓰지 않는다. 캡스톤이 원하면 신뢰도 점수를 선택적 게이트 입력으로 쓸 수 있지만, 결과를 양쪽에 중복으로 주장하지 않는다. 공유하는 것은 데이터 인프라뿐이다 |
| **ERC** | 직접 연결은 약하다. "인지 모델의 자기 진단" 방법론은 LogoNav 실패 분석([B4](../02_주제후보/B4_주행로그_군집.md))에 옮겨 쓸 수 있다 |
