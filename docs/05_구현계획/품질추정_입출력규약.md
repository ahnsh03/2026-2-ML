> task·특징·target·GT 변환을 A/B 취합 후 새 버전으로 맞춘다.

> 범위 정본: [확정 설계](./프로젝트_확정설계_20261103.md).

## 1. 공통 식별자와 버전

`sample_id`는 dataset 안에서 유일한 `run_id/view/frame_id` 문자열이다. `frame_id` 숫자만으로 join하지 않는다.
각 산출물은 `schema_version, dataset_version, model_id, checkpoint_sha256, source_revision,
target_policy_sha256, geometry_sha256, roi_sha256, feature_schema_sha256, split_sha256`를 기록한다.
target/feature가 필요 없는 단계에서는 해당 해시가 null일 수 있으나, 학습 bundle과 최종 평가에서는 필수다.
같은 파일 이름을 새 결과로 덮어쓰지 않고 새 experiment ID를 사용한다.

공유 저장소에는 코드·작은 설정·익명화한 집계만 둔다. RGB/GT/확률맵/feature/모델/시각화는
`ML_DATA_ROOT`, `ML_OUTPUT_ROOT`, `PERCEPTION_CKPT_ROOT`의 저장소 밖 경로에 둔다.
아래 파일 이름·필드는 신규 모듈을 만들 때의 제안이며, 기존 CLI가 이미 지원한다고 간주하지 않는다.

## 2. Capture → 검증된 sample manifest

| 필드 | 형식·의미 |
|---|---|
| sample_id / run_id / parent_session_id | 문자열. 환경 변형·여러 view가 공유하는 부모 그룹을 명시 |
| view / camera_id | 기본 `front`; 카메라 ID와 view의 실제 매핑 기록 |
| capture_id / custom_name | RGB와 GT를 결합할 시뮬레이터 capture 식별자 |
| image / semantic_gt | 루트 기준 상대경로. 같은 capture·camera, 크기 일치 검증 |
| timestamps | simulator/ROS/host 각각의 시간과 단위. 확인할 수 없는 값은 null |
| environment | 요청한 weather·시각·강수·fog 파라미터와 실제 readback 값 |
| environment_verification | `verified`, `requested_only`, `unknown`; 요청 성공만으로 실제 상태 확정 금지 |
| pose / route / layout / seed | 좌표계·위치·자세·객체 배치·맵/시나리오 버전 |
| camera | 해상도·intrinsics·extrinsics·센서 설정 해시 |
| annotation_policy | semantic palette·클래스 매핑·actor-negative 정책 버전 |
| audit | RGB/GT SHA, 누락·디코딩·해상도·palette·상태 전환 검증 결과 |
| provenance | f0 학습 노출 yes/no/unknown, 과거 개발 평가 노출, 수집 출처 |

날씨·위치·GT 경로 등은 **메타데이터이지 모델 입력 열이 아니다**.
부모 그룹·조건은 파일 이름 추정이 아닌 별도 기록을 우선한다. 구형 기록의 파싱 결과는 추정임을 표시한다.
Capture 성공 응답만으로 Semantic GT의 존재·정확한 동기화를 보장하지 않는다.
새 수집은 RGB와 Semantic을 필수로 검증한다. Instance/Depth/BBox 전체가 필요하다고 강제하지 않는다.
구형 sync의 `legacy18` 등 profile에 맞지 않으면 필요한 `rgb_semantic_front` profile을 명시적으로 추가한다.

## 3. GT 정책과 기하

- M의 과거 GT 정책은 actor-negative binary lane/drivable이다. 새 데이터도 같은 정의로 bake한다.
- 흰색·노란색·정지선을 어떤 binary lane에 포함할지는 동결한 v5 정책 파일을 따른다.
  4-class 캐시를 임의로 `>0` 처리하거나 L용 cache를 그대로 재사용하지 않는다.
- RGB: BGR/BGRA → RGB, float32 [0,1], `[3,384,640]`. 입력 정규화·보간은 기존 M 계약을 유지한다.
- `geometry`: original_hw, resized_hw, target_hw, scale_xy, pad_ltrb, valid_roi_xyxy.
- 확률·마스크·GT·ROI의 정량 비교 공간은 **384×640 letterbox 공간**으로 통일한다.
- 입력 영역 특징의 유효 픽셀은 **GT 없이 알 수 있는 기하 유효 마스크**로만 정한다.
  GT에서 얻은 actor ignore/unknown mask를 특징 추출에 주입하지 않는다.
- 평가 정답은 각 head의 GT 유효 마스크와 기하 마스크를 적용한다. 제외 사유·픽셀 수를 기록한다.
- 원본 해상도 overlay는 설명용이다. 확률 복원 후 threshold 결과와 letterbox threshold의 차이를
  섞어서 같은 정량 점수로 보고하지 않는다. padding은 feature/평가 모두 제외한다.

## 4. M 추론 → PredictionRecord

| 필드 | 계약 |
|---|---|
| logits | 각 head float32 `[2,384,640]`; 선택 저장, energy 실험에는 필요 |
| foreground probability | `softmax(logits, class_axis)[1]`, 각 head float32 `[384,640]`, [0,1] |
| pred_mask | 각 head uint8 `{0,1}`, `p >= 0.5` |
| geometric_valid | bool `[384,640]`, GT 독립 |
| model provenance | M 크기, EMA/raw 선택, checkpoint/upstream SHA |

분석에는 float32 확률을 쓴다. 기존 0~255 확률 PNG는 발표용이며 feature 원본이 아니다.
전체 확률맵 영구 저장이 부담되면 float32로 특징을 계산한 뒤 필요한 subset만 보존한다.
색칠한 overlay를 읽어 특징을 역산하지 않는다. 기존 로더는 upstream SHA 불일치를 거부해야 한다.

## 5. ROI 계약

ROI는 원본 영상의 정규화 좌표 `(x/W,y/H)` 다각형으로 정의하고, 실제 letterbox 변환으로 rasterize한다.
변환 결과는 같은 좌표 공간의 bool mask다. 해상도·장착 위치·FOV가 바뀌면 같은 profile을 쓰지 않는다.
현재 다각형 좌표는 **미지정**이다. 개발용 전방 프레임에서 작성·검토하고 overlay 확인 후 동결한다.

| ROI ID | 역할 |
|---|---|
| upper_context | 상단 영역. 실제 하늘 GT라는 뜻은 아님 |
| ego_body | 차체가 보이는 고정 다각형 |
| road_left / road_center / road_right | 도로가 예상되는 좌·중·우 영역 |
| road_all | 위 세 road 영역의 union. 겹친 픽셀은 한 번만 계산 |

입력 ROI 6개와 2×3 단순 격자 6개에 같은 지역 통계를 적용해 차원 수를 맞춘다.
ROI끼리 겹칠 수 있으나 서로 배타적 클래스나 거리 정답으로 해석하지 않는다.
기하 유효 픽셀 0인 ROI는 잘못된 profile로 간주해 중단한다. GT가 없는 배포에서도 같은 검사다.
상단·차체의 실제 FP는 full-frame GT 평가에 남긴다. 영역을 좁힌 점수를 full IoU 개선이라고 부르지 않는다.

## 6. FeatureRecord — 한 프레임의 입력 X

각 binary head에서 `p`, `c=max(p,1-p)`, `m=|2p-1|`,
`H=-(p log p+(1-p)log(1-p))/log 2`를 계산한다. log 입력만 epsilon=1e-7로 clip한다.

| 전역 특징 (head별 15개) | 정의 |
|---|---|
| p_mean / p_std | 기하 유효 픽셀의 p 평균/모표준편차 |
| confidence_mean | c 평균 |
| entropy_mean / entropy_p90 | H 평균/90분위 |
| margin_mean / uncertain_fraction | m 평균, H>0.8인 비율 |
| fg_fraction / fg_confidence_mean | pred=1 비율, 그 픽셀의 c 평균 |
| fg_empty | pred=1이 없으면 1 |
| component_count_log1p | 8-connectivity 전경 연결 요소 수의 log(1+n) |
| small_component_area_fraction | 각 면적이 유효 영상 면적의 1e-4 미만인 component의 총 면적 / 전경 면적 |
| boundary_entropy_mean | 전경 - 3×3 erosion(전경)의 H 평균 |
| interior_entropy_mean / interior_empty | erosion 내부 H 평균, 내부가 비면 1 |

비어 있는 전경/내부의 조건부 평균·비율은 0으로 채우고 empty flag로 구분한다.
경계·내부 통계는 MetaSeg의 아이디어를 프레임에 요약한 **adaptation**이며 원 논문과 동일한 segment 지표는 아니다.
각 ROI에서는 head별 `p_mean, entropy_mean, fg_fraction, fg_empty` 4개를 계산한다.

두 head 전역 30 + ROI 6×head 2×통계 4 = **78개 입력 특징**이다.
열 순서는 JSON의 `ordered_features`로 고정한다. sample_id는 join key이며 X에 들어가지 않는다.
GT/IoU/FN/FP, 날씨·시각·위치, run 이름, GT 기준 support를 X에서 금지한다.
시간 특징은 미래 frame을 보지 않으며 run/view/scene 전환·시간 역행·과도한 간격에서 초기화한다.

## 7. LabelRecord — GT로만 만드는 정답 Y

각 head/ROI에서 `V = geometric_valid AND head_gt_valid AND roi_mask`.
`TP=sum(V & pred & gt)`, `FP=sum(V & pred & ~gt)`, `FN=sum(V & ~pred & gt)`.
`IoU=TP/(TP+FP+FN)`. 정답 4개는 lane_full, drivable_full, lane_road, drivable_road.

- union>0이면 0~1 점수를 저장한다. 모두 누락 또는 모두 오검출이면 0이다.
- union=0이면 **null / label_defined=false**. 1점으로 채우지 않는다.
- 각 target에 TP/FP/FN/union/GT 픽셀 수/유효 픽셀 수를 별도 저장한다.
- 작은 차선 support는 표본 수와 함께 보고한다. 점수가 나쁘다고 평가에서 사후 삭제하지 않는다.
- 기본 실패 정답은 정의된 `lane_full IoU < 0.7`. 0.7은 사전 지정한 운영 정의이며 안전 기준이 아니다.
- undefined는 회귀·실패 지표에서 제외한 수와 비율을 보고하고, empty-empty 장면의 경고·선별도 별도 분석한다.
  ROI target마다 정의된 행이 달라 target별 회귀기를 학습한다.
- 오류 형태(FN 우세/FP 우세/위치별 누락)는 GT 기반 부가 분석이며 원인 라벨이 아니다.

입력·정답을 별도 파일로 저장하고 sample_id 일대일 join을 검증한다.
MetaSeg의 GT ignore 처리가 예측 component 생성에 들어가는 코드를 그대로 배포 feature에 사용하지 않는다.

## 8. 학습 bundle과 GT 없는 예측

예정 인터페이스:

```python
# 설계 예시: 아직 구현된 함수가 아니다.
extract_features(prediction, geometric_valid, roi_profile, previous=None) -> FeatureRecord
build_labels(prediction, gt_targets, gt_valid, roi_profile) -> LabelRecord
predict_quality(feature_record, model_bundle) -> QualityRecord
```

bundle: estimator별 모델, train-only scaler/imputation, ordered_features, target 목록,
checkpoint/policy/ROI/feature/split SHA, train/development groups, seed, 환경 패키지 버전,
모델 선택 기준, dev 경고 임계값, `1-IoU` 점수의 의미를 저장한다.
새 f0나 다른 ROI/feature 버전은 호환 오류로 거부한다. ROI 없는 자동 fallback을 하지 않는다.

QualityRecord는 sample_id, 모델·계약 버전, target별 raw_estimate와 [0,1]로 clip한 estimated_iou,
primary_target=lane_full, risk_score=1-estimated_iou, dev 기준 review_flag를 가진다.
**risk_score는 실패 확률이 아니다.** 실행 중 GT 정의 여부를 알 수 있다고 가정하지 않는다.

## 9. 검수 목록·추가학습 manifest

검수 목록 필수: sample_id, risk_score, rank, selection_method, budget_unit,
duplicate_group, episode_id, 원래 후보 pool 버전, 수동 검수 상태, GT 확보 상태, selection 설정 SHA.
표준 예산은 중복 제거한 전방 프레임 수다. 시간·거리 기반 중복 그룹 규칙을 모든 방법에 동일 적용한다.
GT의 label_defined나 실제 IoU로 후보 pool을 미리 줄이지 않는다. undefined 장면도 선택되면 예산에 포함한다.
실제 라벨링 분 단위 절감을 측정하지 않았다면 annotation time 절감이라고 표현하지 않는다.

재학습 admission은 `candidate_pool`에서만 한다. 기존 train을 함께 사용하고 GT 검증 후 추가한다.
meta_dev/final_test를 train으로 이동하지 않는다. 예측 마스크를 GT로 자동 채택하지 않는다.
추가학습으로 f0가 바뀌면 새 model_id를 부여하고 품질 추정기의 성능·임계값을 다시 평가한다.
