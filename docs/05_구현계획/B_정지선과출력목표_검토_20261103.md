# 정지선 활용과 품질 모델의 출력 목표 검토

> 2026-11-03 · 2번 담당의 검토 메모. **M v6의 정지선 본학습을 재확인해 기존 설명을 정정했다.**
> [M v6 근거·수치·입출력 주의점](./M_v6_정지선_재확인_20261103.md)이 M 클래스 설명의 정본이다.

## 1. 정지선은 이미 학습한 M v6에서 활용한다

이전 설명은 v5 binary 체크포인트를 M 전체 이력으로 일반화한 오류였다.
v5는 차선/도로 binary지만 **v6는 도로 2클래스와 노면표시 4클래스**를 출력한다.
노면표시 클래스는 background/white_lane/yellow_lane/stopline이다.
18 epoch 본학습 완료, best_mean 선택 epoch 11과 checkpoint SHA를 확인했다.
해당 과거 validation에서 전방 stopline 누적 IoU는 **0.873175**다.

따라서 기존 M v6를 고정하고 정지선 출력에서도 확률·형태·ROI 특징을 만들 수 있다.
GT와 비교한 정지선 IoU를 별도 회귀 정답으로 두어 차선과 다른 실패를 분석한다.
정지선을 추가하기 위한 새 M 학습이나 L 전환은 필수 작업이 아니다.

남은 것은 ML 쪽 로더·GT 변환·특징·target 계약을 4클래스 task에 맞추는 이식이다.
기존 binary 정책과 14/30/78개 특징 JSON을 v6 규약으로 그대로 사용하지 않는다.
v5 그림은 과거 참고 사례로만 표시하며 v6의 정지선 결과로 재사용하지 않는다.

## 2. 논문에서 ML이 실제로 출력하는 것

| 논문 | 단위 | 학습 정답 | ML 출력과 활용 |
|---|---|---|---|
| [MetaSeg, IJCNN 2020](https://arxiv.org/abs/1811.00648) | 예측 connected segment | IoU=0 여부와 segment 품질 IoU | Logistic 분류 점수와 선형 회귀 IoU. 오류 분류와 품질 회귀를 모두 다룸 |
| [Küchler 2024](https://arxiv.org/html/2401.09245v2) | 예측 segment | precision>0.5 / ≤0.5 | XGBoost 등의 저품질 분류 점수. 큰 값은 낮은 품질, segment 불확실성 맵으로 활용 |
| [SEE, ISCAS 2026](https://epapers2.org/iscas2026/ESR/paper_details.php?paper_id=2485) | 이미지 | 영상별 분할 성능 | RF의 연속적인 성능 추정. 공식 초록·확인한 설명 기준이며 정확 재현 세부는 미확인 |
| [TCSR-Monitor, UNSURE 2026](https://arxiv.org/html/2608.16748v1) | 프레임 | 실제 IoU<tau | XGBoost의 실패 위험 점수. 별도 threshold로 alarm 출력 |

MetaSeg의 segment adjusted IoU와 우리 frame/ROI 일반 IoU는 같은 target이 아니다.
Küchler의 precision을 IoU라고 부르지 않는다. TCSR의 IoU는 분류 정답 생성에 쓰이고,
모델 자체의 최종 출력은 연속 IoU가 아닌 실패 분류 점수다.
0~1 분류 점수도 새 조건에서 보정된 실패 확률을 자동 보장하지 않는다.

## 3. IoU가 유일한 최선의 출력은 아니다

| 목표 | 적합한 학습 출력 | 평가 |
|---|---|---|
| 얼마나 잘 분할했는지 표시 | 전체/ROI별 예상 IoU 회귀 | MAE·순위·과대평가 사례 |
| 저품질 장면 우선 검수 | 회귀 기반 quality deficit 또는 직접 실패 분류 점수 | 동일 검수 예산의 실패 발견율·AP |
| 실행 중 경고 | 점수 + dev에서 정한 threshold | 놓친 실패·오경보·지연시간 |
| 주행 대응 | 특정 기능의 오류 점수·판단 신호 | 실제 기능·대체 동작 효과의 별도 검증 |

IoU는 GT로 쉽게 만들 수 있고 분할 품질을 설명하기 좋다. 다만 얇은 선의 위치 변화에 민감하고,
도로와 여러 표시를 한 mIoU로 평균하면 정지선의 중요한 오류를 숨길 수 있다.
따라서 stopline 품질을 별도로 유지하고 주행 안전도와 동일시하지 않는다.
정지선의 존재·누락이나 거리 오차도 후속 target 후보지만 별도 GT/매칭·기하 정의가 필요하다.

## 4. 2번 담당 제안: 품질 표시와 실패 선별을 나누어 검증

기본 회귀 출력은 유지하되 **같은 X에서 Logistic Regression 실패 분류를 작은 비교 실험**으로 제안한다.
이는 기존 회귀 우선 설계를 폐기하는 결정이 아니라 선별 목표에 더 적합한 출력을 확인하는 실험이다.

```text
같은 출력 특징 X
  ├─ 회귀: 실제 IoU를 학습 → estimated_iou
  │                         quality_deficit = 1-estimated_iou
  └─ 분류: 1[실제 IoU<tau] 학습 → failure_score

두 순위를 동일 검수 예산에서 비교 → 실제 선별에 사용할 점수 선정
고정한 점수에 dev threshold 적용 → review_flag
```

estimated_iou와 quality_deficit, 별도 classifier의 failure_score는 다른 값이다.
1에서 예상 IoU를 빼거나 회귀 점수에 threshold를 적용하는 것만으로 실패 확률이 되지는 않는다.
현재 JSON의 risk_score는 `1-estimated_iou`라는 기존 의미를 유지한다.
새 classifier 점수를 채택하면 다른 필드와 새 schema/version으로 구분해야 한다.

차선·도로·정지선과 영역별 threshold를 모두 동일하게 잡을 필요는 없다. class별 GT 정의·표본 수·
후속 용도와 dev 분포를 근거로 사전 결정하고 최종 test에서 재조정하지 않는다.
정지선이 GT/예측에 모두 없으면 union=0이다. 이를 IoU=0 실패 또는 무조건 1점으로 채우지 않는다.
GT는 있는데 예측이 없으면 누락, GT는 없는데 예측이 있으면 오검출로 구분한다.

이번 문서 작업에서 새 학습은 하지 않았다. 기존 정지선 M v6는 이미 학습됐고,
새 품질 회귀기·분류기는 설계 단계다.
