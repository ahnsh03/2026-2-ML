# 수집·평가·추가학습 계획

> 2026-11-03 · 세부 기술 초안, 11/4 취합 후 규약 동결. 아직 실행 결과 없음.
> [전체 설계](./프로젝트_확정설계_20261103.md) · [입출력](./품질추정_입출력규약.md)

## 1. 데이터 역할을 먼저 나눈다

인지 모델 f0의 학습 split과 품질 추정기 g의 split은 다르다. 기존 v5의 train/val을
이름만 바꿔 곧바로 g의 train/test로 쓰지 않는다.

| 역할 | 사용 | 금지 |
|---|---|---|
| f0_train | 이미 M을 학습한 과거 데이터, 선택 추가학습의 기존 데이터 | g의 최종 일반화 평가라고 주장 |
| historical_dev | 과거 모델 선택·발표에 쓴 val, ROI/코드 파일럿 | 새 blind test라고 주장 |
| meta_train | f0 학습 노출이 없는 새 capture의 X/Y, g 적합 | 다른 역할과 부모 세션 중복 |
| meta_dev | ROI·모델·튜닝·경고 임계값·선별 규칙 선정 | 최종 성능 수치로 사용 |
| candidate_pool | g를 고정한 뒤 검수 후보 선별, 선택 재학습 | final_test에서 후보 가져오기 |
| final_test | 잠근 최종 품질·선별 평가 및 f0 개선 비교 | feature/threshold 수정·재학습 편입 |

f0 학습 노출이 unknown인 자료는 파일럿으로 표시하고 주 최종 test에서 제외한다.
특히 기존 17시 데이터는 모델 개발 이력에 사용됐을 수 있으므로 시간대만 보고 f0 OOD라고 부르지 않는다.
과거 v7/L split 역시 M의 학습 이력을 보장하지 않는다.

split 단위는 **부모 수집 세션/객체 layout 묶음**이다. 같은 묶음의 날씨·시각 변형과
동일 시점의 여러 view는 한 역할에 둔다. 같은 raw capture/RGB 해시·인접 프레임이 역할을 넘지 않도록 검사한다.
한 지도에서의 다른 주행은 지리적 일반화가 아니다. 샘플 수와 함께 독립 세션 수를 보고한다.

## 2. MORAI 수집 설계

초기 핵심 조건은 `SUNNY/FOGGY × 11시/15시`의 4개 cell로 한다. 13시·추가 날씨는
데이터·시간 여유가 있을 때 조건 일반화 실험으로 확장한다. 실제 API 설정값·단위를 기록한다.

- 모든 cell에서 같은 anchor 위치·방향 또는 같은 짧은 경로를 수집해 장소–환경 혼동을 줄인다.
- 차량 자세·센서 설정·맵 버전·주변 객체 배치·seed를 기록한다. 제어하지 못한 것은 미통제로 명시한다.
- 요청한 환경, readback/스크린샷 등 실제 확인 근거, 전환 시점, 안정화 후 첫 capture를 기록한다.
- 각 부모 세션에서 4조건을 모두 포함하되 가능한 한 순서를 교차한다. 반복 실험은 새 세션 ID로 기록한다.
- 후보 규모: 전방 1,200~3,000개 정도로 시작하되 프레임 수보다 독립 수집 묶음과 실패 수를 우선한다.
  중복 제거 후 각 역할·조건의 양성/음성 수를 조사한다. 매우 드문 실패의 지표는 한계를 표시한다.
- 목표 역할 수: meta_train 3개 이상, meta_dev 1개 이상, candidate_pool 1개 이상,
  final_test 2개 이상 부모 수집 묶음. 이는 작업 목표이며 통계적 충분성을 보장하지 않는다.
  적게 확보되면 주행 단위 불확실성을 숨기지 않고 데이터 수집을 먼저 보강한다.
- Capture RGB/Semantic이 실제 존재·동기화·해상도·palette 검사를 통과한 경우만 admission한다.
  Depth/Instance/BBox는 필수 입력이 아니다. 수집 도구를 detection 전용 설정째 복사하지 않는다.
- 원본 파일은 보존하고 audit 제외 이유를 남긴다. 어려운 장면의 정상 RGB를 품질 필터로 삭제하지 않는다.

새 수집은 이번 정리 작업에서 실행하지 않았다. 시뮬레이터·차량 제어·환경 변경은 실제 수집 담당자가 수행한다.

## 3. 모델·특징 비교 행렬

| ID | 모델/점수 | 입력 | 목적 |
|---|---|---|---|
| B0 | train target 평균 상수 | 없음 | 회귀의 최소 기준선 |
| B1 | 낮은 평균 confidence / 높은 평균 entropy | 출력 확률 | 기존 자기 확신과 비교 |
| B2 | Ridge | F_conf 14 | 확률 통계의 학습 효과 |
| B3 | Ridge | F_global 30 | 형태·경계 정보 효과 |
| B4 | Ridge | F_grid 78 | 단순 공간 분할 효과 |
| B5 | Ridge | F_camera_roi 78 | 카메라 기반 ROI 효과 |
| B6 | Random Forest | F_camera_roi 78 | 같은 특징에서 비선형 모델 효과 |
| 선택 | RF F_global/F_grid, 출력 temporal 추가 | 같은 계약 | 상호작용·시간 특징 추가 검증 |

B1의 raw confidence/entropy는 예상 IoU가 아니다. MAE 비교에는 meta_train에서 단변량 회귀를
적합해 점수→IoU 매핑을 학습한 B1-reg를 별도로 사용한다. 순위/선별 비교에는 raw score를 그대로 쓴다.
Ridge 결과는 raw와 [0,1] clip 결과를 모두 보관하고 기본 지표는 모든 회귀 방법에 동일하게 clip한다.
모델 선택은 primary `lane_full`의 meta_dev MAE를 우선하고, 선별 성능도 함께 확인한다.
여러 설정이 비슷하면 작은 모델을 택한다. 전체 데이터로 표준화·대치·특징 선택을 하지 않는다.

MetaSeg는 segment의 adjusted IoU를 다루고 우리는 frame/고정 ROI의 일반 IoU를 다룬다.
따라서 B3~B6는 **MetaSeg-inspired**이며 원 논문 재현 수치라고 쓰지 않는다.

## 4. 품질·오류 평가

- **회귀:** target별 MAE, Spearman 순위 상관, 예상–실제 산점도. 전체 프레임 평균과 세션별 평균을 함께 보고한다.
- **실패 선별:** defined `lane_full IoU < 0.7`을 양성으로 두고 average precision(AP), PR 곡선을 보고한다.
  AP와 trapezoidal PR-AUC를 혼용하지 않는다. 상수 점수·동점 순위 처리도 기록한다.
  양성/음성이 없거나 값이 일정해 지표가 정의되지 않으면 NA와 해당 개수를 보고한다.
- **임계값:** meta_dev의 정상 프레임 오경보율 10% 이하를 목표로 threshold를 고정하고
  final_test의 실제 오경보율·실패 재현율을 보고한다. 테스트에서 10%로 다시 맞추지 않는다.
- **선택적 사용:** 위험 순으로 거부했을 때 coverage 대 남은 frame 평균 `1-IoU`, AURC(낮을수록 좋음).
  모든 방법에 같은 defined subset을 적용하고 undefined 비율을 별도로 표시한다.
- **과신 오류:** meta_dev에서 고정한 높은 confidence 기준 + 실제 낮은 IoU 집단에서
  기존 confidence와 추정기가 각각 얼마나 놓치는지 평가한다. 그 집단의 표본·세션 수도 명시한다.
- **빈 정답/작은 support:** union=0인 장면과 작은 차선 GT 장면을 별도 표로 보고한다.
  ROI마다 동일한 평가 가능 행을 사용하고, 지표를 좋게 만들기 위해 작은 GT를 사후 제거하지 않는다.
- **불확실성:** 세션 단위 bootstrap을 우선한다. test 세션이 너무 적으면 CI를 정밀한 것처럼 해석하지 않는다.
  인접 frame을 독립 표본으로 계산한 좁은 CI를 대표 지표로 쓰지 않는다.

조건별 표는 `환경, 세션 수, n, 실패 비율, 실제 IoU, 추정 MAE, 선별 발견율, 오경보율`을 포함한다.
날씨·시각을 입력하지 않아도 GT와 메타데이터로 사후 비교할 수 있다.

## 5. 같은 검수 예산에서의 데이터 선별

1. g와 규칙을 고정한다. candidate_pool의 X만으로 순위를 계산한다.
2. 모든 방법에 같은 시간/위치 기반 중복 그룹을 적용한다. 기본은 장면당 전방 대표 프레임 1개다.
   간격은 수집 주기·속도 기록과 meta_dev를 근거로 고정하고, 이동하지 않은 Capture를 시간만으로 새 장면 취급하지 않는다.
3. 대표 프레임 pool에서 5/10/20% 예산을 적용한다. Random, confidence, entropy, 학습 점수를 비교한다.
4. GT를 평가 단계에서 열어 실패 발견율=`선택된 실패 수/전체 pool 실패 수`,
   precision=`선택된 실패 수/선택 수`, lift=`제안 발견율/Random 발견율`을 구한다.
5. Random은 100 seed 반복의 평균·분산을 보고한다. 제안 방법의 동점은 sample_id 순 등 고정 규칙으로 푼다.
6. 조건별 선택 비율·비선택 실패를 확인한다. 모니터가 놓치는 실패를 위해 무작위 감사 샘플 필요성을 논의한다.

primary 검수 예산 단위는 **프레임 수**다. 실제 분 단위 라벨링 비용은 측정하지 않았으면 주장하지 않는다.
선별·예산 계산은 GT를 보지 않은 전체 eligible pool에서 수행한다. `label_defined`로 미리 후보를
거르지 않는다. IoU undefined 장면을 선택해도 예산은 소비하며 그 수를 별도로 보고한다.
candidate_pool은 재학습 실험용 개발 결과다. 일반화 주장에는 final_test에서도 동일한 선별 평가를 하되
final_test의 선택 프레임은 실제 train에 추가하지 않는다.
GT가 있으므로 직접 IoU로 순위를 매긴 Oracle도 상한으로 제시할 수 있으나 실사용 방법은 아니다.

## 6. 선택: 인지 모델의 동일 예산 추가학습

필수 품질/선별 평가가 끝나고 학습 시간 측정이 가능할 때만 실행한다.

| 통제 항목 | 규칙 |
|---|---|
| 초기 모델 | 모든 arm에서 같은 M EMA 가중치. 새 optimizer/scheduler, resume 아님 |
| 데이터 | 같은 기존 train + 같은 크기의 신규 admission. GT·정책·중복 조건 동일 |
| arm | no-update 기준, Random 추가, 품질 기반 추가. 여유 시 entropy 추가 |
| 예산 | 동일 신규 frame 수, optimizer step 수, replay 비율, augmentation, seed 묶음 |
| 후보 | candidate_pool만 사용. 평가 프레임/인접 묶음 편입 금지 |
| test | 같은 final_test에서 full/ROI/class/조건별 성능과 기존 조건 회귀 확인 |
| 반복 | 1 seed는 탐색 결과. 시간 허용 시 같은 2 seed 이상으로 paired 비교 |

실패 장면만 과다 반복하지 않는다. 기존 train replay는 모든 arm에 동일하게 넣는다.
신규 예측 마스크를 GT로 쓰지 않는다. 시뮬레이터 GT 감사 후 추가한다.
추가학습의 효과가 없거나 회귀하면 그 결과를 보고하고, 선별 효율과 인지 개선을 분리해 결론낸다.
새 f1 성능에 기존 g의 출력이 그대로 맞는다고 가정하지 말고 재검증한다.

## 7. 조건 일반화와 원인 가설

주 실험은 같은 지도에서 독립 부모 세션을 평가한다. 별도 실험에서 한 날씨/시간대를
g 학습에서 제외할 수 있다. 이때 paired 장소를 공유하면 **새 조건 일반화**이지 새 장소 일반화가 아니다.
같은 부모 세션 전체를 묶는 주 split과 조건 제외 실험의 split을 별도 버전으로 기록한다.

TCSR에서 차용할 검증: 안개 같은 동일 조건 안에서 성공·실패를 구분하는지 확인한다.
조건 전체에 낮은 점수를 주는 것만으로 실패를 예측했다고 결론내리지 않는다.
추가 통제 실험은 같은 위치/자세/배치에서 날씨와 시간을 교차하고, 실패가 실제로 달라지는지 확인한다.
Feature importance는 추정기의 사용 정보에 대한 설명이며 조명·날씨의 인과 효과가 아니다.

## 8. 최종 필수 그림

1. 실제 IoU 대 예상 IoU 산점도 + target별 MAE 표.
2. 같은 검수 예산의 실패 발견율 곡선(Random/confidence/entropy/ML).
3. F_global/F_grid/F_camera_roi와 Ridge/RF 비교 표.
4. 조건별 실제 성능·추정 오차와 과신 오류 갤러리.
5. risk–coverage와 오경보/재현율. 재학습 수행 시에만 f0→f1 개선 표를 추가한다.
