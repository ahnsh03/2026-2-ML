# 개발 환경 — 필요한 것, 경로, 실행 방법

> 기준일: 2026-09-23 · 관련: [A1 구현 계획 §9](./A1_구현계획.md#9-구현-구조) · [외부 코드 선별](./외부코드_선별.md)

## 1. 워크스페이스 배치

이 레포는 개인 워크스페이스 안에 둔다. `external/`과 `outputs/`는 **레포 밖**이며 Git에 올리지 않는다.

```text
<워크스페이스>/
├── 2026-2-ML/          이 레포 (팀 공유)
│   └── config/local.env   각자 PC의 경로·이미지 이름 (Git 제외, 예시: local.env.example)
├── external/           인지 코드 레포 클론 — 개인 참고용, 읽기 전용
└── outputs/            생성 결과 (추론 시각화 등) — 원본 데이터 파생물
```

데이터·체크포인트·TwinLiteNet+ 소스는 각자 PC의 원래 위치를 그대로 쓰고, 경로만 `config/local.env`에 적는다.

## 3. 컨테이너 실행 — `scripts/run_container.sh`

인지 모델 학습 이미지를 그대로 쓰되, **이 레포와 출력 폴더를 추가로 마운트한 일회용 컨테이너**를 띄운다.
기존에 쓰던 학습 컨테이너는 인지 코드 레포만 마운트하고 있어서 이 레포 코드를 볼 수 없기 때문이다.

처음 한 번 설정 파일을 만든다.

```bash
cp config/local.env.example config/local.env   # 그리고 자기 PC 경로로 채운다
```

| 변수 (`config/local.env`) | 의미 | 컨테이너 안 경로 |
|---|---|---|
| `PERCEPTION_REPO` | 인지 코드 레포 클론 | `/perception` (ro) |
| `PERCEPTION_DATA` | 데이터 루트 (`datasets/`, `dataset_versions/`) | `/data` (ro) |
| `PERCEPTION_CKPT_ROOT` | 체크포인트 폴더들이 있는 곳 | `/ckpt` (ro) |
| `TWINLITE_SOURCE` | TwinLiteNet+ 원본 소스 | `/opt/baselines/TwinLiteNetPlus` (ro) |
| `PERCEPTION_IMAGE` | 학습 이미지 이름 | — |
| `ML_OUTPUT_ROOT` (선택) | 결과 폴더, 기본은 레포 상위의 `outputs/` | `/outputs` (rw) |

```bash
scripts/run_container.sh <명령...>
scripts/run_container.sh python3 -m visualization.visualize_inference --help
```

- 결과 파일이 root 소유가 되지 않도록 **호스트 사용자 권한(`--user`)으로 실행**한다. 그래서 마운트 위치를 `/root` 밖에 둔다.
- 이 레포는 읽기 전용으로 마운트되고 `PYTHONPATH=/ml/src`로 import한다.
- 설정 파일을 다른 곳에 두려면 `ML_LOCAL_ENV=/경로/local.env scripts/run_container.sh …`.

## 4. 추론 결과 시각화 — `src/visualization/visualize_inference.py`

```bash
# val 전체 (468 frame × 3뷰)
scripts/run_container.sh python3 -m visualization.visualize_inference --split val --name v5b_val

# 특정 run에서 고르게 6 frame
scripts/run_container.sh python3 -m visualization.visualize_inference --split train \
  --run-id 20260903_220750_kcity_comp_sample_sunny_sim5pm_wheel --max-frames-per-run 6 --name sunny5pm
```

| 옵션 | 의미 |
|---|---|
| `--split`, `--run-id`, `--every-n`, `--max-frames-per-run` | frame 선택. front·left·right가 모두 있는 frame만 쓴다 |
| `--grid dev\|pilot` | BEV 격자. `dev` = 전방 −5~30 m·좌우 ±12 m (열화까지 보이는 탐색용), `pilot` = −5~20 m·±8 m (검증된 범위) |
| `--bev-scale` | BEV 확대 배율 (기본 2 → 0.05 m/px) |
| `--skip-existing` | 이미 만든 frame은 건너뛰고 목록만 합친다 |

결과: `<워크스페이스>/outputs/inference_vis/<name>/` — 폴더 구조·색 범례는 그 안의 `README.md`, 전체 보기는 `index.html`.
카메라마다 원본(`rgb/`), 추론 마스크·확률, GT 마스크, overlay, 오류맵, 투명 레이어를 따로 저장하고,
BEV는 3카메라 원본 영상 투영(`bev/rgb`)과 추론·GT를 함께 저장한다.

**처리 방식**
- 추론: 대상 모델(EMA)을 외부 평가 스크립트(`evaluate_twinlite.py`)와 같은 절차로 불러오고, softmax 확률을 `restore_probability`로 원본 해상도에 복원한 뒤 0.5로 이진화한다.
- IoU: 기존 평가와 같은 384×640 letterbox 공간·valid mask 기준. union = 0이면 `nan`.
- BEV: `drivable_bev`의 `cameras_v2.yaml`(노면 z = −0.35 m), 격자 설정, 품질 가중 융합을 그대로 사용한다. 차선은 road-marking class 1로 넣는다.

**검증 기록 (2026-09-23)** `[확정]`
- 컨테이너 안에서 외부 인지 패키지 import 확인 (Python 3.8.10).
- 센서셋 SHA-256과 카메라 보정 스냅샷 일치 확인 (`calibration_warning = null`).
- val 468 frame × 3뷰 = 1,404 sample의 lane·drivable IoU가 기존 평가 기록과 모두 대응 (최대 차이 lane 0.004, drivable 0.0005 — 혼합정밀도 연산 차이 수준).
- 처리 시간: val 전체 약 2분, 이미지 23,400장, 1.7 GB.
