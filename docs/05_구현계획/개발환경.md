> 기준일: 2026-09-28 · 관련: [A1 구현 계획 §9](./A1_구현계획.md#9-구현-구조) · [외부 코드 이관 기록](./외부코드_선별.md)

## 1. 레포 구성과 워크스페이스 배치

**이 레포는 다른 레포 없이 돈다.** 인지 모듈, TwinLiteNet+ 원본(서브모듈), 데이터 수집·가공 코드가 모두 안에 있다.
Git 밖에 두는 것은 데이터, 체크포인트, 결과물, MORAI gRPC proto뿐이다.

```text
<워크스페이스>/
├── 2026-2-ML/                       이 레포 (팀 공유, 공개)
│   ├── config/                      local.env(Git 제외), bake 정책, BEV 보정(bev/), MORAI 센서셋·네트워크 설정(morai/)
│   ├── docker/ros-noetic/           수집 컨테이너 이미지 정의 (참고·재현용)
│   ├── ros/src/                     catkin 워크스페이스: data_collection, morai_msgs(서브모듈)
│   ├── scripts/                     run_container.sh, run_ros.sh, 동기화·감사·선별·bake·dataset 스크립트
│   ├── src/                         twinlite_morai, drivable_bev, camera_semantic_perception, common, visualization
│   └── third_party/TwinLiteNetPlus  공식 TwinLiteNet+ (서브모듈, MIT, 90f1b86 고정)
├── checkpoints/                     대상 체크포인트 (<run 이름>/best_mean.pt)
├── data/                            새로 수집한 데이터
├── external/morai_grpc_proto/       MORAI gRPC proto (MORAI 제공 생성 코드, 공개 레포에 넣지 않는다)
└── outputs/                         생성 결과 (추론 시각화 등)
```

처음 받을 때:

```bash
git clone --recurse-submodules https://github.com/ahnsh03/2026-2-ML.git
git submodule update --init                      # 이미 받은 레포라면
cp config/local.env.example config/local.env     # 자기 PC 경로로 채운다
```

## 3. 추론 컨테이너 — `scripts/run_container.sh`

추론 이미지로 **이 레포와 출력 폴더를 마운트한 일회용 컨테이너**를 띄운다. 추론·시각화·export는 여기서 돈다.

| 변수 | 의미 | 컨테이너 안 경로 |
|---|---|---|
| `PERCEPTION_DATA` | 데이터 루트 (`datasets/`, `dataset_versions/`) | `/data` (ro) |
| `PERCEPTION_CKPT_ROOT` | 체크포인트 폴더들이 있는 곳 | `/ckpt` (ro) |
| `PERCEPTION_IMAGE` | 추론 이미지 이름 | — |
| `ML_OUTPUT_ROOT` (선택) | 결과 폴더, 기본은 레포 상위의 `outputs/` | `/outputs` (rw) |

```bash
scripts/run_container.sh <명령...>
scripts/run_container.sh python3 -m visualization.visualize_inference --help
```

- 결과 파일이 root 소유가 되지 않도록 **호스트 사용자 권한(`--user`)으로 실행**한다. 그래서 마운트 위치를 `/root` 밖에 둔다.
- 이 레포는 `/ml`에 읽기 전용으로 마운트되고 `PYTHONPATH=/ml/src`로 import한다. TwinLiteNet+는 `/ml/third_party/TwinLiteNetPlus`에서 읽는다.
- 설정 파일을 다른 곳에 두려면 `ML_LOCAL_ENV=/경로/local.env scripts/run_container.sh …`.

## 4. 수집 컨테이너 — `scripts/run_ros.sh`

수집 이미지(`ROS_IMAGE`)를 그대로 쓰되, **이 레포 전용 컨테이너**(`ROS_CONTAINER`, 기본 `ml-ros-noetic`)를 따로 띄운다.

| 명령 | 하는 일 |
|---|---|
| `scripts/run_ros.sh up` | 컨테이너를 만들고 시작한다. 레포 → `/ml`(rw), `ML_DATA_ROOT` → `/data`(rw), proto → `/opt/morai_grpc_proto`(ro), host network |
| `scripts/run_ros.sh build` | `ros/` 워크스페이스를 `catkin_make`한다. `ros/build`, `ros/devel`은 Git 제외 |
| `scripts/run_ros.sh exec <명령…>` | ROS 환경(`devel/setup.bash`)이 잡힌 상태로 명령 하나를 실행한다 |
| `scripts/run_ros.sh shell` | ROS 환경이 잡힌 bash |
| `scripts/run_ros.sh status` / `down` | 상태 확인 / 컨테이너 삭제 |

- 컨테이너에 레이블(`ml2026.repo`)을 붙이고, **이 레포가 만든 컨테이너만 다룬다.** 같은 이름의 다른 컨테이너가 있으면 멈춘다.
- **host network라서 ROS master(11311)와 MORAI UDP 포트를 다른 ROS 컨테이너와 공유한다.** 다른 ROS master가 떠 있으면 `up`이 경고한다. 수집은 다른 ROS 스택을 내린 상태에서 한다.
- `docker/ros-noetic/`의 정의로 이미지를 새로 빌드할 때는 **기존 이미지와 다른 태그**를 쓴다. 같은 태그로 빌드하면 기존 이미지를 덮어쓴다.

## 5. 데이터 수집·가공 순서

run_id 규칙: `<YYYYMMDD>_<HHMMSS>_kcity_<scenario>_<weather>_sim<hh><am|pm>_<controller>`. collector가 날씨·시나리오를 기록하지 않으므로 [수집 대장](./A1_구현계획.md#35-수집-대장)에 적는다.

| # | 단계 | 어디서 | 명령·내용 |
|---|---|---|---|
| 1 | MORAI 설정 | Windows | 센서셋 `config/morai/sensor_set_v2.json`, 네트워크 `config/morai/network_set_local.json`을 불러온다. Capture Mode를 켜고 날씨·시각을 UI에서 정한다 |
| 2 | UDP 브리지 | 수집 컨테이너 | `scripts/run_ros.sh exec roslaunch data_collection morai_udp_bridge.launch` — `/Ego_topic` 발행 (3의 `require_ego`·`only_when_moving`에 필요) |
| 3 | 수집 | 수집 컨테이너 | `scripts/run_ros.sh exec roslaunch data_collection capture_mode_collector.launch capture_hz:=1.0 only_when_moving:=true require_ego:=true min_speed_mps:=0.2 run_id:=<run_id>` |
| 4 | 동기화 | **WSL 호스트** (`/mnt/c`가 필요) | `python3 scripts/sync_capture_mode_data.py --run-id <run_id> --dry-run` → 확인 후 `--jobs 4`. Windows `SensorData` → `<ML_DATA_ROOT>/datasets/<run_id>/` |
| 5 | Semantic 감사 | 수집 컨테이너 | `scripts/run_ros.sh exec python3 scripts/audit_semantic_capture.py --run-id <run_id>` |
| 6 | 정차 선별 | 수집 컨테이너 | `scripts/run_ros.sh exec python3 scripts/curate_perception_frames.py --run-id <run_id> --output-name curation_v2` |
| 7 | 마스크 bake | 수집 컨테이너 | 아래 |
| 8 | dataset version | 수집 컨테이너 | 아래 |

```bash
scripts/run_ros.sh exec python3 scripts/bake_perception_masks.py --run-id <run_id> --stage all \
  --policy config/perception_target_policy_v3_actor_negative.json \
  --curation-name curation_v2 \
  --native-output-name perception_targets_native_v3_actor_negative \
  --output-name twinlite_384x640_marking_actor_negative_v1

scripts/run_ros.sh exec python3 scripts/build_perception_dataset.py \
  --dataset-name ml2026_<이름>_v1 --cache-name twinlite_384x640_marking_actor_negative_v1 \
  --train-run <run_id> … --val-run <run_id> … --test-run <run_id> …
```

- 컨테이너 안의 스크립트는 `ML_DATA_ROOT=/data`를 기본 데이터 루트로 쓴다. 호스트의 동기화 스크립트는 `ML_DATA_ROOT` 또는 레포 상위의 `data/`를 쓴다. 다르면 `--data-root`로 넘긴다.
- bake 정책 파일은 **바이트 그대로** 옮겼다(SHA-256 `21521b2b…`). bake 결과에 이 해시가 기록되므로 고치지 않는다. 정책 경로는 작업 폴더 기준이라 레포 루트(`/ml`)에서 실행한다.
- 수집 이미지의 OpenCV는 5.0이고 추론 이미지는 4.9다. 기존 v5 데이터와 새 데이터의 bake 결과가 픽셀 단위로 조금 다를 수 있다. 새 데이터끼리는 같은 이미지에서 bake한다.
- MORAI gRPC proto가 있으면 수집 노드가 gRPC(`127.0.0.1:7789`)로 Capture를 요청하고 응답을 확인한다. 없으면 ROS 토픽 `/SaveSensorData`로 요청한다.

## 6. 추론 결과 시각화 — `src/visualization/visualize_inference.py`

```bash
# val 전체 (468 frame × 3뷰)
scripts/run_container.sh python3 -m visualization.visualize_inference --split val --name v5b_val

# 특정 run에서 고르게 6 frame
scripts/run_container.sh python3 -m visualization.visualize_inference --split train \
  --run-id 20260903_220750_kcity_comp_sample_sunny_sim5pm_wheel --max-frames-per-run 6 --name sunny5pm
```

| 옵션 | 의미 |
|---|---|
| `--split`, `--run-id`, `--every-n`, `--max-frames-per-run` | frame 선택. front·left·right가 모두 있는 frame만 쓴다 |
| `--grid dev\|pilot` | BEV 격자. `dev` = 전방 −5~30 m·좌우 ±12 m (열화까지 보이는 탐색용), `pilot` = −5~20 m·±8 m (검증된 범위) |
| `--bev-scale` | BEV 확대 배율 (기본 2 → 0.05 m/px) |
| `--skip-existing` | 이미 만든 frame은 건너뛰고 목록만 합친다 |

결과: `<워크스페이스>/outputs/inference_vis/<name>/` — 폴더 구조·색 범례는 그 안의 `README.md`, 전체 보기는 `index.html`.
카메라마다 원본(`rgb/`), 추론 마스크·확률, GT 마스크, overlay, 오류맵, 투명 레이어를 따로 저장하고,
BEV는 3카메라 원본 영상 투영(`bev/rgb`)과 추론·GT를 함께 저장한다.

**처리 방식**
- 추론: 대상 모델(EMA)을 원본 평가 스크립트(`evaluate_twinlite.py`)와 같은 절차로 불러오고, softmax 확률을 `restore_probability`로 원본 해상도에 복원한 뒤 0.5로 이진화한다.
- IoU: 기존 평가와 같은 384×640 letterbox 공간·valid mask 기준. union = 0이면 `nan`.
- BEV: `config/bev/cameras_v2.yaml`(노면 z = −0.35 m), 격자 설정, 품질 가중 융합을 그대로 사용한다. 차선은 road-marking class 1로 넣는다.
