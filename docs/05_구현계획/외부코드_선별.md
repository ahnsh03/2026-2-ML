# 외부 코드 이관 기록 — 원본 인지 코드 레포에서 옮긴 것

> 기준일: 2026-09-28 · 원본: 인지 코드 레포(비공개) `main` `d0922bb` · 원작성: 안승현 (Docker 정의 일부 장원태)
> 계획: [A1 구현 계획](./A1_구현계획.md) · 실행: [개발 환경](./개발환경.md)

**이 레포는 원본 레포 없이 돈다.** 필요한 코드는 모두 이 레포로 옮겼고, 원본을 다시 import하거나 원본 스크립트를 경유해 실행하지 않는다.
고칠 것이 생기면 이 레포 안에서 고친다.

- 옮긴 `.py` 파일 머리에 원본 커밋과 경로를 주석으로 남겼다.
- 공개 레포이므로 원본 프로젝트 이름·경로·이미지 이름을 뺐다. 바뀐 것은 환경변수 이름, 설정 파일 이름, 주석뿐이고 동작은 그대로다.
- 9/23판(원본을 `sys.path`로 import하던 방식)의 선별 내용은 git 이력(`2ff215c`)에 있다.

### compose를 옮기지 않은 이유

원본 compose를 이름만 바꿔 쓰면, 같은 compose 프로젝트 이름(폴더 이름 `ros-noetic`)과 이미지 태그를 공유하게 된다.
그러면 `up --force-recreate`·`down`·`build`가 원본 프로젝트의 컨테이너와 이미지를 덮어쓸 수 있다. 그래서 `docker run`으로 이름과 레이블이 다른 컨테이너를 만드는 스크립트로 바꿨다.

## 옮기지 않은 것

| 대상 | 이유 |
|---|---|
| MORAI gRPC proto (생성된 `*_pb2*.py`) | MORAI가 제공한 생성 코드라 공개 레포에 넣지 않는다. 워크스페이스 `external/morai_grpc_proto/`에 두고 `MORAI_GRPC_PROTO_ROOT`로 가리킨다 |
| 시나리오 자동 실행기 | gRPC SDK 전체와 MGeo 지도(약 41 MB)가 필요하고 MORAI 자료가 섞여 있다. 수집 노드와 독립이라 없어도 수집은 된다. 자동주행은 MORAI 쪽 기능으로 한다 |
| bag 녹화·재생·감사 노드, sync collector, bag profile | Capture Mode 수집에 쓰지 않는다 |
| 브리지 패키지의 나머지 (전체 bridge launch, 팀 메시지 패키지 의존) | `/Ego_topic`에는 UDP 브리지 노드 하나로 충분하다 |
| 학습 스크립트 | 필요해지면 같은 방식으로 옮긴다 |
| `drivable_bev`의 차선 구조화·측위 모듈 | BEV 측위는 캡스톤 영역이다. 시각화용 투영·융합만 쓴다 |
| 계획·제어, 신호등, LiDAR 인지 | 범위 밖 |
| 원본 README들 | 원본 프로젝트 경로·이름이 많아 옮기지 않았다. 사용법은 [개발 환경](./개발환경.md)에 새로 썼다 |
