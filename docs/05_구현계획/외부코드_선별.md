# 외부 코드 선별 — A1에서 가져다 쓸 것

> 기준일: 2026-09-23 · 대상: 인지 코드 레포(비공개, `main` `d0922bb`) — 각자 가진 클론을 읽기 전용으로 마운트 ([개발 환경](./개발환경.md))
> 계획: [A1 구현 계획](./A1_구현계획.md)

기존 MORAI 프로젝트의 인지 코드 레포(약 1,800개 파일) 중 A1에 필요한 것만 추린다. 처리 방식은 네 가지다.

| 구분 | 의미 |
|---|---|
| **① import** | 이 레포 코드에서 `sys.path`로 그대로 불러 쓴다. 수정하지 않는다 |
| **② 복사 후 수정** | 이 레포 `src/`로 복사해 확장한다. 원본 경로와 커밋을 파일 머리 주석에 남긴다 |
| **③ 원래 워크스페이스에서 실행** | 데이터 수집·가공용. 복사하지 않고 인지 코드 레포에서 원래 절차대로 돌린다 |
| **④ 참고만** | 확장 단계나 분석 아이디어용. 필요할 때 읽는다 |

---

## ① import — 모델·데이터 로딩 (`src/perception/twinlite_morai/`)

| 파일 | 쓰는 것 | 이유 |
|---|---|---|
| `external_model.py` | `load_external_twinlite(config, root)` | 공식 TwinLiteNet+ 소스를 레포 밖에서 불러오고 **upstream 커밋 `90f1b86`을 검사**한다. 같은 모델임을 보장 |
| `dataset.py` | `MoraiTwinLiteDataset(data_root, dataset_version, split)` | manifest 검증, letterbox, valid mask, `meta`(sample_id·run_id·frame_id·view·geometry)까지 그대로 제공 |
| `losses.py` | `adapt_twinlite_outputs(outputs)` | 모델 출력을 `{"drivable": …, "lane": …}` dict로 정리 |
| `training.py` | `move_batch_to_device(batch, device)` | 중첩 dict batch를 GPU로 이동 |
| `tasks.py` | task 계약 (binary lane vs 4-class) | `dataset.py`가 내부에서 사용. 직접 쓸 일은 없음 |
| `__init__.py` | 위 공개 API | `from twinlite_morai import …` |

### ① import — BEV 투영·원본 해상도 복원 (시각화에서 사용 중)

| 모듈 | 쓰는 것 | 이유 |
|---|---|---|
| `drivable_bev/calibration.py` | `load_calibration_snapshot`, `validate_sensor_set_snapshot` | `config/cameras_v2.yaml`(노면 z = −0.35 m)을 읽고 센서셋과 일치하는지 검사 |
| `drivable_bev/grid.py` | `BevGridSpec` | `bev_grid.yaml`(pilot) / `bev_grid_dev.yaml`(dev) 격자 |
| `drivable_bev/projector.py`, `homography.py` | `CameraBevProjector` | 카메라별 지면 homography와 coverage |
| `drivable_bev/fusion.py` | `build_quality_maps`, `CameraBevFusion` | 품질 가중 3카메라 융합 |
| `drivable_bev/rgb_bev.py` | `warp_rgb_to_bev`, `fuse_rgb_views` | 원본 영상 BEV |
| `camera_semantic_perception/geometry.py` | `LetterboxGeometry`, `restore_probability` | 384×640 출력을 원본 해상도로 복원 (실시간 추론 노드와 같은 방식) |

import 경로는 `src/common/bridge.py`의 `add_perception_import_paths`가 한 번에 추가한다.

```python
from common.bridge import add_perception_import_paths, resolve_perception_repo, load_target_model
add_perception_import_paths(resolve_perception_repo())   # $PERCEPTION_REPO (컨테이너에서는 /perception)
from twinlite_morai import MoraiTwinLiteDataset, adapt_twinlite_outputs
```

의존성: torch 2.1.2, OpenCV, numpy, PyYAML → 인지 모델 학습 이미지에 모두 있다.
두 패키지의 `__init__.py`가 하위 모듈을 모두 import하지만 ROS 의존성은 없어 학습 이미지에서 그대로 동작한다(2026-09-23 확인).

## ② 복사 후 수정 — 이 레포의 핵심 코드 출발점

| 원본 | 복사 위치 | 무엇을 바꾸나 |
|---|---|---|
| `scripts/evaluate_twinlite.py` (283줄) | `src/export/export_frame_features.py` | 체크포인트·EMA·SHA-256 검사는 유지하고, softmax 확률 기반 feature, sample별 계수(`intersection`·`union`·`target_px`·`pred_px`), **`union = 0`이면 NaN**, 24×40 오류맵, 영상 통계, TTA 옵션, ego 상태 결합, `export_meta.json`을 추가 ([계획 §9.2](./A1_구현계획.md#92-export-스크립트-명세-srcexportexport_frame_featurespy)) |
| `scripts/render_twinlite_predictions.py` (237줄) | **`src/visualization/`로 대체 (구현됨)** | 복사 대신 새로 작성했다. run·frame 선택, 카메라별 원본·마스크·overlay·오류맵, BEV, mosaic, `index.html`까지 만든다. 군집 갤러리는 이 렌더링 함수(`visualization/camera.py`, `bev.py`)를 재사용한다 |

> 원본 평가 스크립트의 IoU는 `intersection / max(1, union)`이라 GT·예측이 모두 비면 0이 된다.
> 이 레포 코드에서는 이 경우를 NaN으로 바꾸고, 원본은 건드리지 않는다.

## ③ 원래 워크스페이스에서 실행 — held-out 데이터 수집·가공

순서대로 쓴다. 명령은 [계획 §3.4](./A1_구현계획.md#34-처리-파이프라인--기존-수집-스크립트를-그대로-쓴다)와 인지 코드 레포의 `src/data_collection/README.md`에 있다.
괄호 안의 모듈은 모두 `src/data_collection/src/data_collection/` 아래에 있다.

| 단계 | 파일 | 역할 |
|---|---|---|
| 수집 | `src/data_collection/launch/capture_mode_collector.launch`, `src/data_collection/scripts/capture_mode_collector_node.py` (+ `capture_mode.py`, `capture_grpc.py`) | Capture Mode를 gRPC(7789)로 1 Hz 트리거, 차량 제어는 하지 않음 |
| 센서셋 | `config/morai/sensors/` 의 GT 센서셋 | Semantic 카메라 3대 + Instance LiDAR 포함 |
| 동기화 | `scripts/sync_capture_mode_data.py` (+ `capture_sync.py`) | Windows `SensorData` → `<데이터 루트>/datasets/<run_id>/`, 18파일 무결성 검사 |
| 품질 검사 | `scripts/audit_semantic_capture.py` | Semantic 색상·클래스 감사 |
| 정차 선별 | `scripts/curate_perception_frames.py` | 정차 중 중복 frame 비파괴 선별 |
| 마스크 bake | `scripts/bake_perception_masks.py` (+ `mask_baker.py`), `config/perception_target_policy_v3_actor_negative.json` | **대상 모델(v5 B) 학습 데이터와 같은 정책·cache 이름**으로 생성해야 IoU가 비교 가능 |
| dataset version | `scripts/build_perception_dataset.py` (+ `perception_dataset.py`) | `--test-run` 지원. 단 train이 최소 1 run 필요 → v5 B train/val 유지 + 신규 run을 test로 |
| 실행 환경 | `docker/perception-train/` | 이 레포의 export·시각화도 같은 이미지에서 실행 |
