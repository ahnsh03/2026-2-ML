### 4인째 후보에 대한 제안

**판단·제어 파트(정윤태·양서준·이강태 중 1인)** 를 권한다.

- 인지 신뢰도의 **최종 소비자가 플래너**다. "이 확률값을 받아서 무엇을 하겠는가"를
  발표 마지막에 붙일 수 있어 스토리가 닫힌다.
- GP·튜닝 파트는 기존 프로젝트 담당과 무관하게 맡길 수 있어 진입 장벽이 없다.
- 대안: 학술동아리 내 데이터 분석에 관심 있는 인원.

## 후보별 분업안

### A2 (센서 불일치 기반 인지 실패 예측) — 가장 균형적

| 담당 | 역할 | 앵커 주차 |
|---|---|---|
| 안승현 | 카메라 feature·라벨 파이프라인, 데이터 통합, 베이스라인, 발표 총괄 | 2·3 |
| 손재호 | LiDAR 정합 feature, 앙상블 모델·feature importance | 11 |
| 장원태 | 지도 정합 feature, PCA·GMM 실패모드 군집 | 6·13 |
| 4인째 | GP 신뢰구간·calibration, random search 튜닝 | 12·14 |

**성능 향상 계단이 분업과 일치한다**: 임계값 → logistic → +LiDAR → +지도 → 앙상블 → GP.
각 단계의 AUC 상승분이 그대로 각자의 기여로 표시된다.

### A1 (카메라 단독) — 정합이 막혔을 때

| 담당 | 역할 | 앵커 주차 |
|---|---|---|
| 안승현 | feature CSV export, split 설계, 통합 | 2·3·4 |
| 팀원 A | 앙상블 + 하이퍼파라미터 튜닝 + feature importance | 11·14 |
| 팀원 B | GP·UQ + calibration 분석 | 12 |
| 팀원 C | PCA + GMM/EM 실패모드 군집 + 시각화 | 6·13 |

이 구조에서는 팀원이 **MORAI도 GPU도 원본 영상도 필요 없다.** CSV 한 장으로 작업한다.

### B1 (휠 슬립·stuck 검출) — ERC로 갈 경우

| 담당 | 역할 |
|---|---|
| 1인 | 로그 파싱·시간 정렬 (중첩 JSON IMU, Hz 불일치) |
| 1인 | 라벨 설계 + `기본 거동 실험` 통제 데이터로 검증 |
| 1인 | 앙상블 모델 + 튜닝 |
| 1인 | GP + PCA/GMM 주행 regime 분석 |

## 데이터 공유 원칙 `[확정]`

MORAI 프로젝트 데이터를 강의 프로젝트에 쓰는 것과 관련해 지켜야 할 선:

1. **팀원에게 나가는 것은 feature CSV뿐이다.** 원본 영상·점군·주행 로그 자체는 공유하지 않는다.
   → 공유 범위가 좁아 데이터 소유 팀의 동의를 받기 쉽다.
2. **데이터 소유 팀의 동의를 미리 받아 둔다.** 강의 팀 4인 중 그 팀이 아닌 사람이 포함되면
   해당 인원에게 데이터가 나가는 구조가 되기 때문.
   현재 손재호·장원태는 MORAI 프로젝트를 함께 하고 있어 이 문제가 대부분 해소된다.
3. **중복 제출 문제는 없다.** 이 프로젝트의 산출물(실패 예측기)은 기존 프로젝트 레포에 존재하지 않는
   새 작업이며, 기존에 학습한 모델을 재제출하는 것이 아니다.
4. 다른 프로젝트 일정(10/30) **이후**에 본격 진행되므로 그 일정에 영향을 주지 않는다.

## 모집 문구 (4인째용)

> 자율주행 인지 모델이 **언제 틀리는지를 미리 예측**하는 프로젝트입니다.
> K-City 시뮬레이터에서 직접 모은 2.7만 장 데이터에 정답 라벨이 이미 있고,
> 날씨(맑음/안개)와 시간대(11시~5시)가 통제되어 있어 일반화 실험이 깔끔하게 됩니다.
> **같은 경로를 조건별로 반복 수집한 held-out 데이터로 최종 성능을 냅니다.**
> feature CSV까지 만들어 놓을 테니 scikit-learn만 쓰면 되고, MORAI 설치나 GPU 없이 Colab으로 가능합니다.
