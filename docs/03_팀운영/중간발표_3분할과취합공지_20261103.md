# 중간발표 파이프라인 3분할과 11/4 취합 공지

> 작성 2026-11-03 · 취합 2026-11-04 · 구체 시각은 별도 조율.
> 실명 배정은 팀에서 한다. 아래 A/B/C는 설계·구현 역할 ID다.

## 1. 팀에서 합의한 전제와 구체화할 항목

팀 공통 합의는 **GT 없는 분할 품질 추정 및 데이터 선별이라는 목표, TwinLiteNet+ 사용, 전방 카메라 사용**이다.
기존 문서의 M 체크포인트·78개 특징·ROI·Ridge/RF·평가 기준은 구체화를 위한 기술 초안이다.
각 담당자가 근거와 대안을 준비하고 11/4 취합 때 맞춘 뒤 실행 계약을 동결한다.
기존 M의 학습·평가 자료는 확보한 기반이지만 새 품질 추정기의 구현·학습 완료를 뜻하지 않는다.

```text
전방 영상 → 고정 TwinLiteNet+ → 확률맵·예측 마스크
                                  ↓
              A: 입력 특징 X / GT 기반 학습 정답 Y
                                  ↓
              B: X → 예상 품질을 학습·추론하는 모델
                                  ↓
              C: 검수 선별·효과 평가·추가학습 비교
```

## 2. 역할별 구체화와 준비물

| 역할 | 핵심 질문 | 구체화할 내용 | 가져올 자료 |
|---|---|---|---|
| A — 입력·학습 정답 | 무엇을 보고 무엇을 맞힐 것인가? | 확률·엔트로피·면적·경계/형태 특징, 전체/격자/카메라 ROI, 전체/영역 IoU와 빈 영역 처리, MORAI 조건 기록 | 특징·정답 명세표, 실제 영상 위 ROI 그림, 좋은/나쁜 예측의 GT 비교 |
| B — 품질 모델·학습 | confidence보다 실제 품질을 잘 추정하는가? | 회귀/분류 출력, confidence/entropy 기준선·Ridge/RF, 전처리·주행 split·튜닝·모델 저장 | 모델 비교표, 학습/사용 흐름도, 입력·출력 예시 |
| C — 선별·평가·개선 | 그 점수가 검수·개선에 도움이 되는가? | 위험 순위·중복 제거·예산, Random/confidence/ML 비교, 조건별 오류·과신 사례, 동일 예산 추가학습·향후 활용 | 실험 비교표, 최종 그래프의 축·비교 방법·지표 구상 |

모든 담당자는 **설계 1페이지 + 발표용 슬라이드 1~2장 정도**로 준비한다.
공통 양식은 **해결할 질문 / 입력과 출력 / 비교할 방법 / 완료를 판단할 결과**다.
실제 측정하지 않은 그래프는 설계 예시로 표시하고 결과처럼 표현하지 않는다.

참고 논문은 A가 MetaSeg의 특징, B가 MetaSeg/SEE/Küchler의 학습 설정,
C가 TCSR-Monitor의 조건 일반화 평가를 중심으로 보되 필요한 부분을 함께 참고한다.
원 논문 전체 재현은 필수가 아니다. [논문·코드 참고 범위](../05_구현계획/참고논문_베이스라인.md)를 따른다.

## 3. 역할 간 입출력과 파일 소유권

| 연결 | 전달 내용 | 검토 담당 |
|---|---|---|
| 공통 → A/B/C | checkpoint·정밀도·전처리·GT 정책, sample_id, 데이터 역할 | 공동 합의, 고정 M 로더·확률 export는 B |
| A → B | GT 독립 feature 열·순서·정의, 별도 target 열과 label_defined, 예시 X/Y | B가 학습 가능성, C가 누수·평가 가능성 검토 |
| B → C | sample_id별 예상 품질·검수 점수·모델 버전, dev에서 정한 임계값 | C가 선별·평가, A가 sample join 검토 |
| C → A/B | 예산·중복 규칙, 필요한 조건·실패 사례, 개선 실험의 통제 조건 | A가 데이터 확보, B가 재학습 가능성 검토 |

A는 수집·GT 코드와 **ROI·feature extractor·label builder**를 소유한다.
B는 M 추론·확률 export와 **품질 모델 학습·추론·bundle**을 소유한다.
C는 의미 있는 계약 검증과 **metric·선별·조건별 분석·시각화**를 소유한다.
공유 스키마는 공동 검토하되 한 번에 한 담당자가 변경한다. 실명에 대한 임의 배정은 하지 않는다.
기존 33개 원본 이식 후보의 D/M/V 분류는 유지하고 이 역할에 연결한다.

## 4. 취합 때 확인할 공통 규약

- 같은 checkpoint/EMA·입력 해상도·GT 정책과 전방 카메라 매핑을 사용할 것.
- 전방 한 프레임=한 행, 같은 sample_id로 feature·정답·예측·선별 결과를 연결할 것.
- feature에는 GT·실제 IoU·환경 정답·장소 식별자를 넣지 않을 것.
- 예상 IoU와 실패 확률을 구분할 것. 회귀 점수에서 만든 risk를 확률로 부르지 않을 것.
- 인접 프레임을 무작위 분할하지 않고 수집 세션/부모 묶음별로 학습·평가를 나눌 것.
- ROI·빈 GT·작은 support·전체/ROI 평가 범위를 명시할 것.
- 설계 완료·구현 완료·실험 완료를 구분하고 독립 test를 개발용으로 사용하지 않을 것.

## 5. 8분 발표 취합 원칙

기존 TwinLiteNet+ 학습·실패 결과 2분 → A/B/C 설계 각 1분 40초 → 최종 목표·일정·확장 1분.
이는 내용별 시간 배분이며 발표자를 새로 지정하는 것은 아니다.
기존 [8분 발표 설계](../07_발표/중간발표_설계와근거_20261103.md)의 근거·그림 후보를 활용한다.
온라인 수집·큰 모델·fail-safe는 향후 활용으로 짧게 다룬다.

## 6. 채팅방 게시용 공지

내일(11/4) 중간발표 자료를 취합하려고 합니다. 각자 아래 3개 파트로 나눠서 파이프라인을 구체화해오면 좋겠습니다.

공통으로 합의한 내용은 **GT 없는 분할 품질 추정 및 데이터 선별**, **TwinLiteNet+ 사용**, **전방 카메라 사용**입니다.
세부 방법은 각 파트에서 근거와 함께 제안해주세요.

**1. 입력 특징·학습 정답 설계**

- TwinLiteNet+ 출력에서 어떤 특징을 추출할지: 확률, 엔트로피, 예측 면적, 경계·형태 등
- 영상을 어떻게 나눌지: 전체 영상, 균등 격자, 카메라 구조를 반영한 ROI
- 무엇을 정답으로 학습할지: 전체·영역별 차선/도로 IoU, 빈 영역 처리
- MORAI에서 어떤 조건을 통제하고 기록할지: 날씨, 시각, 위치 등

→ **특징·정답 명세표와 영상 위 ROI 예시**를 준비해주세요. MetaSeg를 중심으로 참고하면 됩니다.

**2. 품질 추정 모델·학습 방법 설계**

- 입력 특징으로 어떤 값을 예측할지: 예상 IoU, 필요하다면 실패 여부
- 어떤 모델을 비교할지: confidence/entropy 기준선, Ridge, Random Forest 등
- 데이터를 어떻게 나누고 학습·튜닝할지
- GT 없이 사용할 때 어떤 형태로 결과를 출력할지

→ **모델 비교표와 학습·추론 흐름도**를 준비해주세요. MetaSeg, SEE, Küchler 등의 방법을 참고하면 됩니다.

**3. 데이터 선별·평가·개선 실험 설계**

- 예상 품질로 실패 의심 장면을 어떻게 선별할지
- 연속 프레임의 중복을 어떻게 줄일지
- Random·confidence 기반 선별과 어떻게 공정하게 비교할지
- 조건별 실패·과신 오류를 어떻게 분석할지
- 선별 데이터를 추가학습했을 때 개선 효과를 어떻게 검증할지

→ **실험 비교표와 최종적으로 보여줄 그래프 구상**을 준비해주세요. TCSR-Monitor의 평가 방법도 참고하면 됩니다.

각자 **설계 1페이지 + 발표용 슬라이드 1~2장 정도**로 정리해오면 취합하기 편할 것 같습니다.
공통으로 **해결할 질문 / 입력과 출력 / 비교할 방법 / 완료를 판단할 결과**가 드러나게 작성해주세요.

중간발표는 **기존 TwinLiteNet+ 학습 내용과 실제 실패 사례 → 새 ML 파이프라인 설계 → 최종 실험·결과 계획** 순서로 구성하려고 합니다.
아직 실험하지 않은 부분은 설계·계획으로 표시하고, 큰 모델 적용이나 온라인 수집·fail-safe 연결은 향후 확장으로 짧게 다루겠습니다.
