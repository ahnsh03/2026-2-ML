> 이 문서는 구현된 X56·버전 쌍 인터페이스를 설명한다. 새 ROI 직접 회귀의 특징·번들 연결은 [품질모델 가이드](../guides/품질모델_학습과_불확실성.md)에서 구현 상태를 확인한다.

> **현재와 이력:** 아래 본문은 11월16일 X56 실행 규약의 보존 기록이다. 본문의 현재·구현 표현은 당시 상태다. 11월26일 이후 품질 입력은 [9영역28열 v3 명세](../../config/region_feature_recipe_v3.json)와 [실행 가이드](../guides/ROI와_특징추출.md)를 따른다. 주 출력은 전체IoU 하나이며 근/원 recall은 오프라인 학습 보조진단이다. .7은 벤치마크이며 운행 실패 기준은 미확정이다. 옛 JSON 필드·버전·수치는 변경하지 않는다.

## 1. 채택한 의미와 구현 상태

## 2. 공통 식별자·원본 검증

`sample_id`는 dataset 안에서 유일한 불투명 식별자다. 기존 adapter는 `run_id/view/frame_id`, native adapter는 capture ID와 view 등을 사용한다. frame_id 숫자만으로 join하지 않는다.
산출물에는 dataset/model/checkpoint, target policy, geometry, ROI, feature schema, split의 버전·해시를 기록한다.
RGB/GT/확률맵/feature/모델/결과는 `ML_DATA_ROOT`, `ML_OUTPUT_ROOT`, `PERCEPTION_CKPT_ROOT`의 Git 밖 자산이다.

Sample manifest는 sample_id, run_id, parent_session_id, view/camera_id, capture 식별자, RGB/Semantic 상대경로,
시간·단위, 요청/확인된 환경, 카메라·기하·정책 버전, 입력 SHA와 audit, f0 학습/개발 노출 이력을 가진다.
RGB와 Semantic GT의 같은 capture·camera 대응, 크기·palette·중복을 검증한다. 요청 성공만으로 수집 성공을 확정하지 않는다.
날씨·시각·장소·GT 경로는 분석 metadata이며 X 열이 아니다. 환경별 변형·동시 여러 view는 같은 부모 그룹으로 관리한다.
원본·기존 결과는 덮어쓰지 않고 새 experiment ID를 사용한다.

## 3. 고정 M v6의 출력과 Lane 마스크

모델 근거는 [M v6 JSON](../baselines/medium_v6_baseline_evidence.json)을 따른다.
체크포인트 SHA-256은 `a26311b3af4e92880f632509eff3c81defc1b95135f5b463c7a08e5b6e23d24b`, 선택 epoch는 11이다.

| 출력 | 의미 |
|---|---|
| drivable logits | `[B,2,384,640]`, background/drivable |
| road_marking logits | `[B,4,384,640]`, background/white_lane/yellow_lane/stopline |
| marking probability | class 축 softmax, float32. 8-bit 시각화 PNG에서 역산하지 않음 |
| marking prediction | 4클래스 argmax |
| 통합 Lane 예측 | argmax class가 white_lane 또는 yellow_lane이면 1, background/stopline이면 0 |
| 통합 Lane GT | 검증된 4클래스 GT를 같은 white/yellow 합집합으로 변환 |

`P(white)+P(yellow)`는 확률 특징 후보이며, 이를 0.5로 자른 마스크와 argmax 합집합은 동일하지 않다.
GT 마스크를 `class > 0`으로 만들면 정지선이 들어가므로 사용하지 않는다.
M v6의 정지선 출력은 보존하지만 새 회귀 모델의 기본 정답은 Lane IoU 하나다.

입력은 RGB float32 [0,1], `[B,3,384,640]` letterbox다. 원본 크기·resize·pad·valid 영역을 기록한다.
특징 유효 영역은 GT 없는 기하로 정하고, GT의 ignore/support 정보를 X에 주입하지 않는다.
정량 평가는 모델 입력 공간에서 padding을 제외한다. GT는 원본 Semantic을 nearest로 resize한 값과 cache를 대조한다.
원본 overlay와 모델 입력 공간의 지표를 섞어 비교하지 않는다.

## 4. FeatureRecord — 한 프레임의 X

슬라이드 10에서 채택한 특징 종류:

- **모델 출력:** 차선 확률/Confidence, Entropy, 차선 예측 면적 비율, 연결된 영역 수.
- **원본 RGB:** 평균 밝기, 어두운 픽셀 비율, 밝기 대비, 경계 밀도.
- **공간:** 전체 영상과 고정 ROI 6개. **rows=3, cols=2**이며 2행×3열이 아니다.

ROI는 영상 위치별 입력 특징을 위한 영역이다. 도로·차체·하늘 의미 다각형이나 ROI별 회귀 목표를 요구하지 않는다.
GT/IoU/FP/FN, 날씨·시각·위치·run 이름, GT support/ignore는 입력에서 금지한다.
sample_id는 대응 키이며 회귀 입력 열이 아니다. RGB 특징은 학습과 운용 모두 원본 영상에서 계산한다.

현재 구현은 **56차원**이다. global 다음 3행×2열을 행 우선으로 순회하며 각 영역의 8개 통계를 기록한다.
confidence는 예측 차선 픽셀의 `P(white)+P(yellow)` 평균(빈 차선은 0), entropy는 4클래스 정규화 평균이다.
8방향 연결 영역, 원본 uint8 grayscale, dark<40, Canny(100,200,L2gradient=True)를 사용한다.
경계·순서·빈 예측 처리까지 [실행 스키마](quality_xy_v2.json)에 고정했으며 [개발 문서](../archive/X_y_데이터셋.md)에 설명한다.

## 5. LabelRecord — 한 프레임의 y

기하 유효 영역과 GT 정책의 유효 픽셀에서 통합 Lane 예측 P와 정답 G를 비교한다.
`TP=sum(P & G)`, `FP=sum(P & ~G)`, `FN=sum(~P & G)`, **`y=TP/(TP+FP+FN)`**.
기본 의미 ID는 `lane_union_iou`이며 실제 CSV 열 이름은 `lane_iou`다.

- 정답은 프레임 전체의 흰·노란 차선 합집합 IoU **하나**다. 클래스 IoU의 평균이 아니다.
- background/stopline은 Lane에서 0이다. 그 위치에 잘못 예측한 Lane은 FP에 포함한다.
- union=0은 null/label_defined=false로 표시한다. 이 처리는 유지할 평가 규칙이며 발표에서 별도 수치로 정한 것은 아니다.
- union>0에서 모두 누락되거나 모두 오검출이면 IoU=0이다. GT 차선이 없더라도 FP가 있으면 정의된 정답이다.
- TP/FP/FN/union/GT 픽셀 수/유효 픽셀 수를 별도 보존한다. 작은 support를 사후에 숨기지 않는다.
- 실패 판정은 사전 동결한 IoU 임계값 미만이다. 현재 실행 프로토콜은 0.7로 사전 고정했다.

X와 y는 분리 저장하고 sample_id 일대일 대응을 검사한다. label_defined는 학습·평가의 유효성 표시이며 운용 입력이 아니다.

## 6. 학습 bundle과 GT 없는 예측

구현한 함수:

```python
# 구현됨: GT 없는 float32 X와 별도 정답 dict
extract_features(rgb, probabilities, geometry)  # ndarray (56,)
build_label(prediction, target, geometric_valid, annotation_valid)  # dict
# GT 없는 회귀: X shape (N,56), 이름·순서·finite·스키마 검사
predict_array(model_bundle, X)  # raw_estimate, estimated_iou, risk_score
```

같은 X/y·같은 split으로 Least Squares(OLS), Ridge, Random Forest를 학습한다.
생성 데이터의 기존 train/val은 `f0_train`/`historical_dev` 노출 이력이다. 품질 회귀 split은 별도 manifest로 고정하며,
부모 수집 세션·사전 역할·정확한 픽셀 중복을 검사한다. 인지 모델 선택에 사용한 자료를 독립 test로 삼지 않는다.
train-only 상수 열 제거·scaler와 ordered_features, target 의미, M/checkpoint/policy/geometry/ROI/feature/split 해시,
학습·검증 그룹, seed, 환경 버전, 모델 선택 기준을 bundle에 저장한다.
동일 검증 자료에서 **clip(raw_estimate,0,1)**의 MAE로 선택한다. raw 값도 보존한다.
비정상 X는 거부하며 임의 대치를 하지 않는다. OLS는 집계 특징의 선형 종속에 대한 rcond=1e-6을 고정했다.
최종 평가에는 모델/프로토콜 해시를 사전 freeze하고 학습·개발 ID/부모/픽셀 중복을 모두 검사한다.
새 f0나 ROI/특징 버전에서는 기존 bundle을 재검증한다.

추론 행은 sample_id, RGB 해시·기하, raw_estimate, estimated_iou, risk_score를 가진다.
인지/품질 모델·특징 규약·경보 버전은 같은 산출물의 `run.json` metadata로 연결한다.
`risk_score=1-estimated_iou`는 검수 순위 점수이며 **실패 확률이 아니다**. GT 없이 X만으로 추론한다.
`infer_images --alarm-calibration`은 오프라인 RGB 단독 추론에서도 경보를 출력한다.
추가 행 필드는 `low_quality_alarm`, `alarm_threshold`, `quality_target_iou`다.
이 옵션이 없으면 기존 회귀 점수만 출력한다. 실제 저품질 정의와 경보 cutoff를 같은 값으로 가정하지 않는다.
개발 정상 FPR≤10%는 새 평가의 FPR≤10%를 보장하지 않는다.

## 7. 검수·재학습 manifest

동일 후보군에서 중복을 줄인 뒤 Random/Confidence/Entropy/Proposed ML을 같은 프레임 수로 비교한다.
검수 예산은 **5%·10%·20%**, 주 지표는 **Recall@예산**이다. GT는 선별 결과를 검증할 때 연다.
GT label_defined나 실제 IoU로 운용 후보를 미리 거르지 않는다. undefined를 선택해도 예산을 소비하며 별도 집계한다.

선별 산출물에는 sample_id, 점수·rank, 방법·예산·후보 pool과 설정을 연결한다.
현재 중복 이력은 픽셀 해시·split eligibility·선별 policy로 추적하며 `duplicate_group` 필드를 강제하지 않는다.
정답 확보·검수 상태와 source hash를 확인한 자료만 학습에 편입한다.
동점은 sample_id 순서, 예산은 ceil로 계산하고 중복 규칙을 모든 방법에 동일하게 적용한다.
재학습은 candidate_pool에서 검수·정답 확인한 자료로 수행하고 final_test를 학습에 편입하지 않는다.
같은 초기 모델·신규 자료 수·학습량에서 비교하며, 실제 수행했을 때만 인지 성능 개선을 보고한다.

## 8. 인지·품질 버전과 다음 주기

위 checkpoint는 기본 f0의 신원이다. f1은 같은 class/기하/56차원 특징 정의를 유지하지만 출력과 실제 IoU를 다시 계산한다.
`--adaptation-run`으로 완료된 재학습 기록·초기 f0·정답 정책·checkpoint hash를 검증한다.
`perception_identity`는 `ml-perception-identity-1`이며 baseline/adaptation, checkpoint, 초기 f0, 정답 정책, adaptation run hash를 연결한다.
f1 dataset·품질 bundle·경보가 이 신원과 맞지 않으면 거부한다. 임의 checkpoint로 기본 검사를 우회하지 않는다.

`review_queue`는 RGB 단독 inference run과 동일 RGB manifest를 확인하고 원본 참조·예상 IoU·선별 이유·purpose를 남긴다.
평가 자료의 기능 시연은 `demonstration_only`로 표시하고 학습에 편입하지 않는다.
현재 구현은 고정 f0에서 f1/g1을 만드는 오프라인 한 주기다. f2 누적 갱신과 ROS 실시간 연계는 후속 작업이다.

[통합 목표·현재 검증](../archive/통합_데이터플라이휠_개발현황_20261116.md)을 따른다.
