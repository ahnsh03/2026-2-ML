# 8분 중간발표 — 확보한 결과에서 품질 추정·선별로

> 2026-11-03 · 발표 설계 문서. **슬라이드/PDF·새 시각화 export는 아직 만들지 않았다.**
> 발표 공지: 8분, 지금까지의 중간 결과와 이를 기반으로 한 구체적 최종 결과를 모두 포함.
> [확정 설계](../05_구현계획/프로젝트_확정설계_20261103.md)
> **현행 모델 근거:** [정지선을 학습한 M v6 재확인](../05_구현계획/M_v6_정지선_재확인_20261103.md).
> 2번의 발표용 정본은 [100초 슬라이드와 대본](./B_담당_슬라이드와대본_20261103.md)이다.
> 기존 [수업 연결 상세](./B_중간발표_전체흐름과강의연결_20261103.md)의 v5 수치·그림은 과거 참고 사례다.

## 1. 발표의 주장

> “직접 수집·학습한 M 모델과 GT 평가 기반을 확보했다. 평균 성능만으로 드러나지 않는 실패를 확인했고,
> 이제 출력·카메라 ROI 특징을 고전 ML로 학습해 GT 없는 품질 추정과 검수 우선순위를 구현·검증하겠다.”

기존 분할 모델의 학습·평가는 **확보한 실험 기반**이다. 이번 학기의 새 결과는 별도 품질 추정기와
선별·분석이다. 실제로 구현하지 않은 ML 모델을 학습·검증 완료라고 말하지 않는다.
“설계는 구체화했다”는 말은 현재의 입력 열·정답·모델·평가·분담 규약으로 뒷받침한다.

## 2. 전체 8분 구성 — 7분 45초 내용 + 15초 여유

| 순서 | 시간대 | 분량 | 내용·슬라이드 목적 |
|---|---|---|---|
| 1. 문제·목표 | 0:00–0:35 | 35초 | 평균 성능만으로 모르는 장면별 실패, GT 없는 품질 추정과 검수 |
| 2. 확보한 데이터·인지 모델 | 0:35–1:30 | 55초 | MORAI RGB/GT·조건 기록, M v6 학습 규모·4클래스 노면표시 출력 |
| 3. 실제 중간 결과 | 1:30–3:00 | 90초 | 전방 클래스별 실측 IoU, RGB/GT/pred/error 그림·실제 한계 |
| 4. 전체 파이프라인 | 3:00–3:40 | 40초 | 고정 M → A 특징/정답 → B 품질 추정 → C 선별·평가 |
| 5. A 입력·정답 설계 | 3:40–4:40 | 60초 | 출력 확률·형태·ROI 특징 X, GT 기반 클래스/영역 IoU Y |
| **6. B 품질 모델·학습** | **4:40–6:20** | **100초** | **선형 회귀 중심**, 최소제곱 수식·GT 없는 추론, 분류는 짧게 |
| 7. C 선별·검증 | 6:20–7:20 | 60초 | confidence/Random 대비 동일 예산 실패 발견율·조건별 분석·선택 추가학습 |
| 8. 기말 산출물·일정 | 7:20–7:45 | 25초 | 5주 인수물·필수 결과, 온라인/fail-safe는 향후 확장 1문장 |
| 전환·시간 여유 | 7:45–8:00 | 15초 | 발표자 교대·그림 설명 지연 |

내용 465초 + 여유 15초 = 480초. 학습 기반·실제 중간 결과에 145초를 배정한다.
2번 파트는 **1분 40초 권장, 최대 2분**이다. 장수는 1~2장으로 제한하고 하이퍼파라미터는 부록으로 뺀다.
이 표는 취합을 위한 수정 제안이다. 기존 120/100/100/100/60초 공지보다 결과 설명과 시간 여유를 늘렸다.
각자 설계 1페이지 + 발표용 슬라이드 1~2장을 준비해 11/4 취합한다.
[분담·공지](../03_팀운영/중간발표_3분할과취합공지_20261103.md)의 공통 양식을 따른다.
발표자 배정은 별도이며 8장이라는 장수 제한은 없다. 논문은 해당 설계의 근거로 짧게 소개한다.

## 3. M 학습을 설명할 때 사용할 사실

| 항목 | 확인한 내용 |
|---|---|
| 학습 | v6 road_marking train 26,001 / val 1,404 이미지, 3 views 공유 가중치 |
| 입력/출력 | 원 학습 384×640, drivable 2 + road_marking 4클래스 두 head. 정지선 포함 |
| 초기화 | 이전 v5 M EMA에서 공통 가중치 이전, 노면표시 head 초기화, optimizer/scheduler reset |
| 학습 설정 | 18 epoch, batch 12, lr 2e-4, weight decay 5e-4, seed 2026, AMP/EMA |
| checkpoint | best_mean epoch 11, SHA 앞부분 `a26311b3af4e`. 18 epoch 완료와 구분 |
| 전방 실측 IoU | 도로 97.75%, 흰 차선 77.69%, 노란 차선 86.19%, 정지선 87.32% |
| 지표 의미 | epoch11 과거 validation 누적 교집합/합집합. 프레임별 평균·새 독립 test 아님 |
| 과거 v5 참고 그림 | 기존 전방 468 frame, lane 0.165/0.940 사례는 **v5**. v6 실패 예시로 표기 금지 |

“가중치를 처음부터 학습했다”, “M이라 개선이 확실하다”, “안개가 실패 원인으로 입증됐다”는 표현은 쓰지 않는다.
학습 loss/val 곡선은 실제 history에서 가져와야 한다. 추정한 곡선을 그리지 않는다.
과거 result의 best 항목과 실제 checkpoint의 재평가 점수는 출처를 구분한다.

## 4. 다음 단계의 시각화 저장 작업

이번 문서 작업 다음에 수행한다. 기존 `outputs/inference_vis/v5b_val/`은 **v5 그림**이다.
v6는 해당 checkpoint/GT/해상도가 맞는 기존 결과를 고르거나 ML 이식 후 새로 export한다.
새로운 PNG/JPEG·확률·GT·slide 후보는 공개 Git 밖 `ML_OUTPUT_ROOT` 아래에 저장한다.

1. 같은 M 체크포인트 SHA, EMA, dataset/policy/geometry를 확인한다.
2. 현재 ML 로더·시각화의 binary 전제를 v6 task에 맞추기 전에는 기존 명령을 그대로 실행하지 않는다.
   task-aware 이식 후 local.env·입력 root를 확인한다. 원본 프로젝트 실행기를 경유하지 않는다.
3. 실제 RGB / GT overlay / prediction overlay / FP·FN error panel / 확률 heatmap을 저장한다.
4. 좋은 장면 2개, 낮은 IoU 2~3개, 높은 confidence인데 틀린 **확인된** 장면을 선정한다.
   마지막 종류가 확인되지 않았다면 가설·조사 예정으로 남긴다.
5. ROI overlay는 “초안/설계 예시”로 표기하고 새 품질 추정 결과처럼 보이지 않게 한다.
6. 선택 sample_id, model/data/policy SHA, 실제 IoU, 실제 confidence, 파일 경로를 sidecar로 보존한다.
7. 기존 validation의 예시를 최종 blind test에서도 반복 제시한 것으로 혼동하지 않도록 구분한다.

## 5. 계획을 설명하는 구체 문장

> “TwinLiteNet+는 고정하고 확률·형태·위치별 출력 통계로 입력 표를 만들었습니다/만들 계획입니다.
> GT와 비교한 도로·차선·정지선의 실제 IoU를 정답으로, 먼저 선형 회귀를 학습할 계획입니다.
> 이후에는 GT 없이 예상 품질을 출력하고, 낮은 점수 순으로 같은 수의 장면을 골랐을 때
> 무작위와 confidence보다 실제 실패를 더 많이 찾는지 검증합니다.”

위 문장의 ‘만들었습니다’는 실제 feature export가 완료된 뒤에만 사용한다.
현재는 “입력·정답의 설계를 구체화했고, v6에 맞춰 규약을 취합한 뒤 구현할 계획입니다”가 정확하다.

## 6. B의 100초 설명과 수식 선택

| 분량 | 설명 |
|---|---|
| 15초 | A의 출력 특징 x와 GT 기반 실제 IoU y를 받는다 |
| 45초 | `h_theta(x)=theta^T x`, `J(theta)=1/2 sum(h_theta(x_i)-y_i)^2`로 회귀를 설명 |
| 20초 | 새 영상은 GT 없이 추정. 주행 단위 분리, MAE와 동일 예산 실패 발견율로 검증 |
| 15초 | 별안: `z=1[y<tau]`, `s(x)=sigmoid(w^T x)`로 낮은 품질 여부를 직접 분류 |
| 5초 | 예상 IoU/검수 점수를 C에 넘긴다 |

Lecture3 PDF p.5의 최소제곱·p.22–24의 sigmoid, main_notes PDF p.9–10에 대응한다.
회귀의 장점은 연속 IoU 정답을 바로 사용하고, 실패 threshold를 먼저 고르지 않아도 되는 점이다.
분류는 이진 질문에 직접 맞지만 threshold와 양성 표본 정의가 추가된다. 어느 쪽이 우수한지는 실험으로 판단한다.
발표 본문은 선형 회귀를 중심으로, Ridge/RF 비교는 기말 계획 1문장이나 부록으로 둔다.
OLS 출력은 [0,1] 밖으로 나갈 수 있어 저장 raw 값과 clip한 표시값을 구분한다.
`1-예상 IoU`는 검수용 점수이며 실패 확률이 아니다.

## 7. 예상 질문

| 질문 | 답변 |
|---|---|
| confidence와 무엇이 다른가? | 공간·형태 정보를 추가해 실제 IoU와의 관계를 학습한다. 이득은 동일 test·검수 예산으로 비교한다 |
| GT가 있는데 왜 추정하나? | GT는 추정기를 학습·채점하는 실험 장치다. 선별 단계에서는 GT를 숨기고 실사용은 GT 없이 수행한다 |
| 왜 M인가? | 기존 가중치·코드·실패 예시와 작은 실험 비용을 활용해 선별 방법의 효과를 분리하기 위해서다 |
| 재학습하면 반드시 좋아지나? | 보장하지 않는다. 동일 예산 Random 비교를 수행한 경우에만 개선 효과를 주장한다 |
| 왜 실패했는지도 아나? | 오류 위치·형태와 조건별 연관성은 분석한다. 환경의 인과 효과는 별도 통제 실험이 필요하다 |
| 온라인/fail-safe는 됐나? | 현재 필수 범위는 오프라인 검증이다. 실시간 지연과 대체 동작 효과는 별도로 검증할 확장이다 |

기존 모델의 실제 실패 그림과 구체적인 새 설계를 함께 보여주는 전략은 공지에 부합한다.
새 기계학습 모델의 수치가 아직 없다면, 중간 결과와 최종 목표의 경계를 명확히 표시한다.
