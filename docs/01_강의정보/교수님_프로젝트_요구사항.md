## ★ 1. 프로젝트 평가 기준 — Lecture 1

> "제가 생각하는 프로젝트는 **알고리즘의 구현이 별로 중요한 거 같진 않고**, 알고리즘은 워낙 많으니까
> **아이디어를 먼저 잘 생각을 하고** — '이런 일을 해보고 싶은데, 이런 일을 해보려고 하니까
> 어떠한 알고리즘이 적합한 거 같아' — 순서가 이렇게 되는 것 같아요.
> **이런 일이 뭔가 재밌을 것 같고, 그럼 이런 일을 위해서 데이터를 찾고, 알고리즘을 찾고,
> 구현을 했고, 거기에 성능을 높였다. 그래서 이렇게 완성을 했다. 정도로 스토리라인이 되면
> 저는 만족을 할 것 같습니다.**"

### 해석 — 요구되는 6단계 스토리라인

| 단계 | 요구 내용 | 프로젝트 설계 시 확인 |
|---|---|---|
| ① | **재밌을 것 같은 일** | 한 문장으로 동기가 서는가 |
| ② | **데이터를 찾고** | 어디서 온 데이터인가 (→ 3번 항목: 직접 가져와야 함) |
| ③ | **알고리즘을 찾고** | *문제 때문에* 그 알고리즘이 선택되었는가 |
| ④ | **구현을 했고** | 동작하는가 |
| ⑤ | **성능을 높였다** | **베이스라인 → 개선의 계단이 있는가** |
| ⑥ | **완성을 했다** | 결과물이 있는가 |

**핵심: 문제가 먼저, 알고리즘은 그다음이다.** "이 기법을 써보고 싶어서 문제를 만들었다"는
순서는 교수님 기준과 반대다. 발표 제목·구성도 문제 중심으로 잡는다.

또한 **"알고리즘의 구현이 별로 중요하지 않다"** → scikit-learn 사용이 감점 요인이 아니다.
직접 구현에 시간을 쏟기보다 문제 정의·데이터·평가 설계에 투자하는 것이 맞다.

## ★ 2. 베이스라인 비교는 필수 — Lecture 9 (Decision Tree and Ensemble)

> "그래서 **여러분들의 프로젝트에 대해서도 베이스라인이랑 비교를 하라고 했잖아요.**
> 베이스라인이랑 비교를 하지 않고도 그냥 앙상블 하면 무조건 좋아질 테니까
> **앙상블을 쓰는 것도 한 가지 방법**이라고 볼 수가 있겠습니다."

### 해석

- **베이스라인 비교는 명시적 요구사항이다.** 별도 공지로도 이미 전달된 상태였다("~하라고 했잖아요").
- **앙상블은 교수님이 직접 권한 성능 향상 카드다.** 주력 모델로 쓰면 ⑤단계를 안전하게 채운다.
- 같은 강의 말미에 *"벌써 팀 하나가 나왔네요. 이거 팀 이렇게 기록 빨리 해 주시고,
  그럼 다음 프로포잘 프레젠테이션을 잘 준비해 주시길"* → **팀 등록을 교수님이 직접 받는다.**

## ★ 3. 데이터셋은 직접 가져온다 — Lecture 3 (Linear/Logistic Regression)

> "여러분 기말고사는 파이널 프로젝트로 **뭔가의 데이터셋을 여러분이 직접 가지고 와서**
> 프로젝트를 진행을 해야 될 텐데, 거기에서의 **재밌는 데이터 디스트리뷰션**이 있고,
> 그 재미있는 데이터 디스트리뷰션을 (…) 새로운 형태의 디스트리뷰션으로 나타내는 것이
> 적합하다 해서 모델링을 하면 그 예측 모델을 만들어 낼 수가 있을 겁니다."

### 해석

- **BYO(Bring Your Own) 데이터셋이 전제다.** 공개 데이터셋도 가능하지만, 직접 수집한 데이터는
  그 자체로 차별화 요소가 된다.
- 우리 팀은 **MORAI 시뮬레이터에서 직접 수집한 데이터**와 **ERC 실차 로버 로그**를 가지고 있다.
  이건 다른 팀이 복제할 수 없는 자산이다. → [주제 후보](../02_주제후보/README.md)

## ★ 4. 하이퍼파라미터 튜닝 — Lecture 13 (Gradient-free Optimization)

> "그 대표적인 예시가 머신 러닝 모델에서는 **하이퍼파라미터 튜닝**인 거 같고, 그래서
> 하이퍼파라미터 튜닝, **여러분들이 프로젝트를 할 때 이런 것들에 대해서 생각을 해 봐야 될 것 같아요.**"

> "하이퍼파라미터 튜닝을 했을 때 그냥 단순하게는 **랜덤 서치**를 이용하면 될 것 같고요."

### 해석

- 튜닝 파트가 사실상 요구된다.
- 교수님은 강의에서 **grid search보다 random search가 왜 나은지**를 길게 설명한다
  (중요하지 않은 파라미터에 grid를 쪼개면 낭비가 된다는 논지).
  → **random search vs grid search 비교**를 넣으면 강의 내용을 그대로 반영한 것이 된다.
