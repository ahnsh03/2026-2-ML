# 선별 자료로 인지 모델을 갱신하는 통제 실험

2026-11-16 구현·실험, 2026-11-22 문서 검토. [품질 추정·선별](회귀학습_선별평가.md) 이후의 통합 파이프라인 단계다.
동일 예산 비교·예약 평가·기존 성능 유지 진단과 f1/g1 새 주행 검증까지 수행했다.
현재 갱신 후보는 유지 기준 미달로 채택을 보류했으며, 기본 f0/g0를 유지한다.
[현재 상태](../project/개발현황.md)와 [측정 결과](../project/품질추정_실험결과_20261116.md)를 구분해 읽는다.
같은 후보에서 같은 수의 정답을 확보했을 때 인지 모델 개선량이 달라지는지 비교한다.
저품질 장면을 많이 찾는 것과 재학습 후 성능이 좋아지는 것은 서로 다른 결과다.

## 후보 선정과 정답 연결

RGB 단독 manifest에 `run_id`, `parent_session_id`, `preregistered_quality_role="candidate_pool"`과
시간·위치 정보를 넣고 품질 추론을 완료한다. 아래 선별기는 Semantic 파일을 열지 않는다.
정확한 픽셀 중복, 1초 및 (5m 또는 10°) 간격을 적용한 뒤 예산을 올림한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.select_candidates \
  --inference-dir /outputs/inference/candidates \
  --manifest /outputs/manifests/candidate_rgb.jsonl \
  --budget 0.1 --random-seed 20261116 --random-seed 20261117 \
  --output-dir /outputs/selections/candidate_10pct
```

`FrozenQualityRank`, `Confidence`, `Entropy`, `Random`의 선정 목록과 순위·모델 해시를 저장한다.
선정이 끝난 뒤 **sample_id로** 같은 프레임의 RGB/Semantic 원본을 연결한다.
연결한 native manifest에는 `semantic`, `expected_sha256`, 원래 역할·부모와 선정 근거를 보존한다.
`selection`의 방법·예산·seed·순위와 추론/모델 해시도 유지한다. 학습기는 이 목록이
선언한 `--arm`, 프로토콜 예산, 난수 seed와 일치하고 순위가 1부터 연속인지 검사한다.
정답을 확인한 뒤 잘 학습될 것 같은 프레임으로 바꾸면 같은 실험이 아니다.

## 동일 신규 정답 수·업데이트 예산으로 f0 → f1

[예시 프로토콜](../../config/perception_adaptation_pilot_v1.json)을 실험 전에 복사·고정한다.
새 정답의 수와 optimizer 업데이트 수를 모두 맞춘다. 예시는 다음 설정이다.

- 같은 Medium v6 EMA에서 각각 시작한다. 원본 checkpoint를 덮어쓰지 않는다.
- 240 updates, batch 8 = 새 후보 4 + 기존 학습 replay 4, AdamW lr=1e-5.
- augmentation 없이 같은 letterbox와 actor-negative Semantic 정책을 사용한다.
- 주행 가능 영역과 4종 노면 표시 두 head를 기존 loss로 학습한다. 차선 IoU는 흰·노란 표시의 합집합이다.
- BatchNorm의 running 통계는 고정하고 affine 파라미터는 학습한다. padding은 loss에서 제외한다.
- 같은 seed의 두 방법은 같은 replay 추출 순서를 사용한다. 새 데이터 추출 RNG는 분리한다.
- 고정된 마지막 step을 평가한다. 개발/최종 점수로 유리한 checkpoint만 골라내지 않는다.

```bash
scripts/run_container.sh python3 -m quality_estimation.retrain_perception \
  --new-manifest /outputs/manifests/quality_selected_native.jsonl \
  --replay-manifest /outputs/manifests/known_f0_train_replay.jsonl \
  --data-root /data --protocol /ml/config/perception_adaptation_pilot_v1.json \
  --seed 20261116 --arm FrozenQualityRank --output-dir /outputs/adaptations/quality_seed1
```

무작위 목록도 같은 설정으로 `--arm Random`을 실행한다. 새 자료는 예약된 candidate_pool,
replay는 확인된 `source_role="f0_train"`이어야 한다. 원본 픽셀 중복과 부모/ID 겹침은 거부한다.
시드 반복에서 품질 순위 목록은 고정되지만, 무작위 방법의 선정 목록과 학습 중 추출 순서는 달라진다.
따라서 이 반복의 분산에는 무작위 선별과 학습 과정의 변동이 함께 들어간다.
같은 후보 풀과 평가 프레임을 반복 사용한 시드 범위를 독립 환경의 신뢰구간으로 해석하지 않는다.
단순 선별 기준을 비교하려면 프로토콜의 `selection_arms`에 `Confidence` 또는 `Entropy`를
등록하고 해당 선별 목록을 같은 이름의 `--arm`으로 전달한다. 목록의 라벨만 바꾸어 실행하지 않는다.
현재 CUDA runtime의 `adaptive_avg_pool2d_backward_cuda`는 완전한 결정적 계산을 제공하지 않는다.
이 연산만 명시적으로 허용하고 경고를 저장한다. seed를 고정해도 bitwise 재현성을 주장하지 않는다.

추가 학습 자체의 효과를 구분하려면 `ReplayOnly` 대조군도 실행한다.
그 프로토콜은 `new_per_batch=0`, `replay_per_batch=8`,
`replacement_replay_per_batch=4`, `common_replay_per_batch=4`, `selection_arms=["ReplayOnly"]`로 설정한다.
빈 새 자료 manifest를 사용하며, 공통 replay 4개는 다른 방법과 같게 유지하고 새 자료 자리 4개를 기존 자료로 채운다.

## 같은 프레임에서 비교

```bash
# --adaptation-run을 생략하면 원래 f0를 평가한다.
scripts/run_container.sh python3 -m quality_estimation.evaluate_perception \
  --manifest /outputs/manifests/development_native.jsonl --data-root /data \
  --adaptation-run /outputs/adaptations/quality_seed1 --role meta_dev \
  --output-dir /outputs/evaluations/quality_seed1_dev
```

`per_frame.jsonl`에는 lane·drivable·white·yellow·stopline 각각의 TP/FP/FN과 IoU를 보존한다.
프레임 IoU의 평균과 픽셀을 합산한 IoU는 별개로 보고한다. 빈 union은 undefined다.
날씨·시각·부모별 결과와 실패/손실 기록도 함께 확인한다.

평가의 CPU 영상·정답 준비는 기본 `--num-workers 4`로 병렬화한다. `--num-workers 0`이면 순차 준비한다.
manifest 순서와 batch 경계를 유지하고 각 batch의 원본 index를 검사한다. batch 크기와 worker 수는 run metadata에 남긴다.
같은 개발 576행에서 기존 순차 평가와 프레임별 입력 해시·픽셀 수·IoU 기록이 바이트 단위로 같았고,
전체·조건별 집계도 일치했다. 이 환경의 평가 구간 시간은 68.6초에서 19.2초로 줄었다.
이는 오프라인 평가 처리량이며 카메라·ROS를 포함한 실시간 지연 측정은 아니다.

최종 자료를 열기 전에 비교할 **모든** checkpoint와 평가 부모 그룹을 고정한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.freeze_perception \
  --evaluation-groups /outputs/protocols/final_groups.json \
  --adaptation-run /outputs/adaptations/random_seed1 \
  --adaptation-run /outputs/adaptations/quality_seed1 \
  --selection-evidence /outputs/protocols/adaptation_protocol.json \
  --output /outputs/protocols/perception_final_freeze.json

scripts/run_container.sh python3 -m quality_estimation.evaluate_perception \
  --manifest /outputs/manifests/final_native.jsonl --data-root /data \
  --adaptation-run /outputs/adaptations/quality_seed1 --role final_test \
  --freeze /outputs/protocols/perception_final_freeze.json \
  --output-dir /outputs/evaluations/quality_seed1_final
```

등록한 모든 방법·seed와 f0를 같은 최종 행에서 평가한다. 최종 점수를 보고 seed를 고르지 않는다.
연속 주행을 간격으로 줄였다면 GT를 보지 않는 동일 규칙을 모든 모델에 적용한다.
같은 지도·세션에서 만든 layout 반복은 독립 지도나 날짜의 반복 실험으로 해석하지 않는다.

품질 추정기는 **f0의 출력 특징과 f0의 IoU**로 학습했다. f1 갱신 후에는 특징·정답을 다시 만들고
품질 추정기의 보정 상태를 확인해야 한다. 오후 후속 개발에서 f1용 g1 재학습과 버전 쌍 검증을 추가했다. ROS 실시간 폐루프 검증은 남아 있다.

## 선택적 replay 출력 유지 제약

개발 진단에는 `replay_distillation` 프로토콜 필드를 추가할 수 있다. 필드가 없으면 원래 감독 학습을 유지한다.
고정 f0의 replay logits를 먼저 FP32 CPU cache로 계산한 뒤 학생 모델을 적재해 GPU에 두 모델을 동시에 두지 않는다.
교사 준비 후 학생 초기화 난수 상태를 원래와 맞추고, 신규·replay 추출 RNG를 분리해 기존 실험과 같은 추출 순서를 유지한다.

```json
{"replay_distillation":{"weight":1.0,"temperature":1.0,"heads":["drivable","road_marking"],"scope":"replay_only","teacher":"initial_f0","cache_dtype":"float32"}}
```

추가 loss는 replay 행의 유효 영역에서 `KL(teacher || student)`를 계산해 두 head를 평균하고 `temperature²`를 곱한다.
교사는 detach하며 padding은 제외한다. 신규 행에는 이 제약을 적용하지 않는다.
원래 loss에 `weight × 추가 loss`를 더하고, 교사 cache 해시와 매 step의 감독 loss·제약 loss를 기록한다.
같은 업데이트 수를 비교하더라도 교사 cache 준비 비용은 추가되므로 같은 연산 시간의 비교라고 부르지 않는다.
개발·기존 조건 진단에 사용하며, 새 잠금 평가 없이 모델을 채택하지 않는다.

개발용 응답 격자를 팀 저장소만으로 재생할 수 있다. 다음 명령은 모든 설정에서 실제 관측된 신규 IoU 이득과 기존 IoU 손실을 읽고, 한 탐색 방식에 그 방식이 선택한 이전 관측만 차례로 공개한다.

```bash
PYTHONPATH=src python -m quality_estimation.replay_adaptation_search \
  --surface docs/baselines/adaptation_search_surface_20261123.json --grid primary
```

각 예산에서 유효한 설정을 한 번 이상 찾은 초기화 수, 선택한 이득과 격자 최적값의 차이, 최적값에 도달한 초기화 수를 출력한다. 개선되는 유효 설정을 찾지 못하면 기존 모델 유지에 해당하는 이득 0을 적용한다. 팀 공개 수치에서 다시 계산한 예산 8·12·20의 두 방법 집계가 원본 실행을 검증한 집계 6행과 일치했다. [환경·품질·설정 탐색 결과](../project/환경_ROI와_품질추정_20261123.md)
