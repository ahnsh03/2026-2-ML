# 회귀 학습·GT 없는 품질 추론·선별 평가

2026-11-16 구현. [X/y 데이터셋](X_y_데이터셋.md)의 56개 특징으로 프레임의 흰·노란 차선 합집합 IoU를 추정한다.
인지 모델은 Medium v6 EMA epoch 11로 고정하며, 품질 회귀 학습이 인지 모델을 변경하지 않는다.
이 모듈은 ML 저장소와 명시적으로 준비한 데이터만 사용한다. 수집 프로젝트나 ROS 환경은 필요하지 않다.

## 입력과 역할

`build_native_dataset`은 native RGB/Semantic 원본을 사용할 때의 adapter다. JSONL 한 행은 다음과 같다.
경로는 `--data-root` 안의 상대경로이며, 원본 크기·palette·파일 해시를 검사한다.

```json
{"sample_id":"capture001/front","run_id":"capture_run_A","parent_session_id":"session_A","view":"front","image":"rgb/capture001.png","semantic":"semantic/capture001.png","source_role":"after_f0_training","expected_sha256":{"rgb":"<sha256>","semantic":"<sha256>"}}
```

`source_role`은 파일 생성일만 보고 추측하지 않는다. 인지 모델의 학습·선택 이력과 원본 수집 기록으로 확인한다.
`capture_requested_at_utc`, `ego.position.{x,y}`, `ego.heading_deg`, `condition`은 중복 제거·사후 분석용 metadata다.
날씨·시각·위치·GT는 X 열에 들어가지 않는다. 환경 변형과 같은 원본 세션에서 나눈 run은 같은 부모 그룹으로 묶는다.
수집 전에 역할을 정했다면 `preregistered_quality_role`도 남긴다. 예약한 `final_test`를 학습/개발 역할로 바꾸면 거부한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.build_native_dataset \
  --manifest /outputs/manifests/native_front.jsonl --data-root /data \
  --output-dir /outputs/datasets/native_front --audit-per-run 2
```

그룹 역할 파일은 dataset의 **모든 부모 그룹**을 정확히 포함하는 JSON이다.

```json
{"session_A":"meta_train","session_B":"meta_dev","session_C":"candidate_pool","session_D":"final_test"}
```

최종 그룹의 X/y는 개발 선택을 끝내기 전까지 별도 보존하는 것을 권장한다. 개발 dataset에는 학습·개발 그룹만 넣어도 된다.
기존 인지 모델 학습/선택 노출 자료는 기본적으로 `diagnostic_only`로 둔다.
명시적 `--allow-exposed-development`는 노출 자료의 개발 사용만 허용하며, `final_test`에는 적용되지 않는다.

```bash
scripts/run_container.sh python3 -m quality_estimation.splits \
  --dataset-dir /outputs/datasets/native_front \
  --group-roles /outputs/protocols/group_roles.json \
  --output /outputs/protocols/split.json
```

같은 RGB 픽셀이 역할을 넘으면 중단한다. 같은 역할 안의 정확한 픽셀 중복은 한 번만 남긴다.
기본 연속 프레임 간격은 **1초 및 (5m 이동 또는 10° 방향 변화)**다. 명시적으로 다른 환경 조건은 유지한다.
위치가 없으면 시간 간격을 사용하고, 시간도 없으면 중복 해시 외에는 걸러지지 않으므로 입력 기록을 확인해야 한다.
이 규칙이 가까운 장소의 유사성을 모두 제거하지는 않는다. 같은 경로 반복은 공간 분할·거리 buffer를 별도 분석한다.

## 같은 행에서 학습·선택

[기본 실행 프로토콜](../../config/quality_training_v1.json)을 복사해 실험 전에 고정한다.

- OLS: 학습 상수 열 제거 → 학습 전용 표준화 → 최소제곱. float32 집계 특징의 선형 종속 때문에 상대 singular-value cutoff `1e-6`을 사용한다.
- Ridge: 같은 전처리, alpha `0.01/0.1/1/10/100/1000/10000`, SVD solver.
- Random Forest: 상수 열 제거, 300 trees, depth `8/16/None` × leaf `2/8/32`, max_features=1.0.
- seed=20261116, 학습 4 jobs. 단일 프레임 추론은 thread dispatch 비용을 줄이기 위해 1 job이다.
- 같은 개발 행의 `clip(raw,0,1)` MAE로 선택한다. 허용 오차 `1e-12` 동점이면 OLS→Ridge→RF, 같은 모델 안에서는 grid 순서를 따른다.
- `full`=56, `output_only`=28, `rgb_only`=28, `global_only`=8개 열이다. 특징 선택도 개발 자료에서만 수행한다.
- 비정상 X는 거부하며 임의 대치를 하지 않는다. y undefined는 지도 적합/MAE에서만 제외하고 선별 pool에서는 유지한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.train_models \
  --dataset-dir /outputs/datasets/native_front \
  --split /outputs/protocols/split.json \
  --protocol /ml/config/quality_training_v1.json --feature-set full \
  --output-dir /outputs/models/quality_full
```

`candidate_progress.jsonl`과 `candidates.json`은 모든 탐색 결과를 보존한다.
`models/*.joblib`, `comparison.json`, `development_predictions.csv`, `development_selection.json`에 각 회귀기와 선택 근거를 저장한다.
`train_membership.json`·`selection_membership.json`에 학습/개발 ID·부모·픽셀 해시를 남긴다.
`source/`에는 실행 Python 원본을 보존하며 protocol·dataset·split·checkpoint·schema의 해시도 기록한다.
완료 해시와 artifact 목록을 검사한 **신뢰할 수 있는 로컬 joblib**만 로드한다.

### GPU 없이 저장된 X/y로 재현

회귀 학습은 완성된 dataset·split·protocol만 읽는다. 원본 영상과 인지 checkpoint를 다시 열지 않는다.
같은 Python 의존성 환경에서 저장소 루트를 기준으로 다음처럼 직접 실행할 수 있다.
컨테이너 실행 스크립트는 GPU 실행용이며, 아래 명령은 GPU 없이도 동작한다.

```bash
PYTHONPATH=src python3 -m quality_estimation.train_models \
  --dataset-dir ../outputs/datasets/native_front \
  --split ../outputs/protocols/split.json \
  --protocol config/quality_training_v1.json --feature-set full \
  --output-dir ../outputs/models/quality_cpu_reproduction
```

실제 CPU 전용 컨테이너에서 원본 데이터·checkpoint 마운트를 제거하고 회귀 비교를 재실행했다.
같은 라이브러리 환경에서 개발 576행의 OLS·Ridge·RF 예측 CSV가 기존 결과와 바이트 단위로 일치했다.
이 확인은 다른 라이브러리 버전 사이의 동일한 직렬화나 수치 재현을 보장하지는 않는다.

## GT 없이 추론

운용 manifest에는 `sample_id`, `view="front"`, RGB `image`만 있으면 된다. Semantic 파일은 열지 않는다.

```bash
scripts/run_container.sh python3 -m quality_estimation.infer_images \
  --manifest /outputs/manifests/rgb_only.jsonl --data-root /data \
  --model-run /outputs/models/quality_full \
  --output-dir /outputs/inference/quality_rgb
```

`predictions.jsonl`에 raw_estimate, [0,1] estimated_iou, `risk_score=1-estimated_iou`를 저장한다.
이는 검수 순위 점수이며 실패 확률이 아니다. X와 행 순서·스키마도 함께 보존한다.
같은 RGB 296프레임에서 paired X/y builder와 RGB 단독 추론을 같은 batch 8로 대조했으며 X가 일치했다.
batch 1과 8 사이에는 일부 confidence 특징이 최대 약 3.70×10⁻⁶ 달랐지만, 고정된 RF의 예상 IoU는 296행 모두 같았다.
이 관측은 다른 장치·모델의 bitwise 일치를 보장하지 않는다.

## 잠금 평가와 선별 예산

최종 모델·특징·규칙을 개발 자료에서 선택한 다음, 최종 그룹 ID 목록만으로 freeze를 만든다.
`freeze_models`는 최종 X/y를 읽지 않는다. prior-access=false는 실험자의 선언이며, 수집·실행 로그와 함께 확인해야 한다.

```bash
scripts/run_container.sh python3 -m quality_estimation.freeze_models \
  --model-run /outputs/models/quality_full \
  --evaluation-groups /outputs/protocols/final_groups.json \
  --selection-evidence /outputs/models/quality_full/comparison.json \
  --output /outputs/protocols/final_freeze.json

# 이후 별도로 생성·검증한 최종 dataset과 split에 적용한다.
scripts/run_container.sh python3 -m quality_estimation.evaluate_models \
  --dataset-dir /outputs/datasets/final_front --split /outputs/protocols/final_split.json \
  --model-run /outputs/models/quality_full --role final_test \
  --freeze /outputs/protocols/final_freeze.json --output-dir /outputs/evaluations/final
```

평가기는 학습 ID·부모·픽셀 중복을 검사한다. 최종 평가는 개발 선택 이력의 중복도 검사한다.
개발 비교는 `--role meta_dev`, 후보 진단은 `candidate_pool`, 과거 분석은 `diagnostic_only`로 실행한다.
최종 성능을 보고 모델·특징·임계값을 다시 선택하지 않는다. 최종 표에 세 모델의 수치를 보여도 선택 모델은 freeze에 고정된 것이다.

실패는 **실제 IoU < 0.7**이며, 예산은 eligible pool의 5/10/20%를 **올림**한 프레임 수다.
임계값 비교는 저장된 target의 정밀도를 유지한다. float32의 0.7을 먼저 float64로 바꿔
경계값 자체를 0.7 미만으로 세는 오류를 방지하며, 보고서에 target dtype을 기록한다.
낮은 예상 IoU, 낮은 global lane confidence, 높은 global entropy, Random을 같은 pool에서 비교한다.
점수 동점은 sample_id 오름차순, Random은 고정 seed에서 100회 반복한다.
undefined 프레임을 선택해도 예산을 소비한다. Recall·precision·발견 수·Random 기대값·Oracle 진단을 따로 저장한다.
프레임이 서로 비슷하거나 독립 부모 그룹이 적으면 frame 수만으로 정밀한 일반화 오차를 주장하지 않는다.

## 현재 검증의 범위

기존 주행 자료 16,044프레임을 부모·시간·이동 간격으로 나눠 회귀 비교를 실행했다.
같은 경로를 공유한 개발 비교보다, 100m 공간 cell과 20m buffer를 적용한 탐색 평가의 오차가 컸다.
후속 신규 정지 2,272행은 수집 전 학습·개발·후보·최종 역할을 배정해 평가했다.
원래 고정 RF의 정지 최종 MAE는 0.0913, 주행 보조 3,111행은 0.0800이었다.
이후 f1/g1의 새 주행 검증과 개발 전용 경보 보정도 실행했다.
[현재 개발 현황](../project/개발현황.md)과 [주 실험 결과](../project/품질추정_실험결과_20261116.md)를 함께 본다.
수집 layout 변화는 새 지도 일반화가 아니다.
동일 예산 추가학습·replay-only 대조군은 [인지 모델 갱신 실험](선별자료_인지모델_재학습.md)에 구현했다.
선별 성능과 추가학습 효과를 별도로 보고하며, ROS를 포함한 실시간 전체 지연은 후속 검증 대상이다.
재실행은 새 출력 이름을 사용하며 실패한 run도 원인을 포함해 보존한다.

## 품질 저하 경보의 평가

`quality_estimation.metrics.failure_detection_metrics(y, estimated_iou, threshold=.7)`는
회귀값으로 만든 고정 경보를 평가한다. 실제 IoU와 예상 IoU에 각각 엄격한 `< threshold`를
적용하며 저장된 배열의 부동소수점 정밀도를 유지한다. 정답이 미정의인 행은 음성으로 바꾸지 않는다.

TP/FP/FN/TN, 정밀도·재현율·오경보율·경보 비율, AUROC와 AP를 함께 반환한다.
실제 정답 클래스가 하나뿐이면 AUROC는 미정의다. 저품질 정답이 없으면 AP·재현율도 미정의이며,
모든 장면이 저품질인 구간에서 높은 재현율만으로 좋은 회귀·분별 성능을 확정하지 않는다.
AP는 저품질 비율과 함께 해석한다. 임계값 0.7은 주행 안전 임계값이 아니다.

품질 추정 성능과 선별 후 인지모델 개선 효과는 별도로 평가한다.
새 날씨·시각 평가에서도 모델·특징·임계값을 먼저 고정하고, RGB만 사용하는 추론을 완료한 후
정답을 연결한다. 같은 지도·경로에서 얻은 결과와 다른 지도·날짜의 일반화 검증을 구분한다.

## 11/16 오후 버전 쌍과 다음 주기 연결

갱신 모델의 X/y 재생성·g1 학습·RGB 단독 추론은 검증된 `--adaptation-run`을 명시한다.
기본 f0는 유지하고, 서로 다른 인지 checkpoint와 품질 bundle의 연결은 거부한다.
개발 자료 전용 경보 보정, GT 없는 우선·무작위 감사 검수 대기열, 기존 성능 유지에 따른 갱신 판단은
[버전 쌍·경보·채택 판정](버전쌍_경보_갱신판정.md)을 따른다.
