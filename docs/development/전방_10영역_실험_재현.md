# 전방 10영역 특징과 차선 품질 추정 재현

고정된 전방 RGB와 TwinLiteNet+ Medium v6의 출력을 이용해 영역 특징을 만들고, 영역별 추정치를 합쳐 전체 차선 IoU를 예측한다. 실행 중인 기본 56차원 품질 추정기와 별도로 평가하는 실험 명령이다. [카메라 프로파일](../../config/roi10_front_v1/profile.json) · [영역 특징 코드](../../src/quality_estimation/roi10.py) · [회귀식 구현](../../src/quality_estimation/roi10_quality.py)

## 영상 한 장에서 환경 특징 확인

저장소 루트에서 Python 모듈 경로를 설정한다. 이미지 입력은 이 프로파일의 원본 1280×720 전방 영상이다. 90도 수평 화각과 2도 피치로 설치한 카메라를 기준으로 했다. 다른 차량이나 카메라에는 보닛과 수평선의 재보정이 필요하다.

```bash
export PYTHONPATH="$PWD/src"
python -m quality_estimation.roi10 --image front.png --output scene.json
```

| 키 | 내용 |
|---|---|
| `nodes` | 상부·원거리·근거리의 좌·중앙·우와 보닛 순서로 10×8. 밝기 평균, 색차, 밝기 표준편차, 다크 채널 중앙값, 국소 대비, 경계 선명도, 고휘도 비율, 중앙값 필터 잔차 |
| `signed_differences` | 코드의 고정 12개 방향쌍에 대해 앞 영역 값에서 뒤 영역 값을 뺀 12×8 배열 |
| `haze30` | 전체 10영역의 색차·다크 채널·국소 대비. 센터를 학습할 때 쓴 평균·표준편차로 표준화한 뒤 군집에 배정 |
| `sky27` | 상부 세 영역에서 RGB로 예측한 하늘 픽셀의 8개 통계와 각 하늘 점유율. 빈 하늘 영역은 통계와 점유율이 모두 0 |
| `weather100` | `sky27`과 기존 고정 7패치 특징 73개를 결합한 날씨 분류 후보 |
| `hour187` | `sky27`과 영역별 블록 분포 160개를 결합한 촬영 시각 분류 후보 |
| `output40` | 선택 입력 `--head-maps`를 줄 때 생성. 네 개의 320×180 바이트 맵을 10영역에서 평균한 값. 채널 순서는 주행가능 면적, 차선 면적, 흰·노란 차선 확률 합, 마킹 엔트로피 |

학습용 Semantic의 하늘 픽셀로 한 번 학습한 결정트리와 고정 보닛 마스크를 프로파일에 포함했다. 영상 처리 때는 RGB로 하늘을 구한다. 블록 분포는 상부의 색상·채도, 원거리의 최저 밝기·선명도, 근거리의 국소 대비, 보닛의 최저 밝기를 사용한다. 색상 히스토그램에는 채도를 가중한다.

## 품질 추정기의 학습과 독립 평가

기존 인지모델 실행 환경과 고정 체크포인트를 사용한다. 위치·주행 단위 중복을 명령에서도 검사하려면 모든 행에 문자열 `split_group`을 넣는다. 학습에 이 필드를 썼다면 개발·보정·평가 팩도 같은 단위로 지정한다. 각 JSONL 행에는 `sample_id`, `view`가 `front`인 값, 데이터 루트 기준 `image` 경로를 넣는다. `--paired`에서는 같은 프레임의 `semantic` 경로도 필요하다. 원본 SHA-256이나 디코딩 픽셀 해시가 있으면 함께 전달해 입력을 검증한다. 먼저 주행·위치 단위로 학습, 보정, 평가 매니페스트를 분리한다. 아래에서 `$ROI_DATA`는 팀원이 사용하는 원본 루트다.

```bash
python -m quality_estimation.roi10_study build --manifest train.jsonl --data-root "$ROI_DATA" \
  --paired --purpose training --output train-pack
python -m quality_estimation.roi10_study fit --data train-pack --output regional-rf

python -m quality_estimation.roi10_study build --manifest evaluation-rgb.jsonl --data-root "$ROI_DATA" \
  --purpose evaluation --output evaluation-pack
python -m quality_estimation.roi10_study score --model regional-rf --data evaluation-pack --output scores
```

`build`의 기본 경로는 RGB만 열어 기존 X56, 각 영역의 RGB 8개, 두 헤드에서 얻은 4개 통계, 원래 모델 격자의 차선 예측 픽셀 수를 기록한다. `--paired` 경로는 추가로 모델 격자의 TP·FP·FN을 생성한다. 흰·노란 차선과 공식 Semantic 팔레트에 기존 규칙을 적용한다. 전체 합집합이 빈 학습 표본은 회귀 적합에서 제외한다. 독립 평가 시 학습 ID나 픽셀이 겹치면 거부한다. 산출물에는 입력 해시, 프로파일·인지모델 식별자, 출력 파일 해시와 완료 표식이 들어간다. 학습 번들은 같은 scikit-learn 버전에서 읽는 것을 기준으로 한다.

각 영역의 현재 RGB·출력, 해당 영역 예측 면적 비율, 영역 ID, 영상 전체의 기존 8개 통계를 입력으로 사용한다. 첫 번째 RF는 예측 차선 픽셀 중 정답 비율을 학습한다. 두 번째 RF는 놓친 차선 픽셀의 영역 면적 비율을 로그 변환해 학습한다. 전체 추정치는 열 영역의 예상 정검출 수 합을 전체 예상 합집합으로 나눈 값이다. `scores.npz`에는 `estimated_iou`, `estimated_union`, `per_region_iou`, `per_region_union`, `estimated_true_positive`, `estimated_missed`가 있다. 예상 합집합이 0인 행·영역의 점수는 0으로 기록하므로 해석 시 합집합 필드를 함께 읽는다.

## 환경 분류 재현

`--native-histograms` 옵션을 주면 원본 해상도에서 10×10 픽셀 블록의 최저 밝기, 국소 대비, Sobel 기울기, 중심 색상과 평균 채도를 각각 10구간으로 집계한다. 블록 중심으로 영역을 정하고 특징마다 해당 영역의 블록 수로 나눈다. 상부 3영역을 모두 사용하는 날씨 입력 `weather150`과 열 영역에서 기울기를 제외한 시각 입력 `hour400`이 나온다. 이 원해상도 특징과 위 표의 `hour187`은 별도 실험이다.

```bash
python -m quality_estimation.evaluate_scene_conditions --native-roi10 \
  --train-manifest scene-train.jsonl --eval-manifest scene-eval.jsonl \
  --data-root "$ROI_DATA" --output-dir scene-evaluation
```

이 명령은 `parent_session_id`와 `condition.weather`·`condition.hour`가 있는 매니페스트를 사용한다. 평가 시 예측기가 읽는 영상 채널은 전방 RGB다. 수집 설정은 정답 채점에만 사용한다. 학습과 평가 사이에 부모 세션·표본 ID·픽셀 해시 중 하나라도 겹치면 평가를 중단한다. 연구 자료처럼 한 위치가 여러 시각·날씨로 반복되면 같은 위치 전체를 한쪽에 넣는다. `trained_class_evaluation`에는 학습된 클래스 안에서 측정한 정확도, `circular_mae_hours`에는 알려진 모든 시각에서 측정한 24시간 주기의 시간 오차를 기록한다.

## 영역별 날씨 확률 결합

학습 매니페스트에는 날씨 정답 `condition.weather`와 공간 묶음 `split_group`을 둔다. 같은 위치에서 조건만 바꾼 사진은 같은 묶음으로 두고, 정차 위치가 인접하면 같은 도로 구간으로 묶는다. 세 개 이상의 학습 묶음이 필요하며 각 공간 교차검증의 학습 부분에 모든 학습 날씨가 있어야 한다. 평가용 매니페스트에는 학습과 겹치지 않는 묶음을 쓰고 날씨 정답을 생략할 수 있다.

```bash
python -m quality_estimation.roi10_study build --weather-views --purpose training \
  --manifest weather-train.jsonl --data-root "$ROI_DATA" --output band-train
python -m quality_estimation.roi10_study fit-weather --data band-train --output band-model
python -m quality_estimation.roi10_study build --weather-views --purpose evaluation \
  --manifest weather-eval-rgb.jsonl --data-root "$ROI_DATA" --output band-eval
python -m quality_estimation.roi10_study score-weather --model band-model \
  --data band-eval --output band-predictions
```

각 영역에서 전체 RGB 8통계, 예측 하늘·도로 위의 RGB 8통계, 그 점유율, 반해상도 블록 분포 50개를 계산한다. 보닛은 실루엣 전체를 사용한다. 영역별 RF 10개의 날씨 확률을 상부·원거리·근거리·보닛 안에서 클래스별 최댓값으로 모은다. 결합 로지스틱 회귀는 학습 중 보지 않은 도로 구간에 낸 예측으로 적합한다. `weather_scores.npz`의 `classes`, `probabilities`, `predicted_weather`가 표본별 결과다. 날씨 정답과 Semantic을 입력으로 제공하지 않고도 점수를 낼 수 있다. [확률 결합 코드](../../src/quality_estimation/roi10_weather.py)

공용 명령으로 6개 도로 구역의 36위치·1,728장을 다시 학습했다. 신규 정차 648장과 세 번의 신규 주행 1,448장에서 연구 코드와 예측 날씨 2,096개가 모두 일치했다. 각 영역의 67개 특징에서 최대 절대 차이는 1.8×10⁻⁷, 클래스 확률의 최대 차이는 0.00173 이하였다.

## e-means 환경 태그

```bash
python -m quality_estimation.roi10_study fit-centers --data train-pack \
  --method emeans --clusters 8 --seed 0 --output roi10-centers
```

학습할 때는 `faiss.contrib.e_means.NumpyEmeans`를 제공하는 Faiss가 필요하다. 같은 명령에서 `--method kmeans`로 대조군을 만들 수 있다. `fit-centers`는 학습 팩의 10영역 색차·다크 채널·국소 대비를 위치별로 표준화한 후 중심을 학습한다. `infer_images` 또는 `stream_review`의 선택 인자 `--environment-centers roi10-centers/environment_centers.json`을 주면 별도 Faiss 설치 없이 RGB에서 중심 ID·최근접 거리·두 번째 중심과의 거리 차이를 구한다. 자동 경보를 쓰려면 같은 중심 해시로 보정한 별도 정책이 필요하다.

이번 실험에서 학습한 8개 중심을 공용 JSON으로 제공한다. 정차 신규 648장과 첫 두 주행 965장에서 별도로 다시 적합한 중심의 배정 ID가 모두 일치했다. [고정 e-means 중심과 전처리 계수](../../config/roi10_front_v1/haze30_emeans_k8.json)

## 사후 GT 연결

```bash
python -m quality_estimation.roi10_study build --paired --purpose evaluation \
  --manifest labeled-subset.jsonl --data-root "$ROI_DATA" --output labeled-pack
python -m quality_estimation.roi10_study evaluate --scores scores --data labeled-pack --output metrics
```

점수 생성 후 일부 장면에만 GT가 도착해도 같은 표본 ID와 디코딩 픽셀 해시로 연결한다. `metrics.json`에 전체 점수 장수, 도착한 라벨, 실제 합집합이 빈 행, 전체 MAE와 편향, 실제 합집합 32픽셀 이상인 영역의 MAE를 남긴다. 하위 10% 검수 예산은 점수를 매긴 전체 풀에 적용하고, 선택 후 GT가 없는 장수도 집계한다. 이 전체 풀 순위와 64프레임 창을 순차 처리한 온라인 검수 결과는 다르다. 별도로 보정한 점수 기준을 실제 경보와 비교하려면 `--alarm-cutoff`를 전달한다.
